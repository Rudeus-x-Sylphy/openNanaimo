# 构建与验证

以下命令均从仓库根目录执行。构建环境使用Python、TinyCC、.NET SDK及使用者自备的Nanaimo客户端；脚本支持指定仓库外工具路径。

## 1. Source closure 与 package

```powershell
python -B scripts/refresh_source_manifest.py
python -B scripts/verify_package.py --source-only
python -B scripts/verify_package.py
```

当前源码闭包为221个文件。`adapter_manifest.json` 登记256个 runtime 文件，目录另含清单自身；`open_release_manifest.json` 登记268个 critical files。验证器核对大小、SHA-256、递归 include、活动 runtime 清单和公开文本。

完整package对使用者自备的 `game.exe` 执行存在性检查，对项目运行文件执行大小及SHA-256校验。

## 5. 完整 adapter 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_complete_adapter.ps1 `
  -OutputRoot '<全新候选目录>' `
  -TccPath '<TCC目录>/tcc.exe' `
  -DotnetPath '<.NET 8 SDK目录>/dotnet.exe' `
  -ResourceDataRoot '<adapter数据目录>' `
  -SelfTest
```

输出为 `net6.0/win-x64/self-contained`，包含 `Nanaimo.Adapter.exe`、managed DLL、`nanaimo_gameplay_bridge.exe`、资源数据及 `adapter_manifest.json`。构建使用全新输出目录，清单按当前产物生成。启动式 `--self-test` 使用固定内部端口，执行前要求全部测试端口空闲。

## 7. 客户端兼容派生

```powershell
python -B scripts/prepare_client_compatibility.py `
  --source-root '<客户端根目录>' `
  --output-root '<全新派生目录>' `
  --furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --dungeon7 --overwrite
```

客户端派生覆盖家具Index、两类结算手动确认、礼物预览、正确窗口类型的空地购房、屋外外观系统及地宫7道路和别名；`--native-state` 撤回已登记的旧复活HUD和P恢复代码，复活次数与连续关卡P状态由adapter原生协议及生命周期维护。屋外组件由 `prepare_client_compatibility.py` 与 `apartment_exterior_panel.py` 配套提供，包含菜单与面板、外观／标语牌资源、中文文本和原生保存提示。派生工具按PE结构和精确站点识别输入，生成本地备份及逐项校验报告；完整范围见[客户端兼容说明](完整适配器与客户端兼容说明.md)。
