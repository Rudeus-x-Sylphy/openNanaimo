# 构建与验证

以下命令均从仓库根目录执行。构建环境使用Python、TinyCC、.NET SDK及使用者自备的Nanaimo客户端；脚本支持指定仓库外工具路径。

## 1. Source closure 与 package

```powershell
python -B scripts/refresh_source_manifest.py
python -B scripts/verify_package.py --source-only
python -B scripts/verify_package.py
```

当前源码闭包为311个文件。`adapter_manifest.json` 登记217个 runtime 文件，目录另含清单自身；`open_release_manifest.json` 登记254个 critical files。运行脚本按可用.NET引用程序集选择 net6.0 或 net8.0；当前发布使用 net8.0/win-x64 self-contained。验证器核对大小、SHA-256、递归 include、活动 runtime 清单和公开文本。

完整package对使用者自备的 `game.exe` 执行存在性检查，对项目运行文件执行大小及SHA-256校验。源码验证使用`--source-only`；完整包验证要求目标目录提供合法取得的客户端。两种验证模式分别记录结果，`ValidateOnly`覆盖启动契约，客户端操作采用独立验收。

## 5. 完整 adapter 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_complete_adapter.ps1 `
  -OutputRoot '<全新候选目录>' `
  -TccPath '<TCC目录>/tcc.exe' `
  -DotnetPath '<.NET 8 SDK目录>/dotnet.exe' `
  -ResourceDataRoot '<adapter数据目录>' `
  -SelfTest
```

固定native端口被占用时，构建候选并运行独立 `--<feature>-self-test`；启动式自检使用空闲测试端口。

输出为当前可用目标框架的 `net6.0/win-x64/self-contained` 或 `net8.0/win-x64/self-contained`，包含 `Nanaimo.Adapter.exe`、managed DLL、`nanaimo_gameplay_bridge.exe`、资源数据及 `adapter_manifest.json`。构建使用全新输出目录，清单按当前产物生成。启动式 `--self-test` 使用固定内部端口，执行前要求全部测试端口空闲。
