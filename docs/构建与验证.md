# 构建与验证

以下命令均从仓库根目录执行。构建环境使用Python、TinyCC、.NET SDK及使用者自备的Nanaimo客户端；脚本支持指定仓库外工具路径。

## 1. Source closure 与 package

```powershell
python -B scripts/refresh_source_manifest.py
python -B scripts/verify_package.py --source-only
python -B scripts/verify_package.py
```

当前源码闭包数量以`manifest/source_closure.json`的`count`为准。`adapter_manifest.json` 登记217个 runtime 文件，目录另含清单自身；`open_release_manifest.json` 逐项登记当前发布关键文件。运行脚本按可用.NET引用程序集选择 net6.0 或 net8.0；当前发布使用 net8.0/win-x64 self-contained。验证器核对大小、SHA-256、递归 include、活动 runtime 清单和公开文本。

完整package对使用者自备的 `game.exe` 执行存在性检查，对项目运行文件执行大小及SHA-256校验。源码验证使用`--source-only`；完整包验证要求目标目录提供合法取得的客户端。两种验证模式分别记录结果，`ValidateOnly`覆盖启动契约，客户端操作采用独立验收。

成套程序与PET资源更新由`deploy_pet_catalog_update.py`维护安装预检、审核授权、逐文件备份、安装回执及恢复。`--reviewed-before`以相对路径到旧文件SHA-256的审核映射授权清单外既有文件，当前字节须与登记摘要完全匹配；`--rollback`按安装回执维护恢复合同。

计分表使用.NET 8生成器，按DCC7战斗目录与HP目标键覆盖484547个目标行及864组关卡资料，校验行域连续性、重叠、键覆盖及输入SHA-256。生成器按普通击杀资格汇总满分，type4仅处理命中的目标与随机道具箱计0分。专项覆盖目标分值、关卡满分、首次终结、组队归属、个人分数、周期重置及评级阈值；全目录864槽通过生产HP计分构造检查，18个调整槽在有效目标全部终结时达到满分。成功角色HP1与HP50000同评级，失败为F，满分差1分为A。验证范围为计分资格与生产路径构造，客户端目标生成、可见性和完整场景采用独立运行验收。
