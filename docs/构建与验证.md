# 构建与验证

以下命令均从仓库根目录执行。仓库不附带 Python、TinyCC、.NET SDK、Nanaimo 客户端或完整 adapter 数据。

## 1. 工具

| 工具 | 用途 |
|---|---|
| Python 3.11 或兼容版本 | 清单、导出、单元测试和 GUI 库存后端 |
| TinyCC 0.9.27 i386 Windows | 原生 adapter 与地宫桥接构建 |
| .NET 8 SDK | managed 源码构建与 publish |
| Windows PowerShell / WinForms | GUI 与发布脚本 |

构建脚本不会下载工具。完整 adapter 构建可通过 `-TccPath` 和 `-DotnetPath` 指定仓库外工具。

## 2. source-only 检查

```powershell
python -B scripts/verify_package.py --source-only
```

当前检查 `manifest/source_closure.json` 中164个原生 include 和 managed 构建输入，核对大小、SHA-256、递归 include、路径和公开文本。该入口不需要客户端、资源或已构建 adapter。

完整 Python 回归：

```powershell
python -m unittest discover -s scripts -p 'test_*.py' -v
```

当前结果：91项通过，6项因 source-only 环境缺少外部客户端或符号链接能力而跳过。

## 3. 构建完整 adapter

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_merged.ps1 `
  -TccPath '<TCC目录>/tcc.exe' `
  -DotnetPath '<.NET 8 SDK目录>/dotnet.exe' `
  -ResourceDataRoot '<已准备的adapter数据目录>' `
  -SelfTest
```

输出目录默认是 `adapter_runtime/`：

```text
Nanaimo.Adapter.exe
nanaimo_gameplay_bridge.exe
adapter_manifest.json
资源/数据/...
```

构建步骤：

1. TCC 编译 `adapter/nanaimo_gameplay_bridge.c`；
2. .NET 8 SDK publish managed 宿主为 `net6.0/win-x64/self-contained`；
3. 复制使用者准备的数据目录；
4. 生成二进制大小／SHA-256 manifest；
5. `-SelfTest` 使用隔离 profile、状态库和端口运行完整检查。

self-test 覆盖：

- 状态交换和角色资料注册；
- 登录、世界入口、背包、任务、拍卖和愿望清单；
- 队伍隔离地宫桥接；
- 角色经验和地宫通关差量；
- 宠物阶段、等级、经验、CF72／CF88／C44C／C379 一致性；
- 商城货币、数据库重开和地宫中未提交货币；
- GM 离线编辑和在线拒绝边界。

`.NET 6` 目标会产生生命周期警告；当前构建仍成功。若后续迁移运行目标，需要重新验证旧 Windows 环境和原客户端依赖，不能只消除警告。

## 5. GUI 自测

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -STA -File gui_launcher/nanaimo_launcher.ps1 -SelfTestLaunchModes
powershell -NoProfile -ExecutionPolicy Bypass -STA -File gui_launcher/nanaimo_launcher.ps1 -SelfTestLayout
powershell -NoProfile -ExecutionPolicy Bypass -STA -File gui_launcher/nanaimo_launcher.ps1 -SelfTestTitleIO
powershell -NoProfile -ExecutionPolicy Bypass -STA -File gui_launcher/nanaimo_launcher.ps1 -SelfTestCatalogPreview
```

自测不启动客户端。布局检查覆盖1000×870／1120×940和100%／125%／150%缩放，并验证可见界面不暴露连接模式、地址或命令行。

## 6. 专项测试

```powershell
python -m unittest scripts.test_shop_appearance_protocol -v
python -m unittest scripts.test_native_ui_protocol -v
```

- 商城／整容：6/6通过。
- 原生 UI 协议回归：4/4通过。

复活专项检查包含购买、激活、计数、death latch、`CF95 -> CF96/CF84/CF72` 顺序、幂等和重启恢复。未发现需要修改的确定性 adapter Bug。

## 7. 完整运行目录校验

准备好客户端、GUI 数据和 `adapter_runtime` 后；P03 村庄 pack 与 SSTG/PON 别名可按兼容派生脚本从使用者自己的游戏文件生成：

```powershell
python -B scripts/verify_client_baseline.py  # 仅结构诊断，不是哈希门禁
python -B scripts/verify_package.py
start_nanaimo_launcher.bat -ValidateOnly
```

`verify_client_baseline.py` 只做 PE32 结构检查，输出大小和 SHA-256 仅供诊断，不作为支持列表。`-ValidateOnly` 不检查 `game.exe` 的大小／哈希，也不检查 P03 pack、SSTG/PON 别名或其他本地派生产物；它校验：

- `adapter_manifest.json` 中完整 adapter 与桥接文件；
- GUI 目录、预览、库存后端和固定 Network 配置。

## 8. 发布前检查

```powershell
python -B scripts/refresh_source_manifest.py
python -B scripts/verify_package.py --source-only
python -m unittest discover -s scripts -p 'test_*.py' -v
git diff --check
```

随后在发布目录重复：

```powershell
start_nanaimo_launcher.bat -ValidateOnly
start_nanaimo_launcher.bat -SelfTestLayout
```

发布清单应记录 GUI、adapter manifest、客户端外部依赖、村庄 pack、SSTG/PON 补丁和启动入口的大小与 SHA-256。

## 9. 验证语言

- **静态／源码链闭合**：函数、字段、状态和响应路径一致。
- **adapter 构造验证通过**：自动检查确认字节、顺序、事务和持久化。
- **原客户端运行观察**：真实客户端在特定输入下产生可归因结果。
- **端到端验收**：从 GUI 一键启动到可见玩法、重进和重登均完成。

当前发布达到前两层；宠物升级显示、整容动画、复活控制恢复、家具选择和拉米诺斯村地宫7完整试玩仍需要原客户端运行观察。
