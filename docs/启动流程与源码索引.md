# GUI 启动链、知识库与源码阅读索引

本文按一键入口、资料保存、完整 adapter、地宫桥接和客户端连接顺序介绍源码。Python、TinyCC、.NET SDK 和 Nanaimo 客户端均由使用者自行准备。

## 路径别名

- `<OPEN_ROOT>`：运行根目录／仓库根目录。
- 完整 adapter 构建结果：`adapter_runtime/`。
- 原生地宫源码入口：`adapter/`，组件：`release/components/`。
- managed 玩法源码：`managed/`，无界面宿主：`managed-host/`。

## 一图看懂

```text
start_nanaimo_launcher.bat
  -> powershell.exe -STA gui_launcher/nanaimo_launcher.ps1
       -> 读取 profile、目录、预览和 adapter manifest
       -> dot-source inventory_admin_gui.ps1
       -> 创建 WinForms 控件
       -> ShowDialog

[保存配置]
  -> Save-Profile
       -> 校验角色、数值、技能、称号和本地库存
       -> 写 nanaimo_launcher_profile.ini/json

[仅启动适配器]
  -> Save-Profile
  -> Test-AdapterBinary
  -> Start-LocalAdapter
       -> Nanaimo.Adapter.exe
       -> 内部启动 nanaimo_gameplay_bridge.exe
       -> 等待 11005 / 11999 / 12050

[一键进入 Nanaimo]
  -> Stop-LocalAdapter
  -> Save-Profile
  -> Test-ClientBinary
  -> Install-LaunchModeConfig
  -> Start-LocalAdapter
  -> Register-ClientProfile -> TCP 11999 -> OK\n
  -> 停止同路径旧 game.exe
  -> Start-Process game.exe [固定 Network 参数]
```

## 1. Windows 入口

| 顺序 | 文件／锚点 | 作用 |
|---|---|---|
| 1 | `start_nanaimo_launcher.bat` | 切换到运行根目录，以 `-STA` 启动 GUI。 |
| 2 | `gui_launcher/nanaimo_launcher.ps1` | 读取客户端路径、adapter runtime、profile、日志和目录；只对项目自带 adapter 使用 manifest 哈希。 |
| 3 | `gui_launcher/inventory_admin_gui.ps1` | 本地库存编辑界面。 |
| 4 | `gui_launcher/inventory_admin_backend.py` | 库存 snapshot/apply 和备份。 |
| 5 | `gui_launcher/client_connect.ps1` | 命令行连接器、资料注册和客户端启动。 |

## 2. 固定的本地 Network 启动

GUI 只接受 `network` 和 `127.0.0.1`，不显示地址或模式编辑控件。`Install-LaunchModeConfig` 从 `gui_launcher/launch_modes/gamestartoption.network.ini` 生成 `StateOption/gamestartoption.ini`。

| 配置 | ClientArgs | adapter | Profile 注册 |
|---|---|---|---|
| Network (`-q`) / `127.0.0.1` | `-q`, `:1:1:0:3:4:-i`, `5:-r`, `6:7:1:127.0.0.1:` | 一键入口总是重启完整 adapter | TCP 11999 |

客户端路径固定为 `<OPEN_ROOT>/game.exe`。Standalone 构造器只用于协议研究，不是 GUI 选项。

## 3. Profile 和本地库存

### GUI 侧

| 锚点 | 作用 |
|---|---|
| `Read-Ini` / `Read-KeyValueFile` | 读取 profile 和状态。 |
| `Encode-NameHex` / `Decode-NameHex` | 名称与 GBK 十六进制身份互转。 |
| `Get-ResourceSelection` | HP/MP、攻击、防御、货币、钥匙和期限字段。 |
| `Get-SkillSelection` | 技能路线、16个等级和 Z/X 槽。 |
| `Write-DungeonGradeState` | 固定称号等级写入。 |
| `Save-Profile` | 完整校验后写 INI/JSON 和库存状态。 |

### 库存管理

```text
inventory_admin_gui.ps1
  -> 选择 tools/python/python.exe；不存在时使用 PATH 中 python
  -> inventory_admin_backend.py snapshot
  -> 编辑衣物、宠物、游戏道具、家具和卡片
  -> inventory_admin_backend.py apply
```

adapter 运行时会缓存状态，因此 GUI 在写入前要求停止 adapter；“一键进入 Nanaimo”会自动执行停止、保存和重启。

## 4. GUI 三个动作

### 保存配置

只写入 profile、称号和库存，不启动 adapter，不启动客户端。

### 仅启动适配器

```text
adapterBtn
  -> 已运行：Stop-LocalAdapter
       -> 写 adapter_data/stop.request
       -> 等待 Nanaimo.Adapter.exe 正常退出
       -> 必要时终止残留桥接进程
  -> 未运行：Save-Profile -> Start-LocalAdapter
```

### 一键进入 Nanaimo

```text
clientBtn
  -> Stop-LocalAdapter
  -> Save-Profile
  -> Test-ClientBinary
       -> 仅确认 game.exe 文件存在
       -> 不检查脱壳实现的大小／哈希
       -> 不检查本地派生的 pack、SSTG 或 PON
  -> Install-LaunchModeConfig
  -> Start-LocalAdapter
  -> Register-ClientProfile 127.0.0.1:11999
  -> 启动 game.exe
```

`Start-LocalAdapter` 不使用固定睡眠后直接放行，而是在10秒窗口内轮询 `11005/11999/12050`，三个入口全部可连接才返回。

## 5. 完整 adapter 源码入口

### 构建入口

```text
scripts/build_merged.ps1
  -> TCC 编译 adapter/nanaimo_gameplay_bridge.c
  -> .NET 8 SDK publish managed-host（net6.0/win-x64/self-contained）
  -> 复制使用者准备的 adapter 数据
  -> 写 adapter_runtime/adapter_manifest.json
  -> 可选 -SelfTest
```

生成：

```text
adapter_runtime/Nanaimo.Adapter.exe
adapter_runtime/nanaimo_gameplay_bridge.exe
adapter_runtime/adapter_manifest.json
adapter_runtime/资源/数据/...
```

原生独立入口仍可用 `scripts/build_adapter.ps1` 确定性重建：

```text
adapter/nanaimo_adapter.c
adapter/nanaimo_adapter_testports.c
adapter/nanaimo_gameplay_bridge.c
```

`manifest/source_closure.json` 当前记录164个原生 include 和 managed 构建输入，以及三个 reviewed 原生输出。

### managed 玩法层

| 路径 | 作用 |
|---|---|
| `managed/Services/NetworkAdapterService*.cs` | 登录、村庄、任务、商城、社交、交易、竞技、娱乐和地宫路由。 |
| `managed/Services/DatabaseService*.cs` | 角色、库存、任务、关系、拍卖、公寓和地宫差量事务。 |
| `managed/Services/PetProgression.cs` | 宠物等级、阶段、攻击和奖励加成。 |
| `managed/Services/NativeDungeonState.cs` | 5120字节地宫状态交换结构。 |
| `managed/Services/NativeDungeonClient.cs` | F100/F101/F102/F103 内部桥接。 |
| `managed-host/Program.cs` | 进程生命周期、端口、停止请求和 self-test。 |

### 原生地宫层

`release/teamplay_common.inc` 仍是原生功能拼装点，包含资料、技能、卡片、Boss、目标、掉落、复活、商城、公寓、多人同步和地宫战斗。`NANAIMO_GAMEPLAY_BRIDGE` 构建额外启用 `release/components/game_session/managed_bridge.inc`。

## 6. 端口

| 端口 | 作用 |
|---:|---|
| 11005 | 客户端登录入口。 |
| 11999 | GUI 角色资料注册。 |
| 12050 | 客户端世界入口。 |
| 22051..22054 | 竞技／娱乐入口。 |
| 51005 / 51999 / 52050 | 主地宫桥接实例。 |
| 62050..62055 | 主地宫内部连接。 |
| 53000..53998 | 按队伍隔离的额外地宫实例。 |
| 3534 | 客户端 P2P 发布／防火墙规则。 |

所有监听应绑定本机回环；固定端口被占用时完整 adapter 直接拒绝启动，不动态改到客户端未知端口。

## 7. 地宫状态交换

```text
managed character / inventory / tasks
  -> NativeDungeonState.Create
  -> F100 导入5120字节状态
  -> 原生地宫请求／响应
  -> F102 快照
  -> ApplyNativeDungeonDeltaAsync
```

当前关键偏移：

| 偏移 | 内容 |
|---:|---|
| 0..47 | 版本、角色、等级经验、HP/MP、两个 u64 余额 |
| 48..95 | 技能点、技能槽、复活次数、快捷栏期限、宠物、战斗参数、姓名长度和性别 |
| 96..159 | GBK 姓名、外观、宠物阶段／最大阶段、宠物等级／经验 |
| 160..271 | 16个技能等级、6个快捷栏槽 |
| 272..1951 | 卡片数量 |
| 1952..3995 | 最多255条道具代码／数量 |
| 4000..5023 | 原生实例句柄 |
| 5024..5119 | 地宫称号、最高前沿和60字节通关 mask |

角色经验、宠物经验、货币、卡片和道具按差量事务提交，提交ID用于幂等。

## 11. 验证范围

- 源码清单、确定性原生构建、managed build、完整 adapter self-test、Python 回归和 GUI 自测相互独立。
- adapter 构造通过不等于原客户端可见验收。
- 运行问题可记录客户端哈希作为诊断指纹，并应保留 adapter manifest、角色、连接、操作时间和首个异常边界；客户端哈希不是支持门禁。
