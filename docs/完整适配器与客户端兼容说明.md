# 完整 adapter 与客户端兼容说明

本文描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。运行输入由使用者从合法取得的客户端副本准备；仓库提供 adapter、启动器、派生工具与兼容性数据。原始文件备份和哈希用于本机恢复与诊断。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 确认 `game.exe` 存在，并调用 `adapter_runtime/Nanaimo.Adapter.exe --tools compatibility --character-creation --furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --apartment-recommendation --dungeon7 --overwrite --apply`；对已知 PE 布局应用新账号建角、家具、结算、礼物预览、空地购房、房屋推荐和屋外装修补丁，迁移已登记的旧复活显示／P 弹恢复编码；表情使用原生代码；
4. 从使用者自己的文件生成本地覆盖，逐文件原子应用并逐项复核 EXE、P03 道路及 SSTG/PON 别名；适配器通过原生 CF71/CF72 维护次数与跨关状态，通过固定 C393 契约提供场景对象；
5. 将原文件按内容 SHA-256 备份到 `adapter_data/client_compatibility_overlay/backups/`；哈希作为本机备份与诊断指纹；
6. 启动完整 adapter，并等待 `11005/11999/12050` 全部可连接；
7. 经 `11999` 注册角色资料；
8. 只在兼容报告 `verification.all_pass=true` 后启动 `game.exe`。

### 新手引导与启动器装备隔离

adapter 按角色档案和引导阶段投影登录外观。`TutorialCompleted=0` 的角色从创建时保存的 `Appearance` 恢复基础外观，教程阶段的 D6特效与D7宠物置0；首次进村、尼莫对话及重登共享同一角色档案。社交新账号进入等级1、零余额、零库存的纯新手创建流程，已有账号直接沿用其角色、进度和装备。INI、sidecar、数据库外观、装备所有权及宠物选择各自保持独立生命周期。

引导阶段 `C354` 返回携宠标志为0的 `C355`。有效 `C353` 原子保存完成状态并返回 `C594`，随后 `C354` 恢复普通 `C355 -> C476 -> C44C` 初始化，`C367/C368` 恢复全部装备并进入村庄。身份、长度校验与重复完成幂等继续生效。

自动化回归覆盖男女各4组特效状态、无角色入口、sidecar优先级、引导中重登、有效／非法／重复完成事件、库存阶段门控、首次进村恢复及配置原文保留。验证范围为数据库状态、协议构造与请求顺序。

1. 使用 `--character-creation` 选择此兼容项；GUI及 `--all` 自动包含该项。

### 1.1.2 推荐人提示确认与重新填写

安装本节推荐人兼容项后，登录帧对提示40、41、42使用继续流程：填写不存在的姓名返回提示，填写已有姓名保存推荐关系并继续登录；留空或填写自己的姓名通过本地校验提示后恢复输入。适配器的推荐结果保持10／20／30，首次有效绑定给推荐人增加200推荐点。普通提示继续与本地重填由客户端兼容项提供，与适配器结果码共同构成完整功能。

普通提示确认将对象 `WORD+0x36` 设为0。登录帧原有确认判断在该值为0时切换全局状态25；推荐提示的局部兼容将这三类消息的上层判断值转换为1，同时保留对象自身的真实结果、关闭动画与释放流程。其余消息沿用原有判断。两个本地输入提示在返回时清理建角对象 `+0x3A4` 的等待旗，后续可重新填写并提交。

```text
最大记录数   84
```

客户端在 `frame+10 == 6000` 时再次发送 C392；`0`、`2000` 及其他非 6000 值结束分页。适配器以 `2000` 表示完整快照终态。记录循环按 `count` 消费，紧凑的 `12+12*count` 完整帧覆盖静态读取；固定 1020 字节与清零尾部提供容量边界。家具点击随后进入独立的受保护 Index getter。

### 2.2 客户端兼容边界

一键流程以当前 `game.exe` 为输入，在确认 PE 布局和目标五字节后应用家具站点重定向：

```text
VA 0x0041235F
E9 9C C3 1B 00 -> E9 7C CC 1B 00
```

五字节或 PE 布局不匹配时，工具保持文件不变。该重定向把受保护入口 `0x5CE700` 指向现有的直接 Index getter `0x5CEFE0`；表情协议边界由 C355 独立承载。

### 2.3 家具状态与布局

家具库存按实例关联选取状态、位置、层级和镜像，容量为84件。空房间及多家具布局共享固定C393快照；装修界面支持摆放、保存、取下和重新进入后的布局恢复。客户端家具点击使用 `0x41235F → 0x5CEFE0` 的直接Index入口，布局提交由C411承载。

### 2.4 表情翻页的适配器端协议边界

The launcher leaves the original emotion code at `VA 0x00837220..0x00837263` unchanged. `C354/8 -> C355/728` keeps access open through `+0x3C..+0x77` and the low44 predecessor bits, while preserving the independent score cache: ordinary ratings at `+0x88..+0xC3`, secret ratings at `+0xC4..+0xC7`, and frontier ratings at `+0xC8..+0xDE`. Every write stops before the 17-byte couple name at `+0xDF..+0xEF`; `WORD+0xF0` is the ring suffix. Invalid or absent relationships remain empty-name/zero-ring.

### 2.5 城镇空地购房入口

`--land-purchase` 将空地鼠标命中连接到原生购房确认窗口。窗口按当前街区读取费用，显示金币和推荐点余额，确认后提交所选地块。空地检测、窗口输入互斥、余额门槛、确认和取消均沿用原生界面逻辑。

| 站点 | 当前修改内容 |
|---|---|
| `0x00C396C0` | 房屋更新虚表指针由 `0x0040E912` 改为 `0x00513690` |
| `0x00513690..0x0051374F` | 192字节代码区：先调用原房屋更新，检查空地状态、背景输入许可和有效地块0..19；调用原命中检测 `0x005126A0`，通过工厂参数30创建内部类型25窗口，以购买模式1调用 `0x00401596`，注册窗口并清理输入；无效命中或分配失败退出 |

C37A/C37B余额交互、C36E/C36F购房交互以及金币／推荐点门槛沿用原生流程。当前兼容组合使用factory30／内部type25入口，并保留 `0x0053207E` 的 `85 C0 74 3E` 余额让出分支，兼顾窗口匹配与余额队列消费。

## 3. 拉米诺斯村地宫7兼容链
拉米诺斯村地宫7入口由五个边界共同构成：C355 前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON。原客户端读取 C355 `+0x80..+0x87`，并对 `k=0..21` 的每项要求两个 bit 同时为 `1`。静态链为：C355 分派 `0x0052C100` → 状态构造 `0x00544000` → 前置字段写入 `0x0054EDD0`；移动流程 `0x005000A0` → 前置判定 `0x00509EC0`，逐项检查 `+0x48` 的 bit `2*k` 与 `2*k+1`。

### 兼容链组成

地宫7由前置进度、村庄道路、关卡资源命名、adapter资源映射和嵌套PON共同提供。`--dungeon7` 负责小地图发布边界、道路、已知补制图像撤回及资源别名派生；家具与屋外外观系统通过上面的完整命令同时应用。C355低44位前置字段由适配器在最终构造阶段统一写入，角色进入使用同一状态周期。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- `+0xC8` 关卡显示字节沿用原生语义；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.6 显示边界

小地图初始化 `0x009000D0..0x00900156` 先循环查询原生前置条件并写入各章节开关，随后 `0x0090012F` 的 `C7 80 7C 0B 00 00 00 00 00 00` 把第7关强制关闭。派生器以整个初始化函数的原始／L7／L8完整字节签名为门禁，只将该指令的偏移 `0xB7C` 改为 `0xB80`（实际唯一变化位于 `0x00900131`，`7C → 80`），使强制关闭边界移到第8关，第7关保留原生条件的查询结果。安装并完整校验L8资源包时，目标位移改为`0xB84`（同一地址字节`7C/80 → 84`），固定关闭第9关，保留第7／第8关的原生条件；保留全局解锁配置。重复应用不再变化；未知函数字节拒绝写入。

该修正仅调整小地图章节开关边界，C355前置进度、移动门槛、战斗资源、page17→18道路和action166保持各自契约。

完整应用与恢复步骤：

1. 使用 `--dungeon7` 或 `--all` 选择该兼容项。
2. 解析PE32区段，将 `0x009000D0..0x00900156` 映射到文件偏移，并对整个初始化函数匹配登记的原字节或已应用字节。
3. 在内存中仅修改 `0x00900131`：无L8资源时使用`80`（B80），已验证L8资源时使用`84`（B84），原始值为`7C`（B7C）。
4. 逐字节复核完整函数、唯一变化位置及第7／第8关开关目标，生成独立覆盖目录和兼容报告。
5. 使用 `--apply` 时先将完整 `game.exe` 按SHA-256保存到 `backups/`，再执行单文件原子替换；重复应用收敛到相同文件。
6. 回滚时关闭客户端，恢复该次报告登记的完整EXE备份并核对SHA-256；单项恢复在完整函数门禁通过后还原该次应用前的 `7C`、`80` 或 `84`，步骤见3.6.1节。

- 新客户端进程的首个 C355 固定发布 `map/page=0/0`，避免原生 `FirstVillageFlag` 在任意存档页面读取缺失入口；

- 家具、入口可见性与碰撞策略保持独立；
- `+0xC8` 表示显示状态，前置进度位于 `+0x80..+0x87`；
- 房间 tuple 保持原身份，资源查找使用限定映射；
- 战斗资源清单只登记实际存在或可重复派生的文件。

### 3.6.1 L7/L8二进制 patch 完整流程

**修改目标：** PE32客户端`game.exe`中小地图初始化函数`0x009000D0..0x00900156`。执行入口为自包含运行包的`Nanaimo.Adapter.exe --tools compatibility`，补丁配方内嵌在托管程序集；本文1.1节列出`--all`涵盖的其他指令与资源组件。

| 客户端资源状态 | `0x0090012F`完整指令 | `0x00900131` | 固定关闭章节 |
|---|---|---|---|
| 原始函数 | `C7 80 7C 0B 00 00 00 00 00 00` | `7C` | L7 |
| L7兼容布局 | `C7 80 80 0B 00 00 00 00 00 00` | `80` | L8 |
| 完整L7/L8资源 | `C7 80 84 0B 00 00 00 00 00 00` | `84` | L9 |

1. **准备。** 退出目标客户端及使用该目录的适配器／桥接进程；保存客户端和资源的完整备份，记录`game.exe`的SHA-256。选择独立覆盖输出目录，保持输入与输出根目录各自独立。
2. **资源预检。** L8目标要求`openNanaimo-l7-l8-resources.json`及其882项安装资源、474项L7战斗保留资源（三份L7 SSTG仅补BGM字段）逐项匹配大小与SHA-256。凭据摘要、路径唯一性及文件身份一起校验。L7兼容布局采用`B80`，完整L8资源采用`B84`。
3. **函数门禁。** 按PE32节表映射VA；完整函数必须匹配原始、L7或L8登记签名之一。输入匹配后仅调整该函数`0x00900131`的一字节位移；章节原生前置计算和其他函数内容按各自配方保留。
4. **只读预检。** 从项目根目录执行以下命令，核对结果中`planned_verification.all_pass`、操作站点及计划文件。

   ```powershell
   $Client = '<客户端根目录>'
   $Overlay = '<独立覆盖输出目录>'
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root $Client --output-root $Overlay --dungeon7 --dry-run
   if ($LASTEXITCODE -ne 0) { throw '客户端兼容预检失败' }
   ```

   L8资源可单独校验：

   ```powershell
   .\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --client-root $Client --kind lumineos
   if ($LASTEXITCODE -ne 0) { throw 'L7/L8资源身份校验失败' }
   ```

5. **派生及应用。** 使用全新的覆盖输出目录，执行相同选项并添加`--apply`。重用已审阅的输出目录时添加`--overwrite`。`--dungeon7`同时处理道路、兼容别名和已登记图像迁移，具体范围见3.1–3.8节；`--all`按1.1节执行全部组件。

   ```powershell
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root $Client --output-root $Overlay --dungeon7 --apply
   if ($LASTEXITCODE -ne 0) { throw '客户端兼容应用失败' }
   ```

   工具先在内存派生全部文件并重复应用配方验证幂等，再写覆盖目录。应用前重新核对源字节并将原文件保存到`backups/<原SHA-256>/<相对路径>`；实际写入采用同目录临时文件原子替换。异常时按逆序恢复已修改文件，并以目标摘要保护并发编辑。
6. **结果校验。** 核对`nanaimo_compatibility_report.json`中的`verification.all_pass`、逐文件`apply_results`与输出摘要；重复只读预检应得到相同目标字节。核对完整函数及`0x00900131`目标值、村庄入口格点和全部L8资源身份。独立记录客户端地图显示和关卡操作验收。
7. **回滚。** 退出目标进程，将当前文件与该次报告的应用后SHA-256比较，确认仍属于本次应用结果；再从内容寻址备份逐文件恢复并核对原SHA-256。针对EXE优先恢复完整备份。单独撤销小地图项时，仍以完整登记函数为门禁，将`0x00900131`恢复到该次应用前的`7C`、`80`或`84`。资源和代码部署产生的事务按各自收据逆序恢复，角色数据库保持独立。

代码与资源整合部署入口`deploy_lumineos_release.py`同样在资源身份通过后应用该位点，默认执行预检，`--apply`执行事务；回滚使用该次输出的收据：

```powershell
python -B scripts/deploy_lumineos_release.py --client $Client --bundle '<已审核资源包>'
python -B scripts/deploy_lumineos_release.py --client $Client --bundle '<已审核资源包>' --apply
python -B scripts/deploy_lumineos_release.py --client $Client --rollback '<该次部署收据>'
```

每一步确认退出码为0后进入下一步。部署收据统一登记代码与资源事务，回滚以应用后摘要保护后续编辑。

## 首领权威血条二进制修改

功能：Boss血条使用当前阶段全部存活组件的权威剩余生命，三分体各自承受的有效伤害在该组件生命上限内结算。

### 站点及完整字节

| VA | 原始字节 | 应用字节 | 作用 |
|---|---|---|---|
| `0x00742DF1` | `83 B9 08 01 00 00 00` | `83 B9 0C 01 00 00 00` | 判零字段由对象+0x108调整到+0x10C |
| `0x00742E12` | `DB 80 08 01 00 00` | `DB 80 0C 01 00 00` | 宽度分子由对象+0x108调整到+0x10C |

两个站点分别以完整7字节和6字节指令校验，实际各修改一个位移字节。最大值仍来自对象+0x104，函数长度和文件大小保持一致。配套适配器发布当前阶段的总剩余量。

### 应用、校验与回退

1. 关闭目标客户端，保存配套适配器的完整运行目录及文件SHA-256。以使用者自备的 `game.exe` 所在目录作为客户端根目录，选择独立派生目录。
2. 工具读取PE节表，将VA映射到节内文件偏移：`PointerToRawData + VA - (ImageBase + VirtualAddress)`。两个站点分别逐字节匹配完整7字节、6字节指令；原始字节进入修改分支，应用字节进入 `already_patched` 分支，其余输入终止派生并报告站点差异。
3. 从项目根目录先检查输入及派生结果，再执行应用：

   ```powershell
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<客户端根目录>' --output-root '<独立派生目录>' --dungeon-state --dry-run
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<客户端根目录>' --output-root '<独立派生目录>' --dungeon-state --overwrite --apply
   ```

   `--dungeon-state` 同时包含1.2节的结算倒计时、鼠标确认、原生P恢复及经验显示处理。本节血条修改实际涉及两个位移字节，完整命令的修改范围由这些配套站点共同组成。GUI一键启动启用同一选项。
4. 工具先生成派生文件，将目标原文件保存为 `<独立派生目录>/backups/<原文件SHA-256>/game.exe`，随后逐文件原子替换。`nanaimo_compatibility_report.json` 记录每个站点的VA、文件偏移、跨度及状态，以及应用前后SHA-256和备份位置。
5. 检查报告中的 `verification.all_pass=true`，复核表中两个完整站点、文件大小及应用后的SHA-256；再次执行检查命令时，已匹配站点应保持 `already_patched`。函数长度、文件大小和对象 `+0x104` 最大值字段保持一致。
6. 使用配套适配器验证地宫1-2、1-3：各组件有效伤害计入当前阶段总剩余量，组件依次结束时血条对应2/3、1/3和0。发布记录保存适配器身份、客户端应用前后SHA-256、备份标识及兼容报告。
7. 回退时关闭客户端和适配器，按兼容报告的备份位置恢复 `game.exe`，并恢复第1步保存的配套运行目录；分别核对客户端原文件SHA-256和运行目录清单后重新启动。客户端派生备份与适配器运行目录备份各自管理。

验证覆盖原始／已应用字节识别、站点差异保护、重复应用、精确改动范围，以及16组权威剩余量与本地估算组合的隔离指令检查。

## 地宫复活快捷栏布局二进制修改

角色资料刷新按原客户端布局模式选择图标尺寸。管理器BYTE+3非零，或DWORD+0x10F0尚非战斗状态4时，保留构造器的全尺寸两行布局：1.0倍，X为615／675／735，槽0–2的Y为518，槽3–5的Y为463。BYTE+3为零且DWORD+0x10F0为4时才恢复原生紧凑布局：0.6倍，X为587／622／657／692／727／762，Y统一为534，并执行紧凑布局原有扩展槽权限处理。金币和彩蛋复活、连续刷新及清空均沿用这一模式边界；共享缩放常量、图标资源及其它快捷栏构造入口保持各自原有规则。

### 站点与完整字节

| 用途 | VA | 原始字节 | 目标字节 |
|---|---|---|---|
| 六槽资料刷新 | `0x006F5B1E` | `E8 67 97 D2 FF` | `E8 DD D5 FE FF` |
| 六槽清空刷新 | `0x006F5B68` | `E8 1D 97 D2 FF` | `E8 93 D5 FE FF` |
| 布局包装函数 | `0x006E3100`，64字节 | 64个`CC` | 下列完整64字节 |

```text
55 8B EC 51 FF 75 1C FF 75 18 FF 75 14 FF 75 10
FF 75 0C FF 75 08 E8 35 9E FF FF 50 E8 BF 27 F8
FF 80 78 03 00 75 11 83 B8 F0 10 00 00 04 75 08
8B 4D FC E8 D8 9B FF FF 58 8B E5 5D C2 18 00 CC
```

包装函数保存角色指针，将六个道具参数按原顺序交给`0x006DCF50`创建／清理图标，保存返回值，再经`0x006658E0`取得管理器，直接读取BYTE+3与DWORD+0x10F0；仅模式为零且状态为4时，以同一角色调用`0x006DCD10`。原生初始化`0x0066CDA3..0x0066CDB4`选择零模式分支，该分支由`0x0066CED7..0x0066CEE0`写状态4，再于`0x0066CF6D`应用紧凑布局；新包装将紧凑布局限定于已进入战斗的零模式。返回值EAX、调用者EBP、非易失寄存器及`ret 0x18`栈清理约定保持一致。两个入口共用同一包装函数。先前无条件执行0.6布局的64字节包装函数登记为可迁移旧输入，当前采用双条件布局规则；迁移校验覆盖全尺寸模式与准备阶段。

### 派生、安装、校验与回退

1. 关闭目标目录的游戏客户端与社交副本，保存`game.exe`及本轮文件大小、SHA-256。
2. 使用兼容工具的`--dungeon-state`选项。该选项也由启动器的标准兼容准备流程执行：

   ```powershell
   adapter_runtime/Nanaimo.Adapter.exe --tools compatibility `
     --source-root '<客户端目录>' `
     --output-root '<独立覆盖目录>' --dungeon-state --apply
   ```

3. 工具通过PE节映射定位上述三处站点，接受原始字节、目标字节，以及代码区内已登记的完整旧版无条件包装函数；旧输入的精确64字节由`QUICKBAR_REFRESH_LEGACY`和嵌入配方共同登记。任何其它内容（包括近似旧版）安全拒绝。64字节代码区与两个调用入口一起形成完整修改集合。
4. 独立覆盖目录先生成候选文件，安装前再次核对输入身份，将原始文件按内容身份保存，再安装并逐项校验。重复执行保持幂等，文件长度保持一致。
5. 六项专项覆盖模式0／1／2／255及状态0／1／2／3／4／6下的432次构造／清空／权限切换、完整缩放坐标、返回值和栈约定、旧包装迁移与未知字节拒绝。负向测试分别要求旧无条件包装在全尺寸模式和零模式的准备阶段失败。原始指令与渲染API模型属于隔离验证，不替代正常显示及复活后的原客户端画面验收。
6. 回退时先核对当前文件身份；当前文件匹配本次安装后的身份，且所有后续修改均纳入回退范围时，可恢复本次备份的完整`game.exe`。保留其它兼容修改时采用定点回退：将两个入口恢复为表内原始字节，并将`0x006E3100..0x006E313F`恢复为64个`CC`，随后复核大小与SHA-256。同步恢复对应版本的兼容工具与运行清单，再重新启动；社交副本按各自备份执行同一校验。

## 可选子弹DIY二进制与资源修改

该功能以独立配置、五个入口和一个代码／数据区实现V键发射及限定名称的反向处理，默认关闭。配方由`manifest/projectile_diy_patch.json`登记完整字节、原始输入与资源身份；安装器为`scripts/prepare_projectile_diy.ps1`。

### 二进制合同与完整修改集合

输入为x86 PE32，ImageBase为`0x00400000`，采用固定地址装载。代码／数据区`0x00B98000..0x00B99FFF`共8192字节，所在节具备读、写、执行权限。五个WinAPI导入槽为`0x00D921E8/0x00D91FAC/0x00D91EA8/0x00D91F50/0x00D91ED0`，安装器校验其导入身份。各站点接受精确原始字节或当前目标字节，采用PE节映射定位。

| 用途 | VA | 原始字节 | 目标字节 |
|---|---|---|---|
| 预载入口 | `0x006A8960` | `55 8B EC 83 EC 10` | `E9 9B F6 4E 00 90` |
| 发射入口 | `0x006A9590` | `55 8B EC 6A FF` | `E9 6B EE 4E 00` |
| 行更新入口 | `0x006B5BA0` | `55 8B EC 83 EC 78` | `E9 5B 31 4E 00 90` |
| 父对象更新 | `0x006BAE60` | `55 8B EC 83 EC 20` | `E9 9B E1 4D 00 90` |
| 行绘制调用 | `0x006B63BA` | `E8 4F 20 D5 FF` | `E8 41 37 4E 00` |
| 代码／数据区 | `0x00B98000`，8192字节 | 8192个`CC` | 配方中该VA的完整`target`字节 |

行对象私有标记位于`+0x728`：名称、规定行数、非空EFF（`+0x28`）、零trail（`+0x5C0`）、零transition（`+0x704`）和既有标记共同构成门控。872字节管理对象采用独立边界。篮球名称限定三行；绘制时复制48字节的12轨道，在副本反转rotation与scaleX；六个ep02兼容副本按row0执行一次初始几何反射。

### 安装、配置、校验与回退

1. 退出目标目录游戏客户端，适配器可继续运行。确认客户端目录与目标`game.exe`，保留文件大小及SHA-256；社交副本按各自目录执行。
2. 执行预检，校验PE、装载地址、节权限、导入槽、完整站点与资源内容：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare_projectile_diy.ps1 -ClientRoot "<client-root>"
   ```

3. 执行安装：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare_projectile_diy.ps1 -ClientRoot "<client-root>" -Apply
   ```

   安装器在`.openNanaimo-projectile-backups/<SHA-256>/`保存被替换文件，复核全部输入及目标身份，先提交资源，最后提交`game.exe`；逐文件执行并发检查，完成后复核全部目标及原输入。失败时按逆序恢复本次已提交文件；并发冲突进入保护分支。安装摘要写入`adapter_data/projectile_install_report.json`。
4. 在启动器“子弹DIY”页选择资源或“选自制篮球”，设置“启用V键连续发射”及反向开关，保存到`nanaimo_projectile.ini`后启动客户端。配置在首次预载时读取；更新配置或旧资源升级均在客户端退出后、下一次启动时生效。战斗中按住V以90ms间隔发射，松开停止；切图与战斗对象重建后以松键重新取得发射资格。
5. 再次预检确认站点、资源与配置身份，重复安装保持幂等。专项覆盖安装、旧资源升级、冲突保护、回退、栈约定、名称／行门控和动画计算；游戏内画面与联机同步按独立验收状态管理。
6. 关闭游戏后执行位点回退：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare_projectile_diy.ps1 -ClientRoot "<client-root>" -Apply -Uninstall
   ```

   回退恢复表中五处原始指令及8192个`CC`，将配置`enabled`置0，保留其它兼容位点、新增独立资源与内容寻址备份。根据当前完整文件身份再次复核；备份按所含兼容版本分别管理。
