# 完整 adapter 与客户端兼容说明

本文描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。运行输入由使用者从合法取得的客户端副本准备；仓库提供 adapter、启动器、派生工具与兼容性数据。原始文件备份和哈希用于本机恢复与诊断。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 确认 `game.exe` 存在，并调用 `scripts/prepare_client_compatibility.py --furniture --revival-display --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --dungeon7 --overwrite --apply`；默认流程对已知 PE 布局应用家具 Index 重定向、准备房复活次数 HUD 刷新、普通结算手动确认、连续关卡 P 弹恢复、空地购房确认入口和屋外装修入口，并派生资源；emotion 代码保持原样；
4. 从使用者自己的文件生成本地覆盖，原子应用家具 Index 重定向、结算／P 弹兼容站点、P03 道路及 SSTG/PON 别名并逐项复核；适配器通过固定 C393 快照契约提供场景对象，本地 getter 处理家具点击路径；
5. 将原文件按内容 SHA-256 备份到 `adapter_data/client_compatibility_overlay/backups/`；哈希作为本机备份与诊断指纹；
6. 启动完整 adapter，并等待 `11005/11999/12050` 全部可连接；
7. 经 `11999` 注册角色资料；
8. 只在兼容报告 `verification.all_pass=true` 后启动 `game.exe`。
### 1.1 地宫结算与连续关卡派生边界

`--dungeon-state` 提供普通结算手动确认与连续关卡 P 弹恢复：

- 普通结算控制器：跳过本地倒计时自动调用 CF8B 的分支，保留原手动输入调用点；
- P 弹恢复：只对 adapter 在新 stage CF80 后发送的 `D035 category40/type1, item UID=0xFFFF` 进入原 P 弹应用函数，普通场景拾取仍走原查找与移除路径。

工具识别登记站点与已派生站点，二次运行保持幂等；应用前按当前文件 SHA-256 保存本地备份，派生后统一复核家具、复活 HUD、普通结算 gate、P 弹恢复逻辑、空地购房入口和屋外装修入口。派生产物保存在用户本机，输入文件大小与哈希用于诊断和备份识别。

## 2. 家具边界：C393 快照与 Index getter 分离

C393 家具快照采用统一布局：**1012 字节 payload、1020 字节完整帧、`payload+0` 对象数、`payload+2` 写入 WORD 2000、`payload+4` 起最多 84 条 12 字节普通家具记录、未使用区域清零**。地板和墙壁由 C38E/C424 承载。C393 负责有界场景快照，本地 Index getter 负责家具点击路径。

启动器选择 `--furniture --revival-display --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --dungeon7`：PE 布局和当前五字节精确匹配时应用家具 Index-getter redirect，同时派生资源；emotion 代码保持原样。站点不匹配时工具保持输入文件不变并报告校验失败。

### 2.1 C393精确布局

```text
完整帧长度  1020
payload长度  1012
frame+8      WORD count
frame+10     WORD info/final = 2000
frame+12     第1条12字节对象记录
最大记录数   84
```

客户端在 `frame+10 == 6000` 时再次发送 C392；`0`、`2000` 及其他非 6000 值结束分页。适配器以 `2000` 表示完整快照终态。记录循环按 `count` 消费，紧凑的 `12+12*count` 完整帧覆盖静态读取；固定 1020 字节与清零尾部提供容量边界。家具点击随后进入独立的受保护 Index getter。

### 2.2 客户端兼容边界

一键流程以当前 `game.exe` 为输入，在确认 PE 布局和目标五字节后应用家具站点重定向：

```text
VA 0x0041235F
E9 9C C3 1B 00 -> E9 7C CC 1B 00
```

五字节或 PE 布局不匹配时，工具保持文件不变。该重定向把受保护入口 `0x5CE700` 指向现有的直接 Index getter `0x5CEFE0`；表情协议边界由 C355 独立承载。

### 2.3 家具状态与布局

家具库存按实例关联选取状态、位置、层级和镜像，容量为84件。空房间及多家具布局共享固定C393快照；装修界面支持摆放、保存、取下和重新进入后的布局恢复。客户端家具点击使用 `0x41235F → 0x5CEFE0` 的直接Index入口，布局提交由C411承载。

### 2.4 表情翻页的适配器端协议边界

The launcher leaves the original emotion code at `VA 0x00837220..0x00837263` unchanged. `C354/8 -> C355/728` keeps access open through `+0x3C..+0x77` and the low44 predecessor bits, while preserving the independent score cache: ordinary ratings at `+0x88..+0xC3`, secret ratings at `+0xC4..+0xC7`, and frontier ratings at `+0xC8..+0xDE`. Every write stops before the 17-byte couple name at `+0xDF..+0xEF`; `WORD+0xF0` is the ring suffix. Invalid or absent relationships remain empty-name/zero-ring.

### 2.5 城镇空地购房入口

`--land-purchase` 将空地鼠标命中连接到原生购房确认窗口。窗口按当前街区读取费用，显示金币和推荐点余额，确认后提交所选地块。空地检测、窗口输入互斥、余额门槛、确认和取消均沿用对应原生界面逻辑。

派生工具逐字节验证房屋更新入口和专用代码区，原子写入并保存本地备份；自动检查覆盖调用约定、有效地块、窗口互斥、边界拒绝和重复应用。

### 2.6 街区住宅与屋外外观系统 patch

`--apartment-exterior` 提供屋外装修菜单、房屋外观与标语牌选取、原生外观商店、文字编辑、保存和街区展示。住宅期限为购买后14天；有效期、已有住宅与地块占用状态统一参与购房判定，期满后支持换购空闲地址。已购家具与外围装饰库存按角色持久保存。

客户端派生由 `scripts/prepare_client_compatibility.py` 调用 `scripts/apartment_exterior_panel.py`，两文件作为同一运行组件发布。完整 patch 覆盖以下内容：

| patch 范围 | 当前实现 |
|---|---|
| 屋外菜单入口 | `0x5DAB27 → 0x5DAD80`，保留室内命中优先级；屋外入口要求房主身份、菜单展开完成及有效街区地址。 |
| 图像与点击区域 | 菜单构造 `0x5DA300/0x5DA30A` 使用 `(13,186)`；原生图像尺寸98×22生成 `(13,186,111,208)` 点击矩形。 |
| 外围库存刷新 | `0x5D274D → 0x5D2A00` 清理并重建总表、外观表与标语牌表，`0x5D27A5 → 0x5D3F90` 逐行追加，保持新购项目和选取状态一致。 |
| 面板输入与背景 | 在当前公寓、房间和装修面板引用匹配时分配专用输入，协调公共HUD和顶部背景；保存、恢复原状、全部取消、关闭使用原生控件。 |

屋外面板组件使用 `0x5CC600..0x5CD5FF` 代码区，登记21个指令／代码区站点及25个文本区间；菜单入口、构造位置和外围库存具有独立站点校验。启动器在家具装饰与地宫7派生中同时启用这一组件：

```powershell
python -B scripts/prepare_client_compatibility.py `
  --source-root '<客户端根目录>' `
  --output-root '<派生目录>' `
  --furniture --revival-display --dungeon-state --inventory-gift-display `
  --land-purchase --apartment-exterior --dungeon7 --overwrite --apply
```

外围库存包含8种房屋外观及6种标语牌。标语牌支持三行文字，每行14个GBK字节；保存后的外观、标语牌和文字由住宅记录统一用于面板恢复与街区展示。详细使用规则见[单身公寓](单身公寓.md)。

## 3. 拉米诺斯村地宫7兼容链
拉米诺斯村地宫7入口由五个边界共同构成：C355 前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON。原客户端读取 C355 `+0x80..+0x87`，并对 `k=0..21` 的每项要求两个 bit 同时为 `1`。静态链为：C355 分派 `0x0052C100` → 状态构造 `0x00544000` → 前置字段写入 `0x0054EDD0`；移动流程 `0x005000A0` → 前置判定 `0x00509EC0`，逐项检查 `+0x48` 的 bit `2*k` 与 `2*k+1`。

### 兼容链组成

地宫7由前置进度、村庄道路、关卡资源命名、adapter资源映射和嵌套PON共同提供。`--dungeon7` 负责道路及资源文件派生；家具与屋外外观系统通过上面的完整命令同时应用。C355低44位前置字段由适配器在最终构造阶段统一写入，角色进入使用同一状态周期。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- 不修改 `+0xC8` 的关卡显示字节；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.2 P03 村庄道路 pack

原始第五村 pack 只有前六个入口的连通道路，page17 没有通往 page18 的出口。地宫7需要 P03 道路 pack：

```text
Village_map_image/Village_map_image.pack
```

派生器读取 pack 目录与第五村 50×36 单元网格，按字段语义生成道路；不要求原始 pack 或输出 pack 命中固定哈希。

P03 包含 16 条补充双向道路，并保留：

- page17/page18 的原生地宫7入口 action `166`；
- page18 `(25,6)` 的返回 marker `169`；
- 返回坐标 `(400,96)`；
- 已有 `160..166` action；
- 未增加虚构的 `167..182` 地宫入口。

P03 提供道路连通性；战斗资源覆盖范围由 SSTG、SMMO 与 PON 清单独立确认。

### 3.3 地宫7关卡 SSTG 别名

客户端请求的兼容路径为：

```text
flying/hd0_ep22_dg00_st01.sstg
```

使用者应从已有的：

```text
flying/hd0_ep22_dg01_st01.sstg
```

制作**逐字节相同**的别名文件。该复制关系由派生器执行；不对源文件或别名文件设置固定大小／哈希门禁。

只复制 SSTG 文件名；文件内部已经存在的 dg01 SMMO 引用保持不变。

### 3.4 adapter 资源查找映射

地宫7在村庄／房间身份中保留 `hd0/ep100/dg6/st1`，但资源目录使用 `ep22/dg1/st1`。完整 adapter 对**普通目标和 Boss**使用限定映射：

```text
hd0 / ep100 / dg6 / st1
    ->
hd0 / ep22 / dg1 / st1
```

该映射只用于资源查找，不改写房间身份、客户端显示 tuple、奖励归属或持久进度。

### 3.5 PON 同家族兼容别名

关卡嵌套依赖使用以下别名：

```text
源  flying/pon/mis_ep22_dg01_m_196.pon
目标 flying/pon/mis_ep22_dg01_m_196_02.pon
操作 逐字节复制，不设置固定大小／哈希门禁
```

该文件是同家族兼容别名，其外观、轨迹与参数沿用源文件。`gui_launcher/resource_patches/superboss_projectile_alias.json` 记录派生关系和适用范围；GUI 以路径与生成结果为准。

### 3.6 显示边界

客户端 `0x0090012F` 单独控制 d07 小地图图层显示。page17→18 道路、入口 action166 与关卡资源加载使用各自边界；派生器保持该显示站点不变。d07 小地图图层作为独立的原客户端视觉验收项记录。

入口兼容链保持以下边界：

- 新客户端进程的首个 C355 固定发布 `map/page=0/0`，避免原生 `FirstVillageFlag` 在任意存档页面读取缺失入口；
- 首个 C367 不被 adapter 覆盖为存档页面，C367/C368 仍保持请求驱动；
- 家具、入口可见性与碰撞策略保持独立；
- `+0xC8` 表示显示状态，前置进度位于 `+0x80..+0x87`；
- 房间 tuple 保持原身份，资源查找使用限定映射；
- 战斗资源清单只登记实际存在或可重复派生的文件。

### 3.7 场景衔接

page17与page18通过P03道路相连，action166进入地宫房间选择及创建界面。关卡使用对应SSTG、SMMO与PON资源；普通目标、Boss及结算共享所选难度。死亡、离开和通关后的返回路径使用marker169及坐标 `(400,96)`，再次进入时延续持久化关卡进度。

## 4. 登录出生点与位置持久化

- 新角色首次进入沿用角色创建与新手引导流程。
- 完成引导后，角色的地图、村庄页面和坐标写入人物档案。
- 新客户端进程经 `map/page=0/0` 安全启动页建立角色，再由正常 C365/C367/CB21 更新人物档案。
- C365/C367/CB21 的 `FFFF/FFFF` 作为场景切换哨兵保留在当前消息，坐标回退使用 `(400,96)`。
- 安全启动、合法坐标、HP/MP 与后续页面移动使用同一持久化状态。
