# 完整 adapter 与客户端兼容说明

本文描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。运行输入由使用者从合法取得的客户端副本准备；仓库提供 adapter、启动器、派生工具与兼容性数据。原始文件备份和哈希用于本机恢复与诊断。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 确认 `game.exe` 存在，并调用 `scripts/prepare_client_compatibility.py --character-creation --furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --apartment-recommendation --dungeon7 --overwrite --apply`；对已知 PE 布局应用新账号建角、家具、结算、礼物预览、空地购房、房屋推荐和屋外装修补丁，迁移已登记的旧复活显示／P 弹恢复编码；表情使用原生代码；
4. 从使用者自己的文件生成本地覆盖，逐文件原子应用并逐项复核 EXE、P03 道路及 SSTG/PON 别名；适配器通过原生 CF71/CF72 维护次数与跨关状态，通过固定 C393 契约提供场景对象；
5. 将原文件按内容 SHA-256 备份到 `adapter_data/client_compatibility_overlay/backups/`；哈希作为本机备份与诊断指纹；
6. 启动完整 adapter，并等待 `11005/11999/12050` 全部可连接；
7. 经 `11999` 注册角色资料；
8. 只在兼容报告 `verification.all_pass=true` 后启动 `game.exe`。

### 新手引导与启动器装备隔离

adapter 按角色档案和引导阶段投影登录外观。`TutorialCompleted=0` 的角色从创建时保存的 `Appearance` 恢复基础外观，教程阶段的 D6特效与D7宠物置0；首次进村、尼莫对话及重登共享同一角色档案。社交新账号进入等级1、零余额、零库存的纯新手创建流程，已有账号直接沿用其角色、进度和装备。INI、sidecar、数据库外观、装备所有权及宠物选择各自保持独立生命周期。

引导阶段 `C354` 返回携宠标志为0的 `C355`。有效 `C353` 原子保存完成状态并返回 `C594`，随后 `C354` 恢复普通 `C355 -> C476 -> C44C` 初始化，`C367/C368` 恢复全部装备并进入村庄。身份、长度校验与重复完成幂等继续生效。

自动化回归覆盖男女各4组特效状态、无角色入口、sidecar优先级、引导中重登、有效／非法／重复完成事件、库存阶段门控、首次进村恢复及配置原文保留。验证范围为数据库状态、协议构造与请求顺序。

### 1.1.2 推荐人提示确认与重新填写

安装本节推荐人兼容项后，登录帧对提示40、41、42使用继续流程：填写不存在的姓名返回提示，填写已有姓名保存推荐关系并继续登录；留空或填写自己的姓名通过本地校验提示后恢复输入。适配器的推荐结果保持10／20／30，首次有效绑定给推荐人增加200推荐点。普通提示继续与本地重填由客户端兼容项提供，与适配器结果码共同构成完整功能。

普通提示确认将对象 `WORD+0x36` 设为0。登录帧原有确认判断在该值为0时切换全局状态25；推荐提示的局部兼容将这三类消息的上层判断值转换为1，同时保留对象自身的真实结果、关闭动画与释放流程。其余消息沿用原有判断。两个本地输入提示在返回时清理建角对象 `+0x3A4` 的等待旗，后续可重新填写并提交。

### 1.2 两类结算控制器的手动确认

`--dungeon-state` 控制两类结算控制器的本地倒计时，同时保留原生鼠标与键盘输入。控制器选择由 `0x66CA32..0x66CAB7` 的模式分支决定，不能只审查其中一个。

| 站点 | 当前行为 | 迁移／保留边界 |

## 2. 家具边界：C393 快照与 Index getter 分离

C393 家具快照采用统一布局：**1012 字节 payload、1020 字节完整帧、`payload+0` 对象数、`payload+2` 写入 WORD 2000、`payload+4` 起最多 84 条 12 字节普通家具记录、未使用区域清零**。地板和墙壁由 C38E/C424 承载。C393 负责有界场景快照，本地 Index getter 负责家具点击路径。

启动器选择 `--furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --dungeon7`：PE 布局和当前五字节精确匹配时应用家具 Index-getter redirect，同时派生资源；表情使用原生代码。站点不匹配时工具保持输入文件不变并报告校验失败。

### 2.1 C393精确布局

```text
完整帧长度  1020
payload长度  1012
frame+8      WORD count
frame+10     WORD info/final = 2000
frame+12     第1条12字节对象记录
最大记录数   84
```

客户端在 `frame+10 == 6000` 时再次发送 C392；`0`、`2000` 及其他非 6000 值结束分页。适配器以 `2000` 表示完整快照终态。记录循环按 `count` 消费，紧凑的 `12+12*count` 完整帧覆盖静态读取；固定 1020 字节与清零尾部提供容量边界。家具点击随后进入独立的受保护 Index getter。

### 2.2 客户端兼容边界

一键流程以当前 `game.exe` 为输入，在确认 PE 布局和目标五字节后应用家具站点重定向：

```text
VA 0x0041235F
E9 9C C3 1B 00 -> E9 7C CC 1B 00
```

五字节或 PE 布局不匹配时，工具保持文件不变。该重定向把受保护入口 `0x5CE700` 指向现有的直接 Index getter `0x5CEFE0`；表情协议边界由 C355 独立承载。

### 2.3 家具状态与布局

家具库存按实例关联选取状态、位置、层级和镜像，容量为84件。空房间及多家具布局共享固定C393快照；装修界面支持摆放、保存、取下和重新进入后的布局恢复。客户端家具点击使用 `0x41235F → 0x5CEFE0` 的直接Index入口，布局提交由C411承载。

### 2.4 表情翻页的适配器端协议边界

The launcher leaves the original emotion code at `VA 0x00837220..0x00837263` unchanged. `C354/8 -> C355/728` keeps access open through `+0x3C..+0x77` and the low44 predecessor bits, while preserving the independent score cache: ordinary ratings at `+0x88..+0xC3`, secret ratings at `+0xC4..+0xC7`, and frontier ratings at `+0xC8..+0xDE`. Every write stops before the 17-byte couple name at `+0xDF..+0xEF`; `WORD+0xF0` is the ring suffix. Invalid or absent relationships remain empty-name/zero-ring.

## 3. 拉米诺斯村地宫7兼容链
拉米诺斯村地宫7入口由五个边界共同构成：C355 前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON。原客户端读取 C355 `+0x80..+0x87`，并对 `k=0..21` 的每项要求两个 bit 同时为 `1`。静态链为：C355 分派 `0x0052C100` → 状态构造 `0x00544000` → 前置字段写入 `0x0054EDD0`；移动流程 `0x005000A0` → 前置判定 `0x00509EC0`，逐项检查 `+0x48` 的 bit `2*k` 与 `2*k+1`。

### 兼容链组成

地宫7由前置进度、村庄道路、关卡资源命名、adapter资源映射和嵌套PON共同提供。`--dungeon7` 负责小地图发布边界、道路、已知补制图像撤回及资源别名派生；家具与屋外外观系统通过上面的完整命令同时应用。C355低44位前置字段由适配器在最终构造阶段统一写入，角色进入使用同一状态周期。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- `+0xC8` 关卡显示字节沿用原生语义；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.2 P03 村庄道路 pack

原始第五村 pack 只有前六个入口的连通道路，page17 没有通往 page18 的出口。地宫7需要 P03 道路 pack：

```text
Village_map_image/Village_map_image.pack
```

派生器读取 pack 目录与第五村 50×36 单元网格，按字段语义生成道路；不要求原始 pack 或输出 pack 命中固定哈希。

P03 包含 16 条补充双向道路，并保留：

- page18 单元格 `x22..27/y3..4` 的地宫7入口 action `166`；
- page18 `(25,6)` 的返回 marker `169`，返回像素坐标 `(400,96)`；
- 入口恢复到补制美术引入前的区域，不再迁往左侧实验室图像；
- 已有 `160..166` action；
- 未增加虚构的 `167..182` 地宫入口。

P03 提供道路连通性；战斗资源覆盖范围由 SSTG、SMMO 与 PON 清单独立确认。

### 3.3 地宫7关卡 SSTG 别名

客户端请求的兼容路径为：

```text
flying/hd0_ep22_dg00_st01.sstg
```

使用者应从已有的：

```text
flying/hd0_ep22_dg01_st01.sstg
```

制作**逐字节相同**的别名文件。该复制关系由派生器执行；不对源文件或别名文件设置固定大小／哈希门禁。

只复制 SSTG 文件名；文件内部已经存在的 dg01 SMMO 引用保持不变。

### 3.4 adapter 资源查找映射

地宫7在村庄／房间身份中保留 `hd0/ep100/dg6/st1`，但资源目录使用 `ep22/dg1/st1`。完整 adapter 对**普通目标和 Boss**使用限定映射：

```text
    ->
hd0 / ep22 / dg1 / st1
```

该映射只用于资源查找，不改写房间身份、客户端显示 tuple、奖励归属或持久进度。

### 3.6 显示边界

小地图初始化 `0x009000D0..0x00900156` 先循环查询原生前置条件并写入各章节开关，随后 `0x0090012F` 的 `C7 80 7C 0B 00 00 00 00 00 00` 把第7关强制关闭。派生器以整个初始化函数的旧／新字节为门禁，只将该指令的偏移 `0xB7C` 改为 `0xB80`（实际唯一变化位于 `0x00900131`，`7C → 80`），使强制关闭边界移到第8关，第7关保留原生条件的查询结果。重复应用不再变化；未知函数字节拒绝写入。

该修正仅调整小地图章节开关边界，C355前置进度、移动门槛、战斗资源、page17→18道路和action166保持各自契约。

完整应用与恢复步骤：

1. 使用 `--dungeon7` 或 `--all` 选择该兼容项。
2. 解析PE32区段，将 `0x009000D0..0x00900156` 映射到文件偏移，并对整个初始化函数匹配登记的原字节或已应用字节。
3. 在内存中仅将 `0x00900131` 的 `7C` 改为 `80`，对应指令位移由 `+0xB7C` 调整为 `+0xB80`。
4. 逐字节复核完整函数、唯一变化位置及第7／第8关开关目标，生成独立覆盖目录和兼容报告。
5. 使用 `--apply` 时先将完整 `game.exe` 按SHA-256保存到 `backups/`，再执行单文件原子替换；重复应用收敛到相同文件。
6. 回滚时关闭客户端，恢复该次报告登记的完整EXE备份并核对SHA-256；单项恢复则在完整函数门禁通过后将 `0x00900131` 恢复为 `7C`。

入口兼容链保持以下边界：

- 新客户端进程的首个 C355 固定发布 `map/page=0/0`，避免原生 `FirstVillageFlag` 在任意存档页面读取缺失入口；
- 首个 C367 不被 adapter 覆盖为存档页面，C367/C368 仍保持请求驱动；
- 家具、入口可见性与碰撞策略保持独立；
- `+0xC8` 表示显示状态，前置进度位于 `+0x80..+0x87`；
- 房间 tuple 保持原身份，资源查找使用限定映射；
- 战斗资源清单只登记实际存在或可重复派生的文件。

### 3.7 场景衔接

page17与page18通过P03道路相连，action166进入地宫房间选择及创建界面。关卡使用对应SSTG、SMMO与PON资源；普通目标、Boss及结算共享所选难度。死亡、离开和通关后的返回路径使用marker169及坐标 `(400,96)`，再次进入时延续持久化关卡进度。

## 4. 登录出生点与位置持久化

- 新角色首次进入沿用角色创建与新手引导流程。
- 完成引导后，角色的地图、村庄页面和最后合法坐标写入人物档案。

- `FFFF/FFFF` 与 `03FF/03FF` 作为无效位置过滤；单轴 `9999` 仅用于地图边界交接，不覆盖持久坐标。
- 明确的合法入口坐标保持原值，下一页面的合法落点成为新的持久位置。
