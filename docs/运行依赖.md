# 运行依赖

源码校验不需要客户端资源；原生 adapter 构建需要 Python／TinyCC，完整 adapter 构建还需要 .NET 8 SDK 和使用者准备的数据目录。**仓库不附带这些工具或 Nanaimo 客户端。** 官方下载入口和已观察版本见 [README 的构建说明](../README.md#构建与验证)。运行启动器及客户端时，还需要下列依赖。

| 类别 | 路径或组件 | 用途 |
|---|---|---|
| 客户端 | `game.exe` | 使用者合法取得的 PE32 客户端；启动器只检查文件存在，不限制脱壳实现、大小或哈希 |
| 客户端 DLL 与资源 | 客户端配套 DLL、数据包、场景、图像、音频等 | 原生加载与渲染 |
| 村庄地图 | `Village_map_image/Village_map_image.pack` | 原始村庄资源；地宫7道路版本可由兼容派生脚本生成，启动器不校验派生产物 |
| Boss 场景 | `flying/hd0_ep22_dg00_st01.sstg`、`flying/hd0_ep22_dg01_st01.sstg` | 原始场景与从其复制的名称别名；启动器不校验别名 |
| 资源配方 | `gui_launcher/resource_patches/*.json` | 记录派生关系和证据边界，不作为启动前哈希登记表 |
| 宠物与装备目录 | `gui_launcher/data/pets.json`、`equipment.json`、`pet_attack_modes.json` | 启动器选项和属性查询 |
| 库存目录 | `gui_launcher/data/inventory_{cards,clothing,furniture,game_items,pets,pet_gems}.json` | 库存管理 |
| 预览数据 | `gui_launcher/data/previews/` | 图集及索引；当前部分预览自检依赖这些文件 |
| 完整 adapter | `adapter_runtime/Nanaimo.Adapter.exe`、`nanaimo_gameplay_bridge.exe`、`adapter_manifest.json` | GUI 一键入口使用的完整运行组件 |
| Python | PATH 中的 `python`；部分入口使用自行准备的 `tools/python/python.exe` | 源码脚本与 GUI 库存后端；不同入口的查找规则见下文 |
| TinyCC | 自行准备的 `tools/tcc/` 或 `-TccPath` 指定位置 | 原生 adapter 和地宫桥接构建 |
| .NET 8 SDK | `-DotnetPath` 指定或 PATH 中的 `dotnet` | 构建 managed 源码并发布自包含运行包 |
| adapter 数据 | `-ResourceDataRoot` 指定的 `资源/数据` 目录 | 商城、任务、卡片、地宫目录等运行数据；不随源码仓库分发 |

客户端本体、客户端 DLL 与游戏原始资源由使用者自行准备；但 `gui_launcher/data/` 的目录数据与预览图集、以及 `gui_launcher/resource_patches/` 已随仓库提供，无需另行获取。本仓库提供 `scripts/prepare_client_compatibility.py`，用于从使用者自己的原始文件派生家具修复、地宫7道路和两个名称别名；它不会下载、携带或按固定哈希授权客户端内容。

GUI 当前尚未实现完整的“无目录数据／无预览素材”降级运行。派生资源不会由启动器或发布校验器检查；若客户端运行时报告缺失或格式错误，应回到派生步骤和原始文件结构排查。

## Python 与 TinyCC 的准备方式

- **源码检查和导出脚本**：使用 PATH 中的 `python`，例如先执行 `python --version` 确认解释器可用；不要求仓库内有 Python。
- **GUI 库存后端**：若本地存在 `tools/python/python.exe`，优先使用该解释器；不存在时使用 PATH 中的 `python`。两者都不可用时无法调用库存后端。
- **原生 adapter 构建**：默认查找 `tools/tcc/tcc.exe`，也可用 `scripts/build_adapter.ps1 -TccPath <实际路径>`。
- **完整 adapter 构建**：`scripts/build_merged.ps1` 同时接受 `-TccPath`、`-DotnetPath` 和 `-ResourceDataRoot`；缺少任一必需输入即拒绝构建。
- **本地原生协议测试**：`scripts/test_native_ui_protocol.py` 只查找 `tools/tcc/tcc.exe`，不支持构建脚本的 `-TccPath`。未准备该位置的工具会报错，不是跳过。
- **完整校验包装脚本**：`scripts/verify_package.ps1` 固定使用 `tools/python/python.exe`，不使用 GUI 的 PATH 回退。运行前须自行在该位置准备完整 Python 环境；单独的 `verify_package.py` 和 `verify_client_baseline.py` 可以使用系统 Python；后者仅检查 PE32 结构，哈希只作诊断输出。

`tools/python/`、`tools/tcc/` 是可选的本地安装位置；.NET SDK 可安装在仓库外，已加入 Git 忽略规则，并不表示仓库附带这些文件。准备本地工具时应保留配套标准库、DLL、头文件、库和发行包许可材料，不要只复制单个 EXE。`-TccPath` 不会改变其他入口的工具配置。

## 运行生成的数据

`nanaimo_launcher_profile.ini`、`nanaimo_launcher_profile.json` 保存启动器设置；`StateOption/gamestartoption.ini` 由 Network 模板生成。完整 adapter 的状态、日志和 SQLite 数据位于 `adapter_data/`。角色、库存和进度存储格式见 [角色资料与背包](../knowledge/authority/03-角色资料与背包.md)。
