# 完整 adapter 与客户端补丁指引

本文只描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。仓库不提供客户端、原始资源或已经修改的客户端文件；所有操作都应在使用者合法取得的副本上完成，并先保存原始文件哈希和备份。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 校验客户端、村庄 pack、关卡别名、资源补丁和 adapter manifest；
4. 启动完整 adapter；
5. 等待 `11005/11999/12050` 全部可连接；
6. 经 `11999` 注册角色资料；
7. 启动 `game.exe`。

## 2. 家具选择崩溃兼容补丁

### 适用基线

补丁地址适用于本工程记录的 `game.exe` 基线：

```text
size   14,198,272
sha256 6E3985CB7BEBA0207DEB6201BFB05D01CF8D548D3B674D8E6BD6A6F2DEB72B90
```

不要把下列地址套用到其他大小或哈希的 EXE。

### 修改位置

原版家具选择通过旧保护器入口比较对象：

```text
VA 0x0041235F
旧跳转目标 0x005CE700
旧字节 E9 9C C3 1B 00
```

改为客户端已有的原生家具 Index getter：

```text
VA 0x0041235F
新跳转目标 0x005CEFE0
新字节 E9 7C CC 1B 00
```

若 PE ImageBase 为 `0x00400000`，对应 RVA 为 `0x0001235F`。文件偏移必须通过该 EXE 自身的 PE 节表换算，不能直接把 RVA 当文件偏移。

### 语义

- `0x005CEFE0` 读取家具节点 `this + 0x33C` 的真实 Index。
- 不改变调用参数和栈布局。
- 不返回固定值。
- 不伪造 C411 或任何家具提交包。
- 不修补其他保护器入口。

### 验证

至少覆盖：

1. 同 code、不同 Index 的两个家具；
2. 不同家具类别；
3. 选择、放置、取下、提交、重新进入公寓；
4. 无异常退出；
5. C411/C412 只在真实提交动作后出现；
6. 重进后 Index 和摆放状态保持一致。

静态证据表明旧路径会进入已经失效的保护器线程映射对象；该重定向恢复了选择比较所需的实例 Index 语义。原客户端可见验收仍应由使用者在自己的客户端副本上完成。

## 3. 拉米诺斯村地宫7兼容链

进入地宫7不是一个单字节显示开关。必须同时满足**前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON**五个边界。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- 不修改 `+0xC8` 的关卡显示字节；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.2 P03 村庄道路 pack

原始第五村 pack 只有前六个入口的连通道路，page17 没有通往 page18 的出口。地宫7需要 P03 道路 pack：

```text
Village_map_image/Village_map_image.pack
size   17,011,373
sha256 69EF0FA688DBCB4EE2A36151F76F78A5A3D4F051253ABE81EA824F37749FCD56
```

P03 在 P02 基础上补入 16 条双向道路，保留：

- page17/page18 的原生地宫7入口 action `166`；
- page18 `(25,6)` 的返回 marker `169`；
- 返回坐标 `(400,96)`；
- 已有 `160..166` action；
- 未增加虚构的 `167..182` 地宫入口。

因此 P03 解决的是道路连通性，不代表后续 23 个地宫战斗资源全部存在。

### 3.3 地宫7关卡 SSTG 别名

客户端请求的兼容路径为：

```text
flying/hd0_ep22_dg00_st01.sstg
```

使用者应从已有的：

```text
flying/hd0_ep22_dg01_st01.sstg
```

制作**逐字节相同**的别名文件。两者应同时满足：

```text
size   103,124
sha256 899B1820EC0F49E032589AEAAA582086D5471C4BB1982EFB104E96FEC74D6D27
```

只复制 SSTG 文件名；文件内部已经存在的 dg01 SMMO 引用保持不变。

### 3.4 adapter 资源查找映射

地宫7在村庄／房间身份中保留 `hd0/ep100/dg6/st1`，但资源目录使用 `ep22/dg1/st1`。完整 adapter 对**普通目标和 Boss**使用限定映射：

```text
hd0 / ep100 / dg6 / st1
    ->
hd0 / ep22 / dg1 / st1
```

该映射只用于资源查找，不改写房间身份、客户端显示 tuple、奖励归属或持久进度。

### 3.5 缺失 PON 同家族回退

关卡嵌套依赖还需要：

```text
源  flying/pon/mis_ep22_dg01_m_196.pon
目标 flying/pon/mis_ep22_dg01_m_196_02.pon
size   21,508
sha256 D25279362ACD02505AEA542DDD05BD9A6A38C1023BF60BD66859E4F8D9AD1EC4
```

这是同家族兼容回退，不是找回缺失的原始 `_02` 文件，也不应宣称其外观、轨迹或参数与历史原件一致。GUI 会根据 `gui_launcher/resource_patches/superboss_projectile_alias.json` 校验源和目标哈希。

### 3.6 不要混淆的显示边界

客户端 `0x0090012F` 会单独把 d07 小地图图层标记为隐藏。该标志影响小地图显示，不是 page17→18 道路、入口 action166 或关卡资源加载的替代条件。

不要通过以下方式“修复”入口：

- 主动伪造 C367/C368；
- 删除家具、隐藏入口或全局 noclip；
- 把 `+0xC8` 显示状态当成前置进度；
- 修改房间 tuple 以绕过资源映射；
- 复制不存在的后续地宫战斗集合并声称为原始内容。

### 3.7 验收清单

1. 重新登录，使客户端重新读取 C355 前置字段；
2. 从 page17 正常步行到 page18；
3. 进入 action166，房间选择／创建界面可操作；
4. 进入地宫7，SSTG、SMMO、PON 无缺失文件错误；
5. 三个难度分别验证普通目标、Boss、结算；
6. 死亡、离开、通关后通过 marker169 返回 `(400,96)`；
7. 再次进入地宫7，不丢失道路、入口和关卡进度；
8. 保留日志和客户端可见结果，区分 adapter 构造通过与原客户端可见验收。
