# 完整 adapter 与客户端补丁指引

本文只描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。仓库不提供客户端、原始资源或已经修改的客户端文件；所有操作都应在使用者合法取得的副本上完成，并先保存原始文件备份；哈希可作为个人诊断指纹，但不是启动门禁。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 只校验项目自带的 adapter manifest，并确认 `game.exe` 存在；不检查客户端或派生资源的大小／哈希；
4. 启动完整 adapter；
5. 等待 `11005/11999/12050` 全部可连接；
6. 经 `11999` 注册角色资料；
7. 启动 `game.exe`。
## 2. 家具选择崩溃 bug 修复

> **修复结论：这是客户端家具选择路径的崩溃 bug。** 原始路径从 `VA 0x0041235F` 跳入已失效的保护器查找，并在 `VA 0x01011A51` 发生异常；选择比较实际需要家具实例 `Index`。静态链已闭合：家具节点 `this + 0x33C` 由 `0x005CEFC0` 写入，`0x005CEFE0` 读取，选择流程的 15 个比较点统一经 `0x0041235F` 调用。

### 修复步骤

推荐先用独立输出目录生成，不覆盖原始客户端：

```powershell
python -B scripts/prepare_client_compatibility.py `
  --source-root '<原始客户端目录>' `
  --output-root '<新建覆盖目录>' --all
```

输出报告会注明执行的结构化变换，但不会把任一输入或产物哈希当作启动条件。
1. 使用自己的 PE32 `game.exe`；不同脱壳实现允许具有不同大小和哈希。自动工具只检查 PE 结构与目标 VA 当前五字节，不使用全文件哈希授权。
2. 退出客户端并备份原文件，记录备份哈希。
3. 在 PE 映像 `VA 0x0041235F`（ImageBase `0x00400000`，RVA `0x0001235F`）原子替换五个字节：`E9 9C C3 1B 00` → `E9 7C CC 1B 00`。文件偏移必须按该 EXE 的 PE 节表换算，不能直接把 RVA 当文件偏移。
4. 复核新跳转目标为 `0x005CEFE0`；该函数读取 `this + 0x33C` 的真实 `Index`，不得改为常量、物品代码或其他入口。
5. 重新进入公寓，依次验证选择、摆放、取下、提交和重新进入；相同 code 的不同家具必须按各自 `Index` 区分，且无异常退出。

该修复不改变调用参数和栈布局，不伪造 C411 或其他家具提交包，也不修补其他保护器入口。

## 3. 拉米诺斯村地宫7兼容链
> **修复结论：这是拉米诺斯村地宫7的进入兼容性 bug；不是客户端二进制中缺少一个开关。** 原始客户端会读取 C355 `+0x80..+0x87` 的前置位，并对 `k=0..21` 的每一项要求两个 bit 同时为 `1`。基线数据为零时，客户端按既定逻辑拒绝 page17→page18 的移动。因此本项修复 C355 前置数据和配套资源，不改写客户端 EXE 指令。静态链为：C355 分派 `0x0052C100` → 状态构造 `0x00544000` → 前置字段写入 `0x0054EDD0`；移动流程 `0x005000A0` → 前置判定 `0x00509EC0`，逐项检查 `+0x48` 的 bit `2*k` 与 `2*k+1`。

### 修复步骤

1. 使用自己的合法客户端副本，并确认适配器在登录后重新发送完整 C355 帧。
2. 在 `release/components/dungeon_unlock/unlock_patch.inc` 的最终 C355 构造阶段写入低 44 个前置位：`C355 +0x80..+0x87 = FF FF FF FF FF 0F 00 00`。保留 bit44..63、`+0xC8` 显示域和其他字段；仍由 C354 驱动 C355。
3. 用 `scripts/prepare_client_compatibility.py --dungeon7` 从自己的 `Village_map_image/Village_map_image.pack` 按 `NANA_PACK` 页面／单元结构派生 P03 道路版本。
4. 创建地宫7的 SSTG 名称兼容文件：将自己的 `flying/hd0_ep22_dg01_st01.sstg` 逐字节复制为 `flying/hd0_ep22_dg00_st01.sstg`；启动器不检查源或产物哈希。
5. 保留资源查找映射 `hd0/ep100/dg6/st1 -> hd0/ep22/dg1/st1`，并从自己的 `flying/pon/mis_ep22_dg01_m_196.pon` 逐字节复制出缺失的 `_02` 同家族回退；启动器不检查产物。
6. 重启适配器并重新登录，使客户端重新读取 C355；从 page17 步行到 page18，再进入 action `166`。验证 SSTG、SMMO、PON 均能按路径加载。
进入地宫7不是一个单字节显示开关。必须同时满足**前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON**五个边界。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- 不修改 `+0xC8` 的关卡显示字节；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.2 P03 村庄道路 pack

原始第五村 pack 只有前六个入口的连通道路，page17 没有通往 page18 的出口。地宫7需要 P03 道路 pack：

```text
Village_map_image/Village_map_image.pack
```

派生器读取 pack 目录与第五村 50×36 单元网格，按字段语义生成道路；不要求原始 pack 或输出 pack 命中固定哈希。

P03 在 P02 基础上补入 16 条双向道路，保留：

- page17/page18 的原生地宫7入口 action `166`；
- page18 `(25,6)` 的返回 marker `169`；
- 返回坐标 `(400,96)`；
- 已有 `160..166` action；
- 未增加虚构的 `167..182` 地宫入口。

因此 P03 解决的是道路连通性，不代表后续 23 个地宫战斗资源全部存在。

### 3.3 地宫7关卡 SSTG 别名

客户端请求的兼容路径为：

```text
flying/hd0_ep22_dg00_st01.sstg
```

使用者应从已有的：

```text
flying/hd0_ep22_dg01_st01.sstg
```

制作**逐字节相同**的别名文件。该复制关系由派生器执行；不对源文件或别名文件设置固定大小／哈希门禁。

只复制 SSTG 文件名；文件内部已经存在的 dg01 SMMO 引用保持不变。

### 3.4 adapter 资源查找映射

地宫7在村庄／房间身份中保留 `hd0/ep100/dg6/st1`，但资源目录使用 `ep22/dg1/st1`。完整 adapter 对**普通目标和 Boss**使用限定映射：

```text
hd0 / ep100 / dg6 / st1
    ->
hd0 / ep22 / dg1 / st1
```

该映射只用于资源查找，不改写房间身份、客户端显示 tuple、奖励归属或持久进度。

### 3.5 缺失 PON 同家族回退

关卡嵌套依赖还需要：

```text
源  flying/pon/mis_ep22_dg01_m_196.pon
目标 flying/pon/mis_ep22_dg01_m_196_02.pon
操作 逐字节复制，不设置固定大小／哈希门禁
```

这是同家族兼容回退，不是找回缺失的原始 `_02` 文件，也不应宣称其外观、轨迹或参数与历史原件一致。`gui_launcher/resource_patches/superboss_projectile_alias.json` 仅记录派生关系和证据边界；GUI 不校验源或目标哈希。

### 3.6 不要混淆的显示边界

客户端 `0x0090012F` 会单独把 d07 小地图图层标记为隐藏。该标志影响小地图显示，不是 page17→18 道路、入口 action166 或关卡资源加载的替代条件。

不要通过以下方式“修复”入口：

- 主动伪造 C367/C368；
- 删除家具、隐藏入口或全局 noclip；
- 把 `+0xC8` 显示状态当成前置进度；
- 修改房间 tuple 以绕过资源映射；
- 复制不存在的后续地宫战斗集合并声称为原始内容。

### 3.7 验收清单

1. 重新登录，使客户端重新读取 C355 前置字段；
2. 从 page17 正常步行到 page18；
3. 进入 action166，房间选择／创建界面可操作；
4. 进入地宫7，SSTG、SMMO、PON 无缺失文件错误；
5. 三个难度分别验证普通目标、Boss、结算；
6. 死亡、离开、通关后通过 marker169 返回 `(400,96)`；
7. 再次进入地宫7，不丢失道路、入口和关卡进度；
8. 保留日志和客户端可见结果，区分 adapter 构造通过与原客户端可见验收。
