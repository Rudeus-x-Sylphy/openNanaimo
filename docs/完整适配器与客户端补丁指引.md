# 完整 adapter 与客户端补丁指引

本文只描述韩国飞行射击游戏 **Nanaimo** 的本地兼容链路。仓库不提供客户端、原始资源或已经修改的客户端文件；所有操作都应在使用者合法取得的副本上完成，并先保存原始文件备份；哈希可作为个人诊断指纹，但不是启动门禁。

## 1. 完整 adapter 结构

GUI 只启动一套完整 adapter：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、首领、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的 **“一键进入 Nanaimo”** 会按顺序：

1. 停止当前完整 adapter 及桥接进程；
2. 保存角色配置和本地库存；
3. 确认 `game.exe` 存在，并在客户端进程已退出后调用 `scripts/prepare_client_compatibility.py --emotion --dungeon7 --overwrite --apply`；
4. 从使用者自己的文件生成本地覆盖，原子应用 emotion null guard、P03 道路、SSTG/PON 别名，并逐项复核；家具由适配器端按固定 C393 快照契约提供，不自动改写客户端 Index getter；
5. 将被替换的原文件按内容 SHA-256 备份到 `adapter_data/client_compatibility_overlay/backups/`；哈希仅作为本机备份指纹，不是客户端授权门禁；
6. 启动完整 adapter，并等待 `11005/11999/12050` 全部可连接；
7. 经 `11999` 注册角色资料；
8. 只在兼容报告 `verification.all_pass=true` 后启动 `game.exe`。
## 2. 家具适配器端 C393 快照契约

当前 C393 家具快照采用统一布局：**1012字节payload、1020字节完整帧、`payload+0`对象数、`payload+2`写入WORD 2000、`payload+4`起最多84条12字节普通家具记录，未使用区域清零**。地板和墙壁仍由C38E/C424承载。

启动器仅选择 `--emotion --dungeon7`，不会自动应用家具 Index-getter redirect。若使用者手工恢复家具站点，只允许在确认 PE 布局和当前五字节后局部恢复 `VA 0x0041235F`；不得整体覆盖客户端，也不得撤销 emotion null guard。

### 2.1 C393精确布局

```text
完整帧长度  1020
payload长度  1012
frame+8      WORD count
frame+10     WORD info/final = 2000
frame+12     第1条12字节对象记录
最大记录数   84
```

客户端只有在 `frame+10 == 6000` 时才会再次发送 C392；因此 `2000` 是适配器端完整快照的当前策略。静态消费者不证明 `info=0` 会持续等待分页，也不证明变长帧是点击异常的根因。家具链仍需以真实客户端可见行为作为最终验收条件。

### 2.2 客户端补丁边界

不要用旧 `game_backup.exe` 整体覆盖当前 `game.exe`；两个文件还有情绪保护等大量差异。只允许在确认PE布局和当前五字节后恢复家具站点：

```text
VA 0x0041235F
E9 7C CC 1B 00 -> E9 9C C3 1B 00
```

客户端应保留 emotion guard；若五字节或 PE 布局不匹配，应停止局部恢复。

### 2.3 验收顺序

1. 进入自己的公寓，确认只收到一个C393/1020完整快照；
2. 分别测试空房间、1件和多件家具；
3. 打开装修界面，点击、摆放、保存、取下家具；
4. 关闭并重新打开装修界面；
5. 退出公寓并重进，确认布局仍在；
6. 记录客户端进程、异常地址、C392/C393/C411顺序和FIN/RST。

现有静态证据指向独立的 Index-getter 异常链；若未补丁客户端仍在 `0x01011A51` 崩溃，应将家具快照路径判为**未解决**，不得用未归因的适配器端响应掩盖客户端异常。

### 2.4 emotion null guard

当前客户端兼容性检查仍在 `VA 0x00837220..0x00837263` 保留 emotion null guard：ring suffix为0或资源查找返回NULL时直接返回false。正式启动器使用 `--emotion` 检查/派生该guard；它与家具 C393 快照契约相互独立。

## 3. 拉米诺斯村地宫7兼容链
> **修复结论：这是拉米诺斯村地宫7的进入兼容性 bug；不是客户端二进制中缺少一个开关。** 原始客户端会读取 C355 `+0x80..+0x87` 的前置位，并对 `k=0..21` 的每一项要求两个 bit 同时为 `1`。基线数据为零时，客户端按既定逻辑拒绝 page17→page18 的移动。因此本项修复 C355 前置数据和配套资源，不改写客户端 EXE 指令。静态链为：C355 分派 `0x0052C100` → 状态构造 `0x00544000` → 前置字段写入 `0x0054EDD0`；移动流程 `0x005000A0` → 前置判定 `0x00509EC0`，逐项检查 `+0x48` 的 bit `2*k` 与 `2*k+1`。

### 修复步骤

1. 使用自己的合法客户端副本，并确认适配器在登录后重新发送完整 C355 帧。
2. 在 `release/components/dungeon_unlock/unlock_patch.inc` 的最终 C355 构造阶段写入低 44 个前置位：`C355 +0x80..+0x87 = FF FF FF FF FF 0F 00 00`。保留 bit44..63、`+0xC8` 显示域和其他字段；仍由 C354 驱动 C355。
3. 用 `scripts/prepare_client_compatibility.py --dungeon7` 从自己的 `Village_map_image/Village_map_image.pack` 按 `NANA_PACK` 页面／单元结构派生 P03 道路版本；启动器的 `--emotion --dungeon7 --apply` 会自动完成同一操作。
4. 创建地宫7的 SSTG 名称兼容文件：将自己的 `flying/hd0_ep22_dg01_st01.sstg` 逐字节复制为 `flying/hd0_ep22_dg00_st01.sstg`；启动器不检查源或产物哈希。
5. 保留资源查找映射 `hd0/ep100/dg6/st1 -> hd0/ep22/dg1/st1`，并从自己的 `flying/pon/mis_ep22_dg01_m_196.pon` 逐字节复制出缺失的 `_02` 同家族回退；启动器不检查产物。
6. 重启适配器并重新登录，使客户端重新读取 C355；从 page17 步行到 page18，再进入 action `166`。验证 SSTG、SMMO、PON 均能按路径加载。
进入地宫7不是一个单字节显示开关。必须同时满足**前置进度、村庄道路、关卡资源命名、adapter 资源映射和嵌套 PON**五个边界。

### 3.1 C355 前置进度

第五村使用 C355 完整帧 `+0x80..+0x87` 的独立 64 位前置字段。客户端移动判定对 `k=0..21` 的每个前置要求两个 bit 同时为 1。

完整 adapter 在所有 C355 构造完成后，仅设置低 44 bit：

```text
C355 +0x80..+0x87
FF FF FF FF FF 0F 00 00
```

实现位置：

```text
release/components/dungeon_unlock/unlock_patch.inc
```

约束：

- 只设置 22 个前置对；
- 保留 bit44..63，包括最终完成对；
- 不修改 `+0xC8` 的关卡显示字节；
- 不主动推送 C367/C368；
- 仍由 C354 请求驱动 C355。

### 3.2 P03 村庄道路 pack

原始第五村 pack 只有前六个入口的连通道路，page17 没有通往 page18 的出口。地宫7需要 P03 道路 pack：

```text
Village_map_image/Village_map_image.pack
```

派生器读取 pack 目录与第五村 50×36 单元网格，按字段语义生成道路；不要求原始 pack 或输出 pack 命中固定哈希。

P03 在 P02 基础上补入 16 条双向道路，保留：

- page17/page18 的原生地宫7入口 action `166`；
- page18 `(25,6)` 的返回 marker `169`；
- 返回坐标 `(400,96)`；
- 已有 `160..166` action；
- 未增加虚构的 `167..182` 地宫入口。

因此 P03 解决的是道路连通性，不代表后续 23 个地宫战斗资源全部存在。

### 3.3 地宫7关卡 SSTG 别名

客户端请求的兼容路径为：

```text
flying/hd0_ep22_dg00_st01.sstg
```

使用者应从已有的：

```text
flying/hd0_ep22_dg01_st01.sstg
```

制作**逐字节相同**的别名文件。该复制关系由派生器执行；不对源文件或别名文件设置固定大小／哈希门禁。

只复制 SSTG 文件名；文件内部已经存在的 dg01 SMMO 引用保持不变。

### 3.4 adapter 资源查找映射

地宫7在村庄／房间身份中保留 `hd0/ep100/dg6/st1`，但资源目录使用 `ep22/dg1/st1`。完整 adapter 对**普通目标和 Boss**使用限定映射：

```text
hd0 / ep100 / dg6 / st1
    ->
hd0 / ep22 / dg1 / st1
```

该映射只用于资源查找，不改写房间身份、客户端显示 tuple、奖励归属或持久进度。

### 3.5 缺失 PON 同家族回退

关卡嵌套依赖还需要：

```text
源  flying/pon/mis_ep22_dg01_m_196.pon
目标 flying/pon/mis_ep22_dg01_m_196_02.pon
操作 逐字节复制，不设置固定大小／哈希门禁
```

这是同家族兼容回退，不是找回缺失的原始 `_02` 文件，也不应宣称其外观、轨迹或参数与缺失的原始文件一致。`gui_launcher/resource_patches/superboss_projectile_alias.json` 仅记录派生关系和证据边界；GUI 不校验源或目标哈希。

### 3.6 不要混淆的显示边界

客户端 `0x0090012F` 会单独把 d07 小地图图层标记为隐藏。该标志影响小地图显示，不是 page17→18 道路、入口 action166 或关卡资源加载的替代条件。当前派生器不修改该站点，因为它不属于“可步行／可进入／可加载资源”的必要链。即使地宫7可进入，小地图 d07 图层仍可能隐藏，必须作为独立真实客户端视觉验收项记录。

不要通过以下方式“修复”入口：

- 主动伪造 C367/C368；
- 删除家具、隐藏入口或全局 noclip；
- 把 `+0xC8` 显示状态当成前置进度；
- 修改房间 tuple 以绕过资源映射；
- 复制不存在的后续地宫战斗集合并声称为原始内容。

### 3.7 验收清单

1. 重新登录，使客户端重新读取 C355 前置字段；
2. 从 page17 正常步行到 page18；
3. 进入 action166，房间选择／创建界面可操作；
4. 进入地宫7，SSTG、SMMO、PON 无缺失文件错误；
5. 三个难度分别验证普通目标、Boss、结算；
6. 死亡、离开、通关后通过 marker169 返回 `(400,96)`；
7. 再次进入地宫7，不丢失道路、入口和关卡进度；
8. 保留日志和客户端可见结果，区分 adapter 构造通过与原客户端可见验收。
