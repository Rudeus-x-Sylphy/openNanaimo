# L7 外观／BGM 与 L8 代码／资源部署

`scripts/port_lumineos_resources.py` 从使用者自备资源生成选择性增量包。转换和安装分开：安装、校验及回滚仅使用 Python 标准库；构建转换还需要 PyCryptodome。输入资源由使用者合法提供。

## 范围

- L7：原生村庄场景、入口、指示、加载图和准备预览；三份SSTG只补齐韩服的BGM引用，保留音乐字段之外的已有战斗定义及旧版本所需的两项兼容别名。
- L8：ep23 命名族、两阶段各九个真实 SMMO 槽、明确引用的共享依赖、村庄场景、加载图及准备预览。MMO/PON 转换到读取器支持的格式，SSTG 逻辑身份修正为 `0/100/7/{0,1}`，保留stage1内部`dg01_st00`槽名。
- 仅替换村庄包中的 page18/page19 记录，然后合并既有道路修复；18↔19 保留，19↔14 的未来关卡连接双向封闭。
- 资源安装器按882项清单更新资源，保留EXE、GS、PI、QS、适配器程序和角色存档。代码部署器独立更新适配器，并在资源身份验证后精确修改小地图固定关闭边界，保留全局解锁配置。

**代码与资源已接入，验证范围为资源身份、格式转换、安装事务和适配器构造。** 集成内容包括ep23普通／Boss／运行目标／碰撞／结算目录、带区域上下文的导航、R8授予与数据库迁移。GPU、碰撞、音效、完整Boss／结算与多人属于独立客户端验收范围。

## 资源事务

转换、安装和验证采用相互独立的阶段，目标资源由清单精确限定。

`manifest/lumineos_resource_port.json` 固定每个输入、原客户端基线及转换输出的大小/哈希。`compatible_recipe_sha256s`登记可兼容的既有配方身份，所有版本共同执行逐文件基线、目标摘要、操作类型与保留清单校验。未知来源、未知覆盖目标、转换结果偏离、缺少共享依赖都会拒绝。源版本不同不能通过临时修改清单或全目录覆盖绕过，应重新审计。

L7两阶段及stage1兼容别名的BGM统一为`sounds/23_ssky_game_bgm.ogg`，L8两阶段保持`35_ssky_game_bgm.ogg`；两份音频均已与韩服原文件逐字节一致，保留而不重复覆盖。三份L7 SSTG从原477项全文件保留清单移入BGM字段转换清单，另外474项保持原哈希。

安装前先关闭目标副本的游戏进程；读取适配器目录的adapter进程无需退出。安装器先校验全部目标，再保存备份与事务收据，逐文件通过同目录临时文件原子替换。普通异常自动回滚；进程中断留下的 `applying` 收据会阻止后续安装，需先显式恢复。重复安装会重新核对所有资源，而不只是查看标记文件。

仅对`upgrade_from_manifest_ids`登记的精确旧标记允许原位升级；升级前核对旧包全部资源，新事务备份旧标记和三份SSTG。普通新增安装仍使用原CN基线。未知旧包、内容后续修改或未完成事务均拒绝。成功输出包含相对于客户端根目录的事务收据。

回滚先全量验证备份及现有文件，只删除该事务新建且仍匹配安装哈希的文件；其他文件恢复原字节。遇到后续编辑会拒绝，不强行覆盖。备份和收据保留，不递归删除目录。

## 启动一致性

兼容脚本识别成对原生场景及精确入口格点，保持它们，不再套用旧 L7 入口坐标。缺一页或触发区异常会拒绝处理。无原生场景时仍沿用既有布局。

社交副本启动前核对资源身份及内容。目录链接会读取相同内容；若系统退回独立目录复制且副本已过期，则拒绝启动，要求重建副本，确保资源版本一致。资源标记只在内容一致后更新。移除源资源包后，带旧标记的副本也会被拒绝。战斗目录另由`manifest/lumineos_combat.json`约束，不用资源标记代替代码身份校验。小地图在完整资源验证后使用B84关闭未来关卡，保留L7/L8原生前置；无资源包仍使用B80，不全局解锁。

## 定向验证

两个真实资源检查按本地资源可用性执行或条件跳过；事务和合成场景检查使用隔离输入。

## 代码与状态一致性

生成器输出到独立目录，须审核后纳入源码与发布数据；它不会自行覆盖正式目录。DCC7、普通HP和Boss目录同时生成，再以当前脚本生成碰撞／地形目录并更新清单，不能只拷贝其中一个表。托管构建从`adapter_runtime`取数据，避免使用旧的本地构建缓存。

部署命令默认只预检；`--apply`先拒绝活动进程，保存代码原字节及配置／存档快照，调用资源事务，再发布清单内文件及单字节小地图兼容项。正式配置与存档保持原内容，下一次启动执行保留旧称号行的R8数据库约束迁移。失败结果不授予R8；成绩按独立区域、阶段和难度保存。HP采用资源字段与适配器缩放规则；卡池和地形对象采用已确认条目的严格资格规则。

回滚需要所有游戏／适配器退出，且文件匹配应用后摘要。代码收据包含资源事务收据；角色存档保持当前进度。开始新游戏后若需要退回旧数据库版本，应另行审查备份与新增进度，不能把安装前存档直接覆盖回来。

客户端EXE修改的前置条件、精确位点、应用和回滚步骤统一见[客户端兼容说明](完整适配器与客户端兼容说明.md#36-显示边界)。
