### 统一发布包

修道僧挑战配套发布包含前四村出口对白、37项场景／立绘／创建及结果页资源、1,154项战斗资源、36槽独立战斗目录、本地选关与来源位置恢复配方。客户端、overlay、DCC7与运行程序按活动发布清单配套；安装及回退归[客户端二进制补丁](../../指南/客户端二进制补丁.md#第五村原生破关入口-action-资源)，验收范围归[验证状态](../验证状态.md)。

当前发布采用net8.0自包含运行包，托管程序集、原生入口、资源目录与兼容配方共同登记于活动清单。源码闭包、运行文件和发布文件分别按精确大小及SHA-256校验；安装与回退采用逐文件事务。验证层级为构造、数据库事务、隔离指令、工作进程及发布约定；客户端任务、娱乐难度和竞技连续对局按匹配版本独立验收，`runtime_acceptance=false`。

当前发布以`manifest/source_closure.json`、`adapter_runtime/adapter_manifest.json`和`manifest/open_release_manifest.json`共同登记源码及产物身份。运行入口为托管适配器与原生桥接（bridge）组合；适配器使用11005／11999／12050端口，原生桥接使用51005。金币、积分、卡牌、角色装备与连续挑战按各自功能主题的当前规则执行。

| 身份对象 | 唯一登记入口 | 核对方式 |
|---|---|---|
| 完整runtime文件，包括Adapter、Gameplay、原生桥接和资源目录 | `adapter_runtime/adapter_manifest.json` 的 `files`（`name`／`size`／`sha256`） | 对照实际文件大小和SHA-256及完整文件身份。 |
| 当前发布关键文件及验收状态 | `manifest/open_release_manifest.json` 的 `critical_files`、`runtime_acceptance` | 与runtime清单和磁盘逐项对照；`runtime_acceptance=false`对应构造／发布验证层级。 |
| 源码闭包及数量 | `manifest/source_closure.json` 的 `files`、`count` | 对照条目及源码身份，数量随活动清单维护。 |
| 原生正式／testports／原生桥接输出 | `manifest/source_closure.json` 的 `build_outputs` | 重复构建逐字节比较，并与发布的原生桥接身份对照。 |

原生三个入口分别执行重复构建字节比较；GUI使用managed入口与原生桥接组合，正式／testports入口按独立用途维护。当前下载与安装身份统一取活动清单的文件大小及SHA-256。

### 当前本机部署

当前源码闭包、发布关键文件及net8.0自包含运行包成套部署到客户端根目录。安装器按清单逐文件核对并更新差异；根目录与适配器数据目录的`gi._D6`、`IE._D23`、`pi._D7`、`ava._D1`和`Sddakg._D35`保持一致。客户端按内嵌配方应用教程血条、选宠提示、兑换图标与余额预览兼容项。完整步骤与资源清单见[教程与商城资源配套](../../指南/客户端二进制补丁/教程与商城资源配套.md)。

99页库存客户端保持原生发送上下文，完整扩展、升级输入和恢复目标按[99页库存安装与恢复](../../指南/客户端二进制补丁/99页库存安装与恢复.md)逐项核对。安装目录中的Adapter与Gameplay程序集、原生桥接及目录资源使用同一活动运行清单，PET投影在旧格式和99页格式下共用定义有效性筛选。

部署以目标目录`deployment_backups`保存受管理文件原字节和逐文件收据，数据库、存档与用户配置按原身份核对。商城、教程奖励、启动器`-ValidateOnly`及发布身份分别执行验证；当前层级为发布一致性、适配器构造与SQLite事务，`runtime_acceptance=false`。

只读查看登记值及计算磁盘身份（在仓库根目录执行）：

```powershell
$runtime = Get-Content -Raw -Encoding UTF8 adapter_runtime/adapter_manifest.json | ConvertFrom-Json
$runtime.files | Where-Object { $_.name -in @('Nanaimo.Adapter.exe','Nanaimo.Adapter.dll','Nanaimo.Gameplay.dll','nanaimo_gameplay_bridge.exe') } | Format-Table name,size,sha256 -AutoSize
(Get-Content -Raw -Encoding UTF8 manifest/source_closure.json | ConvertFrom-Json).count
Get-FileHash -Algorithm SHA256 adapter_runtime/Nanaimo.Adapter.exe,adapter_runtime/Nanaimo.Gameplay.dll
```

清单、磁盘及源码身份一致后进入发布；发现差异时先核对待发布基线，再构建对应产物并逐文件校验。

### 文件校验与客户端存在性

源码闭包、活动清单的全部关键文件、运行包约定及GUI的`-ValidateOnly`分别维护校验结果。完整包校验要求使用者自备的`game.exe`存在，项目运行文件按大小与SHA-256核对；客户端存在性检查不等于PE位点兼容检查或实机验收。

## 构建与发布文件

| 文件 | 作用 |
|---|---|
| `scripts/build_complete_adapter.ps1` | 构建完整适配器和桥接组件，可运行 self-test。 |
| `scripts/build_adapter.ps1` | 重建原生正式／testports 入口并核对清单。 |
| `scripts/verify_package.py` | source-only 或完整运行目录检查。 |
| `scripts/refresh_source_manifest.py` | 刷新当前源码闭包和 reviewed 输出。 |
| `manifest/source_closure.json` | 当前源码身份和原生输出约定。 |
| `adapter_runtime/adapter_manifest.json` | 当前完整适配器二进制身份。 |
