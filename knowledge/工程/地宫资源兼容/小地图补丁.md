# 工程／地宫资源兼容／小地图补丁

使用 C# 兼容工具时须在应用前独立保存每个待改源文件的大小与 SHA-256：C# 报告不含 `before_sha256` 与 `backup`，Python 报告直接提供这些字段；两类报告的字段差异见[两类工具报告的差异](../客户端兼容/自动兼容清单.md#两类工具报告的差异)。通用预检、应用与恢复步骤见[统一安装与恢复](../../指南/客户端二进制补丁/统一安装与恢复.md#df-12-011)。

## 作用与范围

维护 L7/L8 小地图完整函数门禁、一字节关闭边界和安装／恢复步骤。

## 读数与证据约定

`VA`、`完整帧`／`payload` 的偏移基准及地址字节的校验依据统一见[读数与证据约定](../客户端兼容/自动兼容清单.md#读数与证据约定)。

### 显示边界

- 小地图初始化 `0x009000D0..0x00900156` 先循环查询原生前置条件并写入各章节开关，随后 `0x0090012F` 的 `C7 80 7C 0B 00 00 00 00 00 00` 把第7关强制关闭。
- 派生器以整个初始化函数的原始／L7／L8完整字节签名为门禁，只将该指令的偏移 `0xB7C` 改为 `0xB80`（实际唯一变化位于 `0x00900131`，`7C → 80`），使强制关闭边界移到第8关，第7关保留原生条件的查询结果。
- 安装并完整校验L8资源包时，目标位移改为`0xB84`（同一地址字节`7C/80 → 84`），固定关闭第9关，保留第7／第8关的原生条件；保留全局解锁配置。
- 重复应用不再变化；未知函数字节拒绝写入。

该修正仅调整小地图章节开关边界，C355前置进度、移动门槛、战斗资源、page17→18道路和action166保持各自契约。

完整应用与恢复步骤：

1. 托管工具使用`--dungeon7`选择该兼容项。开发期Python工具也支持`--all`，托管工具没有该总开关。
2. 解析PE32区段，将 `0x009000D0..0x00900156` 映射到文件偏移，并对整个初始化函数匹配登记的原字节或已应用字节。
3. 在内存中仅修改 `0x00900131`：无L8资源时使用`80`（B80），已验证L8资源时使用`84`（B84），原始值为`7C`（B7C）。
4. 逐字节复核完整函数、唯一变化位置及第7／第8关开关目标，生成独立覆盖目录和兼容报告。
5. 使用 `--apply` 时先将完整 `game.exe` 按SHA-256保存到 `backups/`，再执行单文件原子替换；重复应用收敛到相同文件。
6. 回滚时关闭客户端，结合应用前独立登记的原 SHA-256 定位并恢复完整 EXE 备份并核对SHA-256；单项恢复在完整函数门禁通过后还原该次应用前的 `7C`、`80` 或 `84`，步骤见本页“L7/L8二进制补丁 完整流程”。

入口兼容链保持以下边界：

- 新客户端进程的首个 C355 固定发布 `map/page=0/0`，避免原生 `FirstVillageFlag` 在任意存档页面读取缺失入口；
- 首个 C367 不被适配器覆盖为存档页面，C367/C368 仍保持请求驱动；
- 家具、入口可见性与碰撞策略保持独立；
- `+0xC8..+0xDE` 是前沿关卡显示区（23 行两位打包评级）；前置进度位于 `+0x80..+0x87`。工程页此前把它记作“显示状态”，与业务页口径不同，两处口径待确认（业务页见[资料与资源载体](../../业务/角色/角色资料/资料与资源载体.md#kb-03-009)）。
- 房间 tuple 保持原身份，资源查找使用限定映射；
- 战斗资源清单只登记实际存在或可重复派生的文件。

### L7/L8二进制补丁 完整流程

**修改目标：** PE32客户端`game.exe`中小地图初始化函数`0x009000D0..0x00900156`。执行入口为自包含运行包的`Nanaimo.Adapter.exe --tools compatibility`，补丁配方内嵌在托管程序集；需要同时应用其他兼容项时，按[自动兼容清单](../客户端兼容/README.md#df-11-002)显式传入对应选项。

| 客户端资源状态 | `0x0090012F`完整指令 | `0x00900131` | 固定关闭章节 |
|---|---|---|---|
| 原始函数 | `C7 80 7C 0B 00 00 00 00 00 00` | `7C` | L7 |
| L7兼容布局 | `C7 80 80 0B 00 00 00 00 00 00` | `80` | L8 |
| 完整L7/L8资源 | `C7 80 84 0B 00 00 00 00 00 00` | `84` | L9 |

1. **准备。** 退出目标客户端及使用该目录的适配器／原生桥接进程；保存客户端和资源的完整备份，记录`game.exe`的SHA-256。选择独立覆盖输出目录，保持输入与输出根目录各自独立。
2. **资源预检。** L8目标要求`openNanaimo-l7-l8-resources.json`及其1328项安装资源逐项匹配大小与SHA-256；当前L7韩服怪物闭包、stage1 SSTG/PON兼容别名与L8资源使用同一清单。凭据摘要、路径唯一性及文件身份一起校验。L7兼容布局采用`B80`，完整L8资源采用`B84`。
3. **函数门禁。** 按PE32节表映射VA；完整函数必须匹配原始、L7或L8登记签名之一。输入匹配后仅调整该函数`0x00900131`的一字节位移；章节原生前置计算和其他函数内容按各自配方保留。
4. **只读预检。** 从项目根目录执行以下命令，核对结果中`planned_verification.all_pass`、操作站点及计划文件。

   ```powershell
   $Client = '<客户端根目录>'
   $Overlay = '<独立覆盖输出目录>'
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root $Client --output-root $Overlay --dungeon7 --dry-run
   if ($LASTEXITCODE -ne 0) { throw '客户端兼容预检失败' }
   ```

   L8资源可单独校验：

   ```powershell
   .\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --client-root $Client --kind lumineos
   if ($LASTEXITCODE -ne 0) { throw 'L7/L8资源身份校验失败' }
   ```

5. **派生及应用。** 使用全新的覆盖输出目录，执行相同选项并添加`--apply`。重用已审阅的输出目录时添加`--overwrite`。`--dungeon7`同时处理道路、兼容别名和已登记图像迁移，具体范围见[前置进度](范围与前置进度.md)、[道路与别名](道路与资源别名.md)及[场景与旧美术迁移](场景衔接与旧美术迁移.md)；其他组件使用[自动兼容清单](../客户端兼容/README.md#df-11-002)列出的对应选项。

   ```powershell
   .\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root $Client --output-root $Overlay --dungeon7 --apply
   if ($LASTEXITCODE -ne 0) { throw '客户端兼容应用失败' }
   ```

- 工具先在内存派生全部文件并重复应用配方验证幂等，再写覆盖目录。
- 应用前重新核对源字节并将原文件保存到`backups/<原SHA-256>/<相对路径>`；实际写入采用同目录临时文件原子替换。
- 异常时按逆序恢复已修改文件，并以目标摘要保护并发编辑。

6. **结果校验。** 核对`nanaimo_compatibility_report.json`中的`verification.all_pass`、逐文件`apply_results`与输出摘要；重复只读预检应得到相同目标字节。

- 核对完整函数及`0x00900131`目标值、村庄入口格点和全部L8资源身份。
- 独立记录客户端地图显示和关卡操作验收。

7. **回滚。** 退出目标进程，将当前文件与该次报告的应用后SHA-256比较，确认仍属于本次应用结果；再从内容寻址备份逐文件恢复并核对原SHA-256。

- 针对EXE优先恢复完整备份。
- 单独撤销小地图项时，仍以完整登记函数为门禁，将`0x00900131`恢复到该次应用前的`7C`、`80`或`84`。
- 资源和代码部署产生的事务按各自收据逆序恢复，角色数据库保持独立。

代码与资源整合部署入口`deploy_lumineos_release.py`同样在资源身份通过后应用该位点，默认执行预检，`--apply`执行事务；回滚使用该次输出的收据：

```powershell
python -B scripts/deploy_lumineos_release.py --client $Client --bundle '<已审核资源包>'
python -B scripts/deploy_lumineos_release.py --client $Client --bundle '<已审核资源包>' --apply
python -B scripts/deploy_lumineos_release.py --client $Client --rollback '<该次部署收据>'
```

每一步确认退出码为0后进入下一步。部署收据统一登记代码与资源事务，回滚以应用后摘要保护后续编辑。
