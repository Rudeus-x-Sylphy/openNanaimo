# 历史文档导出层约定

以下是文档融合前的完整导出层说明，仅作为结构迁移的历史审计材料；不用于当前文件选择。当前目录、层依赖和命令见[文件清单与导出工具](../../指南/文件清单与导出工具.md)。源文路径已重定位到现行入口，原有层定义和三层组织描述保持历史语义。

## 文件层

| 层 | 内容 |
|---|---|
| `runtime` | 启动脚本、本地适配器和运行支持代码 |
| `source` | C／include闭包、构建与校验脚本、源码清单 |
| `knowledge` | 三层知识库入口、基础机制、业务模块、工程主题及历史验证路由 |
| `docs` | README与项目说明 |
| `python`、`tcc` | 可选的外部工具候选层；仓库不附带其中的工具文件，也不会自动下载 |
| `testports` | 隔离测试端口适配器 |

默认选择 `runtime,source,knowledge`；依赖层自动展开，`testports`不默认选择。源码层使用 `manifest/source_closure.json` 核对闭包，文件数量以该清单的 `count` 和实际条目为准，包含构建所需的生成数据表，不在本文另维护固定计数。生成表按清单参与编译；其生成输入与工具按各自清单独立登记。

运行依赖见 [运行依赖.md](../../指南/运行依赖.md)。导出器不处理客户端与游戏资源，不提供binary delta、安装导入器或补丁应用器。

知识库入口为[索引](../../README.md)，内容由基础、业务、工程三层独立维护。导出候选允许既定模块内的Markdown与工程历史验证目录；新增文件须显式登记。迁移清单与压缩原文基线是精确列名的`source`审计材料，其他压缩包仍不属于候选。知识库完整性命令见[知识维护](../知识维护.md)。
