## 修道僧独立挑战

当前发布包含四村NPC对白入口及`hd0/ep24..27/dg0/st0`四关挑战，实现状态为`four-village-dialogue-entry`，入口绑定（`entry_binding`）为`village-dialogue-bound`。源码、运行文件和关键发布文件分别由`manifest/source_closure.json`、`adapter_runtime/adapter_manifest.json`、`manifest/open_release_manifest.json`登记。

## 当前功能

| 主题 | 当前结论 |
|---|---|
| NPC位置与绘制 | 四村出口固定位置，48×96命中范围，场景第1层按脚底Y排序，身体／阴影／名牌采用配套偏移。 |
| 名牌 | 46×24中心锚点，13号中文、白色字面、1像素深棕描边、2像素行距、原版英文像素字形。 |
| 点击与对白 | 手形1，左键按下沿，底部四行分页，Enter／按钮推进，Escape关闭，窗口按打开／关闭状态回收。 |
| 立绘与层次 | 四村NPC62～65立绘，逐帧推进动画；对白及立绘位于聊天／HUD之后、光标之前。 |
| 入口与房间 | 按当前村庄／页面建立挑战身份，创建页使用挑战介绍图，准备房左上角关卡名、中间地宫-01／阶段-01及对应BOSS名。 |
| 结算与返城 | 结果页提供同关重试和回城；胜败对白在恢复来源城镇后显示一次，来源位置绑定本人UID与可走坐标。 |
| 状态记录 | 四位独立通关掩码、成功收据和最佳成绩在同一事务提交，校验角色、会话、战斗周期和结算轮次。 |
| 资源事务 | 37项场景／UI／立绘与1,154项战斗资源联合校验（单位：资源文件项），支持父资源叠加、旧标记升级、幂等应用与精确恢复。 |

准备房检查包含64种身份在名称和BOSS两个位点的文本、坐标、颜色、栈、寄存器、标志及共享记录约束（单位：身份编号×文本位点）；结果控件覆盖256组输入／绘制组合（单位：输入事件×绘制状态）。资源事务逐项校验37项文件（单位：资源文件项）、父包身份、升级标记、备份及恢复。场景排序检查覆盖四村和动画帧，名牌检查覆盖字面、描边、透明度及英文像素。

## 四关排名验证

四关成绩采用单槽模型；每行Epi框使用原生数字贴图显示`01／02／03／04`，提示文案左侧显示当前关卡名，面板为450×336逻辑像素。配套专用EFF／IM3两项，场景／UI／立绘清单合计37项。程序集与资源身份由活动发布清单统一登记。

托管专项覆盖四关×单槽×12角色、十名上限与排序、只读重开、合法难度、入口／重试、生产检查点、重复及较低分保留、事务回滚、旧表合并、最高评级／分数独立保留、耗时归属、重复初始化与外键删除。当前构建的专项结果按活动发布身份登记。

x86检查覆盖四评级槽、八数字控件与帧序、四关标题、两处关闭控件位置和命中矩形、单槽最大值、栈与寄存器、逐数字分配失败、析构、精确元组及旧载荷迁移。资源检查覆盖外框、完整提示／页脚、Epi框、四个内侧圆槽、阴影宽度、37项身份、幂等安装和恢复。边缘像素检查覆盖顶部铆钉、右下圆角、右缘及末行清理范围。
