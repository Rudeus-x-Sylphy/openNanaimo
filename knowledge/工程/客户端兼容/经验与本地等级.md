### 实时得分与权威经验同步

`--dungeon-state`包含临时经验预览兼容项。D00E/D012的三槽DWORD及D010的角色DWORD用于实时分数显示；适配器分别提交首次终结击杀和合法终局奖励，C57C更新局内经验与等级，CF88发布终局结果。客户端经验条使用这些已提交的权威数值。

- 客户端`748C90 → 401005 → 74C190`把本地槽当前分数的25%写入临时经验，`8E1620`将其叠加到已提交经验条。
- 原生预览路径以80级为门控，模式可取全值、一半或零；当前实际经验采用适配器1至200级、CurveVersion3的累计曲线和级内投影，奖励规则归知识库[业务／地宫／计分与结算](../../业务/地宫/计分与结算/README.md)。
- 兼容项将临时setter输入归零，保留实时分数、已提交经验、角色／宠物奖励、调用栈和其余函数状态；原生预览门槛与当前等级上限独立维护。

#### 二进制修改约定

| 项目 | 内容 |
|---|---|
| 目标 | 使用者客户端`game.exe`，受支持的PE布局 |
| 完整函数门禁VA | `0x0074C190`，25字节 |
| 原函数字节 | `55 8B EC 51 89 4D FC 8B 45 FC 8B 4D 08 89 88 D0 0F 00 00 8B E5 5D C2 04 00` |
| 应用后函数字节 | `55 8B EC 51 89 4D FC 8B 45 FC 31 C9 90 89 88 D0 0F 00 00 8B E5 5D C2 04 00` |
| 实际替换VA | `0x0074C19A`，`8B 4D 08` → `31 C9 90` |
| 写入语义 | 临时EXP字段`global+0xFD0`写零；已提交EXP字段`global+0xFCC`继续由资料接口更新 |
| 配方 | `scripts/dungeon_experience_compat.py`；运行配方归`managed-host/Resources/client-compatibility.json` |

#### 完整应用、校验与回退步骤

本节两处站点同属`--dungeon-state`整组兼容项，安装、校验与回退合并为同一套步骤。

1. 关闭目标客户端及其社交槽位，确认客户端目录与独立输出目录，记录`game.exe`大小与SHA-256，保留完整原文件（或该目标的派生前备份）作为本次回退基线，并保存当前运行配方。目标VA按PE节表换算为文件偏移：`PointerToRawData + VA - (ImageBase + VirtualAddress)`。
2. 兼容工具先校验完整地宫兼容集合，再逐站点门禁本组两处：`0x0074C190`完整25字节的原函数进入应用分支、应用后函数进入幂等分支，其余字节组合报告站点差异并停止；`0x00701BB4`完整51字节的原区执行替换、目标区按已应用处理，其余内容由精确字节门禁拒绝。派生阶段尚未应用，此时应保存源文件基线，`--apply` 才按原摘要备份改写目标。任选一种工具派生候选：

   ```powershell
   python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<patch-output>" --dungeon-state --dry-run
   ```

   ```powershell
   adapter_runtime/Nanaimo.Adapter.exe --tools compatibility --source-root "<client-root>" --output-root "<独立派生目录>" --dungeon-state --overwrite
   ```

3. 核对派生报告中的`battle_local_level`站点、两处完整目标字节、同组兼容项、文件长度及重复派生的一致性；确认后以同一命令追加`--apply`（或`--overwrite --apply`）逐文件提交整组兼容项：

   ```powershell
   python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<patch-output>" --dungeon-state --apply
   ```

- 此入口应用本章`--dungeon-state`整组兼容项，包括结算输入和BOSS血条；临时经验站点执行上述三字节原位替换。
- 工具在输出目录`backups/<原文件SHA-256>/game.exe`保留完整备份，原子写入目标，并在`nanaimo_compatibility_report.json`的`apply_results`中登记修改前后身份与备份位置；文件间不具备同时生效的原子性。
- GUI使用同组运行配方。

4. 检查报告`verification.all_pass=true`，核对函数完整新字节、应用后文件大小、SHA-256及完整51字节目标区；再次执行第2步确认幂等。GUI启动前使用相同运行配方完成兼容检查，部署时配套更新适配器与客户端兼容项。
- 字节级自动检查覆盖完整函数门禁、三字节替换、重复应用、恢复及状态保持；功能约定覆盖实时分数、C57C权威经验和CF88独立终局，客户端场景按知识库[工程／验证状态](../验证状态/README.md)的验证层级验收。

5. 整组回退时关闭目标客户端及其社交槽位，核对本次报告中的备份身份，将该次完整备份恢复为`game.exe`，逐项恢复报告中同组修改的其他文件，同步恢复配套运行配方，再校验恢复后的大小和SHA-256。
- 单项回退：经验站先匹配完整25字节应用后函数，再将`0x0074C19A`恢复为`8B 4D 08`，核对完整原函数并保留其他兼容项；本地等级站先完整匹配51字节目标区，再恢复上列51字节原区，核对完整原区及其他兼容项保持原状态。
- 单项回退后，GUI统一兼容检查按活动配方重新应用该站点；持续回退须同步采用对应运行配方。

#### 关内人物脚边等级同步

- C57C维护全局等级与经验条，C60D/12按角色UID更新战斗人物脚边等级。
- `--dungeon-state`同时安装`battle_local_level`兼容项：在本地人物分支缓存指针、检查非空与UID，复用既有等级setter，并保留队员链表、房间资料和返回路径。
- 补丁使用原有代码区，保持角色／宠物身份、HP/MP及Power连续；关内存活角色跨级回满有效HP/MP由适配器执行。
- 接口字段与调用链见知识库[角色等级经验消费链](../../业务/角色/等级经验/协议载体/客户端经验与HUD消费链.md#kb-08-016)，存活角色升级回满有效HP/MP策略见[地宫战斗资源](../../业务/地宫/战斗资源/README.md)，验证范围见[工程／验证状态](../验证状态/README.md)。

补丁约定：目标为`game.exe`，PE VA `0x00701BB4`，长度51字节；按PE节表将VA映射为文件偏移，完整匹配下列原区或目标区。原区执行替换，目标区按已应用处理，其余内容由精确字节门禁拒绝。跳转目标`0x00701B94`复用现有等级setter。

原区字节：

```text
83 7D FC 00 75 2D E8 95 5D D1 FF 8B C8 E8 F7 5D D1 FF
8B C8 E8 1C 06 D0 FF 8B 4D 08 0F B7 51 08 3B C2 75 0F
E8 77 5D D1 FF 8B C8 E8 D9 5D D1 FF 89 45 FC
```

目标区字节：

```text
83 7D FC 00 75 2D E8 95 5D D1 FF 8B C8 E8 F7 5D D1 FF
85 C0 74 1D 89 45 FC 8B C8 E8 15 06 D0 FF 8B 55 08 0F
B7 52 08 3B C2 75 08 EB B3 90 90 90 90 90 90
```

本节站点的应用、校验与回退与本节其他站点合并维护，见[完整应用、校验与回退步骤](#完整应用校验与回退步骤)；原区与目标区字节见上列代码块。

当前验证覆盖本人／队员等级写入、UID匹配、本地人物缺失、栈平衡、精确字节门禁、重复应用及回退；确认层级为静态接口与隔离指令，运行验收状态由知识库[工程／验证状态](../验证状态/README.md)维护。

## 局内经验预览与本地角色等级

局内经验预览值由受保护的setter写入`global+0xFD0`，已提交经验位于`global+0xFCC`。兼容配方将临时预览值固定为0，实时分数、已提交经验及CF88终局奖励各自按原有字段维护。C60D本地角色分支缓存角色指针、校验UID并复用等级setter，人物等级、PET阶段和Power分别使用各自字段。

两处站点的原字节与应用后字节不在此重复：经验预览见[经验预览二进制约定](#df-11-002-experience)，本地等级见[本地等级二进制约定](#关内人物脚边等级同步)。

经验setter的实际替换点为`0x0074C19A`，`8B 4D 08`改为`31 C9 90`；完整25字节保护范围（实际替换3字节）保持thiscall／ret4约定、栈平衡及返回值。本地等级分支使用原有代码区与角色等级写入路径，保留远端列表和房间资料更新。精确配方由`scripts/dungeon_experience_compat.py::patch_sites()`维护，两项随`--dungeon-state`统一生成、安装、核验及恢复。
