# 工程／客户端兼容／自动兼容清单

## 作用与范围

维护自动兼容项、启动前门禁和逐文件应用边界。

依据 gui_launcher/nanaimo_launcher.ps1、managed-host/LauncherTools.Compatibility.cs 与内嵌配方；不以文档中的地址替代站点校验。

## 读数与证据约定

- `VA` 表示 PE 虚拟地址，文件偏移须由 PE 节表换算；表中明确标为文件偏移的值直接相对文件首字节。
- `完整帧` 从协议头首字节计偏移，`payload` 从8字节协议头之后计偏移；对象、记录与代码区偏移相对各自基址。原生指令消费与协议构造只证明各自层级，画面验收状态见验证状态。
- 地址、字节及旧版编码以生成脚本和 `managed-host/Resources/client-compatibility.json` 为校验依据；未知编码保持冲突拒绝。

## 完整适配器结构

GUI 只启动一套完整适配器：

```text
Nanaimo.Adapter.exe
  ├─ 登录、角色、村庄、社交、任务、商城、公寓、交易、竞技与娱乐
  └─ nanaimo_gameplay_bridge.exe
       └─ 地宫房间、战斗、BOSS、掉落、结算与原生状态交换
```

`Nanaimo.Adapter.exe` 监听客户端固定入口 `11005/11999/12050`；桥接进程使用单独的本机端口，不直接暴露给 GUI。运行状态位于 `adapter_data/`，日志位于 `adapter_data/logs/`。

GUI 的本地 **“进入 Nanaimo”** 会按顺序：

1. 校验已运行的完整适配器及`127.0.0.1`绑定，进入操作复用该服务；
2. 按用户名／角色显示名解析所选已保存档案，纯新手模式写入隔离runtime profile；角色数值和库存通过显式保存入口维护；
3. 确认 `game.exe` 存在，并调用 `adapter_runtime/Nanaimo.Adapter.exe --tools compatibility --source-root "<OPEN_ROOT>" --output-root "<OPEN_ROOT>/adapter_data/client_compatibility_overlay" --legacy-startup --character-creation --furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --apartment-recommendation --dungeon7 --overwrite --apply`；先准备[陈旧组件启动兼容](陈旧组件启动兼容.md)，再对已知PE布局应用新账号建角、家具、结算、礼物预览、空地购房、房屋推荐和屋外装修补丁，迁移已登记的旧复活显示／P弹恢复编码；表情使用原生代码；
4. 从使用者自己的文件生成本地覆盖，逐文件原子应用并逐项复核 EXE、P03 道路及 SSTG/PON 别名；适配器通过原生 CF71/CF72 维护次数与跨关状态，通过固定 C393 约定提供场景对象；
5. 将原文件按内容 SHA-256 备份到 `adapter_data/client_compatibility_overlay/backups/`；哈希作为本机备份与诊断指纹；
6. 复用已运行的完整适配器；三端口就绪及监听归属校验在适配器启动操作中完成；
7. 经 `11999` 注册角色资料；
8. 只在兼容报告 `verification.all_pass=true` 后启动 `game.exe`。

适配器启动／停止、客户端进入和角色保存是三个独立操作。本地进入保留现有客户端，但直接启动原客户端仍受其单实例互斥体限制；本机多开使用社交槽位入口。社交服务启动及P1／P2／P3参与的职责见 [启动流程](../../指南/启动流程与源码索引.md) 与知识库[工程／启动运行](../启动运行/启动模式与服务.md#kb-09-017-1)。

### 当前自动应用的完整清单与分类

- 这里的二进制补丁指直接改写使用者磁盘上 `game.exe` 的指令、指针、代码区或文本字节。
- 适配器协议实现单独维护。
- 下列VA为当前受支持PE布局的虚拟地址，文件偏移由PE节表换算；具体原字节、新字节及允许迁移的旧编码以`managed-host/Resources/client-compatibility.json`为准，运行校验由`LauncherTools.Compatibility.cs`及`LauncherTools.Village.cs`执行；构建期生成及对照来源保留在对应Python脚本中。

| 功能项 | 启动参数 | 全部修改范围／详述位置 | 边界 |
|---|---|---|---|
| 陈旧组件启动兼容 | `--legacy-startup` | 原版结构转换、原生主函数及浮点初始化；[完整范围](陈旧组件启动兼容.md) | 原版转换校验输入／输出身份，原生布局校验精确启动位点 |
| 新账号建角与推荐人 | `--character-creation` | 建角入口2处、推荐提示5处；[建角与新手引导](建角与新手引导.md) | 外观、命名、推荐提示确认与重新填写 |
| 家具交互 | `--furniture` | Index 入口五字节重定向；[家具兼容边界](../住宅与家具客户端兼容/家具快照与点击.md#客户端兼容边界) | 绕过受保护 getter 路径；C393 快照仍由 适配器 提供 |
| 结算、经验与BOSS血条 | `--dungeon-state` | 两类结算控制器倒计时、鼠标恢复、结果页入口及输入快照、战斗临时经验归零及BOSS权威血条；[手动结算](手动结算与队员回城.md)、[经验与本地等级](经验与本地等级.md)、[BOSS血条](BOSS血条.md) | 手动确认、权威经验同步及实时得分 |
| 地宫兼容组的附带修改 | `--dungeon-state` | 200级八个位点、连续挑战旧控制器复位、结果总分排序、复活快捷栏、玩家直接交易取消、娱乐室模式／房间／结果及竞技结果／复赛；[客户端二进制补丁](../../指南/客户端二进制补丁/README.md) | 启用地宫组同时安装这些配套项；200级曲线、程序与快照版本须一致 |
| 礼物刷新 HP/MP 显示 | `--inventory-gift-display` | C476 清理调用和32字节代码区；[礼物刷新预览](礼物刷新预览.md) | 保存并恢复装备预览上限 |
| 空地购房 | `--land-purchase` | 房屋更新虚表、192字节代码区；保留必需的 C37B 余额让出分支；[空地购房入口](../住宅与家具客户端兼容/购房与房屋推荐.md#城镇空地购房入口) | 原生窗口类型25；入口补丁与余额分发分别维护 |
| 房屋推荐 | `--apartment-recommendation` | C397成功分支20字节、重复推荐绘制上限4字节；[推荐结果与弹框](../住宅与家具客户端兼容/购房与房屋推荐.md#房屋推荐结果与弹框) | C397刷新当前UI；C38E保持进入／恢复边界 |
| 屋外装修 | `--apartment-exterior` | 菜单、布局、库存、预览及面板21个站点和25处文本；[屋外外观系统](../住宅与家具客户端兼容/屋外装修.md#街区住宅与屋外外观系统补丁) | 包含兼容修复、界面整合及本地化 |
| 撤回旧状态补丁 | `--native-state` | 复活绘制入口／代码区、P 哨兵入口／代码区恢复原字节；[原生状态与旧版迁移](原生状态与旧版迁移.md) | 迁移已登记编码；未知修改触发安全拒绝 |
| 地宫7兼容 | `--dungeon7` | 小地图发布边界、村庄道路、补制美术撤回、SSTG 与 PON 别名；[地宫7兼容链](../地宫资源兼容/README.md#df-11-004) | 派生局部 EXE、道路与资源别名；保留用户现有资源 |

GUI 统一启用上述兼容项。协议状态账本、住宅期限／价格／库存持久化、C355前置进度与资源目录映射由适配器实现。原生状态迁移与新版适配器配套使用，复活次数和跨关P状态由统一生命周期管理。

- 应用前检查 PE 结构及每个目标站点；派生产物先写入本机覆盖目录，`--apply` 仅将指定文件逐个原子写入客户端目录，已有文件按内容 SHA-256 备份。
- 原生、已登记旧版及新版编码可迁移或重复识别；未知编码拒绝，不能把未知代码区当作空白擦除。
- 写入后逐项验证，报告通过才继续启动；这里的原子性是单文件替换，不是跨文件原子提交。
- 应用器预检整组选定文件，普通异常按逆序尝试恢复已改文件；遇到并发修改则拒绝覆盖。
- 它没有资源安装器那样持久化的 `applying` 收据，不能把异常恢复等同断电／进程中断恢复。
- 站点校验、隔离执行及构建结果按各自验证范围登记。

### 两类工具报告的差异

| 项目 | Python 开发工具 | 自包含 C# 运行工具 |
|---|---|---|
| 入口 | `scripts/prepare_client_compatibility.py` | `Nanaimo.Adapter.exe --tools compatibility` |
| 应用条目 | `apply_results` 含 `before_sha256`、`after_sha256`、`backup` 等字段 | `apply_results` 仅含 `path`、`status`、`sha256` |
| 回退基线 | 按该次报告的应用前摘要与备份位置核对 | 应用前独立保存每个源文件大小／SHA-256；实际备份位于 `backups/<原SHA-256>/<相对路径>` |
| 只读预检 | `--dry-run` 只派生并校验计划 | `--dry-run` 不写候选、目标或报告文件，JSON 输出仍包含 `verification.all_pass=true` |
| 应用完成判断 | 退出码、应用条目及写后身份共同判断 | 要求命令成功且 `apply_requested=true`、`dry_run=false`，并核对 `apply_results` 和磁盘目标身份；单看 `all_pass` 不能证明已安装 |

依据：`scripts/prepare_client_compatibility.py::_apply_outputs` 与 `managed-host/LauncherTools.Compatibility.cs::Compatibility`。两类工具使用一致位点配方，但报告字段不完全相同。
