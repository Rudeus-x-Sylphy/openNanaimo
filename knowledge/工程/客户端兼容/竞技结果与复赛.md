## 天空竞技场结果页

- CF8A完成多人结果行排序并清理旧竞技结束状态后进入可交互结算页。
- 兼容配方通过`0x006E35A0`的80字节包装保留原排序调用`0x0041B635`，仅在manager `BYTE+3==1`、`DWORD+0x10F0`为4／6且竞技单例`[0x00D72FC0]`非空时调用原生复位`0x0074FFE0`。
- 清理发生在结果页切换前，覆盖重试和离房重新组房，人物与独立结果行保持原有生命周期。
- `DWORD+8`保存连续败场数，胜方值为0；复位资格覆盖胜败双方并保留该计数。
- 80字节代码区接受已登记的旧计数条件编码并精确迁移。

`0x006E3500`的96字节结果入口继续检查多人模式和当前页面：战斗页4转结果页6，结果页6同步前一帧输入快照，其他状态保持原值。该代码区接受连续CC原值或已登记的旧直接排序编码，并迁移首条调用为清理包装；其余字节保持原值。地宫续关代码区`0x006E3340`、娱乐奖励代码区`0x006E3400`和竞技结果／清理代码区分别维护。

精确配方由`scripts/arena_result_compat.py::patch_sites()`生成，进入Python的`--dungeon-state`及托管启动器内嵌兼容表。专项覆盖18种模式／页面组合、寄存器／flags／栈、键鼠快照和Python／托管配方一致性，验证层级为隔离x86执行及适配器构造。

- 竞技复赛使用`0x006E3560`的独立64字节代码区：先调用原manager获取器`0x00419BBE`，在manager `BYTE+3==1`时清零`BYTE+7`离场锁，再以既有竞技单例为this调用`0x0074FFE0`。
- manager大小为`0x1FB30`，其`+0x34/+0x40`属于从`+0x12`开始的2000字节标记数组；当前配方保护整个数组。
- 活动计数属于大小`0x50`的主循环对象，由原生准备房入口`0x0066C961..0x0066C96E`初始化。
- 补丁保留原调用返回值、寄存器、flags及栈约定，复赛授权由CF8C调用边界限定。
- 代码区支持连续CC原值、四种已登记旧64字节编码和当前目标值；通过精确识别完成迁移，冲突时终止派生。
- 安装及联合验收范围由[工程／验证状态](../验证状态.md)维护。

| 位点 | 原值 | 当前职责 |
|---|---|---|
| `0x006E3500` | 连续96字节`CC` | 先排序结果行，检查manager `BYTE+3==1`及`DWORD+0x10F0`，经`0x006692E0`设置结果页并同步输入快照 |
| `0x006FBCFF` | `E8 31 F9 D1 FF` | 5字节调用改为`E8 FC 77 FE FF`，目标为`0x006E3500` |
| `0x006E3560` | 连续64字节`CC` | 复赛离场锁与竞技对象复位；保护管理器标记数组，完整编码由配方生成 |
| `0x006FBD88` | `E8 31 DE D1 FF` | 5字节调用改为`E8 D3 77 FE FF`，目标为`0x006E3560` |
| `0x006E35A0` | 连续80字节`CC` | 原生结果排序后复位旧竞技控制器；保留原返回值、寄存器、flags及栈，完整编码由配方生成 |

### 结果页补丁统一流程

1. 退出待更新的客户端及其派生副本，确认客户端目录、当前运行包和兼容配方版本匹配；保存当前文件身份与本次安装回执。
2. 更新配方后执行`python -B scripts/generate_managed_compatibility_recipe.py`，按《构建与验证》生成匹配运行包。核对Python和`managed-host/Resources/client-compatibility.json`中的所有位点原值、目标值和已登记旧值。
3. 在独立输出目录预检并派生兼容文件：

```powershell
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<fresh-overlay>" --dungeon-state --dry-run
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<fresh-overlay>" --dungeon-state
```

4. 核对兼容报告、PE节映射、各位点精确字节、文件长度和位点范围外字节。娱乐卡四个位点、竞技结果／复赛／结束清理五个位点及同组其他兼容项统一核验；确认结果入口首条调用指向结束清理包装、结束清理区为当前80字节编码，复赛区为当前64字节编码；复赛旧配方中的`8B 48 34 89 48 40`迁移为保护管理器数组的当前逻辑，并重新计算区内分支位移。两处当前复位配方均按各自边界执行，覆盖连续败场数为0的胜方；确认旧`83 78 08 01`／`83 78 08 04`计数条件已经迁移。重复派生须产生相同字节，未知字节冲突终止安装。
5. 使用匹配运行包完成受控安装：

```powershell
adapter_runtime/Nanaimo.Adapter.exe --tools compatibility --source-root "<client-root>" --output-root "<fresh-install-overlay>" --dungeon-state --apply
```

6. 工具按SHA-256保存原文件，逐文件确认后原子替换并重新核验全部位点，保留备份、原／新文件身份和安装回执。通过启动器重新派生各社交槽位副本，逐个核对源文件身份及兼容报告。
7. 执行`test_entertainment_result_client.py`、`test_arena_result_compat.py`、`test_arena_round_boundary_client.py`和`test_client_binary_migrations.py`，核对迁移、幂等、调用约定和范围保护；结束清理专项执行原生复位、旧state7及world停止写入。TIME UP／TIME LIMIT后的结果行、奖励图像、输入响应、返回房间及连续开局已有独立用户确认，范围与受测版本待补录状态见[竞技首局与复赛](../验证状态/社交竞技与娱乐验收.md#kb-09-042-6)与[娱乐室奖励与连续对局](../验证状态/社交竞技与娱乐验收.md#娱乐室奖励与连续对局)，不由隔离检查反推实机通过。
8. 恢复时退出对应客户端，按本次安装回执核对备份SHA-256与当前文件身份，原子恢复该次原文件。定点恢复先逐一匹配当前目标字节，再按配方逆序还原；恢复后的客户端、内嵌配方和派生副本使用匹配版本，并再次核验位点和完整清单。
