## 启动与保存调用图

```text
start_nanaimo_launcher.bat
  -> powershell.exe -STA gui_launcher/nanaimo_launcher.ps1
       -> 读取 profile、目录、预览和 adapter manifest
       -> dot-source inventory_admin_gui.ps1
       -> 创建 WinForms 控件
       -> ShowDialog

[保存配置]
  -> Save-Profile
       -> 校验角色、数值、技能、称号和本地库存
       -> 离线工具按差量事务保存数据库资料与库存，实际变更时生成备份
       -> 写 nanaimo_launcher_profile.ini/json

[本地模式：仅启动适配器]
  -> 确认编辑状态与已保存配置一致
  -> Test-AdapterBinary
  -> Start-LocalAdapter 127.0.0.1
       -> Nanaimo.Adapter.exe
       -> 内部启动 nanaimo_gameplay_bridge.exe
       -> 等待 11005 / 11999 / 12050

[社交模式：启动适配器]
  -> 自动检测或填写局域网 IPv4
  -> Stop-LocalAdapter（仅本项目进程）
  -> Start-LocalAdapter <LAN IPv4>
  -> 验证固定端口监听归属并显示该 IPv4

[社交模式：P1/P2/P3 参与]
  -> 共享客户端兼容准备
  -> start_social_client.ps1 在槽位锁内准备副本和独立 Network 配置
  -> BeforeLaunch：按用户名注册数据库账户 -> TCP <LAN IPv4>:11999
  -> 注册结果按来源 IPv4 入队
  -> 启动对应槽位副本并等待可见窗口

[本地模式：进入 Nanaimo]
  -> 解析所选已有档案；纯新手模式写隔离 runtime profile
  -> Test-ClientBinary
  -> Install-LaunchModeConfig 127.0.0.1
  -> Ensure-ClientCompatibility：预检、派生／应用与写后校验
  -> 向已运行的 127.0.0.1适配器注册账户 -> TCP 11999 -> OK\n
  -> Start-Process game.exe [固定 Network 参数]
  -> 不停止／重启 adapter，不结束任何现有 game.exe
```

## Windows 入口

| 顺序 | 文件／锚点 | 作用 |
|---|---|---|
| 1 | `start_nanaimo_launcher.bat` | 切换到运行根目录，以 `-STA` 启动 GUI。 |
| 2 | `gui_launcher/nanaimo_launcher.ps1` | 读取客户端路径、适配器runtime、profile、日志和目录；只对项目自带适配器使用 manifest 哈希。 |
| 3 | `gui_launcher/inventory_admin_gui.ps1` | 本地库存编辑界面。 |
| 4 | `managed-host/LauncherTools.Inventory*.cs` | `Nanaimo.Adapter.exe --tools inventory` 的档案查询、snapshot/apply、增量事务及备份。 |
| 5 | `gui_launcher/client_connect.ps1` | 命令行连接器、资料注册和客户端启动。 |

## 完整适配器源码入口

### 构建入口

```text
scripts/build_complete_adapter.ps1
  -> TCC 编译 adapter/nanaimo_gameplay_bridge.c
  -> .NET 8 SDK publish managed-host（支持 net6.0 / net8.0；当前发布为 net8.0）
  -> 读取 adapter_runtime/资源/数据，或 -ResourceDataRoot 指定的匹配数据
  -> 写 adapter_runtime/adapter_manifest.json
  -> 可选 -SelfTest
```

生成：

```text
adapter_runtime/Nanaimo.Adapter.exe
adapter_runtime/nanaimo_gameplay_bridge.exe
adapter_runtime/adapter_manifest.json
adapter_runtime/资源/数据/...
```

原生独立入口仍可用 `scripts/build_adapter.ps1` 确定性重建：

```text
adapter/nanaimo_adapter.c
adapter/nanaimo_adapter_testports.c
adapter/nanaimo_gameplay_bridge.c
```

`manifest/source_closure.json` 记录当前原生 include、managed 构建输入及已验证原生输出；实际数量与哈希以该活动清单和验证器输出为准。

### 托管玩法层

| 路径 | 作用 |
|---|---|
| `managed/Services/NetworkAdapterService*.cs` | 登录、村庄、任务、商城、社交、交易、竞技、娱乐和地宫路由。 |
| `managed/Services/DatabaseService*.cs` | 角色、库存、任务、关系、拍卖、公寓和地宫差量事务。 |
| `managed/Services/PetProgression.cs` | 宠物等级、阶段、攻击和奖励加成。 |
| `managed/Services/NativeDungeonState.cs` | schema4 地宫状态：载荷（payload）5704字节，完整帧5712字节；精确布局见[桥接布局](../基础/桥接布局.md)。 |
| `managed/Services/NativeDungeonClient.cs` | F100/F101/F102/F103 内部桥接。 |
| `managed-host/Program.cs` | 进程生命周期、端口、停止请求和 self-test。 |

### 原生地宫层

`release/teamplay_common.inc` 仍是原生功能拼装点，包含资料、技能、卡片、BOSS、目标、掉落、复活、商城、公寓、多人同步和地宫战斗。`NANAIMO_GAMEPLAY_BRIDGE` 构建额外启用 `release/components/game_session/managed_bridge.inc`。

## 端口

| 端口 | 作用 |
|---:|---|
| 11005 | 客户端登录入口。 |
| 11999 | GUI 角色资料注册。 |
| 12050 | 客户端世界入口。 |
| 22051..22054 | 竞技／娱乐入口。 |
| 51005 / 51999 / 52050 | 主地宫桥接实例。 |
| 62050..62055 | 主地宫内部连接。 |
| 53000..53998 | 按队伍隔离的额外地宫实例。 |
| 3534 | 客户端 P2P 发布／防火墙规则。 |

本地模式将公开入口绑定 `127.0.0.1`；社交模式将登录、世界和资料注册入口绑定用户确认的特定局域网 IPv4。固定端口被占用时完整适配器直接拒绝启动，不动态改到客户端未知端口。地宫桥接的内部回环端口保持本机内部通信。

## 地宫状态交换

```text
managed character / inventory / tasks
  -> NativeDungeonState.Create
  -> F100 导入 schema4 地宫状态（载荷长度与完整帧见上节“完整适配器源码入口”表）
  -> 原生地宫请求／响应
  -> F102 快照
  -> ApplyNativeDungeonDeltaAsync
```

当前关键偏移均相对载荷（payload）。下表仅作源码导航，完整字段、版本校验和迁移边界见 [内部布局](../基础/桥接布局.md)：

| 偏移 | 内容 |
|---:|---|
| 0..47 | schema判别、角色、等级、+12保留零值、HP/MP与两个u64余额；人物累计经验位于扩展区 |
| 48..95 | 技能点、技能槽、复活次数、快捷栏期限、宠物代码及成长阶段、攻防、姓名长度和性别 |
| 96..159 | GBK姓名、外观、日期、宠物宝石和宠物等级／经验；宠物造型阶段字段位于载荷+72／+76（本区间之前） |
| 160..271 | 16个技能等级、6个快捷栏槽 |
| 272..1951 | 卡片数量 |
| 1952..3995 | 最多255条道具代码／数量 |
| 3996..3999 | 情侣戒指代码（完整字段见[内部布局](../基础/桥接布局.md#df-04-002)）|
| 4000..5023 | 原生实例句柄 |
| 5024..5119 | 地宫称号、最高前沿和60字节通关 mask |
| 5120..5143 | 伴侣UID、schema4、payload长度、CurveVersion3、64位人物累计经验 |
| 5144..5703 | SP、事件及特殊／VIP卡片的独立扩展区 |

角色经验、宠物经验、货币、卡片和道具按差量事务提交，提交ID用于幂等。

- 连续挑战另有战斗周期（battle epoch）资源层：CF71/CF72提供有效最大／当前HP/MP，D010 提供较新的当前 HP，CF87 冻结结算值。
- CF72 的复活显示字节与角色账本保持一致；相同PET连续关卡通过原生生命周期保留发射器与P状态。
- 客户端派生覆盖两类结算控制器的自动倒计时，恢复旧版误改的鼠标确认；CF8B承载动作模式，输入来源由客户端控制器处理。
- 失败结算重新挑战建立新的战斗周期，恢复本周期 HP/MP 上限并等待准备房重新加载；玩家选择回城时按 CF73/CF1D 闭合到 CF74/CF1E 和 DeathReturn。

BOSS组件账本位于原生层：组件HP按资源定义的子对象／序号（authored child/ordinal）独立维护；严格并行拓扑中重复的局部0/0按首个仍存活的资源组件顺序解析。该策略已完成构造回归，客户端显示按当前产物独立验收。
