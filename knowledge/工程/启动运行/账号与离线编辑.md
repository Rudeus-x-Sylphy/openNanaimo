## 账号选择与持久化载体

- 本地入口以“用户名／角色显示名”文本框为账号选择依据：已有用户名优先匹配账号，角色显示名解析到其所属账号。
- 新名字从当前管理档生成独立快照，并同步六个管理页的选择。
- 首次本地注册在一个事务中创建账号、角色和库存；再次进入保留数据库中后续产生的进度。
- GUI 在选档／保存前重读账号列表；数据库草稿首次注册为角色后，在同一窗口内升级为实际 `CharacterId`，同步六个选择器但不丢弃当前编辑内容。
- 保存后端也重新解析缺失 `CharacterId` 的账号／角色名（用户名优先、角色名大小写不敏感），已有数据库角色不会继续写到草稿记录或旧JSON／DAT；显式克隆仍保持独立数据库草稿，不隐式覆盖来源角色。
- 目录外卡片按源档记录完整保留，普通编辑继续采用只读保护。
- 普通本地注册、纯新手注册与远程注册各自维护导入边界。

- 社交账号按主机 `adapter_data/game.db` 中的用户名复用账户，再由 `AccountId/CharacterId` 定位角色及背包。
- P1／P2／P3 是客户端启动槽位，不是存档键；相同用户名重新注册会保留已有角色，游戏内持久化不依赖 GUI 启动按钮执行 `Save-Profile`。
- 普通离线资料编辑选择具体角色后写该 `CharacterId`；没有正式角色的资料使用名称编码区分的数据库草稿。
- 协议容量与GUI可编辑目录分别定义；完整字段见[桥接布局](../../基础/桥接布局.md)，库存目录与保护规则见下节。

## 离线库存授权与增量保存

- GUI 全量目录由 `scripts/generate_inventory_card_catalog.py` 从现行 `ddakg._D4`、`EDdakgi._D19`、`Sddakg._D35` 的确定记录构建，保留既有420条普通卡文案；生成与测试逐一要求 `card_drop_cn.csv` 的每个卡号均可发放。
- SP／活动／VIP与幸运卡不能再被当成目录外只读数据；“全部添加”和“移除已知卡”使用同一560条目录。
- 资源中有定义而未配置掉落的卡仍可人工发放，但不据此新增掉落地点、概率或自动赠送；发放幸运卡不等于已实现其抽奖使用。

- 离线保存只授权修改 GUI 目录内的卡片，不把 `CharacterCards` 按角色整表清空。
- 目录外条目显示“未收录卡片（只读保留）”，不能在 GUI 增减；数据库原数量及 `UpdatedAt` 等元数据原位保留，数据库草稿／原生记录保留原代码及数量。
- 提交省略这些条目（包括旧 GUI 清空列表）不授予删除权限；伪造新目录外代码、改变既有数量或重复提交同一代码均拒绝，数据库事务回滚。
- 目录内删除仍然生效。
- “移除已知卡”只处理编辑目录，不能用保存绕过未知代码校验或向新账号复制不明权益。

土地权益仍归属独立的 `CharacterApartmentHouses` 与 `CharacterApartmentLandCards` 住宅／地址／租期事务，见[房屋归属](../../业务/住宅/房屋归属/README.md)；库存编辑不生成、删除或改写这两张表，也不因旧编号重叠把一条 `12000001` 记录转换成住宅权益。

- C#离线保存在`BEGIN IMMEDIATE`内核验目标账号／角色存在、名称编码一致和双方离线资格，校验五类库存及明确提交的技能字段，并按当前数据库行计算修改计划；未知卡片保护、宠物容量／宝石槽限制和库存授权保持不变。
- 无实际变化返回`changed=false/backup=null`，不写角色／库存表也不生成备份；存在变化时，在首次编辑前用独立读连接完成一份完整SQLite备份，再在同一事务内提交改变的字段／行与可选固定称号。
- 卡片只删已移除的目录内代码，家具只替换改变的槽位，其它行及`UpdatedAt`原位保留；技能逐等级、物品逐数量／宝石／阶段对比，不因为仅改HP而刷新全部库存。
- 明确改变MaxHP/MP时沿用资源校正规则，未修改上限且未显式提交当前值时不补满当前HP/MP。
- 称号写入保留资料快照版本／曲线升级和前沿清零规则，主资料、原生称号及数据库称号记录共享一次事务；任何SQL失败全部回滚，失败前的单份备份保留。
- 克隆与草稿仍保存为数据库记录，固定称号也合并进草稿事务，不另调称号工具；并发注册／重名冲突拒绝重试，不能悄悄写入已不再生效的草稿。
- GUI管理写入以游戏适配器停止为前提，常驻离线工具不计作游戏服务。
- 隔离生产工具与GUI管道检查见[会话工具与增量库存验证](../验证状态/层级与版本归属.md#kb-09-001-1)，不等于原客户端运行验收。

- 已有角色的五部位装备、特效与当前宠物必须同时保存至持久 `Appearance` BLOB 和 `EquippedPetItemCode`，不能仅增加库存或写启动 INI。
- 选中装备／宠物在合法目录及容量校验后补齐所有权；零值表示卸下，GUI 切换角色时也显式选中零值，不能沿用上一角色的装备或默认宠物。
- 首次载入已有角色从数据库投影控件，“保存配置”和“保存所选档案”均采集当前装备选择。
- 装备写入不改角色等级／经验、双树SP／任务进度、性别、Face、教程起源 `PetVariant`，也不将这些字段当作装备选择器；明确提交的技能等级及Z/X独立按本主题技能编辑事务处理，不能再把启动器技能编辑排除在数据库保存之外。

保留的 `CharacterItems` 行使用 upsert，不按全部目录先删除重建；保留宠物等级／经验／耐久及已有取得时间，升级材料勾选状态未变化时保留已进化阶段，更新宝石与明确编辑的数量／材料状态。切换当前宠物时，角色级等级／经验摘要从所选库存行同步，卸下时清零；未切换宠物的无关编辑不重写该摘要；被明确移除的目录内物品仍删除。目录外卡片和独立住宅表保护保持上述边界。

该保存链的既有验证记录覆盖隔离数据库和真实WinForms选择器，以及正式数据库的只读备份副本上的角色宠物／道具落盘、其他账号和任务／技能／地宫进度表不变；验证层级为持久化及控件行为。全量卡目录专项覆盖560卡的WinForms批量添加→保存→重读→批量删除、生产C#工具的SP／活动／VIP数量边界及克隆，以及未知卡／住宅／其他角色保留。上述范围不代表本次文档修订已重跑检查；版本归属见[验证状态](../验证状态/README.md)。

## 地宫等级与资料导入边界

GUI 新建本地角色的炮弹型与肉弹型技能点均从0开始；本地账号初始赠送与原生角色缺省初始化使用同一规则。已有角色再次注册时保留两套技能树各自的持久 SP。

- 副本等级（称号等级）的权威持久值由角色资料账本维护，并通过已确认的 C355、CF71 与 CF88 载体同步；字段与显示链见[角色称号](../../业务/角色/称号/README.md)，结算载体见[地宫计分与结算](../../业务/地宫/计分与结算/README.md)。
- GUI 固定称号与跟随进度的优先级见[称号编辑规则](../../业务/角色/称号/README.md)和当前 profile 导入实现。
- 教程选项、卡片钥匙、宠物年龄和 Z/X 技能状态属于独立字段，导入时不得互相覆盖。
- 尚未由源码和测试确认的旧配置别名保持未决，不写入当前协议契约。

## 库存即时刷新与启动器期限控制

启动器提供完整快捷栏期限`quickbar_expiry`及可选的Z/X期限`skill_slot_expiry`。未配置快捷栏期限时默认为0，不再自动生成2099年的长期权限。仅在勾选对应复选框时写入Z/X期限，默认保留角色已有值。合法的未来到期时间表示权益有效，并阻止重复续办相应扩容。神秘钥匙与复活道具的消耗刷新独立于扩容权益状态。

## 角色配置与本地库存

### GUI 侧

| 锚点 | 作用 |
|---|---|
| `Read-Ini` / `Read-KeyValueFile` | 读取 profile 和状态。 |
| `Encode-NameHex` / `Decode-NameHex` | 名称与 GBK 十六进制身份互转。 |
| `Get-ResourceSelection` | HP/MP、攻击、防御、货币、钥匙和期限字段。 |
| `Get-SkillSelection` | 技能路线、16个等级和 Z/X 槽。 |
| `Write-DungeonGradeState` | 固定称号等级写入。 |
| `Save-Profile` | 完整校验后写 INI/JSON 和库存状态。 |
| `Write-PureNewPlayerRuntimeProfile` | 写入隔离的新手runtime profile，固定教程必做并按真实进度开放地宫，已有账号继续原档案。 |
| `Register-SocialAccount` / `Start-SocialParticipant` | 以用户名注册数据库账户并从指定局域网 IPv4 启动参与客户端。 |

### 库存管理

```text
inventory_admin_gui.ps1
  -> Nanaimo.Adapter.exe --tools inventory
  -> profiles / snapshot；launcher_tools=2 时复用会话常驻工具
  -> 编辑衣物、宠物、游戏道具、家具和卡片
  -> apply；提交规则见本页《离线库存授权与增量保存》
```

普通角色配置通过11999注册导入已运行的适配器；直接编辑数据库角色、数据库草稿或重置进度前应先停止游戏适配器，存储位置见[持久化](../../基础/持久化.md)。社交模式的“启动适配器”负责停止本项目已有适配器／原生桥接进程、拒绝占用端口并按指定IPv4单例启动；P1／P2／P3参与按钮执行资料注册、客户端兼容准备、槽位配置和启动。
