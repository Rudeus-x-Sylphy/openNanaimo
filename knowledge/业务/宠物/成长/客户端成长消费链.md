### CN宠物成长表装载与资料分母

- PET表链独立维护：`9EB1B0`在PET记录尾部读取成长类别数量，每类3阶段、每阶段4个数值，经`40F754 → 9F4850`写入；`413FF2 → 9EBFF0`按成长类别检索；`412468 → 9F4830`取`base+4+16*stage`，C355处理`530C90`读取该行+4作为宠物阶段每级经验分母。
- 35类成长行按宠物成长约定消费。

### CN结算成长字段及生产构造差异

CN与KR的宠物成长消费链使用各自的数组布局和字段约定；两端420个阶段值相同，结算进度均按应答携带的当前经验与本地阶段要求换算。

- **CN装载／资料消费**：沿用前文`9EB1B0 → 40F754 → 9F4850`与`413FF2 → 9EBFF0`、`412468 → 9F4830`，每段四DWORD原样装载；装载器以0、1、2调用setter，getter在`9F4837..9F4840`直接计算`this+4+16×参数`，没有减1。
- CF86的`643F0D..643F4C`及`643F6A..643FA4`以收到的阶段直接取行，段+4为分母；阶段1因此取第二资源行，不因适配器最低模型阶段1而改成段0。
- C355／`530C90`、地宫和娱乐室进度均取段+4为分母。
- CN／KR尾表420个阶段值逐项相同，数值及模式提示归[宠物成长表与结算经验来源](阶段与奖励策略.md#kb-07-005)。
- 验证范围为成长字段和阶段索引，业务规则归[宠物成长表与结算经验来源](阶段与奖励策略.md#kb-07-005)。
- **CN地宫CF88静态消费链**：战斗分派器`6EBAC0`的`6F97F7`明确为case53128；WORD帧+8是count，`r=frame+0x0C+0x34×i`。
- BYTE `r+5`为成长变化标志，`r+6`是宠物清零／移除分支门控，`r+8/+9`为当前／最大阶段。
- DWORD `r+0x20`在`6F9E94..6F9E9E`从响应读取；`6F9FDC..6FA077`取定义成长类及收到的阶段、读段+4；`6FA0EE..6FA12E`将收到的当前EXP除本地要求、乘100作为进度。
- `6FA6BB → 41EF01 → A75B50`写manager+0x1035的BYTE阶段；`6FA6DD/6FA721 → 4063D4 → A75B70`写manager+0x1036的BYTE百分比／255哨兵，移除分支清零。
- 数组布局为`12+52×count`，CN使用独立于KR的记录步长。
- 这里描述的是客户端读取链；现行适配器的`BuildDungeonEndGamePayload`与`PatchNativePetSettlementFrame`在行`+8/+9`写入阶段内等级／当前阶段等级上限，与本段按阶段索引读表的静态解释存在差异。
- 该差异不能由构造测试宣称已闭合，仍需按具体客户端版本核对结算进度和变身显示。
- **CN娱乐室请求／分派**：`63BCC0`从完整帧+6读opcode，55555分支经`41DA93 → 6439B0`构造请求；`412166 → 64A310`写opcodeCF85、长度8，`6439B0`调用`ADA3E0(1,request)`。
- 响应以`opcode-53103`的case23经`63C03A → 41DEDF → 643A40`消费，即CF86；请求槽参数为1。
- **CN娱乐室CF86**：DWORD帧+8是count，`r=frame+0x10+0x40×i`。
- WORD `r+0`匹配成员，BYTE `r+6/+7`为当前／最大阶段，DWORD `r+0x1C`为应答携带的当前宠物EXP（`643EB9`及`643EFC`）；仅本机成员且已装备PET时更新本机。
- `643E25..643F60`按成长类别及阶段查段+4，非满阶段EXP大于每级要求时将响应值改为1，满变身比例255，否则`100×EXP÷要求`。
- `643F6A..643FA4`独立生成浮点进度显示。
- 数组布局为`16+64×count`；人物三元组、三个卡片字段及尾部读取同属结果行，最高显式读取为`WORD r+0x3A`（`643D4A`）。

### KR成长表、等级与攻击显示

KR使用独立记录约定；记录步长和偏移按KR布局执行。

- 以下字段约定适用于KR `NanaimoClient.exe`（8043520字节，SHA-256 `CA7D65053C9600B08CA31859B2913166D9508CDB6FF379BDB76641B7C853DBA0`）及`pi._D7`（SHA-256 `0EF547A8B5CC5C9A2B383657C30DA3700C9599B0F737609E8572596845D3C038`）。
- 静态校验范围为35043条指令、143779字节；资源数值与奖励策略归[宠物成长表与结算经验来源](阶段与奖励策略.md#kb-07-005)。

- **表装载／显示**：`8A9070`顺序解析PET，零基field24经`8B0AB0`写定义+0x40D，`8B0A90`读取后交`8A99E0`选成长类别。
- 尾表每类分配0x34字节，`8B0CA0`把三段四DWORD写至`base+4+16×stage`；`8B0C80`返回该段。
- 段+0为级数、+4为每级EXP分母、+8为逐级攻击增量、+12为表存总经验。
- `70B580`调用`7356B0/7356D0/7356F0/735730`取得实例阶段／最大阶段／段内等级／EXP；累计等级显示在`70BD54..70BDA3`汇总已完成段+0，未满变身才加段内等级。
- `6ECFF0`与`736CB0`独立以各已完成段`+0×+8`及当前段等级×+8计算属性展示，不能把每级攻击增量解释为奖励经验。

### KR CF87请求与CF88宠物字段

- **地宫请求及状态元组**：飞行战斗发送者`635A50 → 64D540`构造`CF87/12`，`635AC5 → 6340A0 → 989820`发送；+8为现有角色状态的WORD，+10在门控有效时为两计时值之差除60，否则0；该请求不携带计算好的宠物经验奖励。
- 响应在战斗分派器`636A00`的`64499D`（case53128=CF88）进入，不能跨用CN的52字节记录。

- **KR CF88字段**：WORD帧+8为count，结果行`r=frame+0x10+0x48×i`。
- `WORD r+0`匹配角色UID；`BYTE r+5`为宠物成长变化标志，`BYTE r+6`参与宠物移除／清零分支，`BYTE r+8/+9`为当前／最大变身阶段；`DWORD r+0x34`是结果中的当前宠物EXP，读取点`64500F`。
- `645151..645195`用宠物定义成长类别与收到的当前阶段取段+4，`645263..6452A3`以unsigned32经验／分母×100计算比例，`645444 → 692820`覆盖结果显示。
- `645840..6458C2`把收到的阶段交`933CD0`，满变身交`933CF0(255)`，否则写百分比；`6457FC..645836`的移除分支清零。
- 全记录布局为`16+72×count`，该分支已读到行+0x44的DWORD，覆盖至完整行末；这是静态布局，验证范围为静态读取布局。

### KR共享宠物阶段与比例写入

- **共享状态写入**：`933CD0`直接写manager+0x1010的BYTE阶段，`933CF0`直接写+0x1011的BYTE比例／255哨兵；不能把后者当作原始宠物经验或每盘经验增量。
- 阶段内等级与变身阶段在物品／资料显示对象中另存。
- 两条结算链均只有静态接受／显示证明，没有原服数值或新运行验收。
