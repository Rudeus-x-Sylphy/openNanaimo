### 上古科技资源身份与宠物入账边界

`pi._D7`包含四个精确的物品类别15定义**上古科技**，全部为家族9039，等级要求60，基础攻击793（`初攻:800 特殊(复合)`），三个槽位，最大/显示年龄3和生长材料19000031：

|PET代码|生命周期|
|---:|---:|
|15009109|180天|
|15009241|15天|
|15009245|30天|
|15009249|90天|

- 这些是PET定义键，而不是地面掉落/卡片标识符。
- 解码后的`ddakg._D4`有100个`kind=9`PET召唤卡，但没有输出任何四种上古科技代码。
- 隐藏的Epi4的`50000031..50000040`行属于物品类别50的`EDdakgi._D19`事件卡，并描述了一个单独的全页事件奖励；该事件卡遵循事件效果分支>50,000,000。
- 静态数据无法选择原始适配器授予的上古科技生命周期变体。

- 账户所有权仍然通过类别15 C44C行进入，选定摘要通过C379/C44C；仅一个有效的`pi._D7`行证明了本地定义可用性。
- D00E/D012地面展示排除及适配器策略见[秘密关卡宠物展示边界](../../地宫/掉落/索引.md)；本页的[事件卡与宠物所有权证据](#kb-08-047-4)保留相关地址。

### KR密钥、字符串容量与佩戴字段

本组地址属于韩服`NanaimoClient.exe`，SHA256=`CA7D65053C9600B08CA31859B2913166D9508CDB6FF379BDB76641B7C853DBA0`；CN地址显式注明，不混用。

- PET加载`0x8A8B80 -> 0x97DE10 -> 0x97D4E0`。
- 实际key为`12019A23BC45ABF056EFCD348978DE67`、AES-128-CBC、零IV、PKCS7；旧CNkey常量在韩服函数中也存在，但实际传入密钥调度的是另一组字节，不能仅扫描常量选key。
- PET严格CP949解码，4头字段、每行35字段；当前样本990行／35条成长曲线。
- CN`0x9EB1B0`同样按表头行数分配0xA38字节记录，韩服与CN成长尾表逐字段相同。
- 这个读取循环没有写死868，adapter/GUI另有活动目录计数约定，现行仓库增量目录为990行；资源边界见[韩服新增宠物与移植边界](#kb-04-004-1)，外部安装状态见[验证入口](#kb-09-015-2)。

- CN字符串目标容量闭合：PET加载`0x9EB1B0`的field2经thunk`0x40BBCC -> 0x9F3E20 -> 0xB4ACA7`调用有界复制，容量16含NUL；CRT在源字符串长度达到容量时走错误34／参数处理路径。
- 对应Windows异常`0xC000000D`、模块RVA`0x0074ACD0`加实际image base`0x00400000`落在`0x00B4ACD0`同一复制函数内。
- 描述field16/17/18经`0x40A420 -> 0x9F3F50`按64字节槽写入；field3/4/5经`0x40F5C9/0x402333/0x417F7B -> 0x9F3E60/0x9F3F00/0x9F3EB0`容量260；field26..28经`0x4116AD -> 0x9F4360`、field29..31经`0x41E40C -> 0x9F43C0`容量260。
- 8个函数的已登记代码区字节保持一致。
- 旧表第一条超限为零基索引870、code15003341；该位置表示PET表的静态行索引。

- PET field1在`0x8A8E74 -> 0x8B08B0`写定义`+0x3EC`，getter为`0x8B0890`；`0x577350`的领域15分支与玩家等级getter`0x930690`比较后才继续选择，`0x6C8EB0`把同值写item_lvbg等级徽章。
- CN对应`0x9EB1B0 -> 0x41CF80 -> 0x9F4260`写相同偏移。
- 因此英雄龙韩服源行15003361的120属于角色等级需求；CN按韩服原需求恢复及本地译名策略归[韩服新增宠物与移植边界](#kb-04-004-1)。
- 上述背包比较地址适用于KR样本，CN字段加载链独立维护。99／110／120门槛已有[新增宠物与佩戴门槛验收](../../../工程/验证状态/地宫与成长验收.md#新增宠物与佩戴门槛验收)的用户确认，受测版本待补录；该实机确认独立于资源恢复，不额外证明CN比较链的全部静态分支。
