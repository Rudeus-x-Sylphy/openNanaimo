### 速度宝石的生效范围

当前CN的PA type5（蓝碧玺及带速度属性的复合宝石）作用于飞行角色的水平／垂直速度上限，不是起步加速度、射速或城镇步速。本机PA目录18931行中2581行含type5；资源说明与真实数值是独立字段，不能按“速度＋N”的文案直接加N。

| 纯蓝碧玺显示 | PA原始固定值 | 当前CN加载后的每颗上限增量 |
|---|---|---|
| 速度＋1～＋6 | `.4/.5/.6/.7/.8/.9` | 0 |
| 速度＋7～＋12 | `1/1.1/1.2/1.3/1.4/1.5` | 1个内部速度单位 |

- 原因是客户端读表先用整数转换`atol`，再存成float；汇总type5时又逐效果保存为整数。
- 低档宝石的小数在加载阶段已经消失，三颗＋6也不会合成2.7；高档各贡献1，三个独立已装备槽位可累加为3。
- 复合宝石中的type5遵循相同解析／汇总，其它属性各走自己的链。
- 当前源码发送选中PET的准确宝石码，未见另行补回type5小数的适配器运动计算；本结论不把GI加速器或拾取速度道具的其它机制混入宝石。

- CF71／CF72建立含宝石的速度基准，CF80与角色进入战斗状态时将该值同步到实际运动上限；逐帧代码据此限制X、Y速度分量。
- 当前客户端的低档增量取整为零，高档按整数生效。
- 加载、写入及限速地址归[速度宝石的读表精度与运动上限（CN）](#kb-08-043)“速度宝石的读表精度与运动上限”。
- 验证范围为PE字节核对及合成对象指令隔离执行，覆盖60项短链、18项限速和17项资源至速度分量检查。

### HP与MP吸收

- PA._D9 type8 表示 HP 吸收。
- 百分比字节+399..401以0.1个百分点为单位：17000014=0.3%（`percent3`），17000444=1.2%（`percent12`）。
- 完整的18,931条 PA 记录中有27条名为紫水晶的吸收属性，最大值是 `17009787` 紫水晶(3.6%)，type8/percent36。
- 只有**选中宠物**的三个准确槽位参与计算。
- 现行逐战斗自定义策略累计“实际扣除 HP × percent_tenths/1000”，保留小数余量，仅输出整数 HP，不逐次命中截断，并限制在有效最大 HP 内。
- 普通 D00D、D011 BOSS、延迟部件、肉弹普通目标和肉弹BOSS回调均为请求驱动来源；实际伤害为零或 HP 已满时不发送治疗。
- 治疗使用已初始化的 D010/36：WORD+8为实际角色，DWORD+0x0C保留分数，WORD+0x10为绝对 HP。
- 原始适配器的舍入规则和可见修复仍未知。
- 专项本地验证安装三个独立的 `17009787` 实例，经 C379/C44C 及重启后仍保留 `17009787/17009787/17009787`，三次 type8 percent36 合计108（10.8%）；实际伤害200时恢复21 HP，余数0.6 HP（按千分之一累计计为 600）。
- 随后运行观察中，第二个相同的 `17009787` 被装入槽1并收到 C450 status2000，之后用户通过 action3 成功移除。
- 相同代码重复镶嵌已有运行观察；三个同时存在、槽位显示及重启后的可见状态现另已获用户确认。10.8%伤害转治疗、数值／动画和选中宠物隔离也有独立用户确认，范围与受测版本待补录状态见[宝石吸收与移除验收](../../../工程/验证状态/地宫与成长验收.md#宝石吸收与移除验收)，不外推为一般宝石代码及HP／MP加成显示全部通过。

一组无效的吸收测试输入选中PET15009074，其宝石为17001844/17001835/17013148，均非type8；PET15009248虽持有17000014，但未被选中。该输入不能测试未选中宠物的吸收效果。选中实例的生命恢复另有本地构造检查，不等于客户端可见治疗验收。

- PET15009218可持久保存宝石组合 `17013105/17001844/17009787`，其HP吸收由第三槽type8/percent36提供，合计3.6%。
- 替换按库存实例操作：17009787对应实例68时消耗该实例，17000014返还库存，替换工具扣减1；重开及重启保留精确代码。
- 伤害转治疗的显示已有[宝石吸收与移除验收](../../../工程/验证状态/地宫与成长验收.md#宝石吸收与移除验收)的用户确认；MP吸收等其他独立效果仍按其证据范围维护。

- MP吸收使用PA type9，百分比单位同为0.1个百分点。
- 选中宠物三个槽位内的同类数值累加至100%，按实际扣血量累计，HP和MP各自保留独立小数余量。
- MP达到有效上限时清空其余量，复活与战斗重建同时重置两类余量。
- 成功吸取通过角色定向CF72同步绝对MP，活跃战斗中的托管资源快照采用该当前值；零伤害、死亡、满资源及其他宠物的宝石保持各自门控。
- 25项战斗状态专项中的2项吸取检查覆盖累计、封顶、零伤害和选中宠物隔离，客户端数值及动画属于独立验收层。

### PET宝石攻击增量与空应用函数

选中宠物的宝石攻击增量与房间人物攻击修正使用独立的定义及消费链：

- CF71/CF72角色／资料应用从完整帧字段`+0x7C/+0x80/+0x84`经`0x6F5277/0x6F5832 -> sub_40D3DC -> sub_6D78A0`传递三个宝石代码；兄弟资料路径`0x6F5B91`使用`+0x58/+0x5C/+0x60`。
- PA查找`sub_40CFB8`读取定义`+395..+412`的类型／百分比／float固定值。
- type1增量从0开始，非零固定值优先，否则按PET定义基准的百分比加算；每个效果均与PET定义上限比较并保存整数结果。
- PET定义基准／上限getter为`0x402121 -> 0x9F42C0`／`0x414ECA -> 0x9F4280`，分别读定义`+0x3E0/+0x3E4`。
- 这不是将PET面板整值加到人物基数。

- **对象归属更正**：`0x6D8585..0x6D858C -> 0x41FA9B -> 0x6E72E0`在`0x6E72EE`先取`[actor+0x7D70]`，然后`0x6E72F4 -> 0x40E5E3 -> 0x6E7310`于`0x6E731D`写`PET发射对象+0xD8`。
- 旧“角色本体+0xD8”说法撤回；0x6A85F0在0x6A8705将该PET字段初始化为0。

- **PET显示独立有效**：`sub_7CE970`将type1宝石增量记入面板WORD`+0x8FC`，按面板WORD`+0x8FA`上限钳制；`sub_7CF7E0`在`0x7CFF81..0x7CFF9A`把WORD`+0x8F8`、WORD`+0x8FC`、本地表项与行加项求和，`0x7CFFB5`格式化至面板文本`+0x7F8`。
- 反编译的char/BYTE类型推断在这里不可信，应采用实际movzx WORD及DWORD栈值。
- 该面板文本不是弹丸攻击输入。

- **增量转交为空操作**：PET的`+0xD8`在`sub_6A9590/6AA6A0/6AA8E0/6AAB30/6AAE70/6AB290/6AB560/6ABC20/6ABCF0/6ABDE0/6ABEB0`的15个读／调用点均进入`0x4064F6 -> sub_6BB8B0`。
- 其中0x6A9590的调用点为`0x6A9864/0x6A9A48/0x6A9C24/0x6AA006/0x6AA2AC`；全部精确读／调用地址清单为未随仓库提交的本地调查产物（原文件名 `pet-bonus-emission-sites.json`），不构成可直接打开的公开证据。
- 循环按`owner+0x34C`的行数和`owner+0x350`数组，逐行将宝石增量传入`0x6BB8F1 -> 0x4035DA -> 0x6BD920`。
- `0x6BD920..0x6BD92C`的13字节为`55 8B EC 51 89 4D FC 8B E5 5D C2 04 00`，仅保存栈帧并ret4，不读增量、不写弹丸对象，也不调用攻击setter；不是反编译遗漏。

- **实际攻击另有写入链**：PON固定记录`+0x114 -> 行+0x1A8 -> source+0xA38/+0xA3C/+0xA40/+0xA44`由本节PON资源组维护。
- 真正的`sub_6B67D0`会写source+0xA38，但type1上述循环没有调用它；`sub_6BB900 -> 0x403A12 -> sub_6B6700`对另外三个来源字段按各自百分比推导，不能与type1空应用函数混为一谈。
- 命中消费仍为下述sub_670E10／CFEC链。

- **验证范围**：当前CN地宫PET发射链按实际指令核对。
- `0x6A9590`的5字节DIY入口跳至`0xB98400`，保存现场、执行可选DIY分支并恢复原prologue，然后返回`0x6A9595`；三个兼容区函数及六个DIY位点按独立配方维护。
- 21项合成对象机器码检查覆盖PET字段归属、0／2／5／123／65535增量、0／1／3行逐弹丸循环与真实攻击setter正对照。
- 该结果的适用范围为当前CN已核对发射链及指令隔离执行。

### 速度宝石的读表精度与运动上限（CN）

玩法结果及蓝碧玺显示档位映射归[速度宝石的生效范围](#kb-04-008)“速度宝石的生效范围”；以下限当前CN安装文件的静态链与隔离机器码验证，验证范围为当前CN指令约定。

- **输入与解析**：PA完整定义布局（24字段行解析为432字节定义，类型`+395..397`、百分比`+399..401`、浮点值`+404/+408/+412`）见[宝石镶嵌、材料消费与确切身份](镶嵌移除与资源.md#kb-03-024-2)；type7 字段明细见[宝石type7、碰撞请求与卡片裁决边界（CN）](#kb-08-046-1)。
- `sub_960B90`在`0x961037/0x96112C/0x961221`调用`0xB4AD37 → 0xB4AD11 → 0xB5BC49`，即`atol → strtol(...,10)`，在`0x961045/0x96113A/0x96122F`用`fild`转换整数，最后`0x961051/0x961146/0x96123B`写定义float `+0x194/+0x198/+0x19C`。
- float是存储类型，不说明输入保留小数；`.4～.9`读为0、`1.1～1.5`读为1。
- 显示文案独立，不经过这一数值读取。

- **宝石载体与汇总**：游戏控制器CF71本地`0x6F5277`／远端`0x6F5832`及CF72 `0x6F5B91`调用`0x40D3DC → sub_6D78A0`；三个宝石码载体偏移分别沿用`+0x7C/+0x80/+0x84`与`+0x58/+0x5C/+0x60`。
- PET必须存在，且`0x41F1A9 → 0x6E7010`读取的PET `+0x20`非零。
- 三枚宝石各三效果的type5分支将固定值累加到整数局部变量`[ebp-0x10]`；首分支`0x6D7A27..0x6D7A38`为`fild + fadd + __ftol2_sse + mov`，其它八处分支同构。
- 不是先把三颗小数相加后才取整。

- **对象和字段**：actor `+0x7D70`指PET，PET `+0xD0`指运动定义。
- `0x41A53C → 0x6E7210 → 0x415D7F → 0x6E7230`读取定义`+0x1440`原始速度基准；`0x6D8559..0x6D8564`将基准＋宝石整数增量写actor `+0x7DAC`。
- `0x6D8580 → 0x41CDFA → 0x6E70C0`随后写同一PET定义`+0x1224`当前速度参数。
- 它不写加力／阻力／质量字段。

- **开始战斗与当前上限**：CF80 case53120的本地及队员路径在`0x6F7505/0x6F75C6 → 0x40806C → 0x6DCC40`读取`0x40B2E9 → 0x6E70A0`的定义`+0x1224`，于`0x6DCC78`写actor `+0x7DA8`，并清`+0x7DB4/+0x7DB8/+0x7DBC`；随后`0x6F7526/0x6F75F2 → 0x40FF1A → 0x6D85B0`恢复含宝石基准的定义参数。
- CF80仍遵守既定8字节完整帧／连接／加载门控。
- 角色状态函数`0x415820 → 0x6D5670`的state3/state9也调用上述当前上限刷新；不能只看宝石写入函数没有直接写`+0x7DA8`就认定运动不消费。

- **逐帧实际消费**：`sub_6D9510`在`0x6D9770/0x6D9778/0x6D9780/0x6D9788`依次调用加力、阻力、速度附加和限速；限速入口`0x41AAA0 → 0x6D67B0 → 0xDABE49`进入已安装保护跳转链。
- 对该实际链执行并由IDA逐条解码的236个PC均与安装PE一致：例如`0xDAF602`读actor `+0x7D94`水平速度，`0xDAF61C/0xDB6430`读上限`+0x7DA8`，`0xDB5DEA/0xDAC97A`写回水平分量；垂直分量为`+0x7D98`，写点包括`0xDA6304/0x4E0C9A`。
- 限制分别为`vx=clamp(vx,-limit,limit)`、`vy=clamp(vy,-limit,limit)`，不是按向量长度归一化；`(9,9),limit4 → (4,4)`。
- 同帧`0x6D97AA → 0x417C10 → 0x6D6F80`在本地分支用速度分量及独立偏移推进坐标。
- 这里的速度单位是内部更新单位，未换算成像素／秒。

- **验证范围**：CF71、CF80、读表与限速函数采用逐指令字节核对。
- 17项合成对象检查覆盖PA文本、type5分支、setter、CF80刷新与限速器。
- 基准4时，三颗17009274仍为上限4，三颗17010884为上限7。
- PET `+0x20`参与限速资格检查。
- 该范围为静态约定及指令隔离执行。

### 宝石type7、碰撞请求与卡片裁决边界（CN）

宝石经济策略由[黑曜石与卡片获得率](../../地宫/掉落/掉卡率与宝石.md#kb-06-016)维护；以下为CN客户端已确认的字段与调用链。

- `sub_960B90`按PA头部行数循环，分配`0x1B0`字节定义。
- 零基字段`6/7/8/9`写`BYTE +0x188/+0x18B`、`float +0x194`、`BYTE +0x18F`；第二、第三效果为字段`10..13/14..17`，分别写`flags +0x189/+0x18A`、`type +0x18C/+0x18D`、`float +0x198/+0x19C`、`percent +0x190/+0x191`。
- 显示名称/说明字段1..4复制到`+4/+0x14/+0x38/+0x5C`。
- 黑曜石的数值字段为type7、fixed0、percent1..9，显示文本由独立字段保存。

- 宝石查表`0x40CFB8 -> 0x9619E0 -> 0x40C149 -> 0x962290`；`sub_7C8430`领域17分支把定义`+4/+0x14/+0x38/+0x5C`格式化到UI`+0x21C/+0x350/+0x450/+0x550`。
- `sub_7CE970`将定义`+4/+0x5C`写宠物页名称/说明，攻击计算仅比较三个type字节是否为1。
- 详情显示与战斗加成计算分别建模。

- CF71在`0x6F5245..0x6F5277`本地／`0x6F5808..0x6F5832`远程读取三个DWORD宝石码`frame+0x7C/+0x80/+0x84`；CF72在`0x6F5B6D..0x6F5B91`读取`+0x58/+0x5C/+0x60`，均调用`0x40D3DC -> sub_6D78A0`。
- 该函数九个效果switch只处理type1/5/10/11/12，type7由default分支处理，宝石代码同步沿用该分派规则。

- 已确认的PA直接字段读者为`sub_6D78A0/7CE970/7F7570/7F7EE0/807200`，涉及`+0x18B..0x18D/+0x18F..0x191`。后三者在装配、库存移除和卸宝石时按type2/3调整HP／MP。该结论限定为这些函数的直接字段访问。
