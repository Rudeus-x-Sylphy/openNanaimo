### 求婚专用库存与戒指实例

- 强制分手的使用入口 `0x7F49F0` 与确认窗口 `0x81D440` 分离；`0x8BF600` 在用户确认后提交关系变更。
- 适配器使用阶段只建立有期限的库存／关系快照，确认阶段原子校验并提交。
- 求婚图标经 `0x53F440/0x53F590 -> 0x8BE280 -> 0x8BF060` 按 `1243 + 地宫等级` 选择资源；请求投影payload `+22/+23` 分别保存人物等级／地宫称号，求婚响应对应payload `+24/+25`。

- `0x008C0730` (`sub_8C0730`) 消费情侣专用库存页：完整帧 `+0x0A` 为行数，行从 `+0x0C` 开始，代码位于 `+0x0C`、实例身份位于 `+0x10`；只接收 物品类别43 代码，并按代码后缀写入银／金／钻戒的数量和实例身份表。
- `0x008BF170` (`sub_8BF170`) 在求婚页按当前戒指槽的数量门控确认按钮，构造请求时同时写入选中的戒指代码和稳定实例身份，确认流程因此依赖专用库存与普通游戏道具页的一致实例映射。

当前适配器以1..84范围内的稳定会话身份实现这条调用链；C430、C46A、快捷栏和求婚事务按同一游戏道具实例投影换算，数据库紧凑序号只用于持久层定位。

### 城镇称号与角色等级

- 城镇 `C36A/112` 的伴侣姓名为完整帧 `+0x5C..+0x6B`（payload `+84..+99`），戒指后缀WORD为 `+0x6C`，称号显示模式WORD为 `+0x6E`（独立于角色UID）。
- `0x53E0C0 -> 0x535530` 将姓名／戒指作为 `a25/a24`，远程角色经 `0x409A16 -> 0x509AD0` 的戒指setter及 `0x40A0BF -> 0x505DD0` 的姓名setter设置；`0x505DD0` 仅在非空姓名时使用字符串资源182拼出情侣文字，并以 `43000000 + 戒指后缀` 查找图标。
- 远程构造0x535530为角色分配新对象，因此已有同身份角色先经C36B移除，再发布C36A、C47F及静止或当前位置。
- 构造必须同时填写姓名与有效戒指；姓名保留NUL结尾，GBK截断按完整字符边界处理。
- 关系变化通过C36B/C36A更新目标角色，并保留当前场景。

### 情侣地宫身份及特殊遭遇状态

- 伴侣地宫身份经 `0x6EBD28 → 0x4029E1 → 0x709060` 写入管理器WORD `+0x1032`。
- 情侣场景C588/12先于最终CF80/8发布，人物伴侣身份与全房共享遭遇状态独立。
- 地图准备按有效同房情侣关系设置遭遇；`CFEC/full808 +0x325`、管理器BYTE+15及子资源标志2的完整读写／生成链统一归[特殊遭遇与闲置资源](../../地宫/关卡与房间/特殊遭遇与闲置资源.md#四类生成资格)。

- 用药结果 `CF94` 完整长度24字节：角色UID位于 `+8`、槽位WORD位于 `+0x0A`、道具代码位于 `+0x0C`、HP／MP恢复WORD位于 `+0x10/+0x12`，尾部两个WORD完整初始化。
- 尾部四字节初始化为零；原生快捷栏用药使用真实槽位，伴侣使用0xFFFF；背包用药的双方槽位均为0xFFFF。
- HP／MP字段分别携带各角色经自身有效上限裁剪后的实际恢复增量，不保证双方数值相同。
- 托管构造的payload必须为16字节，不能保留旧12字节截断。
- `0x6F1D9F` 按角色身份路由；`0x6F1F82..0x6F1FB0` 仅对槽位0–5执行快捷栏消耗，伴侣恢复使用 `0xFFFF`。
- 恢复状态以角色、战斗周期及单次结果身份去重，并同步有效HP／MP上限与持久状态。
- 当前内部角色状态采用结构版本4、payload5704／完整帧5712，payload DWORD `+5120` 保存伴侣UID；其后还有版本、曲线、64位人物累计经验和扩展卡片区，精确布局归[内部布局](../../../基础/桥接布局.md)。
- 伴侣资格在当前活动房间重新绑定。
- 历史5120→5124字节补零机制不是当前迁移处方：已验证的结构版本3／5144字节／CurveVersion3恢复快照按[战斗卡片入库与独立扩展区](../../卡片/卡册/数量与库存迁移.md#kb-03-028)的规则归档原字节，并从主卡片表重建扩展区；未知长度／版本拒绝，旧待提交journal不得隐式升级，须先用匹配旧程序恢复。

### 情侣资料及表情权限

- C355消费链为 `0x00531DA3 -> 0x0041646E -> 0x00530C90`；情侣姓名从包`+0xDF`传至原生`0xA76170`，按是否非空写入`manager+0x4F6C`。
- 戒指`WORD+0xF0 -> 0x4DDA30 -> manager+0x1028`独立于该布尔标志。

C355 进度填充止于完整帧 `+0xDE`；`+0xDF..+0xEF` 保持17字节情侣姓名，`WORD+0xF0` 保持戒指后缀。空情侣关系写入空姓名与零戒指，原生 `0xA76170` 将 `manager+0x4F6C` 置为 false，在翻页戒指资源查找前关闭门控。

- 隔离 original-x86 对照执行原生姓名／戒指设置函数（setter）和下一页门控（gate），CRT 有界复制（bounded-copy）、strlen、memset 为模型，缺失记录查找（lookup）按 NULL 建模。
- 越界姓名构造有一次查找／谓词（lookup／predicate）调用并在上述地址无效读；空姓名 Network 构造及两种 Stand_Alone（独立运行）构造均为零次查找／谓词调用、第2页之前关闭（`closed-before-page2`）。
- 这是有假设的隔离执行，不是全客户端 UI 验收；构造输出也不是实时 网络帧。

### 情侣标识与场景更新

姓名、戒指与字符串构造见[情侣资料字段](#kb-08-012-2)。绘制另有独立门控，构造与显示分别满足各自条件：

- C36A/112的`WORD+0x6E`是被观察角色的显示模式，`0x53E0C0 -> 0x535530 -> 0x4FA9F0`在`0x4FAA95`写入actor`+0x32F8`。该字段独立于UID；场景身份仍由控制值位20..31提供。显示模式按角色选项投影。

- `0x4FE970`绘制actor：`+0x1EC != 0`为本人，读取`[0xD869D8]+0xC0`的option[0]；其他人读取actor`+0x32F8`。
- 模式0隐藏；模式1走其他称号；模式2且伴侣名非空才绘制情侣文字和戒指。
- 名称actor`+0x31D4`、格式化文字`+0x31EC`、图标对象`+0x31D0`、戒指`+0x32F0`是独立字段。

- C355/728的`WORD+0x2D4/+0x2D6`在`0x531125..0x53113F -> 0x410F3C -> 0xA86120`恢复显示模式及六个选项位；模式没有初始化为2时，补发伴侣姓名不能开启本人的绘制。旧档缺少设置行采用默认2/0；显式设置0/1必须保留。

- 选项保存构造`0x8AB0D0`为C5BC/12；`0x8A877B..0x8A8799`在完整帧+8写mode、+10写六位flags并发送。
- 适配器以活动账号/角色/会话原子保存`CharacterTownOptions`，只接受payload4、mode0..2、flags0..63；不伪造C5BD或额外C355/C368。
- 本人UI直接应用设置，他人按后续正常角色快照读取。

- C584/C586经`0x536440`局部更新关系，C355经`0x530C90`进入页面初始化；关系变更使用前者，保留双方原场景和坐标。旁观者按同页可见性获得对应角色的最新关系、坐标与外观。

情侣文字绘制要求本人option[0]及他人mode使用有效显示模式，并同时具备伴侣姓名和戒指。当前修正统一C355选项恢复、C36A被观察角色模式和C5BC持久化；对应构造及发布约定已验证，画面按双端场景验收。
