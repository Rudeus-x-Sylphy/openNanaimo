### 好友与私聊

- 好友申请按收件角色确认，接受、拒绝和稍后处理使用同一持久化申请状态；接受事务重新检查双向屏蔽，重复确认保持单次关系提交。
- 客户端联系人添加、好友列表及管理界面共用 `FriendRelations` 和分类数据。
- 添加验证当前账号／角色／会话及屏蔽关系，双向关系保持幂等和单次通知。
- 首次及反向添加仅在本连接客户端名单缺少该昵称时返回成功添加；客户端已有昵称的重复请求仍维护数据库关系，但返回重复状态10，不再进入无条件新增界面行的分支。
- C355恢复最多20个好友昵称及10个屏蔽昵称；C5AC请求对应的C5AD按该连接客户端昵称顺序输出4字节状态，不按数据库重新排序。
- 地宫称号和角色等级来自目标的持久角色资料，离线也保留。
- 关系从其他会话变更时，在C5AD构造已有界面行后以具名C5AF增删差异；不在无请求时推送联系人变更。
- 载体偏移与读取链由[好友名单、状态与命令结果](#kb-08-051)维护。
- 原生联系人命令 C5AE/payload20 的操作1为添加、2为删除、3为屏蔽、4为解除屏蔽，均返回完整 C5AF/full32。
- 删除按当前账号／角色／会话和已有关系校验，在同一事务中清理关系、分类成员、备注和申请历史；后台删除同样清理申请，避免已接受请求重新物化关系。
- 删除好友不删除任一方独立设置的屏蔽。
- 无目标或重复删除返回完整失败结果，不发送无请求广播。
- 屏蔽按角色昵称持久化，不要求对方已是好友；原生名单最多10人，解除仅清理自己的屏蔽。
- 适配器策略为任一方向屏蔽即阻断双方好友新增、好友私聊、城镇悄悄话、聊天广播的对方投递、组队／娱乐室邀请、求婚和师徒申请。
- 组队接受、情侣及师徒提交重新检查屏蔽，不能通过先邀请后屏蔽绕过；屏蔽不自动解散既有队伍／情侣／师徒，也不阻止解除关系。
- 好友私聊按在线角色名定向送达，发送者姓名由活动会话确定。
- 姓名16字节、正文32字节均采用有效的NUL结尾GBK；输出重新编码并清零剩余空间。
- 离线接收者得到系统提示。
- 城镇悄悄话采用独立CB23/type2000路径，也检查屏蔽。

### 好友名单、状态与命令结果

- C5AF分派 `0x4D36AF → 0x419FF1 → 0x4D4450`。
- `0x8D4F2C..0x8D4F33`读取`WORD+0x08`并以1判断成功；`0x8D4F3C..0x8D4F59`将`WORD+0x0A`作为操作1–4分派。
- 添加分支`0x8D4F60 → 0x41E50B → 0x8CFB80 → 0x41EDD0 → 0xA76FC0`在`0xA77073`加入联系人；删除分支`0x8D4FAB → 0x41C94F → 0x8D00C0 → 0x41052D → 0xA77090`在`0xA7711F`删除匹配姓名。
- 无活动联系人界面时，`0x4D44BB`和操作表`0x4D4690`使用相同语义。
- 结果从`+0x0C`读取16字节姓名，`+0x1C`为在线标志、`+0x1D`为地宫称号grade、`+0x1F`为角色等级；`+0x1E`没有在这条消费链中确认语义，适配器清零。
- 图标构造`0x8CFB80`以grade格式化`1243+grade`，等级另按0..199校验。
- 旧“城镇／页／频道”解释撤回。
- 完整长度至少32字节；操作2消费目标姓名，不得给它空白成功身份。

- `0x8CFB80`先调用`0x41FA1E`插入界面行，最后才调用`0x41EDD0 → 0xA76FC0`检查姓名重复；已有昵称仍发送状态1／操作1会使界面行数大于昵称数，后续按行索引取姓名可返回NULL。
- `0x4D4450`的状态10／操作1进入已存在提示，不创建行。
- 适配器重复添加应使用该分支，不能以数据库关系幂等代替客户端行幂等。
- 操作3由`0x41BA68 → 0x8CEBB0 → 0x4100DC → 0xA771B0`加入屏蔽昵称；操作4由`0x410181 → 0x8CECE0 → 0x415DD9 → 0xA77280`删除屏蔽昵称。

- C355完整帧`+0xF4..+0x233`为20个16字节好友昵称；`0x5311D7..0x531211`逐项调用`0x41EDD0`写本地名单。
- `+0x234..+0x2D3`为10个屏蔽昵称；`0x531233..0x53126D`逐项调用`0x4100DC`。
- C5AC由`0x8DA100`构造full8；C5AD由`0x419295 → 0x4D46A0 → 0x4017B2 → 0x8D5040 → 0x412332 → 0x8D02E0`消费`WORD+8=count`及从`+0x0C`起的count条4字节状态，只构造界面行，既不携带也不补建昵称。
- 逐行消费字节0为在线、1为grade、3为角色等级，含义同C5AF尾部；最小完整长度为`12+4*count`。
- 状态行必须与已恢复的昵称名单顺序／数量一致。
- 适配器构造与原客户端GUI验收的边界由[验证入口](#kb-09-008-2)维护。

### 好友字段、数据库事务与客户端验收范围

- 好友名单修复覆盖C355昵称恢复、C5AD连接内顺序、在线／离线称号与人物等级、重复添加界面行抑制、双向删除及独立屏蔽保留。
- 屏蔽策略归[好友与私聊](#kb-05-002)，字段与客户端消费约定归[好友名单、状态与命令结果](#kb-08-051)。
- 专项验证层级为字段校验、适配器构造及数据库事务；客户端图标、上线昵称、删除后的页面状态及双端交互已有独立用户确认，范围与受测版本待补录状态见[好友界面验收](../../工程/验证状态/社交竞技与娱乐验收.md#好友界面验收)。
- 发布程序与运行中的安装按各自文件身份维护。
