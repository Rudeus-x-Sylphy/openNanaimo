### 复活糖果：商店分配、本地使用和地宫副本死亡边界

- `MI._D22`将类别48复活礼包与类别14普通食物及六槽战斗快捷栏分别定义。
- 每个礼包实例提供的本地使用次数表只在[复活糖果静态调用链和边界](#kb-08-027)维护，本节不再重复枚举。
- 这些次数通过角色复活数据库账本维护；原适配器的价格／奖励策略仍然未知。

- 领取和激活均按确切实例标识执行事务。
- `C475/20` 载有模式 `+8`、操作 `+9`、数量 `+0x0A`、本地令牌 `+0x0C` 和代码 `+0x10`；其结果为 `C476`。
- 一个已领取礼包对应一个C430 `(code,identity)`。
- `C46D/16` 提交代码 `+8` 和身份 `+0x0C`；成功的 `C46E/20` 删除恰好那一行并分派事件35（成功响应的字段布局归[C46D通用物品使用构造](通用物品与券类使用.md#kb-08-029-6)），并通过 `sub_4011B3 -> sub_7090B0` / `sub_408A53 -> sub_54E430` 在管理器`+0x5600`处增加MI定义的复活次数。

### 复活糖果静态调用链和边界

- `MI._D22` 提供了客户端本地复活次数表：`48000001=5`, `48000002=10`, `48000003=30`, `48000004=1`, `48000005=5`, `48000006=11`, `48000007=32`；资源行不是 C430 的数量载体。
- 完整的静态调用链是 C475 分配 -> C476 结果 -> C430 `(code,identity)` 实例 -> C46D 使用 -> C46E 成功。
- `sub_81D440` 删除了具体的标识，触发了 物品类别48 的 event35，通过 `sub_4011B3 -> sub_7090B0` (`this[5504]` (字节偏移 `+0x5600`)) 读取本地计数器，增加了资源值并通过 `sub_408A53 -> sub_54E430` (`this[5504]` (字节偏移 `+0x5600`)) 写入；该计数器链与额度增加的字段表述唯一归[C46D通用物品使用构造](通用物品与券类使用.md#kb-08-029-6)。

- 死亡判定：须区分客户端 World 连接与内部工作进程事务，D010 绝对生命值达到局部零才算死亡。
- 放弃事务：原客户端死亡对话框由`0x708900`构造 CF95/8，经`0x6EAD40`发送放弃请求，公开响应 CF96/8 无载荷。
- 重试资格：结果页重新挑战另发 CF8B/12，资格规则归[业务／地宫／计分与结算](../../地宫/计分与结算/索引.md)。
- CF87是12字节的结果请求，CF88消耗一个12字节的头部加上0x34字节的记录。
- `sub_73F3A0`和`sub_73FF50`读取重试/结果UI的计数器。
- 后续的载体闭合在`0x5310B2 -> sub_408A53`处证明了C355 `BYTE+0xF2`，并在`0x6F53B8 -> sub_41A2CB(value,0) -> sub_6E2F40 -> sub_408A53`处证明本地CF71 `BYTE+0xA8`写入管理器`+0x5600`。
- CF84 variant60在`0x6F5F33..0x6F5F53`通过`sub_4011B3`读取当前值、减1并写入`sub_41A2CB(value,1) -> sub_408A53`；`+0x10/+0x14`经`sub_40B14F -> sub_7091B0`写入actor完整金币余额`+0x7BD8/+0x7BDC`，随后控制恢复分支使用自己的固定放置常量。
- 历史工作进程扣次构造族的`CF96 -> CF84 variant60 -> CF72`顺序只属于内部复活事务，不能套用于公开CF95放弃；CF83彩蛋选择在工作进程内部推进该事务，仅向客户端交付CF84及相应角色恢复。
- 此处关闭字节／顺序与本地构建，不替代可见的客户端控制恢复。

#### 准备房卡片文本路径与本地兼容入口

- 准备房持久显示不是另一个manager直接getter。
- `sub_6E2F40` 在 `0x6E2F49..0x6E2F69` 用 `0x00C6AED8="%02d"` 写actor `+0x8124`；仅mode非2时，`0x6E2F75..0x6E2F7F -> sub_408A53` 更新manager `+0x5600`。
- 独立 `sub_6E2F90` 在逻辑x575/y550经 `sub_40DA1C` 绘制actor缓存。
- 正确manager及死亡/结算getter不证明准备房显示缓存当前有效。

- 旧复活HUD兼容项使用 `0x006E2F90` 七字节入口及 `0x006E30A0` 64字节代码区，读取 `[0x00D869D4]+0x5600`，通过 `sub_B47637(actor+0x8124,8,"%02d",count)`格式化次数，并返回0x006E2F97。
- 当前派生将该入口和代码区迁移回原生状态，完整字节与回退步骤见[原生状态与旧版迁移](../../../工程/客户端兼容/原生状态与旧版迁移.md)。

- CF72显示更新链：完整帧 `BYTE+0x73` 经 `0x006F5DF7 -> sub_41A2CB(value,2) -> sub_6E2F40` 写入actor `+0x8124`；mode2更新显示字符串，管理器 `+0x5600` 由独立次数路径维护。
- 适配器按源 actor 账本填写 CF71／CF72 次数，托管端出口按同一队伍（party）及有效期租约（lease）确认归属者（owner）后同步。
- 每个远端actor保留独立次数，CF71后及pre-CF80刷新共享一致字段。
- `--native-state` 将旧HUD兼容代码迁移回原生路径，验证范围为状态构造及精确迁移。

### 复活额度激活与恢复链

C46E 物品类别48 的额度增加与计数器链表行唯一归[C46D通用物品使用构造](通用物品与券类使用.md#kb-08-029-6)：`sub_81D440` 成功分支删除匹配的库存对象后，通过事件35在管理器 `+0x5600` 增加 MI 定义的复活次数；计数器载体为 `sub_4011B3 -> sub_7090B0` / `sub_408A53 -> sub_54E430`，读写 `this[5504]`（字节偏移 `+0x5600`）。

本节只维护物品类别48 的额度与计数器链；物品类别47（合成钥匙）的 C46D 请求、C46E 应用与容量基础规则归[游戏道具使用与结算](通用物品与券类使用.md#kb-03-046-1)。
