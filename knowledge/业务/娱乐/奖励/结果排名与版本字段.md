### CN幸运卡奖励图标与图片路径


#### CN娱乐室幸运卡结果行

- CF86三个奖励DWORD在`r+0x28/+0x2C/+0x30`，`643A40 → 6440DC → 413DA9 → 64A360`构造排名奖励。
- 原`64A423`以50000000分流：较小代码经`40CA5E → 9BED50`，只覆盖物品类别12及13000001..13000420，幸运卡22000014返回0，`64A4F8`的`movzx edx,word ptr [ecx+0xBC]`直接解引用。
- 当前仅对开放幸运卡22000011..18绕到原通用图标分支`64A430`；`64AC90`使用`41DEB2 → 57E7C0`取得profile+4624的特殊卡管理器，再经`407C7A → 9A9500`读取记录，返回**记录+245的卡名图片路径**。
- `87EF57`的`add ecx,0F5h`及`87EF67 → 41E0E7`闭合相同原生资源来源；字段+8只是中文显示名称。
- 返回值在`64AC9F → 41E0E7 → ABCC10`按group10作为图像路径消费，路径类型不匹配时转`40F8DA → ABD4F0`；`ABD726 → 41B58B → 4EEBF0 → B4D1F0`查找最后一个点，`ABD771 → B4E616`作不区分大小写比较。
- 无扩展名输入返回0，`B4E639 → B47976`触发非法参数，调用返回位置`B4E63E`对应WER模块偏移`0x74E63E`（ImageBase=0x400000）、异常`c000000d`。
- 旧+8配方因此被撤回，不能将模块偏移直接当VA，也不能归因为村庄资源共享或适配器SQL异常。
- 新旧配方用真实PE扩展名／CRT片段对八种幸运卡作隔离核对，卡名图片的pack键2001..2008均在`images/ddakg_images.pack`。
- `64401F`的本地大图路径`40802B → 64B060 → 40CD0B → 868190`不支持物品类别22，兼容将其预览参数置0以清除旧槽，排名行原卡号与持久库存均不变。
- 兼容代码区`6E3400..6E34BF`和三个入口由统一配方维护，仅迁移精确CC／失败+8／当前+245字节，未知内容拒绝；安装、社交副本重派生与恢复见客户端二进制补丁文档。
- 宠物字段职责见本节CF86，奖励策略见[娱乐与师徒奖励策略](卡片宠物与纪录策略.md#kb-07-022-1)；修正后的原客户端验收状态归[验证入口](卡片宠物与纪录策略.md#kb-09-001-5)。

### KR CF85/CF86请求及结果字段

- **娱乐室请求及状态元组**：分派器`5AFD30`从帧+6读opcode，`55555`分支`5B7B50`清等待对象后，经`5BB010`构造`CF85/8`，`5B7BA8`调用`989820(1,request)`。
- 响应同分派器以`opcode-53103`的case23分发到`5B7BE0`，即CF86，不是地宫CF88。
- 未采集该路径实际连接端点／时序，不把常量1命名成某个TCP端口。

- **KR CF86字段与门控**：DWORD帧+8为count，`r=frame+0x10+0x58×i`，WORD r+0匹配成员。
- 仅本机成员且装备PET时更新本人宠物状态；`BYTE r+6/+7`为当前／最大变身阶段，`DWORD r+0x30`为当前宠物EXP。
- `5B7F84..5B7FB3`选宠物成长类别（缺定义时类别0），以`8B0C80(stage)+4`为分母，非满阶段超出该分母的EXP被改成1；满变身百分比使用255哨兵，否则为整数百分比。
- `5B816E → 5AC9D0`另以浮点比率×100更新结果进度；没有在此按排名算20／10。
- 完整数组布局为`16+88×count`；该处理函数还有角色64位经验三元组、卡片及尾部WORD读取，最高显式字段是r+0x52的WORD，不能只构造到宠物EXP。
- `5B8238 → 5AB9B0 → 5AA4C0`创建排名行、`5AAE40`加载`pet_upicon.im3`，属于客户端接收结果后的界面处理，不是发奖算法。

### CF6F目标与CF86实际分数

- CF6F/full88由同一分派器case0经`41CF71→644C20`消费，完整帧WORD+32（payload+24）在`644D0A`写控制器+28124目标分数，并非人物等级；WORD+34为幸运积分。
- CF86的`643BCB`比较记录DWORD+8与该目标。
- CF86实际分数仍为`r+8`，显示写成员+13300；奖励`r+40/+44/+48`在`64401F→40802B→64B060→40CD0B→868190`走大图卡片路径。
- 基础13000001..13000420不命中特殊幸运卡清槽分支，使用真实卡号保留原生预览；特殊幸运卡采用+245图片路径和物品类别22清槽约定，验证层级由[验证入口](卡片宠物与纪录策略.md#kb-09-001-5)统一维护。

### CF0C大厅最高分与身份字段

- 协议元组为ArenaAdapter／娱乐室大厅／`77E720`控制器。
- CF0B/full8由`4025A9→7844B0`构造，`780B50`在`78103C`调用构造器并经`ADA3E0(游戏类型,request)`发送。
- CF0C/full20的BYTE+12为游戏类型、BYTE+13为独立运行值，DWORD+8经`77F595..77F5A2→406131→A74C10`写全局资料对象+0x7A8身份字段，DWORD+16经`77F5A7..77F5B4→41C80A→7820B0`进入大厅九位数字渲染。
- 适配器在后者发布当前角色／游戏类型的持久最高分；UID、当前游戏分数和个人最高纪录分别维护，保存规则归[娱乐奖励策略](卡片宠物与纪录策略.md#kb-07-022-3)。
- 最高固定读取为DWORD+16，完整应答最小20字节。

### CF14十行排行与本人纪录

- 排行榜CF13/full12由`785F60→40F04C→7873E0`构造，DWORD full+8为零基页码，经`ADA3E0(游戏类型,request)`发送。
- CF14/full296由`77E720→416F68→77DD60→408409→786990`消费：DWORD full+8为本人最高分（不是UID），WORD+12为页码，WORD+14为有效行数，行从+16开始、步长28，行+0为24字节昵称，DWORD行+24为最高分。
- `786990→408D5F→786360`绘制本人纪录，`40DE54→786C90`填行，名次由`10×page+i+1`本地生成，不传额外名次字段。
- 有效行数最多10；`77DD60`诊断路径无条件读取全部十行，因此即使空页也必须初始化完整296字节。
- 全零占位回应不能作为已实现排行。
- 保存及稳定排序策略归[娱乐奖励策略](卡片宠物与纪录策略.md#kb-07-022-3)。

## 娱乐室结算人物等级

- **结论**：CF86结果行的人物等级使用结算角色的实际等级字段，等级字段与经验、分数、角色和宠物身份保持独立。兼容版本覆盖1～200级及三位数显示，120级不再折算为90或10。
- **显示兼容**：当前配方同时维护等级更新、三位数绘制、缓存状态恢复和进度刷新；低于100级保持原有两位布局，100级及以上显示百位、十位和个位，重复进入结果页不会累积位置偏移。
- **迁移与资源**：现有版本、历史兼容版本和当前版本按精确字节身份迁移；结果页继续使用既有数字图像资源，经验、分数、奖励和结算事务保持原有数据约定。配方位点、资源依赖与安装／恢复步骤归[娱乐室等级显示](../../../指南/客户端二进制补丁/娱乐室等级显示.md)。
- **交付状态**：适配器构建与专项回归已通过，客户端兼容配方已纳入统一地宫状态发布。当前 `runtime_acceptance=false`，画面验收状态归[验证状态](../../../工程/验证状态/社交竞技与娱乐验收.md#娱乐室人物等级显示)维护。
