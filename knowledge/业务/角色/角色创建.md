### 启动注册、用户名与来源隔离

- 注册入口接受 JSON `{LocalAccount, PureNewPlayer}`。
- 社交参与入口请求纯新手创建，并按账号实际状态计算有效模式：无角色账号进入干净创建，已有角色使用其持久化的档案类型、外观、进度和装备。
- 来源 IPv4 隔离后续登录队列；P1/P2/P3 是客户端槽位，账号键保持为用户名。

- 纯新手生命周期：注册保持无角色状态；`2717/2718` 将提交姓名、性别和36字节外观与 `PureNewProfile=1` 原子保存；`2719/271A` 从数据库恢复档案标志和外观；`C368`、`C36A` 在尼莫及故事引导完成前恢复同一保存形象。
- 验证覆盖响应构造、SQLite 隔离、普通旧账号复用与教程重登。

- GUI 的纯新手模式使用独立角色档案。
- 其“构建与启动纯新手档”和“新手档用户名”控件位于普通“用户名／角色显示名”之上；启用后相关跳过教程和全地宫控件被关闭，教程与地宫开关的固定值见[纯新手档持续游玩与地宫前置](新手引导/教程与外观.md#kb-02-006-1)。
- 初次登录保持无角色状态，并先进入人物形象创建和角色命名界面。
- 完成创建后，新角色固定为等级1、零 Hans/Cash/SP、零库存、零任务行和未完成引导状态，并使用对应性别的完整初始外观。
- 启动器使用独立的默认配置档案（中性 runtime profile：不含用户名、进度与外观，仅供纯新手档初始化），并为需要格式化日期的可选权益写入合法且已过期的值 `2000010100`（yyyyMMddHH 编码，即2000-01-01 00时）；常规 INI/JSON 保持不变。

### Network 无角色建角入口

- `0xA67A60` 处理登录结果，`0xA67B57` 读取角色存在状态。
- 无角色分支以 `0xA67B73 -> 0xA67BE3` 转到建角标志设置，`0xA74350` 写 manager `+0x5CB=1`；`0x4E2F00` 读取标志选择建角子状态，`0x4E32C0` 状态1构造 `0x4E4F90` 原生外观／命名界面。
- 271A的空身份投影与2731角色存在状态分别承担角色资料和入口选择。
- 站点字节、文件偏移与派生步骤由[完整适配器与客户端兼容说明](../../指南/完整适配器与客户端兼容说明.md)统一维护。

### 建角推荐人结果与提示状态

- 建角推荐人：登录连接中客户端发送 `2725/24`（16字节GBK姓名），`sub_4E5E50` 消费单个 `2726/28` 结果。
- 处理器要求 opcode `0x2726`；`DWORD frame+8` 为10/20/30。
- 10与20分别创建消息40/41并清理 `+0x3A4` 等待状态；30读取 `frame+12` 的姓名、关闭建角状态，在 `0x4E60D8` 创建消息42，并于 `0x4E6100` 设置 `+0x39C=1` 完成标志。结果到消息的对应关系归[一村尼莫引导完成与建角推荐人](新手引导/故事引导与推荐人.md#kb-02-003)。
- 成功也需经过提示确认，不是无弹框继续。
- 响应至少覆盖到 `+27`；该边界只返回单个结果帧，登录上下文由独立的常规请求取得。
- 未知结果不执行这些分支，不构成替代成功码。

- 推荐提示父状态：`0x4E3110 → 0x4E3153 → 0x40EAD9` 读取消息结果；确认按钮经 `0x7ED500/0x7ED509` 设置关闭阶段2与结果0，`0x7EC540` 保留关闭对象供后续更新周期处理。
- 登录帧在 `0x4E315F → 0x402EF0 → 0x42FBA0` 将结果0解释为全局状态25。
- 逻辑消息类型13经 `0x7EA900` 映射到内部类型9；成功旗 `+0x39C` 等待消息关闭，随后 `0x4E3E40` 发送登录上下文请求。
- 本地输入在 `0x4E64E3` 设置 `+0x3A4=1`，空名／自己名分别于 `0x4E65C6/0x4E668F` 进入本地提示。
- 兼容代码 `0x4E4600` 对 `BYTE+0x40=40..42` 向父状态返回1并保留对象 `WORD+0x36`；`0x4E65C6/0x4E668F → 0x4E4620` 清理本地等待标志并保持返回值1。
- 精确字节、应用和恢复步骤由[完整适配器与客户端兼容说明](../../指南/完整适配器与客户端兼容说明.md)统一维护。
