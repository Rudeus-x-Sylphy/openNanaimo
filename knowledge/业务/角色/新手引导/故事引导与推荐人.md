### 一村尼莫引导完成与建角推荐人

- 一村故事引导完成使用 `C599/88 -> C59A/36`。
- 普通引导提交 `taskType=0, guideId=0..5`，终章提交 `taskType=7, guideId=6`；72字节尾区按不透明数据接受。
- 哈希奥终章的资格、礼包项目策略、整包发奖及旧档欠发恢复唯一归[任务／终章兑奖](../任务.md#哈希奥终章礼包)，不将完成应答或奖励窗口文本本身当作实际发奖。
- 适配器在同一事务中更新 `CharacterStoryGuides`、发放一次性奖励并始终返回可消费的 `C59A`。
- 尼莫 `guideId=0` 首次完成向普通游戏道具背包发放 `46000008`（100金币兑换凭证）1张；重复提交成功应答并保持单次领取。
- 凭证使用事务扣除1张并增加100 Hans。

- 建角后的推荐人请求为 `2725/24`，固定16字节GBK姓名；响应为 `2726/28`，`DWORD +8` 结果10/20/30分别表示不存在（含原始请求中的空名或格式无效）、自己、成功，成功时 `+12` 写16字节规范角色名。
- 适配器在首次有效绑定的同一SQLite事务中给推荐人角色档案增加200推荐点，重复提交沿用已保存结果。
- 每次请求返回一个完整结果；角色上下文由后续常规登录上下文请求取得。

推荐人结果10／20／30分别创建消息40／41／42；客户端兼容项将三类提示的确认结果接回登录继续流程，并在留空或填写自己姓名时清理本地提交等待标志、恢复填写状态。适配器负责单请求单结果、登录连接作用域、规范姓名和首次有效绑定200推荐点事务。

- 成功姓名使用16字节NUL结尾GBK字段，适配器校验编码、容量与控制字符；失败结果清零姓名尾区。
- 结果构造、提示状态、等待标志恢复、幂等绑定和后续登录上下文已纳入专项回归。
- 字段与状态调用链见[C599故事引导载荷与C59A完成字段](#kb-08-008-2)，完整二进制应用和恢复步骤见[完整适配器与客户端兼容说明](../../../指南/完整适配器与客户端兼容说明.md)。

### 故事引导完成的有效资源上限

- `C599/88 → C59A/36` 的 guideId 0～6 均从当前会话 `NonCombatResourceSnapshot` 构造与D8FF一致的有效HP／MP上限；快照缺省时使用相同的非零基础值回退。
- 成功响应保留当前资源、持久基础属性、经验投影、引导ID／完成类型、赠品及幂等事务；公寓guide5失败结果为3，其余引导为1，失败尾区清零。
- 响应遵循单请求单结果约定。
- 字段与HUD资源消费链归[公寓引导完成的资源消费链](#kb-08-054-2)；全引导构造已集成当前运行包，验证范围归[教程与跨村功能验证范围](验证范围.md#kb-09-020-12)。

### 公寓首次引导与欢迎凭证

- 公寓首次引导使用 `guideId=5`。
- 完成新手教学后，公寓入口与引导完成采用一致资格；欢迎奖励为 `46000008`（100金币兑换凭证）1张；奖励与完成标记的原子提交、凭证扣减与100 Hans入账、重复确认与重登的单次领取边界统一见[公寓引导](../../住宅/公寓引导.md)。
- 恢复性拒绝使用客户端继续会话的分支。
- 适配器构造检查覆盖LV1／2／3、旧引导状态、重复确认、完整场景响应及后续请求；宠物店本地领奖窗口与完成引导后的同步／会话另已获用户确认，范围及受测版本待补录状态见[故事引导与会话连续性](../../../工程/验证状态/社交竞技与娱乐验收.md#kb-09-030-3)。建角的成功推荐及继续进入游戏已有[部分验收](../../../工程/验证状态/社交竞技与娱乐验收.md#建角推荐人部分验收)的用户确认；留空重填、不存在姓名与自己姓名仍待验。

### C599故事引导载荷与C59A完成字段

- 一村故事引导：`C599/88` 的载荷前8字节（完整帧+8..+15）为类型、运行状态和guide/task ID；尼莫使用小整数guideId，不属于QT普通任务ID。
- 完成端必须返回 `C59A/36`，其结果在 `+8`、ID在 `+12`、完成类型在 `+16`。
- 空响应会留下客户端等待状态。

### 公寓引导完成的资源消费链

- guide0～6共用C59A资源写入与引导分发链。
- 公寓引导 `0xA515B0` 在步骤5经 `0x402E00 → 0x4D5460` 构造 `C599/88`，类型0、guideId5。
- `0x58F540` 的首次公寓引导入口条件为房主房间（C38E类型10／20）、LV≥3且guide5未完成；适配器完成资格仍为已完成主教学。
- `0x4D56A0` 在成功 `C59A/36` 的 `0x4D5AB2..0x4D5AD8` 先消费WORD+20／+22，经 `0x41714D → 0x4D7C30`、`0x4026DA → 0xA757E0` 覆写 `[D869D4]` 指向的MyInfo最大HP+0xFDA／最大MP+0xFE2（MP逐字节XOR0x46），保留当前HP+0xFD8／MP+0xFE0。
- 随后才将状态22中的完成响应交给 `0xA14900`：成功要求BYTE+8=0、WORD+16=0及DWORD+12匹配当前guideId；结果1进入退出状态25，结果3进入恢复性拒绝提示。

- 故事引导成功完成响应（guideId0～6）沿用[故事引导完成的有效资源上限](#kb-02-004)定义的有效资源上限，统一全引导集成及分层验收边界归[教程与跨村功能验证范围](验证范围.md#kb-09-020-12)。
- `0x5408D0` 在 `0x540A10／23／36／49` 用同一MyInfo写入D8FF当前HP／当前MP／最大HP／最大MP；C59A随后写入相同的有效值最大HP／MP，并保留当前HP／MP及持久基础值。
- `0xA235D0` 按 `(current / maximum) × 100` 计算血条宽度；统一上限可使含宠物加成的当前值保持在有效纹理范围。
- 血条绘制链为 `0xA23664 → 0xAB3540 → 0xABA780 → 0xACC740`。

- 宠物与道具店shop110使用`C599/88`（type0/state0/guideId1）及`C59A/36`。
- 有效上限与当前资源共同约束HUD纹理宽度：当前HP64500／最大HP21500会计算出300%的宽度；当前MP7510同样要求对应的有效MP上限。
- 引导HUD调用链为`0xA3087E → 0xA23664 → 0xAB35BA → 0xABAA86 → 0xABA9CA → 0xACCB2A → d3dim700+0x95DF`。
- 赠品由库存事务维护，预览`0xA31DD0`使用15005007／17000003／21000001／14000005四个代码，资源上限由C59A维护。

- 宠物店引导步骤15在`0xA2FCB3`经`0x402E00 → 0x4D5460`提交，guideId由`0x40BDA2 → 0xA15620`读取后减1，当前值为1；`0x41F690 → 0x4D7A00`写opcode C599及长度88，`0xADA3E0`发送。
- C59A经`0x4D56A0`读取至DWORD+32，最低安全全长36，再由state22经`0x40907A → 0xA14900`分发引导结果；`0xA30879 → 0x4197B8 → 0xA235D0`为HUD调用点。

奖励窗口路径由 `0x41AAA5 → 0xA5AB70` 设置窗口；公寓使用文本1029，GBK单行18字节，`0xA5A9B0` 的六行缓冲每行41字节。构造／绘制为 `0xA5A7A0／0xA5A570`，释放为 `0xA5A310／0xA5A6B0`。引导资源上限与奖励窗口使用独立生命周期。
