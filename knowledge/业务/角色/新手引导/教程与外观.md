### 主线新手引导与配置装备隔离

- 所有已建角色从持久化 `Appearance` 恢复登录外观；未完成教程时，仅对 `271A` 的 D6/D7 执行教程安全投影。
- `Characters.PureNewProfile` 与建角同事务保存，每次登录和频道刷新恢复；该标志为1的全新角色保持1级、不附赠奖励、不预建库存／任务行，各账户分别保存提交的外观。
- `C368`、`C36A` 与尼莫对话前后共享角色保存的外观，档案生命周期由账号和角色身份维护。

- 引导阶段 `C354` 返回 `C355/728`，携宠标志 `+0x0D=0`。
- 有效 `C353` 原子保存完成状态并返回 `C594/12`；后续 `C354` 按 `C355 -> C476 -> C44C` 初始化普通库存及宠物，首次 `C367/C368` 恢复全部保存装备。
- 非法身份、长度和重复完成事件沿用输入校验与幂等规则。

阶段门控由适配器实现。男女各4组装备状态、无角色入口、配置保留与完成后即时恢复已通过数据库及协议构造检查。静态边界见[主线引导 D6 与普通村庄加载差异](#kb-08-010)，发布产物与验证范围见[教程与跨村功能验证范围](验证范围.md#kb-09-020-12)。

### 纯新手档持续游玩与地宫前置

纯新手档在创建角色后保留玩家选定的基础外观槽位；教程阶段只暂时屏蔽特效和宠物槽，教程完成或重新进入村庄时恢复已保存的完整外观。纯新手档用户名由启动器单独保存，填写已有用户名即可继续对应角色；历史生成的纯新手账号也支持以其已有角色名找回，已有角色不会被重新创建或覆盖。

- 纯新手档始终按原始进度逐个开放地宫，只有前一地宫链完成后才允许进入下一地宫；该模式不允许开启“全部地宫进入权限”，运行值固定为 `unlock_all_dungeons=0`，教程开关同样固定为 `skip_tutorial=0`。
- 第五村继续保留既有进入兼容机制，但仍要求前置普通地宫全部满足。
- 常规角色档是否使用便捷开放策略属于独立配置，不改变纯新手档约束。

### 新手教程门控

主教程的进入判定已定位到适配器控制的登录字段：

```text
271A byte +0x0E
  -> sub_4E3830
  -> 角色信息对象 byte +3
C352 成功
  -> sub_4DFAA0 本地 phase5
sub_4DF1E0 phase5
  byte +3 == 0  -> 全局 state12（主教程）
  byte +3 != 0  -> 全局 state1 （跳过教程）
```

Network 模式使用角色资料参数 `skip_tutorial` 控制教程入口。跳过路径仍由请求驱动：C351 只收到 C352，随后客户端直接发出 C354；适配器返回 C355，重新应用角色资料门控，再发送 EA61 scene0。此路径不发送教程 EA61，也不合成 C353。

直接进入游戏的状态链为 `C351 → C352 → C354 → C355 → EA61(scene0) → C367/C368`，按角色与页面状态逐步完成初始化。

主教程BOSS采用本地战斗更新，血条衔接与普通地宫的权威生命分别限定状态；字段、写入链及兼容边界归[BOSS血条初始化与权威剩余量](../../地宫/BOSS/协议与部件回收.md#kb-08-072-4)。

### 每个角色教程选项

角色资料参数：

```text

skip_tutorial=0|1

```

对于网络模式，此值在每次上传客户端角色资料时携带。显式的`1`写入271A `+0x0E=1`；显式的`0`写入零。遗留的上传角色资料中省略该键默认为零，而不是继承适配器范围内的跳过设置。该字段是适配器自定义策略，并非库存/账户持久性声明。

教程参数作用于角色初始化状态链，见[主线新手引导与配置装备隔离](#kb-02-002)；库存采用独立持久化规则。

### C355首次进入标记与村庄页面选择

- C355 处理函数 `sub_530C90` 在 `0x00530F69..0x00530F88` 读取 manager+`0x7B4` 的一次性门（getter `0x0054D470`；构造时 `0x00A6E3C4` 初始化为1），随后经 `0x0054D450` 清门，并通过 `0x00A75270` 把 manager+`0xD38` 的 `FirstVillageFlag` 置1。
- C355 完整帧 `+0x20/+0x21` 同时在 `0x00530F1A..0x00530F5E` 选择当前村庄／页面，发生在首个 C367 前。

### 主线引导 D6 与普通村庄加载差异

- `CGuideChar` 的 `sub_917D90` 在 `0x0091812A` 读取正确 D6 参数，却在 `0x0091811A` 传入标志0，经 `0x00918144 -> 0x00413A84 -> sub_4EE3A0 -> sub_4EDEA0` 进入普通图片分支。
- 普通村庄 `sub_4FE260` 的D6传入效果标志1。
- `.eff` 经图片加载器的 pack／cache 门后可能触发不支持扩展名分支（未确认行为，未经运行复核）；不能仅凭EXE中无 `a_ef` 字符串判定不支持该资源。

适配器采用[主线新手引导与配置装备隔离](#kb-02-002)定义的引导阶段外观投影，保留原生加载指令。引导阶段与普通村庄分别使用各自的资源加载路径，状态及外观恢复已纳入构造回归。

## 主教程完成钥匙奖励

本服规则：有效C353首次完成主教程（包括教程内SKIP）时，在保存教程完成、出生点和宠物的同一SQLite事务中给`Characters.CardSummonCount`加19。教程界面的20／19属于本地演示计数，正式余额由持久字段维护。

### 当前奖励事务

- 账号与角色匹配、同时在线，并共同持有活动世界`sessionId`；分派器校验C353完整帧28字节及16字节身份，奖励数量由适配器规则确定。
- 单条UPDATE以更新前`TutorialCompleted=0`为一次性门，增加19并置完成标记。并发、重复提交、重登与花费后重放共用该门；原普通钥匙余额按加法累积，黄金及神秘钥匙沿用独立计数。
- `CardKeyStateVersion=1`与奖励同事务写入，数据库重开沿用普通钥匙语义。余额上限255，首次完成要求原余额至多236；容量或宠物写入失败时回滚完成状态、钥匙、位置和宠物，保留重试条件。
- 现有`TutorialCompleted=1`沿用原领取状态；旧档额外授奖通过独立授权处理。
- C353按请求返回C594，正式C3E9/C3EA与C3E7/C3E8从持久字段返回余额。教程内SKIP提交C353并沿用19奖励；启动器`skip_tutorial`使用独立初始化路径。

### 客户端字段结论

- 教程卡片控制器`sub_872240`在`0x872A8A`将本地`BYTE this+0x370`初始化为19，另一分支`0x872A96`初始化为20，条件为角色信息`WORD +4==1`。
- 演示更新`sub_86F0D0`在`0x86F29D..0x86F2AB`递减该字节，经`0x41267F`推进演示；正式普通配方通过独立的C3ED事务处理。
- `sub_872B40 -> 0x40DDFA -> sub_85E810`将本地计数写入钥匙控件`DWORD +0x10`，正式C3EA使用同一控件设置器和独立余额来源。
- 教程结束／跳过调用点`0x9293B8`、`0x929F5C`、`0x92ECA3`经`0x41AD70 -> sub_92E5D0`构造C353完整帧28字节；`+8..+23`为16字节账号／角色身份，`+24`为宠物上下文，经`0xADA3E0`发送。
- 上述地址所属解包基线SHA-256为`7c782a842e7a3de5eef42865283fb0391d2ba945c3ecad0445c85270bd5703de`；当前安装身份由活动清单登记。

### 正式余额与验证范围

正式一般钥匙由`Characters.CardSummonCount`计数，C3EA完整帧`+9/+10/+11`对应三种钥匙余额。旧完成状态`TutorialCompleted=1`与余额`CardSummonCount=0`可以同时存在，新规则以首次有效完成作为授奖边界。村内`C599 guideId=2`另奖一般钥匙10，归[故事引导](故事引导与推荐人.md#kb-02-003)。

验证覆盖C353分派、C3EA/C3E8余额、四路并发、非法会话、容量与宠物写入回滚、数据库重开、花费后重放、旧档状态保持，以及村内独立+10后总余额29。当前层级为适配器构造与SQLite事务，`runtime_acceptance=false`。
