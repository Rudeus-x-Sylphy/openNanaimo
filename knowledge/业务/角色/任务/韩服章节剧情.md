# 业务／角色／任务／韩服章节剧情

## 范围与结论

韩服客户端同时保留两条不同的任务链：类型1的勋章／成长任务 `71000000..71000012`，以及类型2的章节剧情 `73000000..73000015`。后者包含前四村的16章、52个目标、32段进出章节的对白脚本与4段跨村挑战脚本，章节与挑战分别维护身份。

本页维护资源内容、任务关系、韩服客户端字段消费和CN接入边界。73系列提供完整16章离线目录、待审译文与宿主实现；准备产物保留`activation_allowed=false`，完整流程为`runtime_acceptance=false`，均不代表服务默认关闭。当前CN章节默认开启与推进规则归[章节剧情移植进展](章节剧情移植进展.md)，普通任务归[目录进度与交付事务](目录进度与交付事务.md)。目录准备与既有实现复用见[任务DIY](../../DIY/任务/索引.md)。

## 两条任务链的关系

- 勋章链前12项 `71000000..71000011` 各有 `type8/code0/amount1` 奖励；`71000012` 为独立的师徒成长链尾，不是第13枚勋章。CN终章兑奖与项目奖励见[哈希奥终章礼包](哈希奥终章礼包.md)。
- KR勋章链的序列后继字段最终为0，章节链从Episode1开始，逐项指向下一章，Episode16后继为0。两条链以各自目录后继维护，跨链授予属于独立策略。
- `QS10028` 将12勋章描述为新手任务完成；`GQ` 引导6仍关联兑奖文本10027。章节首次授予、勋章与章节并行资格、原进度策略属于待确定条件。
- 单纯把所有“不出售的任务”追加到现有CN主线，会把两条链混为一条；当前 `QuestCatalog.ComputeMainLine` 的此类选择策略不能原样用于新增章节链。

## 客户端静态消费链

下列地址适用于本页登记SHA-256的KR程序，对应6444条已核对指令；CN字段与控制器在各自主题维护。

| 边界 | 已确认行为 |
|---|---|
| `0x855870` | 加载QT，解析目标与任务；目标定义后部从+0x68起存三组值，首组第三值（目录目标零基字段19）为本样本动作脚本UID；`0x8567EA`将奖励后的序列字段写入任务定义+0x90 |
| `0x483820 → 0x485B70` | C59C任务列表消费。完整帧+212为type2固定记录，+232为type1固定记录，各20字节；分别从+224／+244取任务ID |
| `0x8CDAC0 → 0x856E80` | 按任务ID取得QT定义；`0x8CDB50`消费记录+3的目标索引，调用`0x8CDB00` |
| `0x8CDB00 → 0x857270 → 0x856E30` | 目标数组按8字节项选取；要求索引小于定义+0x7C的目标数，数组指针位于+0x80，再查目标定义。对象+0x24保存任务类型，不能与记录类型字节的偏移混写 |
| `0x7EB3B0` | 遍历活动任务，检查对象+0x24=2、+0x0C=0、目标类型39，并与本地场景匹配，随后`0x7EB555 → 0x93BB20`读取动作脚本；对白按当前任务、场景与脚本共同触发 |
| `0x8E72A0` | 修道僧点击按type2当前目标经`0x857410`核对NPC关联，匹配后`0x8E4760 → 0x93BB20`；不匹配显示普通说明 |
| `0x93BB20` | 加载`action._S1`并按SCRIPT UID构造动作；36个脚本覆盖32段章节对白与4段挑战 |
| `0x7EC0F0 → 0x7EC860 → 0x7EC5A0` | COMPLETE动作进入C5A0发送路径；构造器`0x7EC950`写完整帧长度12、操作码C5A0；WORD+8／+0xA来源于当前任务对象+0x24／+0x18，`0x7EC5F5 → 0x989820(0,frame)`发送 |
| `0x483820 → 0x485B20` | 分派C5A1，读取完整帧DWORD+8，零／非零分流到`0x7EC610`；这里只确认消费与分支，12为该handler可见读取下界，完整长度由独立协议契约确定 |
| `0x483820 → 0x485150` | 分派C5A2，按DWORD+12找任务，WORD+8用于目标索引，WORD+10写状态；满足局部状态后重评剧情。16为该handler可见读取下界，表示该处理器的最低输入长度 |

C59C的252字节框架与两个固定槽位可用于独立任务投影。章节执行仍需定义应答顺序、失败恢复、type40通关条件、目标索引授权与奖励映射，功能归属按实际字段和调用行为确定。

类型读取器为`0x7EB5D0`，调用点为`0x7EB48E`，代码调用者包括`0x7EB3B0`、`0x7EC4E0`、`0x8E51C0`。`0x7EC4E0`的脚本队列接受类型1或39，`0x8E51C0`按类型1更新NPC状态；该局部调用集合覆盖300条一致指令。type40的结算集合、难度与适配器规则属于独立启用条件。

## 移植与验证边界

CN任务链为`0x4D34D0 → 0x419042 → 0x4D5ED0`，支持C59C固定type2记录；该控制器的章节确认扩展需要补齐C5A1/C5A2分支。`0x98EE10`从目标对象+0x68起按五组二元字段读取，KR的三元script字段使用独立映射。CN布局归[窗口协议与客户端消费](窗口协议与客户端消费.md#cn章节接入边界)。

当前CN交付范围为既有任务目录、修道僧中文对白及独立挑战；章节数据和`action._S1`／`NPC._D39`按独立移植契约维护。完整章节契约包含活动任务、进场剧情、玩法目标、离场剧情、单次奖励与下一章。

目录种类、目标顺序、脚本／文本／NPC／奖励编号必须各自映射；QS文本ID与动作SCRIPT UID即使同为10000，也属于不同命名空间。原始CN基线对119个台词ID无冲突，但当前安装QS已有6000..6011；这12条按既有修道僧实现复用，不另行占号或覆盖，具体消费者与复用检查见[任务DIY目录与对白](../../DIY/任务/目录与对白.md#复用既有实现)。保留原有12勋章、师徒链尾、普通卷轴、已兑奖哨兵与已有存档事务。

## 目录交付与验证

离线目录包含16章、52个目标、36个脚本和119条对白的原文与引用关系。中文审核表分别维护107条章节对白、16条章节说明、16条奖励文本、16个标题和52个目标名；12条修道僧对白复用现有本地化所有者。

CN目录格式、任务窗口和跨村策略按对应主题独立维护。目录与本地化状态见[任务DIY](../../DIY/任务/索引.md)，程序身份与验证范围见[章节剧情与跨村门槛验收](../../../工程/验证状态/章节剧情与跨村门槛.md)。

第一村范围为`73000000..73000003`、`75100000..75100012`、SCRIPT10000..10007及既有挑战引用10032。新增QS3000..3026中，19条是正文、4条任务说明、4条奖励说明。SCRIPT10003按QS3006→3007执行，SCRIPT10005按QS3012..3017执行；多说话者和`value/close/face_count`不能折叠。

QS3001的NPC52是在转述尼莫的委托（KR原名플라이），不能把说话者认作尼莫；CNNPC52词条为QS552“伊露卡”。QS3010..3017也不是成长链QS10004的“火焰之雨”教程，不能把71链正文混进73链。人物身份与任务归属分别由对应action/QS字段和任务链定义。当前名称、缺证先祖称呼与奖励ID映射的唯一规则见[术语与奖励本地化](章节剧情移植进展.md#术语与奖励本地化)。
