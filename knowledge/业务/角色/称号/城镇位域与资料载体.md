# 业务／角色／称号／城镇位域与资料载体

## 范围与适用条件

本页维护城镇位域、称号与角色等级载体；结论适用于CN `C36A/112` 与KR `ANS_TOWN_USER_INFO` 两套位域及当前200级城镇构造，未修补旧版本差异按各片段标注。

主题入口：[主题索引](README.md)。

### 城镇称号与角色等级

- 200级兼容将城镇称号设为6位（bit6..11）、等级设为8位（bit12..19），UID保持bit20..31、低6位保持原义；入口使用imm32比较200。
- 托管初始构造、TownTitleProjection增量／广播、原生构造与客户端读取统一使用称号mask=0x3F<<6、等级mask=0xFF<<12，分别保留等级bit12及UID。
- 边界与保位回归覆盖127／128／199／200／201和称号0～255归一化。
- 精确原／新字节、独立代码区、冲突检查、迁移与恢复步骤统一归[客户端二进制补丁](../../../指南/客户端二进制补丁/README.md)。
- 指令隔离验证覆盖200种城镇组合及入口1..255分支。
- 下文CN原布局说明兼容前的字段编码。

- `0x53E0C0` 消费城镇角色控制值：位6..12为地宫称号，位13..19为角色等级，位20..31为场景身份。
- 角色构造经 `0x402432 -> 0x535530` 将称号传入参数 `a16`，经 `0x40B2B2 -> 0x504E40` 写入角色 `+0x31BC` 并选择 `1243 + 称号值` 的资源；`0x40AAF6 -> 0xA72530` 保存称号。
- 独立的等级参数 `a18` 经 `0x40D373 -> 0x505D90` 写入角色 `+0x31BE`，经 `0x40FEE8 -> 0xA72570` 保存等级。
- 适配器共享城镇构造同时写入两个独立字段，并保留构造模式及分配身份。

- 城镇压缩等级的位宽与地区版本必须分开：CN `C36A/112` 完整帧 `DWORD+0x3C` 在 `0x53E138..0x53E182` 解析为 `grade=(v>>6)&0x7F`、`level=(v>>13)&0x7F`、`scene_uid=(v>>20)&0xFFF`（等级右移 `0x53E15A`、掩码 `0x53E15D`）。
- KR对应 `ANS_TOWN_USER_INFO` 处理器 `0x4DEDF0` 在 `0x4DEE68..0x4DEEBC` 改为 `grade=(v>>6)&0x3F`、`level=(v>>12)&0xFF`，UID仍从bit20开始（等级右移 `0x4DEE94`、掩码 `0x4DEE97`）；即称号由7位减为6位，等级由7位扩为8位。
- 已发布旧版本按CN的 `level<<13` 构造，99策略下安全；200级配套托管及原生城镇构造改为 `level<<12`，必须配套CN解析补丁。
- 只放开应答方等级、仍用旧位域会使200被读为72，并可能污染UID最低位。
- 100..127不触及此位宽边界；128..255至少需要配套修改解析与打包。
- 现有称号0..42可装入6位，但不能据此省略其余消费者审计或移植整套KR包布局。
- 以上结论限定于字段布局和隔离位域计算，三位等级界面采用独立验收状态。

### 结算和角色资料结果锚点

- 副本等级和玩家等级相邻但独立。
- `sub_41E0D8 -> sub_A72510` 读取副本等级 `WORD [*(manager+0x5C4)+0]`；`sub_40AAF6 -> sub_A72530` 写入它。
- 玩家等级使用相应的 `+2` 获取/设置对。
- 载体写入包括：271A case30 `+0x0D`；C355 `0x00530F90..0x00530F9B` 从 `+0x24`；CF71 case53105 `0x006F4FC0..0x006F4FCB` 从 `+0x49`；CF0E case53006 `0x006F8938..0x006F8943` 从 `+0x0B`；CF88 case53128 记录 `+0x07`；CF8A case53130 记录 `+0x06`。
- C355 `+0x25` 通过 `sub_40CA04 -> sub_54E410` 写入管理器 `+0x4F70`；其唯一的获取路径 `sub_402BD0 -> sub_540350` 显示/清除对话框52，因此它不是地宫称号状态。

- 标题渲染在 `sub_82E4B0` 处结束：本地等级在 `0x0082E584` 读取，检查过的远程资料提供帧 `+0x29`，`sub_B475A2` 使用常量 `0xC9211C` `interface\%06d-qz_inter_lv_icon%d.im3` 格式化 IMAGE 记录 `1243+grade`；随后的 switch 覆盖等级0..42，使用TEXT键2038..2058/2394..2412。
- 等级24图像1267是R8；文本2397是马斯特洛克。
- grade25..42的解码文本为空，记录1283..1285未包含在两个检查的界面包中。
- 选定阶段的等级是独立DWORD `+0x1E534`；CF6C/CF77/CF87不传输它，因此持久奖励映射属于适配器。
- 新闭环将1～4村 `ep0..15/dg2/st1` 映射grade1..16，将5村通信元组 `ep100/dg0..7/st1` 映射grade17..24；难度不参与。
- 此前ep15/dg2/st0写grade23的运行样本现证明是奖励策略错误，不是合法里程碑。
- CF16行 `+0x20` 是角色等级，`+0x22` 是精确称号grade，两者不可分桶混写。
