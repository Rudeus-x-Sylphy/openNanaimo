# 业务／角色／等级经验／协议载体／权威状态与对外字段

## 范围与适用条件

本页维护经验权威状态与对外字段；结论适用于CurveVersion3、内部快照版本4及1..200级区间，CN显示载体为级内u32投影。

主题入口：[主题索引](索引.md)。

### 200级经验状态与内部版本边界

- 人物内部权威字段为真实64位累计、等级和CurveVersion3；读取时校验曲线一致性。
- `NativeDungeonState`采用库存结构版本4、payload5704/full5712，联合校验版本、长度和曲线。
- CurveVersion为3，F10B为v3、payload48/full56。
- 精确布局见[桥接布局](../../../../基础/桥接布局.md)；64位累计使用独立尾部字段，宠物经验沿用既有契约。
- 运行产物身份归[200级成套发布与数据版本](../持久化与离线迁移.md#kb-09-007-2)。

- C355、CF71、C57C、CF88以及任务C59A、竞技/娱乐室结果统一投影为级内DWORD。
- CF88每条记录按本人状态投影，added是独立真实奖励；不得把级内当前值覆盖数据库。
- 完整构造清单见[对外经验载体扫描及落点](#df-05-003)，迁移流程见[曲线迁移约定](../持久化与离线迁移.md#df-05-005)。
- 200级仍有真实的最后一级经验条，完整区间／停止奖励策略归[玩家累计经验范围与原生曲线边界](../曲线与经验奖励.md#kb-07-004)；跨级动画、满级经验条、页面缓存及重登显示已获用户验收确认，范围与受测版本待补录状态见[人物200级成长验收](../../../../工程/验证状态/地宫与成长验收.md#人物200级成长验收)。此画面确认不额外证明CF71继承lower0等内部字段消费链。

本主题按资料载体和交易机制维护当前协议、适配器策略、持久化边界与验证范围。

### 经验载体元组与进阶记录读取

- 玩家等级／经验使用按角色持久化的进阶记录。
- 原生配置参数 `level` 仅初始化缺失的 `level_progress_state_v1_<name-hex>.dat` 数据库记录，已有进度不会因登录或资料应用而重置。
- 登录／房间资料应用时重新加载该记录，击杀及CF88结算各自提交后更新当前连接等级（策略见[玩家累计经验范围与原生曲线边界](../曲线与经验奖励.md#kb-07-004)）。
- C355／CF71构造在校验和计算前统一经验载体，沿用既有发送边界、进阶记录、阈值曲线和结算升级标志。
- HP/MP保持独立的u16资源，并叠加选中宠物宝石增益；适配器实际升级按[人物成长策略](../人物成长与同步.md#kb-04-005-1)增加基础上限，客户端消费适配器提交的成长值。
- 攻击／防御策略见[人物攻击与防御](../../../地宫/伤害与目标/攻击与防御.md#kb-04-005-2)，选中宠物／装备属性保持独立。

| 资料元组 | 当前经验载体约定 |
|---|---|
| 登录 271A/68 | 字节+0x0C等级；无经验三元组 |
| 村庄/频道 C354/8 -> C355/728 | 字节+0x23等级；双字+0x28级内当前经验，+0x2C本级下界0，+0x30本级经验跨度 |
| 房间/下一阶段 CF70/12 -> CF71/184 | 字节+0x48等级；双字+0x40本级经验跨度，+0x44级内当前经验。包内无下界字段，沿用C355/C57C/CF88的本级下界0 |
| 战斗首次终结击杀 -> C57C/52 | 完整帧DWORD+0x0C级内当前经验、+0x10本级下界0、+0x14本级经验跨度；WORD+0x18/+0x1A当前HP/MP，BYTE+0x1C等级；静态及静默选择字段归[玩家经验载体和HUD静态调用链闭合](客户端经验与HUD消费链.md#kb-08-016) |
| 战斗成长 -> C60D/12 | 独立于全局经验的角色定向等级通知，直接更新现有角色；字段与本地分支兼容修复归[玩家经验载体和HUD静态调用链闭合](客户端经验与HUD消费链.md#kb-08-016) |
| 结算 CF87 -> CF88 | 每条记录按本人状态投影级内经验三元组；独立新增经验值、升级标志和去重规则见[玩家累计经验范围与原生曲线边界](../曲线与经验奖励.md#kb-07-004) |

- C355不采用C57C在+0x0C/+0x10/+0x14存储经验的布局，不能混用。
- 本地和远程CF71序列化的是角色应用的资料上下文：普通名单和后加入名单的调用者在构造前应用角色资料，随后恢复接收方上下文。
- 经验记录不能以接收方套接字或截断的显示名称为键。
- 静态调用链见[玩家经验载体和HUD静态调用链闭合](客户端经验与HUD消费链.md#kb-08-016)；历史本地自测覆盖等级1..99序列化、双资料隔离、村庄／下一阶段／重新登录连续性，以及已确认击杀／终局事务触发的经验同步；该历史范围不等于当前等级上限。
- 验证范围为资料构造及状态连续性，客户端渲染按对应场景独立验收。

- 历史字段说明曾把C355／CF71的当前经验写成累计值、把下界／下一阈值写成累计阈值，并把C57C的HP/MP写成有效上限；这些解释已由上表的当前规则替代。
- 当前显示值来自级内投影，C57C资源字段来自实时当前值；升级补满后当前值可能等于有效上限，但字段语义仍为当前值。
- 源码依据为`release/components/protocol/experience_carriers.inc`的`release_normalize_experience_carrier`与`release/components/game_session/managed_bridge.inc`的C57C构造。

- 当前CN人物显示载体使用u32级内经验；适配器保留64位累计，并统一投影为本级下界0、级内当前值及本级跨度。
- 满级仍使用第200级真实区间。
- 此处元组、帧长和偏移保持原契约；曲线与边界归[玩家累计经验范围与原生曲线边界](../曲线与经验奖励.md#kb-07-004)，数值消费路径及人物／PET成长字段归[玩家经验载体和HUD静态调用链闭合](客户端经验与HUD消费链.md#kb-08-016)。

- 历史上，99级上限属于适配器策略，不能解释为客户端显示字段只有两位；当时记录的“99级规则未变、尚无三位等级运行验收”仅描述旧版本状态。
- 当前人物上限为200级，托管`CharacterProgression.MaximumLevel`与原生`PROGRESSION_MAX_LEVEL`均为200。
- 城镇压缩等级与主要BYTE载体的不同位宽、CN/KR差异及扩展范围由[玩家等级上限、三位显示与入口资格](../客户端版本与显示.md#kb-08-020-1)统一维护；200级的原客户端运行验收范围以[验证状态](../../../../工程/验证状态.md)为准，不能由旧1..99构造测试推断。

- 原生进阶记录通过数据库中的`.new`/`.bak`键事务替换。
- 历史说明记录过`version=1`、`level`和累计`exp_total`，以及曲线不一致时回退到该等级下限种子的旧规则；这不再是当前读取规则。
- 当前记录名仍保留`level_progress_state_v1_<name-hex>.dat`，载荷实际写入`version=3`、`curve_version=3`、`level`和64位累计`exp_total`，校验版本、曲线、1..200等级及累计经验对应等级。
- 主记录存在但无效时立即拒绝启动，不尝试以备份或配置种子覆盖；主记录缺失时可恢复有效备份，备份存在但无效时拒绝并要求离线迁移；仅当主记录和备份均不存在时，才按配置等级的下限初始化种子。
- 角色键使用配置名称字节的大写十六进制编码，与其他按角色保存的记录一致。
- 源码依据为`release/components/dungeon_progression/progression_runtime.inc`的`progression_progression_parse_path`、`progression_progression_save_name`和`progression_progression_read_name`；数值策略和CF88字段见[玩家累计经验范围与原生曲线边界](../曲线与经验奖励.md#kb-07-004)。

### 对外经验载体扫描及落点

各载体保持原帧长、校验、请求／周期条件及属性布局。

| 载体 | 生产构造/修正入口 | 32位显示字段 |
|---|---|---|
| C355/728 | `NetworkAdapterService.BuildLoadNecessityPayload`；`protocol/experience_carriers.inc` | 帧+0x28/+0x2C/+0x30 |
| CF71/184 | `DungeonProtocol.BuildRoomMember`；`protocol/experience_carriers.inc` | 帧+0x40 next、+0x44 当前值；lower须继承0 |
| C57C/52 | `game_session/managed_bridge.inc` 的F10B提交 | 帧+0x0C/+0x10/+0x14 |
| CF88 | `BuildDungeonEndGamePayload`、`PatchNativeCharacterProgressionFrame`、原生 `progression_progression_fill_record` | 每条记录+0x10/+0x14/+0x18；帧+0x0C起，步长0x34 |
| C59A任务结果 | `BuildTaskCompletionResultPayload` | payload+16/+20/+24 |
| 竞技结果 | `BuildArenaPvpResultRecord` | 统一投影后交竞技序列化器 |
| 娱乐室结果 | `NetworkAdapterService.Entertainment`结算记录 | 各成员按各自角色统一投影 |

CF88 record+0x0C仍为本次真实奖励。宽内部快照的差额只有合法旧奖励回放缺失显式奖励字段时才参与奖励计算；普通检查点的差额不授予经验、不窄化为u32。

C36A/112托管及原生构造共同改为：低6位不变，称号6位、等级8位、UID12位。校验称号与UID范围，不截断UID。不同成员使用自己的名字/UID/人物状态。
