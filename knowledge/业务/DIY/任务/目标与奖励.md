# DIY／任务／目标与奖励

## 范围与适用条件

本页整理任务DIY的条件选择、状态投影、结算归属和单次领奖。普通任务规则归[目录进度与交付事务](../../角色/任务/目录进度与交付事务.md)，章节的精确状态及持久字段归[章节剧情](../../角色/任务/章节剧情移植进展.md)。本页用现行实现说明可复用的设计约束。

## 条件模型选择

| 条件类别 | 可复用类型或机制 | 判定时机与数据 |
|---|---|---|
| 普通／多次通关 | 类型2／20 | 对应地宫的已提交成功结算及逐目标累计。 |
| 组队、单人、指定宠物或BOSS | 类型9／25 | 本轮结算中的队伍、宠物与BOSS条件。 |
| 限制条件 | 类型21／22／23 | 本轮`Charged`、`ItemUsed`、`Revived`状态。 |
| 家具、卡片及宠物条件 | 类型5／37 | 当前家具、库存、卡片或合成结果及目标定义。 |
| 收徒 | 类型11 | 有效关系中按学生角色去重计数，包含在读及已毕业关系。 |
| 怪物命中／技能成功 | 类型26／35 | QT目标代码、成功事件及类型35的等级门控。 |
| 章节战斗 | type40与章节策略 | 当前章节入口激活后的本章超级BOSS成功结算。 |
| 章节修道僧 | 当前目标修订号与成功凭据 | 本章步骤激活后、对应村庄的新成功结算。 |

类型14的语义保留待确定；新增DIY条件应绑定明确的判定器和可提交事件。实时拥有条件、累计次数、单轮限制和任务激活后的事件分别定义，任务说明须准确表达其实际满足方式。

## 进度字段分工

`State3`表示当前QT目标的零基索引，始终在目标数组范围内，全部完成时保留最后一个有效索引。`Progress1`表示可提交状态。`Progress3`按任务类型解释：普通多目标任务保存完成累计数，收徒任务保存受目标上限约束的有效学生数，章节保存剧情阶段。

多目标任务按目录顺序投影首个未完成目标，后面目标提前满足时保留其账本，再继续显示最早缺项。收徒实例“老师的感恩”要求两名有效学生，一名显示1/2，两名达到2/2；已解除关系按当前关系状态评估。各条件与客户端字段的完整定义见[普通任务进度](../../角色/任务/目录进度与交付事务.md#kb-03-048)。

章节任务槽由章节状态投影：普通章索引上限2，修道僧章上限3，`Progress1 = RewardPending && !Finished`。对白的阶段号、正文段号、正文页号及QT当前目标分别维护。

## 场景与战斗条件

当前章节房间身份为`(townId, page, episode)`；页面按`31 + 21 * ((episode - 1) % 4)`计算，村庄与目录绑定。四村各自拥有31／52／73／94，战斗episode输入使用零基编号，章节展示使用1～16。

| 持久阶段 | 满足事件 | 结果 |
|---|---|---|
| 0：等待入口 | 在线角色进入当前章节所属村庄及房间 | 阶段转1，任务槽刷新并选择入口对白。 |
| 1：等待战斗／返场 | 可信结算匹配本章，记录对应位 | 保存普通位1／2／4与超级BOSS位8；战斗门槛为`(ClearMask & 8) == 8`。 |
| 1且BOSS位已满足 | 返回本章所属房间 | 阶段转2并选择出口；普通章设置`RewardPending`。 |
| 2：修道僧章出口已确认 | 随后的所属村庄事件 | 阶段转3，激活本章修道僧步骤。 |
| 3：等待本村修道僧 | 当前步骤所属的新成功结算 | 保存章节完成凭据并设置`RewardPending`。 |
| 待领奖 | 玩家提交当前章且审核、容量、身份及修订号有效 | 奖励与下一章状态共同提交。 |

普通地宫位保存独立历史，章节战斗门槛以超级BOSS位8为准。客户端退出对白窗口与房间事件分别管理，当前持久阶段由房间事件确认。逐页票据机制单独绑定任务、修订号、场景代次和会话，战斗票据另绑定战斗代次、episode和dungeon。

## 修道僧目标

第四／八／十二／十六章采用任务作用域完成凭据。凭据按角色／章节保存`ObjectiveRevision`、`SessionId`和`SettlementId`，与本轮挑战成功提交处于同一事务。创建时要求当前阶段3、BOSS位8已满足、章节尚在进行且对应村庄匹配。

确认时联合核对本步骤修订号、成功收据和永久挑战通关位。首次确认将`RewardPending`置为真并增加修订号，后续查询和重登沿用已提交凭据。激活前胜利、其他村庄成绩和失败结果继续由独立挑战账本记录，章节资格由当前步骤的有效成功凭据确定。

永久通关位负责独立挑战及可选跨村授权，排名账本负责历史成绩，章节凭据负责线性主线完成。三个用途各有独立所有者。详细持久约束归[修道僧目标与任务槽](../../角色/任务/章节剧情移植进展.md#修道僧目标与任务槽)。

## 奖励事务

章节领奖使用`C599`的type2、runtime0和当前章节身份，提交前重新校验账号、角色、在线会话、任务状态及修订号。玩家领取与目标满足分别发生，成功后刷新下一章任务槽；第16章提交终章标记并释放type2槽。

奖励审核绑定当前章节包SHA-256、任务ID、原始奖励顺序及三元组、目录期限和审核编号。当前16章模板均从`approved=false`开始；目录映射、任务完成和审核批准是三个独立条件。章节包任一字节变更后，授权按新包身份重新核对。

整包事务同时处理金币、经验、库存／卡片／宠物、快捷栏、领取账本和下一章。容量、数量、物品兼容、数值上限及后续写入共同决定提交结果，失败时整包回滚。经验按当前成长曲线校验，满级溢出按容量失败处理。

领取账本以角色／任务为唯一键，保存修订号、奖励摘要和审核标识。相同收据重试沿用已领取结果，既有领取记录保证单次发奖。宿主独立会话接口的领奖票据以任务修订号、出口场景和场景代次限定有效期，消费后按当前状态重新取得；当前客户端领取使用上述C599入口。

| 返回分类 | 当前处理 |
|---|---|
| `CapacityExceeded` | 结果3，客户端容量提示。 |
| `ReviewRequired`及状态／身份拒绝 | 结果1，保留任务进度；审核配置原因由同次响应的系统消息说明。 |
| 已提交的同一领取 | 沿用领取结果，奖励保持单次发放。 |

结果字段与客户端消费归[章节领奖失败原因](../../角色/任务/窗口协议与客户端消费.md#章节领奖失败原因)。

## 性别与期限

奖励名称以实际ID、数量、种类和期限为准。男女映射保持种类、数量、分类与期限，双向转换具幂等性。当前8章有CN奖励映射，男女各16章构成32例事务矩阵。

章节套装身份、等级和逐章期限统一归[奖励本地化](../../角色/任务/章节剧情移植进展.md#术语与奖励本地化)：第五章为按性别发放的24级永久海军装，后期提督奖励独立保留。同款限时装升级永久沿用同一库存行及数量1，已有永久装备与旧零期限服装保留既有权益，重复领取不重复发放。目录的`HasExpiry=true/DurationDays=0`表示永久配置，持久永久值为`PermanentExpiration=2100123100`；更换任务奖励定义不自动回填历史领取或修改既有角色库存。

第四章男女秘密关卡免费券期限1天，第六章炎炎火花期限15天；第九章扩容券／自由魔法钥匙的30／1天为使用后的效果期限。第七章复活彩蛋奖励数量为1个、每个可用5次。道具数量、实例期限、使用次数及使用后效果分别表达，具体ID由[奖励本地化](../../角色/任务/章节剧情移植进展.md#术语与奖励本地化)维护。

## 存档与重复操作

当前未领奖章的阶段2／3若缺BOSS位8，恢复为阶段1、清除待领奖并增加修订号，保留普通位。已具BOSS位且缺本步骤修道僧凭据时恢复等待资格；重复读取保持修订号稳定，历史领取和终章记录保留。

离线检查点按指定角色与当前或更早章节处理，超级BOSS检查点为阶段1、mask8、等待出口。该角色当前及后续章节凭据按重置范围清理，其他角色、库存、历史成绩和领取账本保留。已领取章节再次满足全部目标后，只有更新修订号及相同奖励摘要可推进下一章，奖励仍以原领取记录为准。

旧表迁移与合法状态修复使用精确结构及状态约束。未知结构或损坏状态进入拒绝处理；任务修订号、结算归属与领取摘要共同限定恢复边界。
