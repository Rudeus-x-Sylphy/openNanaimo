# 业务／DIY／子弹／验证与伤害边界

## 范围与适用条件

本页维护 DIY 子弹的验证层次与伤害归属边界；接入顺序与资源依赖见[接入与资源链](接入与资源链.md)，目录与本地配置见[目录与配置](配置与兼容策略.md)。各层次只证明其登记范围，低层级通过不能替代客户端实机验收。

## 验证层次

| 层次 | 必须核验 | 现有证据与边界 |
|---|---|---|
| 静态资源 | 目录唯一文件名、预览闭包、PON／EFF 引用、行结构、图像帧、输入／目标内容身份 | `test_catalog_preview_closure`、`test_procedural_frames_and_im3_roundtrip`；它们不证明每个目录项的完整轨迹 |
| 配置与 GUI | 启用／关闭、反向两值、别名往返、保存时客户端已退出、列表与预览布局 | `SelfTestProjectile` 与 `BrowserLayoutTests`；代表图像不模拟 PON |
| 安装事务 | 原字节／已安装字节识别、精确旧版升级、幂等、未知同名内容拒绝覆盖、源保留、失败恢复、位点卸载 | `InstallerTests`；实际命令和安装预检范围见[位点与安装](../../../工程/子弹DIY兼容/位点与安装.md) |
| 隔离执行 | 预载、90 ms 节流、松键、对象重建、所有资源的 side 参数、精确别名／行门控、管理对象边界、绘制副本 | `BridgeTests`；WinAPI、原生工厂、getter／setter 与浮点转整数存在模型边界 |
| 效果求值隔离 | 原生 EFF 求值器 `0xAB5B30` 的 3 行 × 200 个时间点；索引 11（从 0 计数）的选帧轨道 `floor(t/4)%16`，alpha 为 255／0／0 | 对应测试需要受测客户端原生指令；不等于完整客户端连续游玩 |
| 客户端实机 | 出生位置、移动方向、完整轨迹、碰撞、伤害、死亡停射、第二张地图、复合效果、联机双方可见性 | 单独登记产物身份、配置、资源、场景与观察；子弹清单与安装配方（`manifest/projectile_diy_patch.json`、启动器内嵌报告）中的 `runtime_acceptance=false` 不构成通过 |

DIY／篮球子弹已有独立用户验收确认，实际使用配置的画面、轨迹、碰撞、伤害及联机范围与受测版本待补录状态见[可选子弹实机边界](../../../工程/验证状态/地宫与成长验收.md#kb-09-040-4)。该确认不代替全部PON目录项或新组合的逐项验证，也不补造owner／source的数值语义。

现有脚本为 test_projectile_diy.py（`scripts/test_projectile_diy.py`）。依赖与前提：

- 构建依赖 Keystone。
- 图像依赖 Pillow。
- x86 隔离执行依赖 Unicorn。
- GUI 专项依赖 Windows Forms。
- 原生 EFF 与安装实例还需要受测客户端。

跳过的专项应记录跳过条件，不能计为通过。历史覆盖见[资源与可选子弹](../../../工程/历史验证/既有记录/资源与可选子弹.md#kb-09-040-2)；当前验收边界见[地宫与成长验收](../../../工程/验证状态/地宫与成长验收.md#kb-09-040-4)。

## 伤害归属

DIY 桥接负责客户端预载与发射，安装器没有新增通用伤害协议，也没有修改角色数据库。外观、PON 攻击候选与适配器最终伤害应分别登记。

| 路径 | 当前代码证据 | 可得出的结论 |
|---|---|---|
| 托管地宫普通目标 `D00D` | NetworkAdapterService.cs（`managed/Services/NetworkAdapterService.cs`） 的 `case 0xD00D`：目标运行时 UID 经地宫战斗目录解析，基础攻击来自宠物成长／当前技能上下文 | PON 本地类型没有随该上报序列化；不能把 owner 1279 或候选 1845 直接解释为此路径的固定伤害 |
| 发布版 C 子弹技能归属 | projectile_runtime.inc（`release/components/combat_attribution/projectile_runtime.inc`）：技能码 `52000000..52000007`、等级 1..5 映射 owner `505..544`，8 秒窗口绑定房间／战斗 epoch | 这是本地适配器技能归属策略；篮球 owner 1279 不在该技能映射内，不会仅凭名称自动成为已验证技能子弹 |
| 发布版 C 伤害候选 | 同文件严格 source 分支及受功能开关控制的 one-past／effective 分支 | PON 候选、已验证技能归属与局部策略有不同来源；不能把这些分支归并成统一原生公式 |

每个 DIY 实机验收应记录实际运行入口（托管适配器或发布版 C 原生兼容路径）、请求类型、owner／source 可观察值、目标身份和最终 HP 变化。更换外观或配置只证明接入客户端资源；实际联机同步与伤害归属需以对应运行路径的数据确认。
