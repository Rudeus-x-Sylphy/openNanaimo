# DIY／地宫／源码与验证

本页列出NPC和地宫DIY的实际源码入口及检查层级。命令在仓库根目录执行，`CLIENT`、`KR_SOURCE`、`BUILD_DIR`需替换为自己的匹配输入和全新输出目录。

资源转换与战斗数据生成均需PyCryptodome；`generate_monk_combat.py`经`lumineos_codec.py`导入AES，未安装该依赖时连`--help`也会在参数解析前失败。纯资源安装／校验／回滚复用标准库事务代码；依赖与构建环境见[运行依赖](../../../指南/运行依赖.md)。

## 源码导航

| 工作 | 源码／清单 | 行为与边界 |
|---|---|---|
| L7／L8资源转换与事务 | `scripts/port_lumineos_resources.py`、`manifest/lumineos_resource_port.json` | `build/apply/verify/rollback`；build需要PyCryptodome，安装／回滚使用标准库。 |
| L8战斗目录 | `scripts/generate_lumineos_combat.py` | 读取已校验资源，生成ep23两阶段数据与输入／输出摘要。 |
| 四关资源闭包 | `scripts/prepare_monk_challenges.py`、`manifest/monk_challenge_resources.json` | 设置四关专用配方、schema和事务marker，再复用资源生成／安装。 |
| 四关战斗目录 | `scripts/generate_monk_combat.py`、`manifest/monk_challenge_combat.json` | 默认只处理第一关；`--all-challenges`处理完整四关。 |
| NPC场景与图文 | `scripts/prepare_monk_dialogue.py`、`manifest/monk_dialogue_resources.json` | 四村场景资源独立事务；场景配方含专用EFF／IM3，共37项；代码与资源配方分别验证。 |
| 挑战学分背景 | `scripts/monk_ranking_resources.py` | 核验原始位图／EFF摘要后派生四行单格背景，普通与秘密计分板使用各自背景。 |
| CN对白与结果控制器 | `scripts/monk_dialogue_compat.py` | 生成CN代码字节、场景资格、按下沿、窗口、立绘、来源与结果反馈。 |
| 文案 | `manifest/monk_localization.json` | 名称、村庄、关卡、BOSS名、入口及胜败文本的共同来源。 |
| 资格与协议 | `MonkChallengePolicy.cs`、`NetworkAdapterService.NativeDungeon.cs` | 单人、精确元组、来源页面、合法难度、加载／结算／重试门禁。 |
| 独立进度 | `DatabaseService.MonkChallenges.cs` | 角色四位通关掩码、会话／结算ID唯一收据及四关单槽最佳分／评级，旧表事务迁移、非零难度与陈旧结算拒绝，同事务持久化。 |

## 构造命令与输出选择

```powershell
python scripts/prepare_monk_challenges.py build --source KR_SOURCE --client CLIENT --output BUILD_DIR
python scripts/generate_monk_combat.py --client CLIENT --output build/diy-monk-all --all-challenges
```

四关战斗生成器要求输出为仓库`build/`下的全新目录，以隔离生成。输出有`baseline/`及`episode-24/`～`episode-27/`；最终完整数据集位于`episode-27/`，不能把各关中间结果分别覆盖正式目录。`--source-root`可提供匹配基线；`--manifest`只允许写入与所选范围匹配的现有manifest目标，审查后再更新发布清单。

上述命令是资源／数据构造入口。客户端代码、资源事务和运行包部署完整顺序见[四村对白安装](../../../指南/客户端二进制补丁/修道僧四村对白安装.md)及[L7／L8资源移植](../../../指南/L7-L8资源移植.md)。

## 检查覆盖

| 检查层级 | 现有入口 | 证明范围 |
|---|---|---|
| 场景／交互构造 | `test_monk_entry.py`、`test_monk_dialogue_resources.py`、`test_monk_dialogue_compat.py`、`test_monk_portrait.py`、`test_monk_result_controls.py`、`test_monk_ranking.py` | 格式、代码字节、位置／足点／分页／立绘及结果控件构造。 |
| 四关资源与战斗 | `test_monk_challenges.py`、`test_monk_combat.py`、`test_monk_native.py`、`test_monk_launcher_resources.py` | 四关闭包、生成目录、原生资源身份、启动器约定与部署一致性。 |
| 历史入口迁移 | `test_monk_village_entries.py`、`test_monk_village_compat.py` | 第五村旧入口身份、精确迁移与现行道路保留。 |
| L7／L8转换与部署 | `test_lumineos_resource_port.py`、`test_lumineos_combat.py`、`test_deploy_lumineos_release.py` | 合成事务及可用真实输入上的转换、数据和部署；真实资源缺失的条件跳过要单独登记。 |
| 托管业务 | `tests/MonkChallengeRegression`及地宫导航／迁移回归 | 生产资格、单人／来源约束、事务、幂等、陈旧周期和拒绝路径。 |
| 原客户端验收 | [修道僧挑战验收](../../../工程/验证状态/修道僧挑战验收.md)、[地宫与成长验收](../../../工程/验证状态/地宫与成长验收.md) | 实际画面、声音、输入、BOSS行为、完整胜败／重试／返城和持久恢复。 |

既有清单的客户端验收字段分别登记：修道僧本地化、战斗与资源清单（如`manifest/monk_localization.json`、`manifest/monk_challenge_resources.json`、`manifest/monk_combat.json`）使用`runtime_accepted=false`，而`manifest/monk_dialogue_resources.json`等场景配方使用`runtime_acceptance=false`；两处字段名分属不同清单，须按各自清单读取，不互相替代。代码、事务和主机构造检查本身不能证明客户端完整游玩；修道僧入口、四关挑战与排名现已有独立用户确认，L7／L8也已有用户确认，具体范围及受测版本待补录状态见上表验收入口，不自动改写原清单字段。

具体专项执行命令见[地宫专项](../../../指南/构建与验证/地宫专项.md)。返回[地宫DIY索引](索引.md)。
