# DIY／地宫／资源格式与闭包

资源闭包从关卡根文件向显式依赖递归展开，再按已核对的字段模型转换、重命名和校验。新增地图、怪物或子弹时，需要审查其所在关卡的完整引用关系。

## 文件职责与转换边界

| 格式 | 用途 | 接入校验 |
|---|---|---|
| SSTG | 场景根、身份、音乐、怪物／BOSS与选择槽引用 | 核对内部四元组、所有实际槽及每槽预加载列表；文件名不自动决定内部身份。 |
| SMMO | 所选槽的目标放置 | 与槽独立选择器域、资源UID及运行UID对应；每次只消费一份实际列表。 |
| SM2／IM3 | 地图、碰撞、背景及图像 | 校验地图图层与图块引用；保留已确认的固定碰撞图块依赖。 |
| MMO | 怪物、附件、变形目标及动作引用 | 韩服300→CN200按字段模型转换；区分KIND、HP、关联行、计分和终结掉落字段。 |
| BMO | BOSS模式、子对象（`child`）与组件资源 | 模式／子对象／组件逐项生成；支持范围以各样例已核对的布局为准。 |
| PON | 弹药、归属字段`owner`、轨迹、行攻击及嵌套引用 | 韩服108→CN106转换后核对`owner`与攻击数组；同一归属字段对应的不同向量要保留歧义状态。 |
| CRS／EFF | 几何、轨道、效果及图像引用 | 只对已解析字段作转换；任意CRS几何或隐式依赖另行验证。 |
| OGG／WAV | 场景音乐、BOSS音乐和动作音效 | 使用登记路径及原字节，随所属资源闭包安装、核验和恢复。 |
| 文本／UI | 本地化、创建图、结果与地图预览 | 核对GBK编码、文本ID、episode偏移规则及图片格式／尺寸。 |

## 修道僧闭包的实际处理

1. `prepare_monk_resources.py::closure`从`hu_ep000..003.sstg`逐关收集引用；`reference_overrides`解析已登记的共用／第三关依赖。
2. `_plan_stage`改写资源身份至`0/24..27/0/0`，同步所有固定名称字段；`renames`把冲突共用MMO独立命名为`monk_cloud_obj_00.mmo`、`monk_ep21_dg00_obj_sq_off_00.mmo`及其对应引用。
3. `plan`合并四关输出，同一路径不同字节即拒绝；重新核对展开后的文件列表与`preserve_cn`清单，不能以某个关卡的局部清单覆盖其他关卡共享文件。
4. `generate_monk_combat.py`将资源变为每槽目标、预加载、BOSS组件、PON攻击、接触伤害、场景危险和计分数据；`--all-challenges`按24～27依次累积，最终发布最后一关输出目录中的完整集合。

当前`manifest/monk_challenge_resources.json`共有1,154项，包含4个SSTG、4个SMMO、25个SM2、4个BMO、115个MMO、68个PON、142个CRS、282个EFF、486个IM3、7个OGG、13个WAV和4项文本／配置；这是当前清单的快照，不是新增DIY的固定配额。NPC／立绘／挑战UI的37项另属场景事务。
