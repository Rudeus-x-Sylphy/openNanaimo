### 家具Index兼容入口与工作缓冲区

家具点击使用本地 Index 兼容入口 `0x41235F → 0x5CEFE0`；重定向以目标PE布局及站点字节匹配为前提，由启动器幂等应用。原生兼容构造器保持共享4096字节工作缓冲区约定，通信长度按各接口独立校验。完整适配器的运行期布局由数据库事务维护，既有文件载体的格式约束归入启动兼容层。

### C409库存请求和C40A模式分派

- C409 构造函数 `0x566300`；房间/内部发送 `0x595040/0x563330 -> thunk 0x4160EA`。
- 普通背包发送完成为 C430 完成 `0x804999 -> thunk0x4114BE -> sub_7F4690`；在 `0x7F46C4` 它写入 DWORD+8=10，然后是 `0x7F46D7 -> sub_ADA3E0(0,packet)`。
- 构造函数写入 WORD+4=12 和 WORD+6=C409。
- Inventory+0x9A 是请求完成门控条件。

- C40A 在各场景中使用独立处理函数，case50186 分派点如下：

| 场景 | 处理函数 | case50186 分派点／调用链 |
|---|---|---|
| 村庄 | `sub_531BD0` | `0x534BA9`；调用 `0x534BB6 -> thunk0x41A663 -> sub_541B30` |
| 公寓场景 | `sub_59F660` | `0x5A2BB8` |
| 内部控制器 | `0x561070` | 未记录 case50186 分派点 |
| 普通库存 | `sub_8005F0` | `0x8049A3` |
| 特殊列表 | `0x5D2610` 接受30、`0x5D90C0` 明确请求30 | 未记录 case50186 分派点 |
- 正常完成时，库存+0x9A 写入 `0x805300`；BYTE+10==6 时额外读取 DWORD+0x400是 `0x804A1E`（长度与字段见[家具库存协议](库存布局与期限.md#kb-03-039-1)）。

### 家具Index、布局提交与C393快照

- C40B 构造函数 `0x5B2630` 由 CRoomState 构造函数 `0x58DC40` 包含；buy 发送 `0x5949F0`；C40C 情况50188 通过 `0x40CF4F -> 0x5AA7B0`。

- 构造函数 C411 `0x5B2960`；解析/构建器 `0x593E10 -> thunk 0x41A0C3`；C412 情况50194 在 `0x59F660`。

- C423 构造函数 `0x54D960`；首次请求 `0x5A8D30 -> thunk 0x403846`；C424 情况50212 在 `0x59F660`，最高消耗字节+0x413。

公寓与普通村庄按各自控制器限定数据包处理范围，字段布局、实例访问和菜单调用分别校验。

- 家具实例写入链：房间C40A调用点0x5A3101 -> thunk0x41C251 ->0x5C65D0(code,TakeOn,Index)；在0x5C67A2及十个类别分支中，经0x405E5C ->0x5CEFC0，在0x5CEFCD处写入node+0x33C。
- 物品代码独立位于node+0x338（设置函数0x5CF470／读取函数0x5CF490）。
- 已有Index读取链0x41DB6F ->0x5CEFE0在0x5CEFEA读取+0x33C。

- 选中项0x5C90D0 使用控制器+0x3DC 作为选定索引。
- 对0x41235F 的十五次比较调用分别对应0x5C9B89/0x5C9C33/0x5C9CF8/0x5C9DC6/0x5C9E94/0x5C9F62/0x5CA030/0x5CA929/0x5CABA0/0x5CAE2E/0x5CB095/0x5CB30C/0x5CB583/0x5CB7FA/0x5CBA61；兄弟楼层/墙壁比较已经使用了原生索引获取器。
- 选择完成0x413C9B ->0x5C6130 将上/下索引列表排队；C411 是稍后的显式提交，而不是家具点击的先决条件。

- 家具Index读取链为 `0x41235F → 0x5CE700 → 0x100F646 → 0x1011A51`。
- 映射快照头指针位于 `0x16A3E80`，查找读取 `[0x16A3E84]` 的4字节内容；该读取边界对应访问异常0xC0000005、模块偏移0x00C11A51。
- Index访问先于适配器行字段消费，C411提交位于家具选择之后。
- 当前家具兼容入口直接读取对象Index，应用步骤归入客户端兼容文档。

- 相关函数区间为 `0x5CE700`、`0x100F646`、`0x1010140`、`0x1010850`、`0x10112D0`、`0x1011A30`、`0x1011A40`、`0x1011F70`。
- 启动器按PE结构与精确站点幂等应用五字节Index重定向；家具显示、选取与保存按完整客户端场景验收。

- C392构造函数0x5B2810／跳板0x411B8F写入12/C392。
- 初始化发送点0x590011和控制器请求0x592099写入info1000，在0x5920B7经0xADA3E0发送。
- C393 case50067位于0x59F660中，从0x5A0FF0开始：数量WORD+8、info WORD+10、普通记录+12／步长12；在0x5A1663..0x5A1672只比较6000，相等才进入0x5A167A续传分支，否则结束。
- 故0和2000都不会继续请求，2000是当前适配器选择的结束状态值，客户端也接受其他非6000值；记录消费由count决定，与固定1020字节长度无关。
- 历史结论：“固定1020字节导致点击异常”的说法已由上述C393消费链否定——续传分支只比较info值（`0x5A1663..0x5A1672`），不校验长度；该说法不构成当前规则，适用范围限于本节所列位点。
- type4定义+1036==2时，在scene+0x4CC分配矩形，以scene+0x56C索引，范围为40个指针。
- C393快照的协议尺寸、行数与清零规则，以及协议／布局上界与适用范围，仅由[家具库存、协议、支付与到期边界](库存布局与期限.md#kb-03-039-1)维护。

C38E安全地覆盖所有消耗的字节，适用范围为接口构造。

#### 保存确认与布局重读边界

- 装修保存以数据库事务提交为完成条件，成功确认后清理本地修改标志，并保存地板、墙壁的选择状态。
- 布局读取负责恢复家具实例及地板／墙壁选项；地板和墙壁的可见更新由当前装修模式及场景资源应用共同决定。
- 保存确认、库存选中状态、布局重读与场景资源应用分别维护完成状态；一次保存即可提交完整布局。
- 房间家具同步面向同室其他角色，包含普通家具实例；房主地板／墙壁的可见状态由其装修控制器维护。
- 温度计采用独立的房间恢复参数，规则见[住宅访问恢复](../访问恢复.md#入室缓存与温度计重建错配)。
