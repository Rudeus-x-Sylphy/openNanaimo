### 家具库存、协议、支付与到期边界

- 完整适配器以 SQLite 中的家具库存、室内布局、每日推荐和街区住宅记录共同维护单身公寓。
- `CharacterItems` 按角色与物品代码聚合数量和到期值，协议列表再按数量展开为家具实例；布局通过 `(Index, ItemCode)` 区分同款实例的选取状态和位置。
- 同代码实例共享库存行的到期值，不分别保存购买时间或独立期限。
- 普通家具基线为781个定义，接入韩服增量后为2008个定义；零基字段6为Hans金币价格、字段7为NaNa/Cash价格，与 `PetShopCatalog.LoadInteriors` 和 `ApartmentCatalogChecks` 的读取一致。新增条目定价归[商城](../../经济/商城/目录币种与购买.md#韩服增量商品定价)，资源与可见性边界归[追加装扮与家具](../../../工程/资源安装/追加装扮与家具.md)。

| 边界 | 长度与字段 |
|---|---|
| C409 → C40A 库存 | 请求12；mode10普通背包、mode20室内装修、mode30外围装饰；普通家具响应在无扩容到期字段时为12+12N，有该字段时为1028字节；记录 `(code:u32, TakeOn:u16, Index:u16, expiration:u32)`；第四字段按 `yyyyMMddHH` 编码。库存到期值0通过 `ClothingExpirationTime.Effective` 投影为远期哨兵 `2100123100`；限时家具使用真实到期值，外围库存按独立结构构造 |
| C40B → C40C 购买 | 请求216，payload+0支付模式，+4购物券开关、+5券索引、+7商品种数、+8数量数组、+48代码数组；响应1040，Cash位于完整帧+1024，Hans位于+1032 |
| C40F → C410 删除 | 请求20、响应20；按精确 `(code,Index)` 删除实例，原子调整后续已摆放实例索引 |
| C411 → C412 布局 | 请求768，最多84个TakeOn及84个TakeOff；响应12，完整帧DWORD+8：1000失败、2000成功 |
| C423 → C424 布局快照 | 请求12、响应1044；84条普通对象容量，地板与墙壁单独承载 |

本节只维护家具库存、购买、删除、布局与快照协议。推荐结果码与购房协议（C396/C397、C36E/C36F）归[推荐、购房费用与住宅租期](../房屋归属/推荐购房与租期.md#kb-03-039-3)；C399 客户端映射归[推荐结果与本地推荐点更新](../访问恢复.md#kb-08-052-4)；C398 尚无归属页；外围装饰（C407/C408、C40D/C40E、C414/C415、C425/C426）协议归[外围文字、菜单资格与保存](../屋外装修.md#kb-03-039-4)。

- C40A 的 BYTE+8 选择库存模式；BYTE+9 为新增提示，BYTE+11 为记录数。
- 每条家具记录的 TakeOn 在已摆放时为1，其余为0。
- 普通背包扩容使用 BYTE+10=6 与 DWORD+1024，响应覆盖该字段。
- mode30 的外围实例独立保存，房屋外观索引位于0..127，招牌索引从128开始。

- C411 TakeOn行从完整帧+8开始，步长8：Index:u16、X:i16、Y:i16、Layer:u8、Mirror:u8。
- TakeOff索引从+680开始，按BYTE排列，最多84项；两个WORD计数在+764/+766。
- C424普通行从+12开始，步长12：ItemCode:u32、X:i16、Y:i16、Layer:u8、Type:u8、Mirror:u8、Index:u8；地板记录位于+1020，墙壁记录位于+1032。

C392/12 → C393/1020 提供完整家具快照：完整帧+8为WORD对象数，+10为WORD2000，+12起最多84条12字节普通对象记录，其余空间清零。WORD+10为6000时请求续页；2000完成快照。地板和墙壁由C38E/C424承载，C38F/C390维护各访客自己的角色信息。

家具插入、领取和丢弃通过事务调整布局索引。存量布局校准优先保留正确索引，再以同款可用实例匹配其余记录，完整保留坐标、层级、镜像和类型。金币购买按mode0结算，NaNa/Cash购买按mode4结算，购物券按物品类别与面值核算；C40C直接发放记录携带所分配的实例索引，待领取物品通过C475领取。

- 家具按目录 `inter._D3` 零基字段5的使用期限（15／20／30／90天等）持有。
- 发放、购买与领取按 `DurationDays` 更新到期值，同代码库存行累加数量并共享续期结果；旧行 `ItemExpiration=0` 在再次发放时从本次发放时间起算，在未更新前仍按永久哨兵投影。
- 家具与限时衣服共用 `HasExpiry` 和 `ClothingExpirationTime.IsActive` 判定，目录期限为0的家具保持永久。
- 已到期的待领取物品不能领取；已到期家具从普通库存快照、房间快照和有效容量计算中排除，后续布局重排移除失效关联。

- 当前删除入口 `DatabaseService.DeleteInteriorInventoryItemAsync` 构造删除前的索引表时只读取代码和数量，尚未按到期值筛选；判定条件为同一代码的库存行内过期实例与有效实例并存，此时该删除前索引的实例顺序与普通快照的有效实例顺序不一致（同一行全有效或全过期时两者一致）。
- 因此，过期家具与有效家具并存时的删除一致性仍需修复，不能将全部变更路径描述为已统一期限过滤。
- 存量期限补齐属历史／未确认事项：既有说明提到一次存量期限补齐，而 `deployment_backups/` 是外部运行目录，仓库不提供该次执行的记录、版本或适用条件，这不代表当前程序会在每次启动时自动补齐所有旧行。

### 家具与装修

房主身份与街区住宅地址分别判定。自己的公寓显示室内装修入口；街区房主可通过“装修房屋外面”设置外围装饰、招牌和文字，访客使用访问界面。

- 家具列表按独立实例显示已选取状态，地板、墙壁和普通家具使用同一套库存与布局关联。
- 相同款式的多个家具分别保存选择状态、位置、层级和镜像。
- 保存、取下、购买、领取及重新登录沿有效实例投影维护列表与室内布置。
- 丢弃入口的到期值筛选缺口归[家具库存、协议、支付与到期边界](#kb-03-039-1)维护。

初始家具按有效家具目录校验，并按角色一次性发放；家具列表支持正常显示带金币价格的初始家具。

家具库存容量为 84 个实例。购买与领取在同一事务中更新库存及装修索引，已摆放家具的实例关联随库存排序同步调整。现有布局按所持家具实例校准，并保留各项装修属性。

### 装饰商店结算

Hans 金币商品与 NaNa/Cash 商品分别使用对应目录价格和余额。装饰购物券用于抵扣符合条件的金币装饰商品，余额支付剩余金额。每笔成功使用购物券的交易消耗一张所选券。

商品根据支付类别进入家具背包或待领取栏；待领取商品通过领取转入正式背包。结算、购物券消耗、容量检查和物品发放使用同一个事务，重复请求与过期会话受到一致性校验。购房成功后即时同步金币与推荐点余额，外围装饰商店打开时同步当前余额。
