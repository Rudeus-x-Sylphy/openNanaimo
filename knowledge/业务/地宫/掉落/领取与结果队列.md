## D034/D035

以下偏移均相对完整帧，单位为字节；D034为16字节请求，D035为24字节共享响应。

| 报文 | 完整帧偏移 | 类型 | 作用 |
|---|---|---|---|
| D034 | +0x08 | WORD | 类别：20卡片、40战斗效果；独立星星管理器另有category30 |
| D034 | +0x0A | WORD | 场景物品UID |
| D034 | +0x0C | DWORD | category20卡号；category40效果类型：1 Power、2 HP、3 MP、4速度 |
| D035 | +0x08 | WORD | 领取者角色UID，供本地效果身份比较 |
| D035 | +0x0A | WORD | 同一领取者角色UID的兼容重复字段 |
| D035 | +0x0C | WORD | 回显类别 |
| D035 | +0x0E | WORD | 回显场景物品UID，用于移除场景对象 |
| D035 | +0x10 | DWORD | 回显卡号／效果类型；category20用于结果队列 |

- 本地 UID 相等性对于本地效果路径是必需的。
- 8/8构造样本未满足`0x006F0A0E`处的UID比较；当前逐客户端响应使用实际收集者UID。
- 共享响应保持 24 字节；category20 本身通过 `+0x13` 消耗，而其他类别分支使用保留的尾部。
- category40需要当前battle epoch已有的掉落资格；延迟请求按既有FIFO/场景UID账本领取一次，不因最近一次D00E的时间决定归属。
- L8的HP终结箱必须先按[箱子掉落账本](箱子与终结道具.md#kb-06-017)登记资格；“客户端生成了可见道具”本身不替代适配器登记，也不能通过无请求推送D035或放开任意领取修复。

- 对于category20，非零D035 `DWORD +0x10` 是原生的**本战获取卡牌结果载体**。
- 客户端创建一个16字节的`{collector UID, card code, prev, next}`节点，并将其附加到战斗控制器`+0x970`。
- CF88随后清空该队列，将UID匹配到玩家结果块中的三个之一（位于`+0x64C + 0xC0*i`），并记录最多14个不同的卡牌代码；重复的代码会增加一个字节的计数。
- `WORD +0x0E`独立地移除场景卡牌对象，无法替换这个结果载体。

- D034 的 `+0x08..+0x0F` 复制到 D035 的 `+0x0C..+0x13`；category20 的 `DWORD +0x10` 保持奖励值。
- D034 由构造函数 `sub_708850`（闭包 `0x405731`）写 opcode `0xD034` 与长度 16，无构造函数侧载荷；四类发送函数为 `sub_6EAB00` cat10／`sub_6EAB80` cat20／`sub_6EABC0` cat30／`sub_6EAB40` cat40，各写 `+0x08 WORD` 并经 `sub_40A821` 发送。D035 category20 的分派 `0x6F06AF..0x6F0758` 读取领取者 UID 及远端 code 并进入 `sub_762810` 结果队列；原有移除、结果队列和持久化分层保持。
- category40/category20拾取按当前战斗与场景物体身份保持单次提交：首次领取发布D035，重复领取沿用原账本。
- 共享卡片账本在新战斗开始时统一重置；同代码多张卡片先匹配已绑定物体，再选择可领取记录，持久化成功后提交物体绑定。
- 生命／魔法效果同时更新实际领取者的资源。
- category20的codes13000028、13000094和13000139由D035发布，CF88结算各增加1份持久计数并更新结果列表。
- 该行为已通过构造与工作进程回归；本地化名称与排序、同代码count2、空奖励、重登持久性及多人领取归属已获用户验收确认，范围与受测版本待补录状态见[掉落与奖励队列验收](../../../工程/验证状态/地宫与成长验收.md#掉落与奖励队列验收)。

## 幸运卡场景构造与领取

- D00E subtype30及D012卡片字段仍经`0x4118A6→0x685810`构造卡片；后者经`0x40470F→0x6B49D0`初始化场景对象，`code/1000000==22 && code%1000<=100`进入已有特殊卡效果分支，故22000011..18不需要伪装成domain13。
- `0x6EAB80`按[D034/D035](#kb-07-002)的构造与字段口径发送D034/16（WORD+8=20、WORD+10场景UID、DWORD+12原卡号）；D035 category20 的原有结果队列／移除字段不变，详见该节。

## 卡片结果构造与D034／D035消费

- 正向卡片结果链沿用本主题卡片表：`D00E +0x1A=200,+0x1B=30,+0x1C=code`在`0x6EC002..0x6EC039`调用`0x4118A6 -> sub_685810`；D012在`0x6ECB83..0x6ECB8E`读取独立`+0x20=code`调用同一函数。
- 该入口的两个调用点分别对应以上结果类型；`sub_685810`以code非零为门控，分配296字节、获取场景UID并构造／插入对象，其输入为已裁定的卡片代码。
- `sub_6B49D0`把远端code存于对象`+0x11C`。
- D00E安全帧48，D012按既定60／带排名尾的64字节规则，卡片结果沿用完整结构长度。

- 另一构造入口`0x4093E5 -> sub_6858C0 -> 0x405371 -> sub_6B4E50`接收位置，将对象`+0x11C`设为0并使用固定效果，由`sub_67A320/67D610`局部终端进入；该入口属于零代码效果对象。
- `D034/16` 的构造函数、四类发送函数与字段口径见[D034/D035](#kb-07-002)；其中 `0x6EAB80` 为 category20 发送入口，`sub_6EABC0` 为 category30 发送入口，各写 `WORD +0xA` 场景身份、`DWORD +0xC` 代码并经游戏控制器发送。
- D035 category20 的分派区间、领取者 UID／远端 code 读取及 `sub_762810` 结果队列归[D034/D035](#kb-07-002)维护。
- 领取请求消费适配器已授予的卡片资格。

分派器`sub_6EBAC0`及上述字段的确认层级为静态指令；概率策略归[精确卡池与分组抽取](卡池与奖励资格.md#kb-06-014)。
