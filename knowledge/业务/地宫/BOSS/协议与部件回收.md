## 肉弹与BOSS接触边界及验证限制

- Kind40接触使用精确mode/child/ordinal，同D011共享部位终结账本。
- 当前模式完成后，携带下一连续模式、合法child和正生命ordinal的肉弹接触可直接推进模式并扣减命中部件生命；模式、部件与正伤害校验在账本变更前完成。
- 伤害以上限钳制，最终结算按战斗周期去重。
- 泛用外部组件伤害仍限定当前模式，肉弹保护周期由[业务／宠物／索引](../../宠物/索引.md)维护。
- 普通type4对象退场、组件D013、聚合最终D012和CF87/CF88保持独立边界。


- 血条判零与宽度字段的兼容修改口径，以及对象 `+0x10C` 由血条初始化与权威生命更新维护这一结论，见[BOSS血条初始化与权威剩余量](#kb-08-072-4)。
- 阶段最大值保持对象 `+0x104` 的资源总量。
- 当前与未来阶段分别建账，当前阶段归零按既定完成门控推进。
- 三分体专项覆盖地宫1-2／1-3全部三种难度的过量伤害、精确组件终结与剩余量；局部指令检查覆盖本地估算为零、负值及过量值时的显示选择。

### 聚合生命与组件定位

- D012完整帧 `+0x28` 为客户端 recording 更新值（即上文 `BossNowEnergy`／适配器 `mode_recording_hp`），组件回收由child／ordinal独立定位。
- 火焰宝珠 `hd0/ep4/dg2/st0` 的当前适配器策略汇总本体与冰棱生命，每次有效命中发布共同剩余量；本体和辅助对象各自的本地能量与共同显示量分别维护。
- 必要主体/部位的完成条件与残血回收统一归[主体斩杀线](组件与零生命附件.md#主体斩杀线)；组件退场、当前mode完成和最终结算仍是独立边界。

- D011身份字段仍为 `+0x0C/+0x0E` 的 `owner/source`，以及 `+0x12/+0x13/+0x14` 的 `mode/child/ordinal`；没有推导出新数据包字段。
- 适配器攻击来源仅采用精确匹配的PON拥有者行和有效正向来源槽；不能用邻近来源替代精确归属。
- 客户端关联：owner834攻击420和owner837攻击554，映射到BOSS基础19，本地伤害401/535，精确21对21序列匹配。
- 同一子对象的序号命中会更新该子对象/组的局部能量；不能仅凭该子对象局部能量变化证明其他ordinal组件也已死亡。
- D013 是子对象级别的终结机制，与 D012 的聚合记录不同。
- 保留的ep7/dg2资源/运行时关联证明接受子对象0的伤害超过70992，然后强制回收仍为正的子对象1。
- D012 情况 `0x6EC8F6`：DWORD+0x28 记录/读取 `0x6EC901..0x6EC914`；owner recording 写入 `0x6EC96F..0x6EC979 -> sub_6BF200`；BYTE+0x19 子对象比较 `0x6EC9E7..0x6EC9F4`；WORD+0x1A 组件比较 `0x6ED0FE..0x6ED11B`；无条件匹配子对象扇出 `0x6ED5F8..0x6ED60C -> sub_40C0C2 -> sub_6C9B20`。
- `sub_6C9B20` 立即通过选择器索引组件向量并终止它/关联，因此回收中性选择值应写入D012帧child字段+0x19，而不是序号+0x1A。
- 子对象循环在 `0x6ED62A` 后退出，之后继续处理 HP0/最终状态；因此子对象255也安全地携带最终的 D012 状态。
- 对真实子对象构造 D012 时，完整帧偏移 `+0x1A/+0x1B` 若写入 `00 04`，客户端会将其作为组件序号 WORD1024 读取，而不是对象的本地状态或终结标志；这不是安全的回收编码。组件序号消费点为 `0x6ED115`，报文构造见 `release/components/winter_boss/boss_hp_sync_runtime.inc::boss_hp_sync_encode_d012_payload`；应按上文使用有效 ordinal 或中性 child255。
- 精确child／有效ordinal的D012用于组件首次终结及明确的模式退场；必要主体集合完成或总量归零时可同时构造D013与精确D012。普通完成的重复最终D012使用child255；主体斩杀后的迟到D011隔离，成功表现保持单次。D013负责子对象级回收，能量字段使用当前mode recording。

- D011 本地路径 `sub_670E10`：type3 攻击读取位于 `0x671B4F..0x671B72`；伤害／限幅及子对象累计值 `+0x214` 写入位于 `0x671C31..0x671C80`；D011 构造点位于 `0x671E88/0x671F25/0x672362`。
- D011 不传输数值伤害或致死字段。
- 147 条 D011 与本地变化量的对应关系符合“原始 PON 攻击减去部件基准并执行终止限幅”；宠物加成在适配器侧只应用一次。

- BOSS子项计时／重新初始化链已核实：玩法更新经过`0x66FBF1/0x67931D -> sub_41B707/sub_6881D0 -> 0x68821F -> sub_40D0CB/sub_6BE5A0`。
- 控制器从`controller + mode*0x324 + 0x45C`（模式块`+0x318`）出发，沿next链接`+0x21C`遍历当前模式的全部子项；没有针对第四个索引的特殊分支。
- `+0x208!=0`的记录可启用controller `+0x04/+0x0C`；tick差超过`0x7D0` ms且存在下一模式时，`0x6BEA7F -> sub_417BD4/sub_6BE2B0`推进并重新初始化下一模式。
- 实际写入子项能量的是`0x6BE4DA..0x6BE510`，它将记录向量`+0x218`中各关联部件的`DWORD+0x08`求和，写入记录`+0x210/+0x214`。
- 因此，所述第四子项只是沿`+0x21C`推进三次后的链表节点index3，与其他子项处理一致；2秒路径是有门控的单次模式切换，并非专门周期写入child4。
- 写入thunk的直接调用点为`0x688179`、`0x6881B4`及定时路径`0x6BEA7F`。
- 逐帧`sub_6C9970/sub_6C9780`更新／检查子项图像，不写`+0x214`；事件驱动的`sub_670E10/sub_67A320/sub_67D610`写入路径保持独立。

## 冬季持久体资源和回收闭合

- 拓扑、策略范围及验证边界见[零生命附件](组件与零生命附件.md#kb-06-019)与[通用组件账本](组件与零生命附件.md#kb-06-021)。
- `0x69FB10` 类型3阶段资源 -> `0x4123AA/0x6BF2F0` BMO加载器；模式-子数据使用XOR0x38。
- 对于相关的BMO，count2是文件+0x15C；子路径从+0x160/+0x230开始，记录步幅为0xD0。
- 加载器调用`0x6BFFE8 ->0x419961/0x6C27A0`；MMO版本200情况开始`0x6C2BA6`。
- 本地字段直接读取；`0x40C7BB/0x6C9310` 使用XOR0xAB 解码64字节字符串和72字节数组记录。
- 两个检查过的MMO流解析到精确的EOF。
- `0x41E5D3/0x6CA6C0` 将目标+8按选定的百分比缩放；客户端本地共享能量独立地证实了观察到的总和。

- D012 子对象匹配 `0x6EC9E7..0x6EC9F4`，序号 `WORD` 读取 `0x6ED5F8..0x6ED5FF`，以及调用 `0x6ED60C ->0x40C0C2/0x6C9B20` 构成了因果删除链。
- `0x6C9B20` 终止了选定组件及其 +0x198 等于其序号的行；version200 直接读取这种关联，保留的旧格式转换器按[普通终结和碰撞信道](../伤害与目标/目标身份与生命账本.md#kb-06-011)登记的加载器字段复制规则处理（源+0x334 复制到 +0x198）。
- `0x412B75/0x6CD770` 运行自定义的终止效果，然后 `0x401C3A/0x6CB490` 设置 state2 (+0x3C0)。
- 没有 HP 正向保护来防止真实子对象 D012 的回收选择。

- 普通生命更新D012完整帧为60字节；继承的顶层发送器包含排名字节+0x3C..+0x3F时，首次／重复最终状态帧为64字节；高episode的中间终结也使用64字节，见[mode推进门控](阶段推进与开场.md#kb-08-056)，客户端在0x6EDC14/0x6EDF10及相邻分支读取这些字节。
- child255跳过部件选择，不跳过后续最终状态分支。
- D013读取WORD+8数量、WORD+0xA owner、WORD+0xC+4*n child和DWORD+0x5C能量；初始化的单记录96B帧覆盖至+0x5F。
- 最终分发 `0x6EE856..0x6EE869` 使用同一回收跳板。
- D01132构造函数 `0x6E9F00/0x6E9FB0` -> `0x40A821/0x6E90C0` 仍按既有游戏控制器元组分派，未改动。
- 适配器侧生命同步与资源目录分别见 `release/components/winter_boss/boss_hp_sync_runtime.inc` 及 `release/components/target_resources/hp_resource_runtime.inc`；这些源码依据与前述客户端指令证据分别核对。
- 分派器完整函数反编译返回None；上述结论依据已采集指令，不依据空的伪C输出。

## BOSS血条初始化与权威剩余量

- `0x6BE2B0 -> 0x742CB0` 按阶段全部组件生命之和初始化血条最大值；`0x6BF200 -> 0x742D20` 写入权威剩余量。
- 绘制器 `0x742DC0` 的 `0x742DF1` 判零及 `0x742E12` 宽度读数统一使用对象 `+0x10C`，除数使用对象 `+0x104`。
- 主教程入口`0x4DF539..0x4DF541`进入讲解state12；教程操作经`sub_92EB80`的`0x92EE76..0x92EE7E -> 0x402EF0 -> 0x42FBA0`将当前状态改为14、上一状态改为12。主循环`sub_439FE0 case14`进入`0x40B5BE -> sub_6627D0`，在`0x6627E9..0x6627F7`以当前state14维持飞行循环。
- 飞行战斗本地更新`0x6BE5A0`汇总各子对象`+0x214`，经`0x6BE9AE -> 0x409525 -> 0x742D00`写本地估算`+0x108`。兼容配方在`0x742D00..0x742D1F`保留该写入，当前状态`DWORD [DWORD 0xD6F280]==14`时同步`+0x10C`；上一状态存于对象`+4`。其他状态的显示量由既有权威链维护，伤害、组件回收和结算沿用原计算。
- 当前工具精确认识原生设置器与旧state12配方，将比较立即数`0x0C`迁为`0x0E`，在state14同步本地血条显示。精确位点与原／目标字节归[BOSS血条兼容](../../../工程/客户端兼容/BOSS血条.md)，验证层级归[主教程BOSS血条](../../../工程/验证状态/地宫与成长验收.md#主教程boss血条)。
- 精确修改步骤由客户端兼容文档维护。
