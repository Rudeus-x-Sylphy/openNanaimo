## 接触伤害与零生命附件

BOSS接触攻击目录与可击杀组件账本分别维护。零HP危险部件按自身精确攻击值结算玩家受伤，其生命、部件终结、BOSS总生命与奖励状态保持各自生命周期。L7超级BOSS的机械手、锁链及同类零生命附件继续依附所属BOSS阶段；子弹连续命中保持附件存续，阶段与BOSS完成沿既定退场边界处理。

- 资源分类保留正HP根附属部件、冬季本体、地宫3-3门框及独立退场对象的作用域。
- 既有专项覆盖24,443个保留型零HP部件身份，包含L7超级BOSS第一形态九槽共810个零HP身份；重复弹击与肉弹边界保持原有生命及终结状态。当前目录的覆盖归[验证状态](../../../工程/验证状态/地宫与成长验收.md#boss主体斩杀线)。
- kind70玩家受伤保持整个BOSS上下文一致。
- 独立部件账本的历史检查覆盖1,278个形态、864次最终终结及414次中间阶段切换；主体斩杀线的当前覆盖归[验证状态](../../../工程/验证状态/地宫与成长验收.md#boss主体斩杀线)。
- 接触数值与跨地宫覆盖见[角色伤害和得分](../伤害与目标/入伤与协议.md#kb-04-013)，客户端场景验收归[验证状态](../../../工程/验证状态/README.md)。

## 独立零生命对象组的处理边界

零生命对象的受击资格、接触伤害和退场时机是三个独立属性。当前BOSS组件处理有以下边界：同一child含正HP部位时，零HP附件随该组生命周期处理；全组HP为零的type4行首次受击时，现行通用分支会独立终结该行及其关联行。3-3门框、4-3火球机器场景建筑和冬季持久体按各自显式规则处理。该通用分支适用于多个地宫，独立的场景／阶段设施需要按对象职责确定保留范围。

| 关卡与阶段 | 已确认对象 | 难度槽范围及当前受击行为 |
|---|---|---|
| 普通5-1 | 7个悬挂尖石 | slot3..8独立child1；零HP行首次受击独立退场。 |
| 普通5-2 | 骷髅障碍及关联效果，共2行 | slot3..8独立child1；首次受击独立退场。 |
| 普通5超级BOSS，mode0／1 | 7个／3个岩石 | slot3..8各阶段独立child1；首次受击独立退场。 |
| 普通6-2 | 3个竹刺障碍 | slot3..8独立child1；首次受击独立退场。 |
| 普通10-3 | 上下两块球形场景结构 | slot0..5属于child0，slot6..8属于child1；slot6采用专用对象筛选，其余8槽两行均可首次受击独立退场。 |
| 普通2超级BOSS，mode0 | 尾翼、推进部件及其附件，共4行 | 九槽分别属于child2／3／5；首次受击独立退场。 |
| 隐藏`hd1/ep0/dg0/st0/mode0` | 2个方形场景障碍 | 九槽child1；首次受击独立退场。 |
| 隐藏`hd1/ep1/dg2/st1/mode3` | 18行零HP部件，其中15行具有碰撞轮廓 | 九槽child1；首次受击独立退场。 |

上述对象的资源身份和当前适配器行为已经确认。场景常驻、随主体退场和随阶段退场分别列为独立的画面验收项，当前状态见[零生命组件范围核对](../../../工程/验证状态/地宫与成长验收.md#零生命组件范围核对)。脚部装饰、传送效果及挑战门设施采用独立分类；碰撞轮廓、受击资格和阶段回收分别维护。

终局child级回收具有独立规则：共享HP耗尽且其余正HP部件全部清空时，通用残血清理结束；仅一个正HP child的最终处理固定回收child0。4-3采用显式场景保留规则；`hd0/ep19/dg0/st1/mode1`的child0传送效果按该终局回收规则处理。

普通静态目标和预加载变形目标使用独立的保留策略，范围见[预加载目标与场景障碍](../伤害与目标/预加载与变形目标.md#kb-06-002)。

## 地宫3-3零生命门框

- hd0／episode2／dungeon2／stage0／mode0的九个槽，SMMO绑定`ep03_st03_e_gate_l.bmo`（槽0..5）或`_m.bmo`（槽6..8）。
- child0的`ep03_st03_e_gate.mmo`仅有ordinal0、type4、原始HP0；child1的`ep03_st03_e_gate_00_L/M.mmo`含两个正HP type3发射部件（ordinal0/1）及两个零HP附件；child2的`ep03_st03_e_gate_mon_23_L/M.mmo`有三个正HP type2召唤怪。

- 资源名ep03对应通信episode2；门框采用零生命附件身份。

- 当前适配器策略仅对此精确元组抑制门框受击产生的独立D012终结，保持其HP及BOSS总量不变。
- child1两个正HP部件是显式主体清单中的两个必要部位，二者都归零时触发本阶段斩杀。同一次伤害请求中，先发D013/96清理child0门框，再清理child1及尚存的child2，最后发零recording的D012；child2此前已经完成的终结保持幂等，强制回收独立于有效伤害及掉落记账。
- 门框清理按mode／battle ledger单次发送，新战斗重置；弹击D011及kind40接触共用该规则。
- 冬季BOSS保留规则、其它零HP目标及普通D00D账本分别按原有作用域维护。
- 既有72条生产构造路径的独立回收观察保留；主体斩杀后的构造及客户端验收边界见[验证状态](../../../工程/验证状态/地宫与成长验收.md#boss主体斩杀线)。

## 通用组件账本

### 组件生命与幂等

- BOSS正生命组件账本限定在 `(battle epoch, mode, authored child, authored ordinal)`。
- 每个组件拥有独立 `component_hp`；弹击与肉弹均以精确部位身份同步组件、child与当前mode生命，伤害钳制到命中组件剩余HP。
- 首次归零产生一次组件终结，重复报告保持幂等。
- 新mode与新战斗清理运行时部位绑定。
- 普通 runtime UID 怪物、runtime/deform、crate 与BOSS账本继续相互独立。

### 主体斩杀线

- 当前本服采用主体斩杀策略。当前mode初始总量由所选槽的全部有效正HP资源行相加；命中本体或组件都按有效伤害扣共享总量，组件保留自身独立耐久。
- 当前阶段在共享总量耗尽，或全部必要主体／主体部位归零时结束，任一条件成立即可；本体和组件均可完成最后一击，组件伤害可将共享总量降至0。
- 主体资格按`hd/episode/dungeon/stage_index/slot/mode/child/ordinal`显式绑定。难度、关卡、所选槽位和阶段共同限定集合；九槽为替代配置，每次战斗使用当前选中槽。基础完成条件继续采用该阶段的完整正HP部位集合。
- 同一主体的多个正HP部位均为必要成员：集合全部归零时完成当前阶段。4-3保留三个主体部位，6-1保留三个主齿轮，8-3保留两个主体部位；4超级BOSS第一阶段的头部与前体共同完成后进入第二阶段。零HP附件归属阶段回收，修道僧沿用挑战自身的完成条件。
- 下表26组关卡／阶段各覆盖九槽，共234个槽位配置。普通关卡采用`stage_index=0`，超级BOSS采用`stage_index=1`；界面阶段1／2对应`mode0/1`。资源族按实际所选槽绑定`_L/_M/_H`版本，必要成员取该资源全部正HP行。槽位变化引起的child变化在表中分别列出。

- 触发斩杀时，共享剩余量及尚存战斗部件账本在同一次请求中清零，标记当前mode的残血回收；先发送必要D013，再发送零recording的D012。整组回收限当前mode并按child去重，响应归触发请求所有；火球机器的场景建筑按下节保持存续。
- `execution_residual_hp`记录强制清理的残血，`applied_damage/cumulative_damage`记录真实有效伤害；跨mode聚合累计伤害扣除已经斩杀的残血。组件击杀分、掉落和经验按有效终结记账，最终奖励沿既有首次终局路径一次提交。

- 实现入口为`boss_hp_sync_load_execution_cores/boss_hp_sync_execute_if_complete`，发送入口为`teamplay_send_d013_boss_result_retirements/shop_catalogs_send_boss_result`。构造测试与客户端验收分别归[验证状态](../../../工程/验证状态/地宫与成长验收.md#boss主体斩杀线)维护。

### 火球机器与场景建筑

一村地宫4-3「火球机器」对应`hd0/ep3/dg2/st0/mode0`。核心战斗对象为三个正生命火球，必要部位为ordinal0／2／4；三者全部归零后完成战斗。九个槽位各自独立：slot0..5的火球属于child1、场景建筑属于child0；slot6..8的火球属于child0、场景建筑属于child1。

场景建筑由13个零生命type4资源行组成，整个战斗及终局均保持存续。其受击处理保持当前BOSS生命量和场景状态；终局仅回收火球所属child，并发布完成状态。火球的独立生命、有效伤害、计分和奖励沿各自账本结算。重新进入本关建立新的战斗周期。

### 选图与房间资格

- 共享BOSS账本的选图与阶段重置受当前房间成员资格约束。
- `boss_hp_sync_select_stage`初始化phase为PREPARED(1)、profile_kind为LOOKUP_MISS(7)，并清理HP与profile；D011/32仅在合法战斗阶段计算伤害，其余阶段返回BAD_PHASE(-2)。
- 活跃房间门控在非成员请求进入上述重置前完成检查，保持现有BOSS伤害账本。
- 隔离范围归[业务／地宫／索引](../README.md)，验证层级归[验证状态](../../../工程/验证状态/README.md)。

### 本体与冰棱

火焰宝珠 `hd0/ep4/dg2/st0` 的本体与冰棱均计入当前mode初始总生命，每个有效命中即时发布总剩余量。各部件独立扣血、独立终结，普通生命更新使用中性部件选择值255；组件首次归零使用精确child／ordinal。本体`child0/ordinal0`归零时按[主体斩杀线](#主体斩杀线)完成阶段并清理六个冰棱中尚存的对象。九槽保留各自部件数、伤害截断及重复终结边界。

### 平行分体与阶段总量

- 同一子对象的平行分体BOSS按独立组件生命结算，阶段剩余量等于全部存活组件生命之和。
- D012 +0x28 发布当前阶段总剩余量，客户端血条的零值判断与宽度统一读取该权威值。
- UI关卡1地宫1包含两个2000生命组件，总量4000；地宫1-2、1-3的三分体依次保留2/3、1/3和0的总生命比例。
- 单次伤害以命中组件剩余量为上界；全部默认必要分体完成后结束阶段，存在显式主体清单时按[主体斩杀线](#主体斩杀线)执行。
- 局部首元组按既定首个存活组件规则解析，明确的后续序号保持精确寻址。

### 当前mode与聚合生命

- 多模式BOSS的内部 `c->hp` 是当前 mode 账本，`result.hp` 可保留当前加后续 mode 的总剩余量，但两者不能无条件当作终结时的客户端 recording。
- 原客户端要求当前 mode 结束的 D012 `+0x28==0` 才授予完成许可，更新循环还再次要求 recording 为0才推进 mode；此前把未来6000留在这里导致组件爆炸后永不换阶段。
- wire `+0x28` 按当前 mode 账本发布（`mode_recording_hp`，即客户端 recording）；中间终结处该账本为0，编码器直接发布该值，聚合保留在 `hp`/`cumulative_damage`；states、奖励、排名和 HP/MP 回复增量全部为0，`awaiting_next_mode` 不提前结算。
- 中间终结使用64字节并显式初始化排名尾部（该条件覆盖规则优先于普通D012/60长度），覆盖其他 episode 的条件读取。
- 一次请求只构造一次响应，不补推后续阶段数据。

### 血条连续性限制

- 跨 mode 总血条完全连续的旧承诺已撤回：阶段终结发送0后，若下一 mode 初始化按该阶段全部组件生命之和重新初始化血条，则血条显示从0重置为该阶段总量，不做跨阶段连续显示。
- 正确换阶段与显示层连续总条是两个边界，后者需单独支持，不再用正 recording 绕开原生终结条件。
- 既有失败样本在内部资源槽 `slot7`：当前阶段的部件已经爆炸退场，但客户端仍保留后续阶段的生命量，导致卡住、不自动进入下一阶段。`slot7`是资源槽编号，不是游戏中的第七关；修复要求当前阶段结束时生命量归零，再进入下一阶段。构造、重复报告隔离和发送函数回归通过；2026-10-20用户另行确认修复后部件退场能够自动进入下一阶段，已验收，受测版本待补录。该确认不代替必要主体集合与辅助对象顺序等斩杀线的独立验收。

### 资源与构造覆盖

- 既有资源审计覆盖1,278个mode，其中348个为多部位mode；弹击与精确接触分别覆盖2,642种完整击杀顺序，关卡4地宫1与超级BOSS各路径另覆盖45,414种击杀排列。当前目录和斩杀线的受测范围统一归[验证状态](../../../工程/验证状态/地宫与成长验收.md#boss主体斩杀线)。
- 专项验证独立HP、组件／child／阶段终结、运行时绑定重置与重复报告幂等。
- 普通三组件场景已有原客户端可见观察；其余 mode 保持对应构造验证范围。

## 终局整组回收的完成状态保护

### 兼容策略

BOSS组件完成退场动画后进入终结状态。终局整组回收会再次遍历同一child的对象；旧保护只跳过中间状态，已完成动画的对象仍可能再次创建退场效果，导致最后一次终结出现重复爆破声。当前兼容策略将终局效果保护扩展到全部已完成退场状态：首次归零仍正常播放，已完成退场的对象不再重复创建效果。BOSS生命、奖励、模式推进和组件回收规则保持独立。

### 一村地宫3-1资源核对

一村地宫3-1的当前资源元组为`hd0/ep2/dg0/st0`，三喷火部件使用`ani_mon_um_03_02_L/M.mmo`；九个槽为替代选项，不合并。MMO共26行：正HP本体ordinal7／16／25分别绑定`fly_mon_mb_burst.wav`，其7／8／8个零HP type4附件通过`+0x198`关联各自本体并绑定`fly_mon_m_burst.wav`。一次精确本体退场可分别调用8／9／9个对象的效果路径；并非需要8／9／9次重复死亡回包。三个本体还各有三个非空退场效果槽，附件各一个。

### 大魔王大门（地宫3-3）资源核对

大魔王大门对应地宫3-3、`hd0/ep2/dg2/st0`：child0门框一行、child1两个正HP喷射部件和两个无声音附件、child2三个正HP目标，六个带声音对象均使用`fly_mon_mb_burst.wav`，各有独立生命周期。门框在两个喷射部件都终结后退场，策略和九槽构造检查见[地宫3-3零生命门框](#kb-06-020)。大门没有三喷火资源那样23个关联音效附件，不能把两者的扇出量混用。

三喷火本体分别拥有多个关联退场对象；每个本体单独终结时按资源关系播放首次退场效果，最后一个本体完成全场终结时执行child级整组回收。终局完成状态保护使已退场的本体和附件保持完成状态，首次终结效果按资源关系正常播放。大魔王大门采用相同的完成状态保护。

同类多对象BOSS资源沿用相同的完成状态保护，首次部件终结与终局整组回收分别处理。
