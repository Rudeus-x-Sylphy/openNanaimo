## 拉米诺斯（Lumineos）战斗资源选择

- 独立入口索引：movement0x5000A0，情况166/167调用0x404A52（6/7）；`0x404A52 ->0xA74450`写入manager+0x5CC的字节，getter `0x403D19 ->0xA743B0`读取相同的字节。
- 结合下面的episode100转换，入口7/索引6选择资源ep22；入口8/索引7选择ep23；同一转换规则将入口23/索引22映射到ep38。
- `0x66EC30`通过常量0xC5F374 `hd%d_ep%02d_dg%02d_st%02d.sstg`格式化射击资源的getter。
- 归因的入口7请求射击hd0，而不是村庄hd4。
- 入口地址与资源选择转换由本节维护；CN基线与选择性L7/L8资源包的覆盖、缺失及验证边界见[身份和资源边界](拉米诺斯身份与资源集成.md#kb-06-003-1)。
- 入口索引映射不代表对应关卡资源已经齐全。

- 房间初始化 `sub_72F0F0` 单独保存章节哨兵值，并在 **0x72F239** 与100比较。
- 特殊分支0x72F23E..0x72F265通过0x403D19取得副本字节，在0x72F24C加16，再调用0x40E2AA ->0x72EFC0（0x72EFCD处写入射击管理器+0x1E534），随后向0x408CAB ->0x708D20传入0（资源副本字段+0x1E538）。
- 普通分支0x72F26C..0x72F2BC不替换。
- 这是资源名转换，不是改写房间／传输数据包的依据。

- 资源获取者0x403D2D -> 0x677290 (+0x1E530 hd),0x418499 -> 0x6772B0 (+0x1E534 episode),0x40EE08 -> 0x6772D0 (+0x1E538 dungeon),0x418AF2 -> 0x6772F0 (+0x1E540 stage) 为0x66EC30的SSTG格式化器提供资源。
- 单例Thunk 0x419BBE -> 0x6658E0 返回射击管理器。
- 选定的SMMO闭合（0x66F1A0/0x69D510/0x69D680/0x69FB10）见[普通目标、源攻击和选定资源 / 针对传入kind10身份的PON基础攻击](#kb-08-040-2)。

- 可追溯的raw CF6C/52：完整帧+0x22 hd0，+0x23 episode100，+0x24 dungeon5，+0x25 stage0，WORD+0x26 difficulty0；客户端调试打开`hd0_ep21_dg00_st00.sstg`然后`hd0_ep21_dg00_st00_L_00.smmo`。
- 现有生成的表格包含匹配的ep16至ep22战斗编号大类。
- 这并不能填补上方村庄地图出口/触发器的缺失，也不能证明其他计划中的战斗编号大类不存在于所有可能的存档中。

- 768项x86条件验证覆盖全部BYTE副本值的ep100分支、栈保持及章节99/101的普通分支；资源范围使用ep16..22。当前实现按资源名查找转换，映射及构造验证范围见[身份和资源边界](拉米诺斯身份与资源集成.md#kb-06-003-1)。

## 普通目标、源攻击和选定资源 / 针对传入kind10身份的PON基础攻击

- `sub_66F1A0 -> sub_40284C -> sub_69D510` 选择阶段字节+0xB49；文件名是+0x21C+260*槽位。
- `sub_410BD6 -> sub_69D680` 重置/解析该槽位列表；`sub_69FB10` 读取/遍历该槽位仅此一次。
- 生成的段列表示槽位的替代方案；不能累计替代列表进行选择器查找。
- 保留的槽位7运行时打开 st01_H_01，而不是 st01_H_00。
