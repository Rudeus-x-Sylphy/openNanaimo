## 活跃房间与诊断隔离

- 一个原生工作进程内的BOSS上下文由`multiplayer_shared_boss_context()`共享，不能把新连接等同于新房间。
- 无当前房间资格的连接不得在已有成员的RUNNING／TERMINAL战斗中执行CF6C、CF70、CF77或CF7F：这些请求在任何成员登记、地图选择、共享账本重置和名单广播前被消费，不发送CF6D／CF71／CF72／CF80；已在房间的成员及正常战前加载仍走既有边界。
- 当前实现采用此门控，发布归[验证状态](../../../工程/验证状态/README.md)。

`DungeonSaveChecks`通过`NativeDungeonPool(usePrimaryWorker:false)`创建独立工作进程，状态目录与临时数据库同属测试范围，连接使用租约指定端口。默认使用52050的其它测试入口在独占测试环境执行。

- 活跃房间的成员登记、准备快照和离房广播均按当前成员资格执行，共享BOSS状态按房间与战斗周期维护。
- BOSS账本边界归[身份和资源边界](拉米诺斯资源.md#kb-06-003-1)，客户端字段归[房间角色、加载、地图和继续条件门控](#kb-08-023-1)，验证层级归[验证状态](../../../工程/验证状态/README.md)。

```text
CF09 传输
-> 房主／房间创建
-> CF70/CF71 成员名单和 CF7E 准备／队伍快照
-> CFEB/CFEC 房间资料
-> CFD3/CFD4 与 CFD5/CFD6 对等连接元组
-> CFEC 关卡资料与预加载
-> 每个客户端 CF7F
-> 全员加载确认到齐后，各发送一次 CF80/8
-> 实时转发
-> 战斗与结算
-> 离开／断线／村庄恢复

```
每个后续阶段仍需核对相应请求、房间成员资格及当前加载周期；较早阶段成功不能替代后续授权。

## 加载和转发

房间加载、个人战斗状态和共享战斗状态分开维护：

```text
房主 CFEB -> 房主及各成员 CFEC -> 各客户端加载
各成员 CF7F -> 按活动房间与加载周期登记确认
全部确认到齐 -> 向每个成员发送一次 CF80/8 -> 客户端本地倒计时

```
- CFEC负责完整关卡资料；CF80负责启动本地倒计时。
- 每个加载周期只初始化一次共享BOSS、目标和分数；每位成员独立初始化受伤、技能、资源和死亡状态。
- 成员继承本轮完整关卡、难度及阶段身份，支持房主先完成和成员先完成两种顺序。
- 重复开始确认保持幂等，继续关卡与重新建房分别重置加载屏障。
- 最终响应保留各成员自己的请求低位。

- 受伤结算先写入角色绝对生命值，再更新同房成员的受伤表现与角色资源。
- 结算按各角色自己的请求返回，个人死亡与成功结果分别处理；等待BOSS完成的个人结算在本轮最终状态到达后独立完成。
- 客户端状态与倒计时调用链统一见[房间角色、加载、地图和继续条件门控](#kb-08-023-1)；验证范围见[验证状态](../../../工程/验证状态/README.md)。

当前适配器转发的编号大类包括移动/活动、0x03E8/0x044C 游戏玩法、成功的效果 CF9C/CF9D 角色效果、普通终结状态、BOSS生命值/分数，以及拾取物的移除。射击室聊天尚未纳入此转发列表。

每个转发都保留源身份、房间/页面、连接生命周期、请求优先级和顺序规则。

## 多人加载完成边界

- 队长取得CFEC地图资料时，为当前房间成员建立独立预载授权。
- 首次准备房间依据成员资料就绪状态加载，授权续关依据各成员本轮重载状态加载；延迟释放的续关资料继续经过完整的资源恢复边界。
- 各成员完成自己的CF7F后，当前加载屏障向全部有效成员发布CF80/8；伴侣身份在最终开始确认之前发布。
- 资料刷新保留本成员当前授权，跨关重置上一场的完成标志。
- 离场、断线及连接槽位代次变化释放对应成员状态。

普通续关与超级BOSS加载均覆盖快慢成员交错、重复资料请求及连续三个加载周期。退出地宫以CF73/CF74与CF1D/CF1E完成房间和传输清理，城镇初始化由后续入口请求独立驱动。验证等级由[验证状态](../../../工程/验证状态/README.md)维护。

## CFEC资料布局与本地开场倒计时

- 房间游戏资料由 **CFEC/0x328** 承载：case53228 `0x6F6292..0x6F6F1E` 消费至 `+0x327`，其中 `0x6F6504..0x6F6C08` 安装资料，`0x6F6BFC → 0x41E4AC(16)` 推进加载页面；数组主体最小值0x328、最高字节+0x327，该数量既非CF80也非 subtype20 数量。
- 150个散射坐标对位于 `+0x0A/+0x0C`；`+0x262` 是20项可重复的单字节房间槽位分配序列，`0x6F6666..0x6F671B` 将其匹配到actor `+0x7A4C`，该字段由CF71 `BYTE+0x56`设置，再转换为actor UID。
- 50个拾取代码位于 `+0x276`，50个有符号星数量代码位于 `+0x2A8`；阶段、显示阶段及槽位位于 `+0x2DA/+0x2DB/+0x2DC`。
- `0x669870/0x669960` 将0–9映射为10/50/100/200/500/-10/-50/-100/-200/-500。
- Hans subtype20使用独立散射路径；`0x68D660`属于星数量进度处理。

- CF80 case53120 `0x6F747C..0x6F768F` 使用接收控制器字段 `+0x6C`及actor链 `+0x8130`，最小完整长度为8字节。
- 普通模式 `0x6F7651 → 0x409BEC → 0x70B740` 与另一模式 `0x6F760E → 0x4177EC → 0x718F30` 均将控制器设为状态3；另一分派 `0x63C099 → 0x410681 → 0x6436A0` 使用本地时钟记录时间。
- CF80只在全员最终加载确认完成后各发送一次。

- 本地倒计时由 `0x709C80` 执行，时钟入口为 `GetTickCount` IAT `0xD91FAC`。
- 对象 `+0/+4/+8/+0x0C/+0x10` 分别保存首次更新标志、GO已播放标志、上次提示时间、倒计时起点及动画对象。
- `0x709C8F..0x709CA4`初始化计时，`0x709CB7`播放count；`0x709CD1`检查提示间隔超过1000ms，`0x709CE4`检查起点间隔超过3000ms，随后 `0x709D04`播放一次GO。
- `0x709D3C`等待动画返回2后调用 `0x709B30`清理；普通控制器 `0x70EC27..0x70EC45`、另一控制器 `0x71BAC6..0x71BAE4`在动画完成后从3切到4。
- 可操作战斗边界同时取决于本地动画完成。
