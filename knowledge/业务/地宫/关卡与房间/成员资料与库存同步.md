# 关卡与房间／成员资料与库存同步

“非死亡 CF87”指适配器维护的该角色存活与成功结算状态，不表示 CF87 内含新增或已证实的死亡字段；该操作码的字段证据与结算资格分别维护。

## 范围与阅读约定

成员列表、资料字段、准备房库存变更与角色外观同步。

以下偏移未另注明时相对完整报文；`record`、`actor`、`manager`、payload、资源逻辑行和文件偏移均是独立基准。统计数字限定于正文登记的样本、资源目录和验证层级。

## 房间阶段 C47D 和村庄重建

- C47D/144 既用于村庄装备/快捷栏更改，也用于准备房间编辑。
- 其成功的响应必须遵循当前房间标志。
- 在村庄状态下，保留 `C47E -> C368 -> C47F -> C379 -> C3CC -> C44C`，以便重建外观和后续的 PET。
- 在房间/准备状态下，仅发送 `C47E -> C379 -> C3CC -> C44C`：C368 调用场景销毁，清除 shared_scene+0x24，并使准备控制器的初始化标志失效；因此，C47F 也会被抑制。
- 这不会改变 CF80/开始构建或伪造一个阶段管理者。

村庄返回及角色可见性分别见[页面生命周期](../../城镇/场景切换/页面返回与生命周期.md#kb-02-007)与[城镇角色可见性](../../城镇/角色实体.md#kb-02-015)；selector4在C367/C368入口完成角色和附着发布，普通选择器使用C36C完成边界。

## 成员名单、身份和外观

- CF09建立大厅传输；CF6C房间创建及CF70成员初始化建立实际准备房成员身份。房主最初取得实际入房名单。
- 成员入房后，已完成初始化的观察者取得一次去重的CF71／CF72更新；重复CF70保持成员身份一致。
- CF73、CF1D及断线按成员身份发布CF74，携带离场角色和当前房主，清理可见成员与待加入记录。
- 新房间和连接代次重新建立名单与加载状态；各角色使用真实场景UID。
多人运行样本使用UID21/22；这些数值是样本身份，不是通用账号ID规则。

CF71字段策略对应公开实现 `release/components/protocol/protocol_state_sync_base.inc`：

```text
+0x34 DWORD = 0 在已保留可见观察对应的元组中
+0x38 DWORD = 选中宠物
+0x3C DWORD = 资料性别 & 1（基础模型 D8）
+0x4A/+0x4C/+0x4E/+0x50 = 角色资料的有效 HP/MP
+0x52 WORD = 0 (房间阶段)
+0x56 BYTE = 房间槽位
+0x57 BYTE = 资料性别 & 1
+0x58 signed DWORD = 选中宠物实例当前寿命
+0xB4 WORD = 所选关卡最佳评级低字节（0空白、1 B、2 A、3 S），高字节0

```
- 旧版固定值1／人物等级映射已撤回。
- CF71 分派分支53105将BYTE+0xB4和BYTE+0x56房间槽位送入原生徽标构造器，后者只支持0..3。
- 适配器按所选阶段／难度读取每位成员的持久最佳评级；C355通关权益与CF16结算记录分别维护。
- 原生地宫路径在后续入房前也会持久化非死亡的成功CF87→CF88成员结果，评级账本不再依赖仅托管的奖励路径。

- **历史修复记录（不构成当前事实或验收）**：2026年9月25日原客户端观察及后续数据库审计发现的两处缺口均已修复——先统一实际原生CF71出口，再于下一次入房请求前持久化非死亡CF87→CF88个人结果；当日用户验收确认了部署版中所报告的场景。修复进入的版本／提交以[验证状态](../../../工程/验证状态.md)登记为准，细节见[准备房所选关卡的最佳评价](../计分与结算/评价持久化与排行榜.md#kb-03-010)。

- `sub_4EF380` 仅初始化低WORD为0/1的基础模型；`+0x3C=0x2000`不能作为该模型值。
- CF72基础D8在+0x34同样使用gender0/1，而不是0x4000。
- CF71的+0x57取资料性别；+0x58在本地与远端分支均交给耐久setter。当前构造与托管出口均按实例寿命投影；精确地址、装载前后时序及实现范围归[寿命消耗与充能](../../宠物/成长/寿命消耗与充能.md#数值载体与状态写入)。
- 效果、PET、HP载体各有包布局，不能跨包移植。

- 每个成员名单条目都会为同一个UID发送CF71然后是CF72，**包括远程角色对象**。
- CF72 分派分支53106会查找带有WORD+8的现有角色；WORD+0x64=1会应用完整角色资料，而BYTE+0x66会刷新PetLevel/启动器。
- 合成UID1的抑制并不等同于远程角色对象的抑制。
- 预CF80的本地刷新是一个独立的边界：现行发布仅发送CF72，适用规则见[CF72完整应用与跨关Power](../战斗资源/CF72与宠物生命周期.md#kb-08-062)。旧括注“03/09”未登记可复核的日期或构建映射，不据此确定发布身份。

## 地宫加入成员与结算回城

地宫准备房资料请求CF70使用12字节完整请求。授权重新挑战后，本人CF71资料确认结束旧控制器离场保护，随后的CF73／CF1D按主动回城处理。第三关结算成员按钮的显示与输入同步开放，具体兼容站点见[队员结算回城按钮](../计分与结算/结算操作与控制器.md#kb-08-074-1)。

通过加入房间进入的队员，以本人CF71中的房主身份取得关卡选择；匹配条件为当前在线角色、同队伍、同工作进程端口与代次、已确认的房主身份以及准备房状态。该选择用于普通／超级地宫的情侣恢复、续关和资料投影；跨队伍、过期工作进程与不匹配身份按各自边界隔离。

- 准备房库存及资源刷新以有效工作进程和“已有选图或合法CF70/12名单请求”为资格条件，覆盖队员先取得名单、随后绑定房主选图的准备阶段。
- C43D／C46D用药及其它库存变更在数据库提交、F100状态导入后请求F108；本人依次接收库存完成应答与CF72/116最新资料，同一工作进程内活动房间成员接收源角色的绝对HP/MP广播。
- F108／CF72刷新资格限定在准备阶段，不限制合法背包食物在战斗／结算期通过CF94恢复；情侣四场景资格和载体分流见[情侣关系与权益](../../社交/情侣/关系权益与共享恢复.md#kb-05-003)。
- 开战申请、授权续关及回城按各自门控，关卡选择、情侣操作和开战权限分别授权。
- 双连接生产路径构造验证覆盖普通与补满食物、双向观察、单次扣药、本人应答顺序及观察者自身资源保持，验证范围见[验证状态](../../../工程/验证状态.md)。
