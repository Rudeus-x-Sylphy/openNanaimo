## CF87/CF88

### 结果行、共享快照与单次提交

- CF88 是结算／角色资料状态，记录步长为 `0x34`。
- 同一工作进程端口／代次、关卡选择及各角色战斗epoch／结算周期内，以UID生成共享人物结果行。
- 装备、有效经验卡、情侣及师徒加成按该行角色计算；各接收者共享最终总分、击中分、奖励分、人物经验增量、结算后等级和当前／上下级经验阈值，按最终总分降序、同分UID升序排列。
- 房主字段、连接序列及独立宠物／称号载体保持各自边界。
- 人物终局奖励与个人CF88发布由该成员自己的合法CF87／延迟终局路径单次提交；队友结果构造负责共享显示数据。
- 终局权威分数先通过既有局内击杀high-water账本归并迟到的队员局内经验，再冻结共享经验快照；局内经验与终局奖励分别记账。
- 请求者持有当前managed epoch的可信F10A时，采用同工作进程 native epoch，并校验成员已知epoch一致性；零击杀请求者通过该行成员自己的当前managed epoch收据归并经验。
- 历史事务构造样本（各值为经验）确认：全队失败／零击杀首次结算时，冻结前归并迟到的90经验，后到收据新增0，两端结果与数据库均为850，队友终局奖励由其个人合法路径提交；默认回归包含此事务边界；受测版本归[验证状态](../../../工程/验证状态/README.md)。
- 成功通关评级最低D/1，失败评级为0。
- 个人先死亡时冻结本人结果行，存活队友的后续分数在其自身终局边界冻结。
- 当前验证等级为静态、适配器构造与数据库事务，发布身份和验证范围归[验证状态](../../../工程/验证状态/README.md)。
- 结果显示与排行榜资格独立判断。
- 全队生命归零后，最后一名参战者的失败请求同时结束同房阵亡成员的观战；已发布个人结果的角色沿用原结算，死亡资源保持冻结，直接退出和显式重试分别处理。
- 队友的零评级保留在各自记录中，本人的有效结算继续发布和保存。
- 每个成员的续关确认都推进自身结算身份，并将资源冻结维持到新阶段的加载确认；重复确认保持单次经验入账。
- 结算发布拥有独立的周期凭据，捕获与异步发布路径共同串行去重。
- 退出请求锁定离场状态，后续战斗及结算请求按离场状态收束。

CF88记录从完整帧+0x0C开始，步长0x34，完整帧安全长度为`12+52×count`（单记录安全长度64）；下表偏移相对单条 `record`，单位为字节。

| record偏移 | 类型 | 作用／现行传值 |
|---|---|---|
| +0x04 | BYTE | 升级表现门控 |
| +0x07 | BYTE | 结算后的副本等级／称号索引 |
| +0x0A | BYTE | 结算后的玩家等级 |
| +0x0C | DWORD | 本次终局增加的经验值 |
| +0x10 | DWORD | 当前经验值；现行适配器为级内经验投影 |
| +0x14 | DWORD | 当前等级下限阈值；现行投影为0 |
| +0x18 | DWORD | 下一等级阈值；现行投影为本级跨度 |

### 副本等级载体

- CF88 同时也是立即获得的副本等级奖励载体。
- 对于本地 UID 记录，`record+0x07` 达到 `0x006FA36E -> sub_40AAF6 -> sub_A72530` 并直接替换账号副本等级；客户端不会根据分数、经验、关卡或难度来计算等级。
- 相同的值稍后必须通过 271A/C355/CF71 来恢复。

### 副本等级映射

- 该值按角色记录提供。
- `hd0/episode15/dungeon2/difficulty2` 的 stage0 对应等级23，stage1 归一化为同一 stage0 前沿，确保超级BOSS只结算一个等级。
- 等级2/st1 状态加载为至少23/st0，并保留更高等级。
- 未知元组使用“字典序严格变强时等级+1”的有界兼容策略。
- 角色死亡结果仍使用 CF88，通关进度增量为0；战斗状态周期去重和 `settlement_sent` 防止重复提交。

### 级内经验投影

- HUD将当前值钳到下一阈值以内，计算无符号的`(current - lower) / (next - lower) * 100`；适配器负责保证`current >= lower`及`next > lower`。
- 原生接收器可消费绝对累计坐标，现行适配器发送`(lower,current,next)=(0,真实累计−本级起点,本级跨度)`的级内投影，64位真实累计单独持久化；不能将record+0x10解释为当前线上发送的绝对累计。
- 人物资料／结算路径从响应读取等级与阈值。
- `record+0x0A`经`0x006FA34E -> sub_40FEE8 -> sub_A72570`写角色等级，非零`record+0x04`在`0x006FA73B`进入升级展示分支，HP/MP由独立资料载体维护。

### 终局经验与资料载体

- 托管适配器采用项目定义的两笔经验奖励与200级KR曲线；曲线、级内投影及授予去重见[经验累计与升级](经验与倍率.md#kb-07-006-1)，具体部署身份归[验证状态](../../../工程/验证状态/README.md)。
- CF88的added字段仅计本次终局新增经验；局内收益已在对应事务持久化。
- 跨级结果使用record+0x04及+0x0A，人物HP/MP由独立载体更新。
- 持久化身份及各页面字段归[准备房所选关卡的最佳评价](评价持久化与排行榜.md#kb-03-010)，静态调用链归[结算和角色资料结果锚点](#kb-08-049-1)。

## 结果/排名向量

D012状态和排名按槽位编号，每个活跃槽位均有记录。双客户端样本观察到`SUCCESS_CLEAR/S`；该样本不替代release的运行验收。

- 分数、结果状态、排名和奖励载体分别维护。
- CF88评级按各成员自己的分数及生存结果计算；已冻结的个人失败沿用其原行，不能因队友后来通关而改写。
- 人物共享结算行、加成归属、去重与验证边界统一由本主题CF87/CF88段维护。
- 原生结果控制器按最终总分优先策略重排人物行；兼容配方及精确位点归[结算按钮与双控制器计时边界](结算操作与控制器.md#kb-08-061-1)和`knowledge/指南/客户端二进制补丁.md`，当前验证等级为静态与隔离指令执行。

- 持久化的“查看成绩”缓存仅保存B/A/S，分别编码为两位打包值1/2/3；C及更低评级保持0，因此不显示评级。
- 普通成绩按章节及逻辑难度索引，秘密成绩使用独立的四章节账本。
- 后续较低成绩不会覆盖已保存的较高评级。

## 结果一致性约束

以下是协议／状态约束，不是全部通过客户端验收的声明。

- 结果／排名按活跃槽位分别构造；
- CF88 等级仍然保持角色资料特定；
- 经验当前值、下限及下一阈值保持一致；
- 结算不应覆盖可编辑的Z/X技能状态；
- 重复拾取不重复提交奖励；容量不足时不生成可领取卡牌记录；
- 自定义评级公式不等于原始适配器行为。

## CF88 结算分数字段与附加分

- CF88结果记录步长0x34，record+0x24为命中分数，+0x28为奖励分数，+0x2C为结算总分，+0x0C为本次人物经验；关系及装备加成计入奖励分数后，总分统一除以4。
- 当前适配器将record+0x1C的score写为与+0x2C相同的击中＋奖励总分，排行榜读取该score；此处属于适配器传值策略。
- 倍率见[翻番卡结算倍率](经验与倍率.md#kb-07-018)，评级见[地宫击杀计分与评级](击杀计分与评级.md#kb-07-009)，排行榜聚合边界见[准备房评级标记与结算排行榜](评价持久化与排行榜.md#kb-07-014)；部署状态归[验证状态](../../../工程/验证状态/README.md)。
- 客户端结算入口、娱乐室原生多人入口及模式选择位点的地址和恢复边界由`knowledge/指南/客户端二进制补丁.md`维护。
