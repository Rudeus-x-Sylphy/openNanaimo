## 经验累计与升级

当前托管适配器的原生地宫路径采用显式适配器策略，角色奖励分为独立的两笔：

- **首次终结击杀**：普通目标和BOSS增加个人绝对分数时发内部F10A。
- SQLite按`角色／拥有会话／managed worker代次／native battle epoch`保留最高已处理分数，发放`floor(新累计分数/4)-floor(原最高分数/4)`。
- 小于4分的余数随累计分数保留，乱序、重复事件及数据库重开保持幂等。
- 普通目标奖励归得分者，BOSS奖励沿用全员计分。
- 奖励授权以首次终结得分变化为准；已提交收益在死亡、离场及重登后保留。

- **合法终局**：CF87/CF88成功或失败结果独立结算。
- 先以个人战斗分数为基数，将已装备AVATA type10/mode1的百分比相加并应用一次（合计上限10000%），再应用本人有效VIP经验卡倍率、同房资格下的情侣戒指倍率及师徒1.5倍；各步按整数向下取整并按u32饱和，原生与托管最终统一钳制到signed32最大总分。
- 加成增加额写入奖励分数，命中分数加奖励分数构成结算总分，人物经验按当前适配器自定义策略统一为`floor(结算总分/4)`，普通与秘密关卡共享该规则。
- 战斗成绩与评级保留各自计分口径。
- 服装权益按已装备状态生效，PA宝石type5属于飞行速度上限而非经验加成，其整数读表导致的低档失效边界见[速度宝石的生效范围](../../宠物/宝石/吸收速度与攻击.md#kb-04-008)，VIP翻番卡必须由[VIP经验卡的主动使用与持久化](../../卡片/兑换/VIP经验权益.md#kb-03-003)的主动使用事务形成未到期权益，仅持卡不加成。
- 失败终局结算人物得分经验，宠物成长、称号及通关进度以成功资格为前提，直接退出按离场事务处理。

- 终局凭据按角色、会话与`NativeBattleEpoch:NativeSettlementCycle`持久去重，快照事务ID与击杀得分账本各自独立。
- 合法失败结果发放本人得分经验并关闭本轮资格；授权CF8B/CF8C建立下一轮，重复确认保持幂等。
- 评级、请求授权、场景和工作进程代次共同校验结果资格。
- 同批交换先提交F10A，再记录CF88的before状态，使最终击杀与终局增加额分别入账；延迟结果同样先持久化后发布。
- 宠物沿用成功结算成长规则。

## 翻番卡结算倍率

- `Sddakg._D35`的十条经验卡定义：`22000001..03`为120%，`22000004..06`为150%，`22000007..09`为200%，每组依次1／2／3小时；`22000010`为300%／1小时且不可在商城购买。
- 百分数是总倍率，不能把名称“翻番”一律解释为2倍；目录最后三项分别为经验效果类别、额外百分比和小时数。
- 主动使用、到期及事务归[VIP经验卡的主动使用与持久化](../../卡片/兑换/VIP经验权益.md#kb-03-003)。

- 人物终局计算顺序为：战斗分数 → 已装备AVATA百分比之和 → 本人未到期经验卡 → 合资格情侣 → 合资格师徒 → 最终总分 → `floor(总分/4)`。
- 与基础战斗分数相比的增量全部进入奖励分数，原有BOSS奖励分数保留；结算score采用击中分数加奖励分数，与最终总分一致，评级仍按未加成的战斗分数计算。
- 宠物经验、Hans和掉卡概率仍走各自规则。
- 局内已经独立发放的首次击杀经验不从终局扣除，也不在这里重算；此叠加顺序属于适配器策略。

## 玩家经验载体和HUD静态调用链闭合 / CN／KR经验位宽与战斗计分对照

- KR `636A00`分派D00E到`636D2C`，`6377E9..6377F9`循环读DWORD+8/+0xC/+0x10并调用`67DCC0`；D012同类读取在`638910..638923`。
- 两版setter覆盖绝对分数而非累加：CN `7489A3..7489A7`、KR `67DCD3..67DCD7`均signed比较参数与-1；CN `748A66..748A79`、KR `67DD96..67DDA9`将绘制字符数限制为7。
- 正分0..2147483647可通过此检查，但超过7位不完整绘制；0x80000000..0xFFFFFFFE按负数拒绝，0xFFFFFFFF是可通过的-1特例，不是有效高额正分证明。

- KR分数临时预览的闭环为：`D00E/D012 → 67DCC0`写三槽绝对分数，`637807/638931 → 67DFC0`排序并匹配本地UID；`67E213 → 930690`读等级，`67E21B`比较0xC8，等级<200时`67E233`乘PE double `AD4A40=0.25`，`67E239`转64位，`67E246 → 6802F0`写manager+0xF98/+0xF9C；等级≥200时`67E257`写两个零。

- 只对合法非负分数可表述为`floor(score/4)`。
- 该函数没有hd、episode、difficulty或奖励装备分支，setter只有这两个直接调用点。
- CN原生临时预览在等级低于80时取本地槽当前总分的25%，后续CN模式取全值、一半或零，HUD叠加后钳到下一阈值；这三种显示值不能作为原服结算倍率表。当前CN兼容项将临时setter输入置零，实时分数和适配器已提交经验继续更新；兼容项应用与回退归[客户端二进制补丁](../../../指南/客户端二进制补丁/README.md)。
- 分数转经验须区分临时预览、应答奖励与适配器策略；人物实际经验仍按本页两笔奖励规则持久化。
- 不能跨版本继承CN的半值分支：KR临时预览倍率固定为0.25，其生成函数不含普通／秘密、关卡／难度、装备或经验卡分支。
- KR地宫CF88分别提供本次人物经验、结算后累计及当前／下一等级阈值；客户端将增量格式化为`+数值`，累计值写入人物状态并清除临时预览，实际经验消费沿用本页独立策略。

- KR `9343C0`直接读取manager+0xF98/+0xF9C；与CN `A76240`不同，它没有selector或除2。
- `7BCC70`在`932760(manager)`返回非零时只显示current，为零时在`7BD227/7BD279`取得temporary，与`73AC50`的current作64位加法，随后钳到next；这是HUD暂存而非结算发奖。
- `486800`写入接收的current后在`48681F/486829`清temporary两DWORD。
- 状态标志不在本结论中强行命名为秘密关卡。

- KR人物结算路径独立于预览：`635A50 → 64D540`构造CF87/12，经`635AC5 → 6340A0 → 989820`发送；请求只包含既有WORD状态及有门控的计时值，不携带经验倍率或算好的奖励。
- 战斗分派器`636A00`从完整帧+6读opcode，CF88在`64499D`进入，WORD+8为count。
- `644F68/644F72`从完整帧`+0x20/+0x24+0x48*i`直接复制本次人物经验至结果临时结构+0x28/+0x2C；`645444 → 692820`将其复制到结果页`this+0x4E8+0xD0*slot`的QWORD，`692BF7 → 6D0D40`按`%I64d`格式化，`AD7B58`的原始4字节是`+%s\0`（IDA误标off，不是指针），后续组成加经验文本。

- 累计经验／阈值进入`4867D0/486800/486840`，没有在这条接收数据流中乘score×0.25或score×0.7。
- 完整布局仍为`0x10+0x48*count`，最高消费至r+0x44的DWORD；接收端按该读取下界执行独立长度校验。

## 地宫经验与升级

- 角色经验分为首次终结击杀收益与合法终局收益，两笔分别持久化、独立去重；已提交击杀收益贯穿死亡、离场及重登。
- 普通状态检查回写持久进度；`--dungeon-state`统一结算确认、持久经验显示与BOSS权威血条，实时得分、最终评级及奖励分别维护生命周期。
- 奖励资格、倍率和公式见[经验累计与升级](#kb-07-006-1)。

- 结算以明确奖励值推进累计经验，由同一阈值表计算等级、基础HP/MP及攻防成长投影；旧五属性和未分配点保持现值，当前资源按存活、跨级及终局状态处理。
- 结算结果界面、后续准备房、回城资料和重新登录统一读取提交后的等级与经验；重复结算与延迟状态保持已提交经验与最新值。
- 旧版结算记录继续按结算前后正向差量恢复，保持已有存档可恢复性。
