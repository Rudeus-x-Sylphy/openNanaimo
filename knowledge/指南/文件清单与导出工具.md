# 文件清单与导出工具

`scripts/export_patch.py` 根据明确的文件清单导出项目组件。默认只盘点，不创建输出目录。它不安装游戏，也不构建适配器。执行这些 Python 命令前，请按 [运行依赖的工具准备说明](运行依赖.md#python-与-tinycc-的准备方式) 自行安装解释器并配置 PATH；仓库不附带 Python 或 TCC。

<!-- FUSION END df-13-001 -->

## 文件层

| 层 | 当前内容 |
|---|---|
| `runtime` | 启动脚本、适配器和运行支持代码 |
| `source` | C／include闭包、构建与校验脚本、源码清单及精确列名的迁移审计材料 |
| `knowledge` | 基础、业务、工程、操作指南与带标签的历史记录；全部文档的统一目录 |
| `docs` | 根目录README；保留为兼容选择入口，并依赖完整knowledge层 |
| `python`、`tcc` | 显式选择的外部工具候选层；仓库不附带或自动下载工具 |
| `testports` | 显式选择的隔离测试端口适配器 |

默认选择`runtime,source,knowledge`。文档依赖递归展开，选择`docs`或`knowledge`均包含README与完整知识库；可选工具和测试端口层不自动选择。源码文件的数量、大小和摘要以`manifest/source_closure.json`为准。

运行前提见[运行依赖](运行依赖.md)，主题入口见[知识库索引](../README.md)。原有三层定义与文件层表完整保留在[历史导出约定](../工程/历史验证/文档导出旧约定.md#df-13-002)，不作为当前规则来源。

## 外部工具与可选层

默认层以及 `--layers source,knowledge` 都不选择 `python`／`tcc`，因此无需为盘点或源码完整性检查恢复这两个工具目录；执行脚本使用自行安装的命令行 Python。导出的 C 源码要编译时，仍需使用者自行准备兼容 TCC。

仓库候选清单不附带第三方工具文件记录。`python`／`tcc` 仅是导出器支持的可选层接口；未显式加入工具候选记录时，选择这些层会得到空层提示并阻止写出。需要单独导出工具时，应提供实际文件、使用显式 `--add` 加入记录，并完成许可材料核对及逐文件审核。不能仅靠补一个 EXE、刷新哈希或加入 Git 忽略规则满足导出条件。

仅导出的 `source,knowledge` 目录可执行源码完整性检查，但不含 GUI 运行脚本及工具，不能直接执行完整测试集。随层导出的工具脚本也不代表其默认输入都在输出中，例如再次运行导出器还需要独立提供候选清单。构建与测试的完整前提见 [构建与验证](构建与验证/README.md)。

## 盘点

```powershell
python -B scripts/export_patch.py
python -B scripts/export_patch.py --dry-run --layers source,knowledge
python -B scripts/export_patch.py --layers docs
```

盘点结果输出为JSON。退出码0表示盘点完成，是否可以导出需查看 `export_ready`。缺失文件、哈希不符、闭包缺项或未完成逐文件审核时，写入操作会被拒绝。

`manifest/patch_allowlist.json` 保存候选文件的路径、层、大小和SHA-256。候选清单不是授权记录。`manifest/patch_runtime_requirements.json` 说明独立于源码构建的运行依赖。

## 审核文件格式

`--review-file` 指定与文件哈希对应的审核结果，例如：

```json
{
  "schema_version": 1,
  "files": [
    {
      "path": "knowledge/指南/文件清单与导出工具.md",
      "sha256": "REPLACE_WITH_EXACT_REVIEWED_64_HEX_SHA256",
      "privacy_reviewed": true,
      "provenance_reviewed": true,
      "redistribution_approved": true,
      "license_choice": "LicenseRef-Rights-Holder-Selected-Terms"
    }
  ]
}
```

每个选中文件都需要匹配的哈希及有效条款标识。`pending`、`unknown`、`none`、`unlicensed`不是有效的许可选择。文件内容变化后，原哈希对应的审核不再适用。第三方组件还需要相应许可与声明文件。

## 写入输出目录

目标目录须位于源目录之外且尚不存在：

```powershell
python -B scripts/export_patch.py --layers source,knowledge --review-file ..\review.json
python -B scripts/export_patch.py --layers source,knowledge --review-file ..\review.json --write --dest ..\nanaimo-source
python -B ..\nanaimo-source\scripts\verify_package.py --root ..\nanaimo-source --source-only
```

导出器先检查全部输入，再逐文件复制并重算哈希。成功后生成 `PATCH_EXPORT_COMPLETE.json`；中途失败时保留 `PATCH_EXPORT_INCOMPLETE`，不会自动清理或覆盖已有目标。

## 候选清单更新

```powershell
python -B scripts/refresh_patch_manifest.py --help
```

刷新工具以已有清单和源码闭包为输入，核对当前文件并更新候选哈希。它不扫描任意目录加入文件，也不自动生成审核结果。新增文件通过显式的 `--add LAYER:relative/path` 指定。

## 完整性与路径检查

- 使用仓库相对POSIX路径，拒绝路径穿越、绝对路径、通配符、ADS、Windows设备名及大小写重复。
- 拒绝符号链接、junction／reparse point、硬链接和非普通文件。
- 检查源码记录的count、唯一性、size／SHA-256及本地quoted include依赖；实际编译仍由构建脚本完成。
- 不导出运行存档、日志、缓存、实验原始记录和游戏素材；目录名或审核标志不能绕过路径策略。
- 复制前后均检查哈希；源和目标应避免并发修改。该工具不提供对抗恶意并发文件系统操作的安全保证。

## 结果含义

- 导出完成只表示选中的项目文件满足工具检查，不表示运行依赖齐全或游戏功能已验证。
- 运行状态字段 `runtime_status=blocked`、`runtime_acceptance=false` 和 `complete_playable_game=false` 说明导出器未启动客户端。
- `binary_delta_implemented=false` 只表示导出器不生成客户端二进制差分；本仓库另有 `scripts/prepare_client_compatibility.py` 从使用者自己的文件派生兼容产物，且这些产物不做固定哈希门禁。

## 融合后的导出目录和候选迁移

当前文件层按以下统一目录规则使用：全部指南、基础机制、业务规则和工程主题都属于 `knowledge` 层；`docs` 层仅保留根目录 `README.md`。原 `docs/` 路径不再是有效导出候选。

`--layers docs` 继续作为文档导出的兼容入口，递归展开后同时选择 `knowledge`；选择 `knowledge` 也会包含 README。`runtime`、`source`、`testports` 依赖文档入口，因此同样带上完整知识库，保证指南与事实页之间的链接可用。默认仍为 `runtime,source,knowledge`，不会自动选择可选工具层或测试端口层。目录统一不会自动增加候选文件，每个新页面仍须显式登记。

指南根页面与 `level200` 保留既有结构；职责子页只允许 `scripts/export_patch.py` 中 `KNOWLEDGE_TOPIC_DIRECTORIES` 精确列出的主题目录，包括构建指南、业务主题、工程兼容／资源／启动及历史验证主题，以及DIY根目录与子弹／NPC／地宫／任务四个子目录、工程子弹DIY兼容目录、指南修道僧四村对白安装目录。额外目录深度、任意新目录、非 Markdown 素材及私有数据仍拒绝；合格路径仍须逐文件加入候选并按当前路径／摘要审核，目录资格不等于导出授权。

刷新工具按脚本内的 18 个精确路径映射将已有旧文档候选替换为新路径，并重新计算新文件的 size／SHA-256；映射与 `manifest/document_fusion.json` 的 `path_mapping` 一致。未列名旧文档路径会被拒绝，新路径缺失也会拒绝刷新，不从旧文件回退。候选报告会分别列出新路径增加与旧路径清退，旧路径的审核记录不能批准新路径，新内容仍须逐文件审核。

新增融合审计材料通过精确路径加入 `source` 候选：

```powershell
python -B scripts/refresh_patch_manifest.py --add source:manifest/document_fusion.json --add source:manifest/document_fusion_baseline.json.gz --add source:scripts/verify_document_fusion.py --add source:scripts/test_verify_document_fusion.py --dry-run
python -B scripts/verify_document_fusion.py
```

- 上述盘点命令不会写入候选清单；审阅报告后，使用刷新器的 `--write` 更新候选哈希。
- 原 `manifest/knowledge_migration.json` 和 `manifest/knowledge_baseline.json.gz` 的历史审计用途保持不变；这两份材料及两份融合材料按精确名称允许导出，其他 JSON 或压缩包不能借用该规则。
- 文档候选只收纳当前知识页、操作指南及其证据边界，不包含审查问题清单、过程稿或检查日志；尚待维护者决定的事项在所属知识页维护。
- 原文覆盖审计的维护要求见[知识维护](../工程/知识维护.md)。
