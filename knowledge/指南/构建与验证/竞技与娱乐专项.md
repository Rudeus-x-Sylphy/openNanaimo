# 构建与验证／竞技与娱乐专项

## 作用与执行条件

执行竞技场、娱乐室与准备房专项，说明构造／事务／隔离指令的覆盖边界。命令均从仓库根目录执行；受测程序、工具链、输入和通过／失败／跳过结果分别登记。

## 娱乐室专项

```powershell
dotnet run --project tests/MentorshipRegression -c Release -- --entertainment-only
python -B scripts/test_entertainment_difficulty_client.py
python -B -m unittest discover -s scripts -p test_entertainment_result_client.py -v
```

- 娱乐室专项覆盖1至6人列表及离房人数、个人最高分保存／提升／重开／游戏类型隔离、1至6人全部21种名次宠物经验及无效人数／名次拒绝、成功三盘领取门槛（零／一／二盘不给、三／四盘发放、失败／超时／重复／迟到不计、本人资格隔离、新局重置及原排名保留）、当前持久阶段与升级／变身、400张奖池及黄金粉卡排除、1500目标载体、连击与实际积分分离、仅幸运积分发卡、分数跨1500／3000／4500不发卡、跨局余量与CF6F显示同步、重复／冻结／新轮边界、超过三张入库和数据库回滚。
- 零经验宠物覆盖全目录首局与第二局单人奖励及全部名次比例；数据库与CF86核对结算后的实际经验。该测试不把客户端显示90%的玩家反馈认定为已复现，也不证明原客户端在4500分附近无闪退。
- 客户端兼容专项仍覆盖全部420个基础卡号在三个预览槽的原生调用身份，兼容范围与娱乐室400张抽奖范围分别维护。
- 验证层级为适配器构造、事务和隔离x86执行；当前规则见知识库[娱乐奖励](../../业务/娱乐/奖励/README.md)与[娱乐对局](../../业务/娱乐/对局.md)，房间纪录与人数见[娱乐房间](../../业务/娱乐/房间/README.md)，结果字段见[娱乐结果消费链](../../业务/娱乐/奖励/结果排名与版本字段.md#kb-08-018-2)，发布及客户端联合验收见[工程／验证状态](../../工程/验证状态/README.md)。

- `EntertainmentLobbyChecks.cs`另外覆盖CF0C身份／最高分分离、CF14个人纪录与排行两页／空槽／玩法隔离、CF1A真实性别与十人双向分页、CF8F真实辅助通道路由、目标昵称与UID一致性、CF90密码令牌、屏蔽后接受拒绝，以及CF75加入密码房。
- CF6D／CF76准备房最高纪录覆盖真正的分数／持有者而非房主UID／昵称，CF6F真实身份与1500目标保持；奖励专项另覆盖无成绩0／空名、已保存4558分重建及未玩类型隔离。
- 验证层级为适配器构造；准备房、邀请和排行榜使用各自独立的显示字段。

## 天空竞技场专项

```powershell
dotnet run --project tests/ArenaRegression -c Release
python -B -m unittest discover -s scripts -p 'test_arena*.py' -v
python -B scripts/generate_arena_targets.py --check
```

- 竞技目标目录由`generate_arena_targets.py --client-root <用户自备客户端目录>`生成，记录六图18槽的SSTG／SMMO／MMO／EFF身份；无外部客户端时`--check`核对已登记目录。
- 生产构造检查包括铜猪变形、最终障碍、圆球HP、星星／道具、致死权威分数转移、队伍胜负、奖励事务、共享重置及多轮／离场；准备房周期检查覆盖三轮名单重建、双向激活、同轮去重、端点保留及离房重组。
- `DeliveryEpochChecks.cs`另用真实TCP写入器验证旧广播D015和直接CF98丢弃、旧CF8A不得跨下一局开始、当前CF8C／CF80发送、丢弃不消耗S2C序列，以及原连接离房再入和异步结算等待的双重代次保护。
- 结果页补丁采用隔离x86执行，`test_arena_round_boundary_client.py`覆盖150组清理条件及胜败计数的原生写入，并分别在结果进入／CF8C复赛边界执行原生旧state7停止分支与复位指令；胜方零值／连续败场独立复位、全部已登记旧复赛与结束清理编码迁移及未知冲突拒绝属于隔离指令和PE派生验证，不替代原客户端双端画面验收。

### 成套构建约定

运行程序、原生bridge、DCC7战斗目录、HP／计分表及兼容配方使用同一源码版本。构建前校验资源摘要，成套输出通过后更新运行清单、源码闭包、活动发布清单和导出候选身份。完整构建命令见[完整适配器构建](托管与完整构建.md#df-14-010)，客户端及资源安装步骤统一见[客户端二进制补丁](../客户端二进制补丁/README.md)。

L7派生输入按HP资源表的实际依赖纳入源码闭包，包括`audit_l7_combat_resources.py`、`generate_boss_contact_catalog.py`、`generate_l7_combat.py`和`test_l7_combat_resources.py`。导出按精确允许集合及逐文件审核执行。构造检查使用独立请求屏障确认每次动作的全部结果，测试进程与玩家会话各自使用独立状态和端口。

启动式自检在固定测试端口空闲的独占环境执行。Windows PowerShell 5.1的原生命令输出由外层调用统一接收，保持警告与退出码的独立语义。验证层级为构建、适配器构造及隔离指令执行，客户端联合验收范围归知识库[工程／验证状态](../../工程/验证状态/README.md)。
