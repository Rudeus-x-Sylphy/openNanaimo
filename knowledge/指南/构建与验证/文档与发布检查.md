## 源码依赖闭包与发布包

```powershell
python -B scripts/refresh_source_manifest.py
python -B scripts/verify_package.py --source-only
python -B scripts/verify_package.py
```

- 当前源码闭包数量以 `manifest/source_closure.json` 的 `count` 为准，runtime数量以 `adapter_runtime/adapter_manifest.json` 的 `files` 实际条目为准（清单自身另计）；`open_release_manifest.json`逐项登记当前发布关键文件。
- 运行脚本按可用.NET引用程序集选择net6.0或net8.0，也接受显式 `-TargetFramework`；当前发布使用net8.0/win-x64 self-contained。
- 验证器核对大小、SHA-256、递归include、活动runtime清单和公开文本，不在本文维护另一套当前文件计数。

完整package对使用者自备的 `game.exe` 执行存在性检查，对项目运行文件执行大小及SHA-256校验。源码验证使用`--source-only`；完整包验证要求目标目录提供合法取得的客户端。两种验证模式分别记录结果，`ValidateOnly`覆盖启动契约，客户端操作采用独立验收。

成套程序与PET资源更新由`deploy_pet_catalog_update.py`维护安装预检、审核授权、逐文件备份、安装回执及恢复。`--reviewed-before`以相对路径到旧文件SHA-256的审核映射授权清单外既有文件，当前字节须与登记摘要完全匹配；`--rollback`按安装回执维护恢复约定。

<a id="9-发布清单"></a>

## 发布清单

```powershell
python -B scripts/refresh_manifest.py
python -B scripts/refresh_patch_manifest.py --dry-run --summary
```

`open_release_manifest.json` 维护活动发布事实。`patch_allowlist.json` 维护候选文件、逐文件身份与审核状态；刷新只更新候选文件身份，不生成审批；既有逐文件审核仍须与当前路径／哈希匹配。

<a id="10-发布前检查"></a>

## 发布前检查

```powershell
git diff --check
```

`git diff --check` 检查补丁中的空白错误，本节只保留该空白检查；包验证命令见上文[源码依赖闭包与发布包](#源码依赖闭包与发布包)。包验证器检查声明文件、源码闭包、运行清单及公开文本中的私有路径等问题，不读取 Git 提交信息。完整包验证还要求使用者自备客户端。发布结果按当前实现、宿主构造、隔离执行及产物约定分别登记。
