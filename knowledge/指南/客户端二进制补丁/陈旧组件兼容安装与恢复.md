# 陈旧组件兼容安装与恢复

## 输入与配套文件

使用自行提供的客户端目录及同版项目运行包。原版和已有原生布局的资格见[陈旧组件启动兼容](../../工程/客户端兼容/陈旧组件启动兼容.md#输入资格)。

| 文件／目录 | 用途与身份 |
|---|---|
| 客户端目录中的`game.exe` | 转换与补丁的安装对象。 |
| `adapter_runtime/`及`adapter_manifest.json` | 自包含托管工具、程序集、原生桥接和配套资源，逐文件身份以活动运行清单为准。 |
| `managed-host/Resources/client-startup.json.gz` | 完整结构转换资源，49,152字节，SHA-256 `C2B40C07269709A98517366DB796CB3CB87C8EB179E445146341C16E7AE53404`；发布适配器内嵌同一资源。 |
| `managed-host/Resources/client-compatibility.json` | 十处启动／接口位点及项目业务兼容的精确字节配方，发布适配器内嵌同一配方。 |
| `manifest/patch_runtime_requirements.json` | 原版转换身份、GUI选择项和依赖契约。 |
| `manifest/source_closure.json`、`manifest/open_release_manifest.json`、`manifest/patch_allowlist.json` | 源码、发布和导出身份，与运行包成套安装。 |
| `adapter_data/client_compatibility_overlay/` | 覆盖文件、兼容报告及按内容摘要保存的本地备份。 |

本项的安装文件集合为`game.exe`；转换内容从使用者的输入文件和内嵌配方派生。GUI选择的家具、地宫、库存及章节等业务兼容项各自携带资源契约，完整依赖由本目录相应安装页维护。

## 二进制转换清单

| 区域 | 执行内容 |
|---|---|
| PE头与节表 | 重建文件布局、原生入口及导入目录；恢复后基础文件长度`14,198,272`，图像基址`0x00400000`。 |
| 原有9个节 | 复制4个原始数据块，校验并解压5个AP32数据块；保留原有RVA，按目标节表写入。AP32同时校验压缩／解压长度和CRC-32。 |
| 内嵌映像的6个数据块 | 从输入文件偏移`0x00887FD8`的结构描述读取文件数据，映射到目标文件区域；应用11,324处`HIGHLOW`重定位。 |
| 固定写入区 | 按转换资源中的329个`writes`区间恢复PE头、导入项、代码入口和固定数据；每项完整字节保存在同一资源的Base64字段。 |
| 入口RVA | `0x009BC17B`转换为`0x00750C03`，进入原生CRT启动链。 |
| 主函数调用VA `0x00B50B95` | `E8 87 BA 8B FF`替换为`E8 46 94 8E FF`，调用`0x00439FE0`。 |
| 浮点初始化VA `0x00B4ED97` | `74 0B`替换为`90 90`，执行该初始化分支。 |
| 对象创建VA `0x00A6B03E` | `E8 53 41 9A FF`替换为`31 C0 90 90 90`，创建结果置零，保留构造器原有字段初始化。 |
| 对象销毁VA `0x00A6B060` | `55 8B EC`替换为`31 C0 C3`，返回0。 |
| 接口创建VA `0x00A6AB20` | `55 8B EC 51 89 4D FC 8B 45 FC A3 84 36`替换为`89 0D 84 36 D7 00 31 C0 89 01 8B C1 C3`；写入全局对象地址、清空对象首字段，并返回对象。 |
| 接口销毁VA `0x00A6AB60` | `55 8B EC`替换为`31 C0 C3`，返回0。 |
| 接口设置VA `0x00A6AB90`／`0x00A6AC80` | 各自将`55 8B EC 81 EC`替换为`31 C0 C2 04 00`，返回0并清理4字节参数。 |
| 原生模式VA `0x00A6AD80` | `55 8B EC B8 30 10 00 00`替换为`B8 02 00 00 00 C2 04 00`，返回2并清理4字节参数。 |
| 原生后续分支VA `0x00A6AED0` | `55 8B EC 81 EC 70`替换为`83 C8 FF C2 0C 00`，返回-1并清理12字节参数。 |

原版结构转换阶段输出SHA-256为`786E70B6AFE815B9DE4D494A5A338D48C03F843027BE2B5EBD7918725FFEBC01`。十处启动／接口位点及所选业务补丁在此基础上继续应用，最终`game.exe`身份记录于本机兼容报告。已有原生布局保持现有PE结构，按十处启动／接口位点及所选业务配方校验。

## 转换资源格式

GZip内层为`schema=1`的JSON：`input_size/input_sha256`锁定原版输入，`output_size/output_sha256`锁定结构转换结果；`blocks`逐项记录`codec/source/length/output/take`，分别表示复制或AP32解压、源偏移、源长度、输出偏移和写入长度；`relocations`列出全部四字节重定位位置，`relocation_delta`用于32位加法；`writes`按偏移递增列出`offset`及Base64编码的完整`data`。运行顺序为分配零填充输出、处理全部数据块、处理全部重定位、处理全部固定写入区，再校验输出摘要。可变映像中的本机路径缓冲按配方归零。

完整329项固定写入和11,324项重定位清单可直接读取随仓库提供的资源：

```powershell
python -c "import gzip,json; from pathlib import Path; print(json.dumps(json.loads(gzip.decompress(Path('managed-host/Resources/client-startup.json.gz').read_bytes())),indent=2))"
```

维护转换资源时，`scripts/build_client_startup_recipe.py`使用`aplib`和`pefile`读取原版与固定原生基线。原生基线为`14,198,272`字节，SHA-256 `6E3985CB7BEBA0207DEB6201BFB05D01CF8D548D3B674D8E6BD6A6F2DEB72B90`；生成器校验两项输入、规范化可变路径缓冲、校验完整输出并写入固定时间戳GZip资源。设置`$Original`和`$NativeBaseline`为这两份文件后执行：

```powershell
python -B scripts/build_client_startup_recipe.py --source $Original --baseline $NativeBaseline
python -B scripts/generate_managed_compatibility_recipe.py
```

资源生成后按本页资源摘要核对，再按完整构建流程生成适配器及发布清单。安装使用同版运行包内嵌的转换资源。

## 安装步骤

1. 结束目标目录的客户端，保留完整客户端和当前运行包备份。
2. 将同版GUI、运行包和清单部署到该客户端目录，启动GUI，选择账号并执行本地进入或社交参与。两种入口均自动执行陈旧组件兼容准备。
3. 兼容工具先完成全量预检和内存派生，再将原客户端保存到`backups/<原文件SHA-256>/game.exe`并替换目标文件。确认报告的布局转换、十项启动／接口兼容操作、`verification.all_pass=true`及应用结果。
4. 使用同版GUI继续启动。重复执行时，已匹配启动位点保持`changed=false`。

单独安装本项时，可在PowerShell中使用以下命令；变量`$Client`与`$Tool`分别设为目标客户端目录和同版适配器完整路径：

```powershell
$Overlay = Join-Path $Client 'adapter_data/client_compatibility_overlay'
& $Tool --tools compatibility --source-root $Client --output-root $Overlay --legacy-startup --dry-run
& $Tool --tools compatibility --source-root $Client --output-root $Overlay --legacy-startup --overwrite --apply
```

第一条命令检查输入并报告拟生成结果；第二条命令创建覆盖文件、备份并应用。完整GUI安装继续使用其全部业务选择项。资源源码编译时，保留上述两个内嵌资源并按[完整构建](../构建与验证/托管与完整构建.md#完整适配器构建)生成运行包。

## 恢复步骤

1. 结束目标目录客户端，读取兼容报告的原文件摘要和`backups/<摘要>/game.exe`，核对备份实际SHA-256与目录摘要一致。
2. 将当前`game.exe`单独备份，使用原文件备份替换目标文件，复核恢复后SHA-256。
3. 将GUI、运行包及清单恢复到所选发布的成套版本。完整业务兼容同时按对应安装页恢复资源及其回执。
4. 再次选择本版GUI进入时，启动器按恢复后的文件重新执行转换和兼容准备。

验证范围见[当前验证归属](../../工程/验证状态/层级与版本归属.md#陈旧组件启动兼容验证)。
