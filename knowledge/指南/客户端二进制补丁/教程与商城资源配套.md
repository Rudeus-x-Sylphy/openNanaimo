## 程序位点

以下均为PE32虚拟地址，文件偏移按`PointerToRawData + VA - (ImageBase + VirtualAddress)`映射。工具逐字节校验原值、登记旧版或目标值，代码区完整跨度一起校验。

| VA／跨度 | 应用内容 |
|---|---|
| `0x742DF1`／7字节 | `83 B9 08 01 00 00 00`改为`83 B9 0C 01 00 00 00`，血条判零读取对象+0x10C |
| `0x742E12`／6字节 | `DB 80 08 01 00 00`改为`DB 80 0C 01 00 00`，血条宽度读取对象+0x10C |
| `0x742D00`／32字节 | 原设置器25字节及7字节CC替换为`A1 80 F2 D6 00 83 38 0E 8B 54 24 04 89 91 08 01 00 00 75 06 89 91 0C 01 00 00 8B C1 C2 04 00 CC`；state14同步本地量到显示字段，保留this与ret4 |
| `0x742D07`／1字节旧版迁移 | 已安装state12配方的`0C`迁为`0E`；完整32字节按登记旧配方匹配 |
| `0x927BCC`／3字节 | `00 00 00`改为`02 02 02`，选宠模式0／1／2按单行提示绘制，mode11沿用三行布局 |
| `0x8C4B67`／5字节 | `E8 17 05 B4 FF`改为`E8 D4 31 00 00`，余额格式刷新转入兑换预览处理 |
| `0x8C7D40`／320字节 | 原CC区写入购物车遍历与64位预计Nana累加，再调用原`0x405083`格式刷新 |
| `0x41E0E7`／5字节 | `E9 24 EB 69 00`改为`E9 94 9D 4A 00`，图像工厂入口转入精确图标映射 |
| `0x8C7E80`／320字节 | 原CC区写入图像包3＋摇钱树完整路径匹配，命中时切换为图像包8；其余参数与调用透传 |

两个320字节区域的完整指令由`scripts/nana_exchange_compat.py`生成，精确原／目标字节随`managed-host/Resources/client-compatibility.json`及运行包内嵌配方发布。教程血条完整原／目标字节另见[BOSS血条](../../工程/客户端兼容/BOSS血条.md)。

## 安装顺序

1. 核对本版源码、关键文件和运行包身份，确认目标目录已具备配方要求的宠物、装扮及图标资源。首次资源安装先执行上表链接的完整资源流程。

```powershell
python -B scripts/verify_package.py --source-only
python -B scripts/package_korean_resource_kit.py verify --archive resource-packs/nanaimo-korean-resource-kit.zip
python -B scripts/package_wardrobe_resources.py verify
```

2. 执行成套部署预检及安装。安装器读取全部清单、核对目标已有身份，备份差异文件并生成`deployment_backups/pet-catalog-<id>/receipt.json`。五张客户端根目录表与对应运行目录表成套写入，PET与英雄龙收据同步登记。

```powershell
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>'
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>' --apply
```

3. 按内嵌配方预检并应用客户端兼容项；`--dungeon-state`同时包含本页程序位点和该组既有兼容项。

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<overlay-root>' --dungeon-state --dry-run
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<overlay-root>' --dungeon-state --overwrite --apply
```

4. 检查兼容报告`verification.all_pass=true`、全部位点目标字节、PE文件长度及安装后摘要。程序原字节按应用前SHA-256保存到`<overlay-root>/backups/<原SHA-256>/game.exe`；再次预检已应用位点为`changed=false`。运行包内嵌配方与Python派生保持一致。

5. 核对客户端根目录五张表与运行目录对应文件SHA-256，执行PET安装检查及启动器离线检查：

```powershell
python -B scripts/prepare_korean_pets.py --client-root '<client-root>' --verify-installed
powershell -NoProfile -ExecutionPolicy Bypass -STA -File '<client-root>/gui_launcher/nanaimo_launcher.ps1' -ValidateOnly
```

资源独立派生使用`scripts/prepare_clover_descriptions.py --source <gi-input> --output <gi-output>`、`prepare_nana_exchange.py --source <ie-input> --output <ie-output>`；PET及装扮排序由`prepare_shortcut_shop.py`按配方生成。完整发布以成套部署后的资源身份为准。

## 恢复

退出对应客户端与服务后，先按[统一恢复](统一安装与恢复.md#4-恢复)校验并恢复客户端完整程序备份，再恢复同批运行包、资源与清单。成套部署使用原收据逆序恢复，并逐文件验证当前值与备份身份：

```powershell
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>' --rollback 'deployment_backups/pet-catalog-<id>/receipt.json'
```

首次PET及装扮安装按各自原始事务恢复。回退后重新核对程序位点、五张表、资源配方与清单，角色数据按相同曲线及状态版本配套。
