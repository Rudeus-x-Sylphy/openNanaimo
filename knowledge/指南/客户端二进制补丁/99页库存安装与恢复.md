# 客户端二进制补丁／99页库存安装与恢复

本页维护99页库存的程序派生、文件清单、成套安装、核对及恢复。容量、免费页和扩充期限归[扩充券与期限](../../业务/库存/消耗品/扩充券与期限.md#背包页数与大容量改造边界)，IN99/v1字段归[实例身份与持久化](../../业务/库存/物品实例/实例身份与持久化.md#99页协商与扩展载荷)，验证层级归[库存验证](../../工程/验证状态/文档与静态调查记录.md#背包大容量调查)。

## 配套文件

命令从完整仓库根目录执行。`<client-root>`为目标客户端目录，`<work-root>`为本次新建的独立派生与备份目录；所有输出文件使用新路径。准备Python 3、仓库内TinyCC及匹配的客户端，指令检查另需Unicorn，宿主回归另需.NET 8 SDK。

| 文件或目录 | 用途与安装位置 |
|---|---|
| 目标客户端`game.exe` | 本机派生输入；安装时由完整99页输出替换，原文件逐字节备份 |
| `scripts/inventory_pages_compat.py` | 第一阶段：四类普通背包99页上限、免费页判断及总页数显示 |
| `scripts/inventory_storage_compat.py` | 第二阶段：真实库存、完整实例身份、家具索引与IN99/v1协商；内置可逆位点记录 |
| `scripts/prepare_client_compatibility.py`及同版`scripts/`依赖模块 | PE位点映射、逐字节校验与原子写入；使用完整仓库中的同版工具 |
| `release/components/client_inventory_storage.c` | 编译并嵌入客户端的库存扩展实现 |
| `tools/tcc/`完整目录 | 编译器及配套文件；入口`tools/tcc/tcc.exe` |
| `adapter_runtime/`完整目录 | 同版Adapter、Gameplay、原生工作进程、依赖程序集、目录资源及`adapter_manifest.json` |
| `manifest/source_closure.json`、`open_release_manifest.json`、`patch_allowlist.json` | 源码闭包、发布身份和导出文件身份，与本版运行包成套保留 |
| `scripts/test_inventory_pages_compat.py`、`test_inventory_storage_compat.py`、`tests/InventoryStorageRegression/` | 页数、指令及1386格宿主回归 |
| 五张客户端目录表与PET／装扮资源包 | 与本次商城更新配套安装，完整文件和资源归[教程与商城资源配套](教程与商城资源配套.md#配套文件) |

99页扩展使用既有背包界面与图像资源，新增内容为客户端内`.inv99`区段及同版程序文件。宠物商城更新替换`pi._D7`和对应目录、配方及资源包，按下一节完成成套部署。

## 程序位点

页数阶段共15项，均按PE32虚拟地址校验。免费页为衣物／宠物2页、道具／家具4页；`0x7F55C9`保留原99页钳制。

| 范围 | 位点与目标 |
|---|---|
| 最大页数8处 | `0x7F533D/0x7F5382/0x7F53C7/0x7F5409/0x7F5789/0x7F57CE/0x7F5813/0x7F5855`，目标99 |
| 免费页判断2处 | `0x7F5629/0x7F5A1B`，按控制器类型独立判断2／4页 |
| 总页数显示4处 | `0x814615/0x814630/0x81464B/0x814666`，目标`push 99; pop eax; nop`，保留随后局部变量写入、栈与标志 |
| 代码区1处 | `0x544800..0x5448FF`，完整256字节校验 |

普通标签渲染入口为`0x813BC0`；总页数原读取`BYTE this+117..120`，写入`[ebp-0x2C]`，经`0x81466D`两位数分支及`0x814681 -> 0xB4C90D`转换绘制。旧255页配方按完整12项匹配后迁移为当前配方。

存储阶段共73处位点，新增`.inv99`区段承载编译代码、适配入口和恢复元数据。覆盖列表WORD计数／尾部期限、选中PET、快捷栏移除身份、粉末与宝石身份、充能页、家具TakeOff／快照索引及情侣物品身份。原粉末调用点`0x809E3C/0x80A909`改为DWORD读取；扩展函数入口包括`0xADA3E0/0x819C90/0x7F4FB0/0x7F5070/0x805FC0/0x54EC40/0x82D0B0`。每处原字节与目标字节由工具的位点表及输出文件内`IN99META`元数据完整登记。

当前已校验的99页控制器输入为14,198,272字节、SHA-256 `F95C63B32FAAC461AF766B0E1C99A3E0459D7DDA1D01246B463EAF09482831C5`；完整存储输出为14,221,824字节、SHA-256 `C2401712DC2A9DF84A30C93C46E554253006B113F2B6FC866AC0BBA5354337B2`。这些摘要标识对应构建；工具对目标客户端执行逐位点校验，并记录该次输入及输出摘要。

## 生成与安装

1. 退出目标客户端、启动器、适配器及工作进程。将当前`game.exe`、运行目录、发布清单、客户端目录表、资源安装收据及角色数据库完整备份到`<work-root>/before/`。备份数据库时一并保存同名SQLite辅助文件，恢复使用同批快照。

2. 核对仓库发布与资源包身份，然后按[教程与商城资源配套](教程与商城资源配套.md)执行目标资源首次安装或版本更新。成套部署命令如下，首次资源的完整输入与路径由该页及所链接资源表枚举。

```powershell
python -B scripts/verify_package.py --source-only
python -B scripts/package_korean_resource_kit.py verify --archive resource-packs/nanaimo-korean-resource-kit.zip
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>'
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>' --apply
```

3. 对备份的程序先派生页数控制器，再派生完整存储扩展。生成时保留目标客户端已有的配套兼容项，库存扩展采用这两个显式工具安装。

```powershell
python -B scripts/inventory_pages_compat.py --client '<work-root>/before/game.exe' --output '<work-root>/game-pages99.exe'
python -B scripts/inventory_storage_compat.py --client '<work-root>/game-pages99.exe' --output '<work-root>/game-inventory99.exe'
Get-Item -LiteralPath '<work-root>/game-inventory99.exe' | Select-Object Length
Get-FileHash -Algorithm SHA256 -LiteralPath '<work-root>/game-inventory99.exe'
```

4. 核对两次输出的`input_sha256/output_sha256`、`max_pages=99`、`slots=1386`和存储位点`sites=73`。把派生输出及工具结果与本次备份一同保留；将完整输出安装为目标`game.exe`并比较摘要。

```powershell
Copy-Item -LiteralPath '<work-root>/game-inventory99.exe' -Destination '<client-root>/game.exe'
Get-FileHash -Algorithm SHA256 -LiteralPath '<client-root>/game.exe'
python -B scripts/verify_package.py --root '<client-root>'
python -B scripts/prepare_korean_pets.py --client-root '<client-root>' --verify-installed
```

5. 启动同版适配器时自动迁移`CharacterQuickSlots.InventoryIndex`与`CharacterApartmentItems.SlotIndex`到0..1385，保留现有有效行。新客户端请求按IN99/v1协商后使用完整库存；旧连接继续接收对应旧格式。角色数据、客户端和运行包作为同一部署批次维护。

## 核对

```powershell
$env:NANAIMO_TEST_CLIENT = '<client-root>/game.exe'
python -B -m unittest discover -s scripts -p test_inventory_pages_compat.py -v
python -B -m unittest discover -s scripts -p test_inventory_storage_compat.py -v
.\.dotnet\dotnet.exe run --project tests/InventoryStorageRegression -c Release
```

页数检查覆盖四类、两种期限状态、99页双向翻页与总页数显示。存储检查覆盖完整身份、行后期限、请求协商、家具全部索引读取、栈／标志、幂等派生及精确恢复。宿主检查覆盖1386行、末页使用／丢弃／绑定、同代码独立宠物、粉末、充能、家具购买／摆放／重读和持久化。当前验证层级为静态、宿主事务与指令隔离执行，客户端完整场景验收状态为`runtime_acceptance=false`。

## 恢复

退出同一批客户端与服务后，按与安装相反的顺序恢复。存储阶段首先校验73处目标字节、区段正文及元数据，再精确重建原程序并校验其输入摘要；页数阶段随后恢复自身15项。

```powershell
python -B scripts/inventory_storage_compat.py --client '<client-root>/game.exe' --output '<work-root>/restored-pages99.exe' --restore
python -B scripts/inventory_pages_compat.py --client '<work-root>/restored-pages99.exe' --output '<work-root>/restored-before.exe' --restore
Get-FileHash -Algorithm SHA256 -LiteralPath '<work-root>/restored-before.exe'
```

存储恢复输出应与本次`game-pages99.exe`逐字节一致。若本次原程序已包含99页或旧255页控制器，恢复到本次安装前状态时使用`before/game.exe`完整备份；两阶段撤销输出对应恢复到普通背包原位点的程序。确认摘要后安装匹配的恢复程序。

资源与运行包按本次`deployment_backups/pet-catalog-<id>/receipt.json`恢复，首次安装资源分别使用其原事务。回退到旧版数据库结构时恢复同批安装前数据库快照与旧运行包，库存、绑定和家具布局一并回到该快照。

```powershell
python -B scripts/deploy_pet_catalog_update.py --client-root '<client-root>' --rollback 'deployment_backups/pet-catalog-<id>/receipt.json'
```

最后核对恢复后的程序、运行包、五张目录表、资源收据和角色数据库。工具对未知位点或摘要冲突执行拒绝并保留现场文件，已登记原程序备份用于整文件恢复。
