# 修道僧四村对白安装／安装与恢复

本页保留配套安装所需的安装与恢复信息；业务接入策略见[DIY专题](../../../业务/DIY/README.md)。

<a id="四村对白入口安装"></a>

## 安装与核对

1. 退出目标客户端及运行程序，保留匹配的程序、数据库、资源收据和备份，准备合法取得的源资源、目标客户端与中文字体。目标基础资源按[资源与场景派生](../修道僧资源与场景派生.md)准备。
2. 生成并安装完整四关资源包，保存资源事务返回的收据。

```powershell
python -B scripts/prepare_monk_challenges.py build --source "<source-client>" --client "<client-root>" --output "<fresh-resource-bundle>"
python -B scripts/prepare_monk_challenges.py apply --bundle "<fresh-resource-bundle>" --client "<client-root>"
python -B scripts/prepare_monk_challenges.py verify --client "<client-root>"
```

3. 使用同一发布包的运行程序、DCC7、战斗目录和基础名牌资源派生四村场景。安装器对已有文件备份后替换，对新增文件登记所有权，同时保存上一版资源标记。

```powershell
python -B scripts/prepare_monk_dialogue.py build --source "<source-client>" --client "<client-root>" --output "<fresh-entry-bundle>" --font "<user-owned-simsun.ttc>"
python -B scripts/prepare_monk_dialogue.py apply --bundle "<fresh-entry-bundle>" --client "<client-root>"
python -B scripts/prepare_monk_dialogue.py verify --client "<client-root>"
```

4. 使用配套启动器派生兼容客户端，联合核验场景、四关战斗资源和L7/L8父包身份。

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root "<client-root>" --output-root "<fresh-overlay>" --dungeon-state --dungeon7 --monk-dialogue --apply
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind monk-dialogue --client-root "<client-root>"
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind lumineos --client-root "<client-root>"
```

5. 核对源目录与overlay的37项场景／UI／立绘、1,154项战斗资源及全部程序位点。启动器依据`.openNanaimo-monk-dialogue.json`启用配方，已有标记升级时校验`previous_marker_sha256`，父文件叠加使用`parent_files`。兼容检查的`verification.all_pass`为true，资源检查分别返回所属通过状态和`LUMINEOS_RESOURCES_PASS`。

## 排名兼容升级

1. 正常停止目标适配器并退出启动器与客户端，保留当前运行时、客户端程序、overlay和资源收据的匹配备份。
2. 从同一次完整构建交付运行时清单中全部文件，逐项核对大小与SHA-256后发布`adapter_manifest.json`。同版`Nanaimo.Adapter.dll`内嵌客户端兼容配方，`Nanaimo.Gameplay.dll`维护成绩事务，原生bridge与DCC7资源共同配套。
3. 先按[单槽计分板升级](../挑战单槽计分板升级.md)准备并安装37项场景资源，保存资源收据。按上节兼容命令增加`--dry-run`完成预检，确认`verification.all_pass=true`；再使用同版工具执行`--apply`。完整位点包括[程序位点](程序位点.md)中的5,632字节代码窗口与四个排名入口。
4. 校验场景／战斗两套资源清单及基础L7/L8父身份；按收据保存全部新增、替换与清理文件的前后摘要。
5. 重新打开启动器，读取新运行时清单和兼容缓存。成绩表使用Epi框内原生贴图01／02／03／04、每行单个评级格及当前关卡标题；450×336面板与关闭命中区域共同更新，重新登录时从真实成绩恢复。

恢复采用完整匹配备份：先恢复程序及配方，再按资源收据逆序恢复替换项、清理摘要相符的新增项，并核对客户端、运行时和资源身份。

## 社交槽位资源同步

基础 L7/L8 与修道僧资源叠加安装后，社交槽位按基础清单与覆盖清单联合校验。所需文件如下：

| 文件或文件组 | 核验与同步要求 |
|---|---|
| `openNanaimo-l7-l8-resources.json` | 基础 L7/L8 安装身份；清单摘要及 `files`／`preserve_l7_combat` 逐项有效。 |
| `.openNanaimo-monk-dialogue.json`、`.openNanaimo-monk-challenges.json` | 场景与战斗两套覆盖身份；源目录和槽位使用内容一致的普通文件。 |
| `Village_map_image/Village_map_image.pack` | 按场景覆盖后的精确摘要核对源目录与槽位。 |
| 两套覆盖清单的全部 `files` | 完整范围见[场景与资源](场景与资源.md#完整资源范围)，包括根目录文本 `QS._D31`、`GS._D20` 和战斗资源；逐文件核对源目录及槽位内容。 |
| `adapter_runtime/Nanaimo.Adapter.exe` 及配套运行文件 | 提供同版本内嵌资源配方和 `verify-resources --kind lumineos` 联合校验。 |

1. 按上节顺序完成源目录的基础资源、战斗资源、场景资源和客户端兼容安装；使用当前发布清单配套的启动器与运行程序。
2. 退出待更新的社交槽位客户端，由启动器执行该槽位准备。目录映射读取源目录资源，复制型槽位使用同版完整资源副本。
3. 启动器在槽位锁内验证基础清单摘要、路径归属和源目录覆盖配方，再逐项核对两套覆盖清单及基础保留资源。身份成立后，原子同步两套覆盖标记与基础标记。
4. 复制型槽位出现资源版本差异时，按当前源目录重新准备匹配副本，再执行联合校验。标记同步以资源字节已经一致为前提；配置和账号身份继续由槽位生命周期管理。
5. 每个槽位分别完成准备和复用校验后启动。源目录及覆盖标记在准备期间保持同一内容身份。

## 恢复

1. 退出客户端与目标运行程序，按兼容回执恢复程序副本和对应摘要。
2. 按入口收据恢复场景原件和上一版标记，再按战斗资源收据恢复替换文件并清理本次新增且摘要一致的文件。

```powershell
python -B scripts/prepare_monk_dialogue.py rollback --client "<client-root>" --receipt "<entry-receipt>"
python -B scripts/prepare_monk_challenges.py rollback --client "<client-root>" --receipt "<resource-receipt>"
```

3. 运行程序、战斗目录、发布清单和overlay恢复为同一备份版本。资源回滚不改角色数据库；若确需迁移回旧程序的数据库版本，先停止适配器并另行核对数据库格式、当前角色及独立挑战进度，不能直接以安装前存档覆盖新进度。两套事务分别以`.openNanaimo-monk-dialogue.json`和`.openNanaimo-monk-challenges.json`维护身份，恢复前完整预检当前文件、备份摘要、清单覆盖与收据归属，再按逆序恢复。

4. 使用恢复后的源目录重新准备各社交槽位；基础与覆盖清单、目录映射或复制资源、客户端兼容配方共同恢复到匹配版本，再完成联合资源检查与槽位身份校验。

上述命令从仓库／客户端同根目录执行。每条外部命令返回后检查`$LASTEXITCODE`，非零即停止后续步骤，保留失败报告和收据。基础L7/L8及场景候选准备完成后才进入这两套安装事务。`--apply`同时写入overlay并应用到源客户端；省略该参数仅派生overlay，`--dry-run`不写入。
