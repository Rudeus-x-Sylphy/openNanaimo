# 飞行效果与资源刷新安装

## 配套功能

本配套版本提供35条个人／全队盾牌定义、独立效果计时、全队作用范围和保留已激活效果的资源更新。五秒盾牌为`21000006`，七秒盾牌为`21000001`，母爱盾牌为`21000121`；全部时长与收益规则见[飞行道具](../../业务/库存/消耗品/飞行道具.md)。

同一战斗内的资源更新保留六槽效果、五组全队效果、独立保护链表、当前P阶段和快捷栏布局。初次入场、新战斗、外观／PET／宝石配置变化、快捷栏内容或扩展权限变化、复活采用完整快捷栏初始化；同PET连续关卡保持P阶段。道具消费后的本地槽位状态与后续资源更新共同维护。

## 文件与资源

| 文件 | 配套作用 |
|---|---|
| 使用者本地的`game.exe` | 按下节四处位点派生并原子安装，文件长度保持一致 |
| `adapter_runtime/Nanaimo.Adapter.exe`、`Nanaimo.Adapter.dll`、`Nanaimo.Adapter.pdb` | 安装工具、内嵌兼容配方与适配器宿主 |
| `adapter_runtime/Nanaimo.Gameplay.dll`、`Nanaimo.Gameplay.pdb` | 资源更新、角色归属、寿命及复活次数同步 |
| `adapter_runtime/nanaimo_gameplay_bridge.exe` | 飞行效果、消费、伤害及资源状态维护 |
| `adapter_runtime/`中的运行依赖 | 按`adapter_manifest.json`逐项配套 |
| `adapter_runtime/资源/数据/gi._D6` | 当前121条飞行道具定义；客户端根目录沿用同版`gi._D6`及其原有图标、特效资源 |
| `managed-host/Resources/client-compatibility.json` | 四处位点的完整目标值及允许升级的输入编码；随完整适配器构建内嵌 |
| `adapter_runtime/adapter_manifest.json`、`manifest/source_closure.json`、`manifest/open_release_manifest.json`、`manifest/patch_allowlist.json` | 配套运行文件、源码、发布及候选身份 |

客户端素材使用既有`gi._D6`引用的图标与效果；本配套的派生安装对象为`game.exe`。各运行文件的当前大小和SHA-256由上述活动清单提供。

## 二进制修改

地址为PE虚拟地址，安装器按节表换算文件偏移。四处完整原值、目标值及代码区字节统一见[站点与完整字节](../../工程/客户端兼容/复活快捷栏布局.md#站点与完整字节)。

| 作用 | VA与范围 | 目标 |
|---|---|---|
| 资料刷新入口 | `0x006F5B1E`，5字节 | `E8 1D D6 FE FF` |
| 清空刷新入口 | `0x006F5B68`，5字节 | `E8 D3 D5 FE FF` |
| 完整初始化与布局 | `0x006E3100`，64字节 | 按布局模式及战斗状态选择全尺寸或紧凑布局 |
| 保留效果判定 | `0x006E3140`，64字节 | 长度120、操作码CF72、apply0、尾标记`VIT1`的资源更新保留当前对象 |

升级输入包含原生入口、已发布的双条件布局入口和已登记的无条件布局包装。安装器逐项确认已知输入后生成同一目标；重复安装保持幂等。

## 安装与升级

1. 退出目标目录的客户端及社交副本，通过启动器停止目标适配器服务，备份当前`game.exe`和角色数据。
2. 在完整发布目录核对发布身份并执行安装预检：

```powershell
python -B scripts/verify_package.py --source-only
python -B scripts/deploy_adapter_runtime.py --client-root '<客户端目录>'
```

3. 安装配套运行文件。安装器逐文件保存原字节及恢复收据：

```powershell
python -B scripts/deploy_adapter_runtime.py --client-root '<客户端目录>' --apply
```

4. 从目标目录执行客户端派生及安装：

```powershell
adapter_runtime/Nanaimo.Adapter.exe --tools compatibility `
  --source-root '<客户端目录>' `
  --output-root '<客户端目录>/adapter_data/client_compatibility_overlay' `
  --dungeon-state --overwrite --apply
```

5. 核对安装结果中的`verification.all_pass=true`、`apply_requested=true`及`apply_results`，并核对磁盘上`game.exe`的大小和SHA-256。兼容工具将输入原字节保存在覆盖目录的`backups/<原SHA-256>/game.exe`，派生目标保存在该覆盖目录。
6. 执行完整发布校验，通过目标目录启动器进入游戏。社交多开副本采用同版兼容配方，并分别完成源文件身份同步。

```powershell
python -B scripts/verify_package.py --root '<客户端目录>'
```

## 恢复

1. 退出目标客户端和社交副本，停止目标适配器服务。
2. 核对当前`game.exe`与该次安装目标摘要、备份文件与原摘要，恢复覆盖目录中对应的完整程序备份。完整备份恢复包含该次安装前的全部兼容状态。
3. 使用该次运行文件安装的收据恢复匹配版本：

```powershell
python -B scripts/deploy_adapter_runtime.py --client-root '<客户端目录>' `
  --rollback 'deployment_backups/<安装目录>/receipt.json'
```

4. 核对恢复后的客户端位点、运行文件清单及启动器检查。定点恢复的完整字节范围见[恢复规则](../../工程/客户端兼容/复活快捷栏布局.md#派生安装校验与回退)。
