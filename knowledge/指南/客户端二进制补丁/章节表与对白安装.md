# 客户端二进制补丁／章节表与对白安装

## 交付范围

本页维护16章QT／QS、对白程序、18名NPC立绘、运行资源和父资源收据的配套安装与恢复。当前内容为107段正文／156页、52目标、16任务、139条新增文本；完整QT含409目标／233任务，QS含772条记录。当前服务默认开启章节及教程后的自动起始，无须加参数或创建flag；逐章奖励仍需独立审核。准备包的 `activation_allowed=false` 不控制服务启动，完整流程仍为 `runtime_acceptance=false`。

任务DIY的目录、正文立绘、目标条件与奖励定义见[任务DIY](../../业务/DIY/任务/索引.md)。本页统一维护这些定义对应的程序patch、资源新增／替换和恢复步骤。

| 必备输入 | 完整范围与作用 |

| 同版完整仓库 | 提供兼容配方、部署工具、运行清单、自包含运行程序及章节QT／QS。 |
| `resource-packs/nanaimo-korean-resource-kit.zip`及`.zip.sha256` | 提供L7/L8前置安装输入和输出，包内清单登记文件身份。 |
| `resource-packs/nanaimo-story-resource-kit.zip`及`.zip.sha256` | 包含37项章节立绘、37项四村场景／立绘／UI及1,154项挑战资源，共1,228项。 |
| 当前奖励审核文件 | 绑定当前章节包、16章奖励三元组、期限、审核标识与批准状态，供奖励授权使用。 |

章节ZIP内的`kit-manifest.json`登记`story_portrait_resources.json`、`monk_dialogue_resources.json`和`monk_challenge_resources.json`三份配方及全部`payload/`文件的大小与摘要。文件所有权与恢复由安装事务统一登记，资源依赖按下表成套处理。

| 修改对象 | 配套交付与顺序 |
|---|---|
| 标题、目标或奖励结构 | 更新章节目录及两端QT；说明／奖励显示投影同步两端QS，逐章审核绑定当前包。 |
| 正文、说话人名字或段落顺序 | 同步本地化、QS与章节程序区域中的段表、名字、字符串和分页正文。 |
| NPC或立绘 | 同步动作中的NPC／表情、程序立绘路径、EFF及其全部IM3依赖，并登记新增／复用身份。 |
| 目标判定或领奖策略 | 配套部署当前Adapter／Gameplay及运行清单，核对本地启用配置和奖励审核身份。 |
| 四村挑战前置 | 联动场景包、场景EFF／IM3、四村立绘、计分板、战斗资源、文本和程序兼容区域。 |

资源层次为L7/L8父资源、四村场景与挑战、章节立绘与章节表、匹配程序及配置。四村资源中的基础QS在章节安装后由完整772条章节QS接替；L7/L8父收据同步最终QS身份。恢复时按同一所有者的逆序操作。

## 自动部署

准备完整CN客户端、完整仓库及随仓库交付的两个ZIP；安装环境为Windows、Python 3.10以上和PyCryptodome。退出目标目录的游戏、适配器及桥接进程，在仓库目录执行：

```powershell
python -B scripts/package_story_resource_kit.py verify
python -B scripts/deploy_story_release.py plan --client '<client-root>'
python -B scripts/deploy_story_release.py apply --client '<client-root>'
python -B scripts/deploy_story_release.py verify --client '<client-root>'
```

`plan` 校验输入并生成隔离兼容候选，报告全部变更；`apply` 保存统一收据并安装。首次安装同时部署既有ZIP中的L7/L8前置资源、章节包1,228项资源、完整运行程序、两端QT／QS和本地派生的 `game.exe`。已安装资源按原收据校验，重复安装重新核验实物。额外宠物资源按其独立入口维护。

章节默认启用，奖励授权采用显式输入。以下保留安装器兼容的`--enable-chapters`审核流程，它不是普通启动的必需参数。可先生成当前包的未批准审核模板，逐章完成奖励身份及期限审核，再安装：

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --chapter-story-reward-review '<reward-review.json>'
python -B scripts/deploy_story_release.py apply --client '<client-root>' --enable-chapters --reward-review '<reviewed-reward-review.json>'
```

工具核对16章完整审核、当前包摘要、奖励三元组、期限和审核标识；模板本身保持未批准。默认部署保留既有配置文件，兼容启用状态仍按安装器审核；服务缺省开关按[章节规则](../../业务/角色/任务/章节剧情移植进展.md#适配器闸与章节前缀)执行。程序和资源安装完成后，从目标目录运行 `start_nanaimo_launcher.bat`。此部署验证范围为文件、兼容位点与安装事务。

统一恢复使用本次输出的相对收据路径：

```powershell
python -B scripts/deploy_story_release.py rollback --client '<client-root>' --receipt '<story-release-receipt>'
```

该收据负责恢复程序、资源、配置和各层收据。保留全部备份；当前文件后续被编辑或备份损坏时停止恢复。完整约定见[章节成套部署](../../工程/资源安装/事务与恢复.md#章节成套部署)。下文的分步工具仅处理由各工具独立创建的安装事务。

## 资源增补与替换规则

| 文件类别 | 应用 | 恢复 |
|---|---|---|
| 章节EFF／IM3 | 清单内缺失文件新增；同路径同字节文件复用；同名异字节按冲突处理。 | 清理本事务新增且摘要匹配的文件，复用文件保留。 |
| QT／QS、场景包及已登记替换资源 | 预检匹配基线，备份原件，按同版目标文件替换并登记after摘要。 | 当前内容与after身份匹配时恢复原件。 |
| `game.exe`与运行程序 | 从目标程序派生兼容版本，运行依赖按完整清单交付，备份程序及元数据。 | 使用本次备份恢复完整程序及其配套运行清单。 |
| 配置、父清单与安装收据 | 在关联文件核验通过后登记当前资源、启用状态和审核身份。 | 由所属安装事务一并恢复。 |

18名NPC的37项立绘逐文件列表见[完整立绘文件清单](章节候选资源.md#完整立绘文件清单)。四村37项配套及1,154项战斗资源的格式数量、路径范围、音频与文本见[完整资源范围](修道僧四村对白安装/场景与资源.md#完整资源范围)；逐文件精确身份以章节ZIP及三份配方为准。计分板两项背景已计入四村37项资源。

统一部署按目标实际状态生成新增／替换／复用计划。新增文件的删除归本事务恢复，原有同名资源的替换归其备份事务；共享资源以父身份和收据关联。完整恢复命令见本页[自动部署](#自动部署)，独立工具创建的事务见[恢复顺序](#恢复顺序)。

## 前置与准备

1. 正常退出目标客户端与运行程序，备份匹配程序、overlay、运行清单、配置、数据库、资源收据和原文件。
2. 准备合法取得的资源、匹配基线及已审核章节目录；编译与37项立绘准备见[章节资源](章节候选资源.md)，四村前置见[安装与恢复](修道僧四村对白安装/安装与恢复.md)。
3. 使用同版脚本、兼容配方与程序集。已装章节的目标先按原事务所有者恢复受支持基线，再派生；审批与玩家进度按匹配事务保留。
4. 独立生成QT、QS，合为仅含上述四文件的表安装包。两份报告的共同输入身份、实际客户端及运行QT须逐项匹配。

```powershell
python -B scripts/story_qt_patch.py build --client '<baseline-client>' --catalog '<catalog-directory>/catalog.json' --localization manifest/story_localization.json --chapters 1-16 --allow-unreviewed --output '<qt-output>'
python -B scripts/story_qs_patch.py build --client '<baseline-client>' --catalog '<catalog-directory>/catalog.json' --localization manifest/story_localization.json --chapters 1-16 --allow-unreviewed --output '<qs-output>'
```

`--allow-unreviewed`生成显式候选输入，实际功能与奖励授权独立管理；合包时交叉核对任务、文本及脚本ID。

## 安装顺序

1. 安装章节立绘，保存新增／复用文件收据：

```powershell
python -B scripts/install_story_portraits.py apply --bundle '<portrait-bundle>' --client '<client-root>' --allow-inactive-preview
python -B scripts/install_story_portraits.py verify --client '<client-root>'
```

2. 先plan核对全部目标，再以窗口事务安装表与托管程序，并同步配置、运行清单及父QS身份：

```powershell
python -B scripts/story_window_accept.py plan --client '<client-root>' --bundle '<four-file-table-bundle>' --build '<matching-runtime>'
python -B scripts/story_window_accept.py apply --client '<client-root>' --bundle '<four-file-table-bundle>' --build '<matching-runtime>'
```

保存返回stamp。该事务记录五项托管程序、表事务、原配置、运行清单和父收据；其余运行依赖按完整清单配套。运行QS随配套运行包交付，再与根目录QS核对。

3. 使用同版适配器预检、应用并核对资源：

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<fresh-overlay>' --dungeon-state --dungeon7 --monk-dialogue --dry-run
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<fresh-overlay>' --dungeon-state --dungeon7 --monk-dialogue --apply
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind lumineos --client-root '<client-root>'
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind monk-dialogue --client-root '<client-root>'
```

4. 已有英雄龙、追加宠物层分别使用 `--kind hero`、`--kind korean`核对。验证五个程序区域、37项立绘、37项场景资源、1,154项战斗资源、两端表、运行清单及启动器。
5. 奖励审核绑定当前包摘要、章节ID、奖励三元组、期限和审核标识；既有授权按原范围复核。可见验收按[验证状态](../../工程/验证状态/章节剧情与跨村门槛.md)登记。

## 父资源身份同步

单独完成表事务后，以完整收据同步L7/L8父QS身份：

```powershell
python -B scripts/story_window_accept.py repair-lumineos --client '<client-root>' --receipt '<story-table-receipt>'
```

工具验证原父回执自摘要、完整安装事务、全部目标文件及原QS备份；持有资源锁后更新大小、摘要和父清单自摘要，再联合校验全部已安装资源层。失败按摘要保护恢复原父回执。

## 恢复顺序

1. 正常退出客户端与运行程序，核对目标after摘要及匹配备份。
2. 窗口事务采用 `story_window_accept.py revert --client '<client-root>' --stamp '<apply-stamp>'`；程序、配置、运行清单、父资源和表由该所有者共同恢复。
3. 独立父事务采用 `port_lumineos_resources.py rollback --client '<client-root>' --receipt '<ledger-receipt>'`，随后 `install_story_tables.py rollback --client '<client-root>' --receipt '<table-receipt>'`。
4. 二进制按[统一恢复](统一安装与恢复.md#4-恢复)恢复完整程序备份并配套恢复程序集／配方。立绘用 `install_story_portraits.py rollback`及其收据；四村场景、计分板和战斗资源按各自事务逆序恢复。
5. 新增文件由所有者在摘要匹配时清理，替换项恢复备份，复用项保留；重验程序位点、运行清单、父资源及全部叠加层后启动。
