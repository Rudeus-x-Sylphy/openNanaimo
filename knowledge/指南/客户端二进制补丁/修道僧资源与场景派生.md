## 修道僧四关资源

前四村修道僧对白分别进入独立标准资源身份`hd0/ep24..27/dg0/st0`，每关九个选关／预加载槽独立维护。配套交付包括四关资源、普通目标与BOSS目录、独立四位通关事务、四村出口场景、中文分页对白和来源位置恢复。当前验证层级为资源完整性、程序位点、隔离执行及适配器构造；客户端完整游玩验收在 `manifest/monk_challenge_resources.json`、`manifest/monk_challenge_combat.json` 中以 `runtime_accepted=false` 登记（活动发布清单的对应字段名为 `runtime_acceptance`）。

### 文件与转换

完整必需资源由 `manifest/monk_challenge_resources.json` 的 `files`、`preserve_cn` 和 `stages` 登记，共1,154项输出、92,417,153字节，逐项包含路径、输入／输出大小与SHA-256及转换类型。安装包 `manifest.json` 登记目标原摘要与事务身份；逐文件清单是安装和恢复的身份校验依据。第一关资源兼容配方继续由 `manifest/monk_resource_port.json` 维护。

### 场景候选的隔离派生

中文名牌和场景基础通过独立资源派生准备。准备自备的目标客户端基线、L7/L8父包清单和可显示中文的字体文件；输出使用全新的隔离目录：

```powershell
python -B scripts/prepare_monk_entry.py --source "<source-client>" --client "<client-root>" --output "<fresh-preview>" --font "<local-Chinese-font>"
$env:NANAIMO_MONK_ENTRY_BUNDLE = "<fresh-preview>"
python -B scripts/test_monk_entry.py
```

输出 `manifest.json` 登记场景、图层、字体和逐文件摘要；`payload` 包含村庄包、QS／GS和独立效果／图像。场景候选保留既有文本、道路和其它村庄记录。视觉更新通过当前L7/L8父资源清单提交，直接覆盖共享包的文件身份不被接受：

```powershell
python -B scripts/prepare_monk_visible_resources.py --client "<client-root>" --candidate "<fresh-preview>" --output "<fresh-visual-bundle>"
python -B scripts/port_lumineos_resources.py apply --bundle "<fresh-visual-bundle>" --client "<client-root>"
python -B scripts/port_lumineos_resources.py verify --client "<client-root>"
```

该步骤准备中文名牌、阴影和第一村场景基础；完整四村场景及对白控制器随后按[四村对白安装](修道僧四村对白安装/README.md)执行。基础视觉事务通过`port_lumineos_resources.py rollback`及其收据恢复。
