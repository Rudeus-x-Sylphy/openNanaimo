## 安装、验证与恢复

### 1. 预检与生成

1. 退出目标客户端，确定源文件、独立输出目录和配套程序版本。记录源文件大小与SHA-256；经验曲线切换同时建立匹配的数据备份。
2. 解析PE节表，将[客户端兼容](../../工程/客户端兼容/README.md)列出的VA映射到有文件内容的偏移，检查位点范围及代码区重叠。各位点须匹配精确原值、登记旧版或当前值；冲突终止生成。
3. 结果发布函数接受原96字节`CC`及`encodings(legacy=True)`定义的单控制器版本，统一迁移到mode0／1版本。其它新增位点按各自原值／当前值匹配；已有兼容项由完整配方统一维护。
4. 以独立目录派生客户端：

```powershell
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<overlay-root>" --dungeon-state --dry-run
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<overlay-root>" --dungeon-state
```

该组同时处理既有地宫状态兼容项。需要全套资源与客户端兼容时使用`--all`；其资源约定见[完整适配器与客户端兼容说明](../完整适配器与客户端兼容说明.md)。派生工具按配方写入代码区和入口，保持文件长度及配方范围外字节。

### 2. 配方与安装一致性

1. 配方更新后执行`python -B scripts/generate_managed_compatibility_recipe.py`生成`managed-host/Resources/client-compatibility.json`，按[构建与验证](../构建与验证/README.md)重新构建运行程序。
2. 托管内嵌配方、Python配方及启动器位点目录逐项一致。对派生文件重新核对全部位点，并重复应用检查字节幂等。
3. 安装由兼容工具的`--apply`或启动器兼容入口执行。目标文件保持退出状态；安装按内容摘要建立本机备份，记录原／新文件身份，逐文件确认后替换。
4. 排序配方包含`dungeon_result_score_order_entry`（6字节）与`dungeon_result_score_order_compare`（154字节）两项，均由`sorting_sites()`生成精确原值／目标值。比较区使用32位无符号总分，按角色UID稳定处理同分，剩余区域以NOP填充。逐项确认原生交换`0x00762371`、保持`0x0076240D`及就绪门控的分支目标；这160字节范围内实际更新137字节。
5. 社交多开派生副本通过当前启动器的源文件更新迁移（source rollover）同步源文件身份、兼容配方和槽位注册摘要；每个副本分别核对上述排序位点及完整兼容报告。
6. 安装后验证目标PE全部位点、文件长度、兼容报告和启动器检查。托管程序、工作进程、启动器及发布清单同步使用同一配套版本。

### 3. 专项校验

应用后执行以下配方与隔离执行检查：

```powershell
python -B scripts/test_dungeon_experience_compat.py
python -B scripts/test_live_dungeon_experience.py
```

经验setter检查覆盖堆栈、返回值、已提交经验与独立分数槽；C60D检查覆盖本地UID匹配、远端角色更新，以及98／99／100／101／127／128／199／200级的人物与PET独立字段。适配器检查覆盖F10B v3、同级同步、跨级恢复、死亡和终局冻结、重复收据幂等及持续等级增长。两类检查分别对应客户端隔离指令执行和适配器生产状态机。

### 4. 恢复

1. 退出对应客户端；涉及程序或经验曲线恢复时，同时停止匹配适配器与工作进程并备份当前数据。
2. 定位该次安装的原文件并校验备份 SHA-256 与当前目标身份：Python 报告提供 `before_sha256`、`after_sha256` 和 `backup`；C# 报告仅提供 `path/status/sha256`，须使用预检前独立记录的原 SHA-256 定位 `backups/<原SHA-256>/<相对路径>`。采用原子替换恢复对应客户端；定点恢复200级修改时由 `restore()` 核对当前字节并按逆序还原。两类报告的完整差异见[自动兼容清单](../../工程/客户端兼容/自动兼容清单.md#两类工具报告的差异)。
3. 客户端与内嵌配方共同恢复到匹配版本。跨CurveVersion恢复采用同批程序与数据快照；同曲线程序更新保持后续角色进度。
4. 对恢复结果重新执行位点、配方及清单检查，确认原／目标字节身份、资源版本和数据曲线一致后启动。

## 任务计数与进入资格配套

32项击打任务的怪物身份、累计进度及普通地宫进入资格使用同一发布版本。交付以完整发布目录为源，按运行清单和活动发布清单核对下列配套文件。

| 文件 | 配套作用 |
|---|---|
| `adapter_runtime/Nanaimo.Adapter.exe`、`Nanaimo.Adapter.dll`、`Nanaimo.Adapter.pdb` | 启动宿主与任务专项校验 |
| `adapter_runtime/Nanaimo.Gameplay.dll`、`Nanaimo.Gameplay.pdb` | 命中身份、计数、任务列表及交付事务 |
| `adapter_runtime/nanaimo_gameplay_bridge.exe` | 原生战斗服务 |
| `adapter_runtime/资源/数据/QT._D30`、`QH._D33` | 任务定义、目标次数与卷轴目录 |
| `adapter_runtime/资源/数据/dungeon_combat_catalog.bin` | 关卡、槽位、选择器与怪物代码 |
| `adapter_runtime/`中的其余依赖与数据 | 以`adapter_manifest.json`逐项登记的完整配套文件为准 |
| `adapter_runtime/adapter_manifest.json`、`manifest/source_closure.json`、`manifest/open_release_manifest.json` | 运行包、源码闭包与发布身份 |
| `manifest/patch_allowlist.json`及源码闭包内文件 | 当前交付目录与候选文件身份 |

1. 退出目标客户端，通过启动器停止适配器服务，保留角色数据和个人配置。
2. 在完整发布目录执行源目录校验和安装预检：

```powershell
python -B scripts/verify_package.py --source-only
python -B scripts/deploy_adapter_runtime.py --client-root "<client-root>"
```

3. 确认配套文件后执行事务安装，安装器逐文件保存原字节及恢复回执：

```powershell
python -B scripts/deploy_adapter_runtime.py --client-root "<client-root>" --apply
python -B scripts/verify_package.py --root "<client-root>"
```

4. 通过目标目录启动器重新进入游戏，检查击打计数在任务刷新、结算和重新登录后持续保留，达标后按任务目录领奖。
5. 恢复时退出客户端并停止服务，使用该次安装的`deployment_backups/<安装目录>/receipt.json`：

```powershell
python -B scripts/deploy_adapter_runtime.py --client-root "<client-root>" --rollback "deployment_backups/<安装目录>/receipt.json"
```

任务规则见[击打任务](../../业务/角色/任务/目录进度与交付事务.md#击打任务的部分进度)，进入资格见[普通地宫](../../业务/地宫/关卡与房间/房间身份.md#普通地宫进入资格)，验证范围见[当前验证](../../工程/验证状态/地宫与成长验收.md#金币击打任务进度)。
