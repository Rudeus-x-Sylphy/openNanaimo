# 03 角色资料、货币、装备和库存

本主题按资料载体和交易机制分组，区分静态分析、本地构造实验与客户端运行观察。实验结果仅适用于其记录的输入和行为，不代表当前 release 已完成客户端验收。

## 资料载体和验证

适配器角色资料包含两个战斗策略键，但 C377 面板载体未与这两个策略值同步：

```text
attack   u32 策略范围 0..1000000 -> CFEC +0x2E0 当前修正量；至多两条远程 UID／修正量记录
defense  u16 策略范围 0..65535   -> 适配器减伤处理，发生于以下封包之前： D010/D015
```

这两个值保存在各连接提交的多人角色资料中，但当前 `multiplayer_send_remote_c377` 向面板字段 `+0x2E/+0x38` 固定写入5。因此，攻击9000／防御10000的运行样本显示防御5、攻击12。独立的 C377 A/B 实验将防御直接映射到 `+0x2E`，将攻击基值写入 `+0x38`，并测得本地额外贡献7。静态定义—使用链证明，攻击总值只格式化到面板对象的 `+0x438` 字符缓冲区，不是副本弹道伤害载体。防御两端都是 u16，可直接表示；攻击则不能仅靠一行通信字段映射实现精确对应：C377 攻击基值为 u16，资料策略允许1000000，且另有本地加项。现行适配器不按等级、服装或宠物宝石推导这些值，也未声称实现原始适配器公式。战斗语义见04，静态偏移见08。

必须在绑定监听端口之前拒绝解析失败、u16/u64 越界或 `current > max` 的资料。低等级测试数据即便字节准确，覆盖高等级角色资料时仍不安全。

结构有效的资料还需满足角色语义一致性；低等级测试资料不得覆盖已有高等级角色状态。

玩家等级／经验使用按角色持久化的进阶记录。配置参数 `level` 仅初始化缺失的 `level_progress_state_v1_<name-hex>.dat`，已有进度不会因登录或资料应用而重置。登录／房间资料应用时重新加载该记录，CF88结算提交后更新当前连接等级。C355／CF71构造在校验和计算前统一经验载体，不额外发送封包，不改变进阶记录、阈值曲线、通关奖励、死亡门控或升级动画标志。HP/MP保持独立的u16资源，并叠加选中宠物宝石增益；等级不推导这些资源。攻击／防御策略见04，选中宠物／装备属性保持独立。

| 资料元组 | 当前经验载体约定 |
|---|---|
| 登录 271A/68 | 字节+0x0C等级；无经验三元组 |
| 村庄/频道 C354/8 -> C355/728 | 字节+0x23等级；双字+0x28累计当前，+0x2C下限阈值，+0x30下一个阈值 |
| 房间/下一阶段 CF70/12 -> CF71/184 | 字节+0x48等级；双字+0x40下一个阈值，+0x44累计当前。无下限阈值写入：它保留C355/CF88的下限值 |

C355不是在+0x0C/+0x10/+0x14存储经验的C57C形状记录，不能套用该布局。本地和远程CF71序列化的是角色应用的资料上下文：普通名单和后加入名单的调用者在构造前应用角色资料，随后恢复接收方上下文。经验记录不能以接收方套接字或截断的显示名称为键。静态调用链见08；本地自测覆盖等级1..99序列化、双资料隔离、村庄／下一阶段／重新登录连续性，以及不额外推送经验封包。客户端渲染尚未得到验证。

进阶文件通过`.new`/`.bak`原子替换，存储`version=1`、`level`和累计`exp_total`，拒绝存储的等级与配置的阈值曲线不一致，并回退到该等级下限的配置种子。角色身份是精确配置的名称字节编码为大写十六进制，匹配其他每个资料的进阶记录。数值策略和CF88字段在07中是标准的。

### C355 副本开放填充与情侣资料边界

村庄/频道 `C354/8 -> C355/728` 的无条件开放策略包含三个彼此独立的最终载体，而不只是低44位前置掩码：完整帧 `+0x3C..+0x77` 的60个普通副本字节统一为 `0x0F`；`QWORD +0x80..+0x87` 仅将低44位（22个前继对）置1并保留 bit44..63；`+0x88..+0xDE` 由最终 writer 写成打包状态1，即 `0x55`。reference implementation reference implementation 的 Network 构造器中间阶段确有 `q=0x88; q<0xDF` 的 `0xFF` 填充，但随后 the final unlock helper with packed state 1 是最后写入者，因此最终发送字节是 `0x55`，不是 `0xFF`。当前适配器在主构造器完成资料字段后及最终校验和前各执行一次同一幂等归一化，覆盖正常登录、频道重连和后续新增构造路径。

所有进度写入严格止于完整帧 `+0xDE`。`+0xDF..+0xEF` 是17字节情侣姓名，`WORD+0xF0` 是戒指后缀，`BYTE+0xF2` 是复活次数。无有效情侣关系时，姓名和戒指字段主动清零，使原生姓名门控在戒指资源查找前关闭；只有目录中有效的 `CI._D28/COUPLERING`、代码 `43,000,000+N` 的戒指才可与非空伴侣名一起序列化。不得用伪造姓名、戒指或越界进度填充换取表情翻页。

运行观察中，低44位全1时 `+0x88..+0xDE` 仍全0、`+0xF2=33`，客户端显示“仍需完成全部关卡／地宫”。适配器归一化只写三个进度域，并保留 `+0x78..+0x7F`、bit44..63、情侣姓名、戒指、复活次数及后续尾部。适配器构造检查通过；第五村移动和保持原 emotion 代码的客户端表情翻页仍待运行验收。

## 副本等级与称号状态

副本等级与玩家等级无关。客户端在`dword_D869D4 + 0x5C4`后存储这对值：副本等级为`WORD [pair+0]`，而玩家等级为`WORD [pair+2]`。权威的副本等级载体是271A `+0x0D`、C355 `+0x24`、CF71 `+0x49`、CF0E `+0x0B`、CF88记录 `+0x07`（第一个记录帧为`+0x13`，步幅为`0x34`）和CF8A记录 `+0x06`（步幅为`0x38`）。C355 `+0x25`是一个单独的一次性对话/状态DWORD，并不是标题等级。

称号／角色资料面板读取副本等级并格式化资源`1243 + grade`；其显式呈现开关覆盖了等级0到42。等级0是用户赋予的“修炼中的初级收集者”的可见本地化标题的状态。现在，原生称号字符串是从GS._D20解码而来的：单独的开关选择文本ID2038至2058/2394至2412；等级23使用文本2396（打败头脑胶囊的收集者），等级24使用文本2397（打败马斯特洛克的收集者）。图像ID和文本ID不能互换。选定阶段也有一个客户端本地副本等级字段，但CF6C/CF77/CF87不传输它；因此，本地阶段选择无法提供持久的账户权限。适配器必须在结算时为每个角色提交副本等级，并通过后续的角色资料载体恢复相同值。确切的原始适配器边界顺序和奖励编号仍然未知。

副本等级状态保存在 `dungeon_grade_state_v1_<name-hex>.dat` 的版本1格式中。文件包含 `grade`、`frontier_valid` 和 `hd/episode/dungeon/difficulty/stage`，使用原子的 `.new/.bak` 替换、备份恢复和等级0到42校验。角色身份是精确配置的名称字节，以大写十六进制编码。

`hd0/episode15/dungeon2/difficulty2/st0` 对应称号等级23；超级 Boss 通信元组中的 `st1` 归一化到同一 `st0` 边界，确保同一里程碑只结算一次。加载等级2/st1状态时提升到至少等级23/st0，并保留更高等级。未知元组使用“严格更强时等级加1”的有界适配策略。

CF88记录 `+0x07` 及后续271A/C355/CF71消费同一账本。专项和集成本地测试覆盖等级23、超级别名去重、v1存档兼容、无降级及资料载体。客户端运行观察识别了等级23，但显示名称转录损坏，不能据此确认确切可见文本；独立解码得到的文本2396见上文。只读观察中，等级23状态文件和准确GBK称号字符串分别存在，但这不证明重新登录后的可见持久性。结算细节见07，静态调用链见08。

### 称号等级的持久化与显示

固定称号等级使用现有 `dungeon_grade_state_v1_<name-hex>.dat` 版本1账本：原子写入所选 `grade`、`frontier_valid=0` 和零化的边界元组；跟随进度时不改写账本。这不修改客户端，也不引入第二个称号字段。适配器通过271A `+0x0D`、C355 `+0x24`、CF71 `+0x49`和后续CF88结算状态恢复该等级。本地测试覆盖了前三个载体上的等级42，但未证明客户端渲染及重新登录后的可见状态。

称号等级取值为0..42。本地图像文件名使用1243+等级；本地化称号字符串通过410E1F/434710中的独立开关获取。1243..1285是图像编号，不是文本ID；2412是文本键，不是共享图标编号。已确认的文本为等级0=`修炼中的初级收集者`、等级2=`打败大机械熊偶的收集者`、等级23=`打败头脑胶囊的收集者`、等级24=`打败马斯特洛克的收集者`，其中等级24对应解码文本2397。可见观察中的等级23/R7和等级39/R23支持连续的等级17..39=R1..R23推断，打包图像1267直接显示等级24/R8。等级39..42共享**文本键2412**，该键在解码表中为空；图像记录1283..1285（等级40..42）未出现在检查过的界面包中。上述证据不能证明等级39..42共享图标渲染。原始适配器排名／奖励策略和缺失图标回退仍未得到证明。
## 外观和应用装备

- C378/C379是主要资料/库存快照边界。
- C379携带装备单元、PET摘要、外观选择器和两个余额。
- C3CB/C3CC携带已应用的服装/背包记录。
- 身体/面部模型身份不是一个普通的库存槽位。
- 效果选择器6是一个外观/效果领域，不能按发生崩溃的D5实验布局序列化。
- C379外观DWORDs占用`+0x84..+0xA4`：D7选择的PET是`+0xA0`，D8性别/基础选择器是`+0xA4`。选择的PET记录从`+0xA8`开始并运行到`+0xC8`；PET摘要初始化绝不能清除D7/D8。

- 当前外观策略：

```text
D5 = 0
D6 = 效果
D7 = 选中宠物
C379/C3CC 保留 selector6 记录
```

将效果放入D5的实验发生了崩溃；该失败不支持以D5代替selector6。

防御是一个本地资源属性，不只是显示标签。完整的`ava._D1`表有3,885行；1,367个定义携带效果类型4，分为681个平值和686个百分比行，带有原始描述如`防御力+45`和`防御力+150%`。这仅证明了角色定义语义。客户端发送装备的身份，原始适配器可以推导出它们的效果；但这并不证明客户端本地的副本减少公式。适配器不会自动汇总ava类型4到其配置的`defense`中；该输入是显式的私有策略。战斗所有权和D00F/D010的负边界是04/08。

## 物品编号大类与资源覆盖

这里的domain是**物品／资源编号的大类码**，计算为 `code / 1000000` 的整数部分。客户端库存分派 `0x7F7EE0` 实际使用这个计算；例如 `14002221 -> 14`、`17012341 -> 17`、`43100001 -> 43`。它不是网络域名、不是包号，也不是背包格子或实例句柄。对这里的8位物品ID，通常可以看前两位。

文件后缀不是domain：`gi._D6` 同时含domain21飞行道具和domain14食物，`MI._D22` 同时含domain42喇叭和domain48复活道具。domain相同也不保证使用场景、效果或处理协议相同。

## 背包实例与原生使用

普通卡片册坐标对全部 13000001..13000420 是封闭公式：1..210 属于 family1，211..420 属于 family2，每页20槽、页码1..11。D034 已持久化的合法代码不能因为可选的本地元数据解析表缺行而在 C3E8 中被过滤；缺少名称/图标元数据时仍须按该坐标公式返回数量。

C430没有数量字段。头部：BYTE+8状态，BYTE+9模式，WORD+0x0A行数。每个8字节行是`(code:u32, identity:u16, selected:u8, reserved:u8)`。`sub_8005F0`规范化案例0xB7通过`0x804622 -> sub_40949E -> sub_7C8430`创建一行对象；代码是对象+0x10，身份+0x14，选择状态+0x24/+0x28。相等的代码在这个边界上不会被去重；移除匹配身份。

账户账本保留计数持久性，并为每个单位分配 1..255 的稳定标识符。购买／分配前预留标识符与容量；C430 按实例逐行枚举，`(code, identity)` 在同一账户中保持唯一。同代码的多个实例使用不同 identity。

C450动作3/4成功移除了确切的待处理对象并压缩了幸存的PET宝石。动作3重新利用消耗的替换宝石身份为返回的宝石；动作4，附着/粉末，背包使用和本地激活回收了确切的身份。C46E成功至少20字节：DWORD+8=1，代码+0x0C，回显的身份+0x10；它移除了确切的对象并分派了本地家族行为。这些本地删除路径不需要补偿的未经请求的C430。一个购买的领域42/48捆绑包是一行，**不是**一行每本地信用（48000007激活时授予32个信用；两次购买需要两个身份）。本地测试覆盖了重复的行、稳定的幸存者、重放保护和重启持久性；这些结果不证明客户端中的实例移除及本地使用效果。

C46D/16携带DWORD+8代码和DWORD+0x0C标识符。它是一个通用项目使用请求，被多个领域使用，而不是仅限于领域47的指令或乘数。关键授予：47000001→1金币；47000002→1个谜团；47000003→10个谜团；47000004→30个谜团。钥匙和行保存一起回滚在处理失败上；消耗的身份重放失败；C430省略了零行。本地号角/复活分支与快捷栏消费分开。C46E状态2映射到事件18/无关的硬币限制提示，不是成功。

## 复活糖果：商店分配、本地使用和副本死亡边界

`MI._D22` 将第48域复活捆绑包与普通的第14域食物以及六槽战斗快捷栏区分开。本地积分是 `48000001=5`, `48000002=10`, `48000003=30`, `48000004=1`, `48000005=5`, `48000006=11`, 和 `48000007=32`。这些积分用于一个捆绑包实例，而不是C430的数量，也不是每个复活对应一行库存；原适配器的价格/奖励策略仍然未知。

分配和激活是精确身份交易。`C475/20` 载有模式 `+8`、操作 `+9`、数量 `+0x0A`、本地令牌 `+0x0C` 和代码 `+0x10`；其结果为 `C476`。一个分配的捆绑包表现为一个C430 `(code,identity)`。`C46D/16` 提交代码 `+8` 和身份 `+0x0C`；成功的 `C46E/20` 返回状态1、代码和回显的身份，删除恰好那一行，分派事件35，并通过 `sub_4011B3 -> sub_7090B0` / `sub_408A53 -> sub_54E430` 在经理 `+0x5600` 处添加MI定义的积分。

副本死亡路径必须按实际元组分开。静态链仍证明 `CF95/8 -> CF96/8` 的重试族、`CF87/12 -> CF88` 的结果族、C355 `BYTE+0xF2` 和本地CF71 `BYTE+0xA8` 对管理器 `+0x5600` 的恢复，以及CF84 variant60的原生计数递减。CF83/12构造链为 `sub_7088D0 -> sub_41919B -> sub_6EACE0 -> sub_40A821`；WORD `+8` 是mode，WORD `+0x0A` 是客户端所选继续表项值。

`sub_73F3A0` 同时存在两族发送点：mode0见 `0x73F61F..0x73F630`、`0x73F688..0x73F699`；当 `sub_4011B3` 复活计数非零时，mode1见 `0x73F6A9..0x73F6EF`、`0x73F747..0x73F758`。原客户端首轮已见mode1/value950、1280、1400；主机时钟标为未来日期2026年9月24日的同一连续运行中，首次mode1/value950收到variant60并恢复后，第二次D010终端死亡发送 `73E30D180C0083CF0000B603`，即mode0/value950。第二次卡死的最早断点因此不是死亡锁、位置或次数，而是native路由只接管mode1、把mode0转给没有该响应实现的worker。

当前策略按mode分离：mode1要求本地D010死亡锁和 `uses>0`，不扣Hans，worker内部推进一次CF95并向客户端仅交付CF84 variant60；mode0要求同一死亡锁，表项值必须来自已建立的继续价格表，原子扣Hans而不扣复活次数，通过内部F104/F105把恢复HP/MP同步到worker `combat_hp`，再向客户端交付CF84 variant20。两种路径都不要求0x044C；重复请求由死亡锁和数据库条件保持幂等。

CF84 case53124的字段也已重新闭合：`WORD+0x08`是variant，`WORD+0x0A`是actor UID，`WORD+0x0C/+0x0E`在 `0x6F60BF..0x6F60E0` 经 `sub_406E74/sub_405AB5 -> sub_6E3000/sub_6E3050` 写入受限HP/MP；`DWORD+0x10/+0x14`在 `0x6F5F1A..0x6F5F28` 写入独立actor辅助字段，不是0x044C坐标，当前初始化为0。上一轮“除variant/UID外12字节全零”以及“+0x0C/+0x0E不作为HP/MP读取”的结论被本次静态链推翻。host专项、全量Python、完整adapter self-test与运行目录发布已通过；发布后二次原客户端可见恢复仍待验收。

C40A BYTE+8 是消费者路由， **不是通用零成功状态**。对于普通的村庄背包，保留显式的C409 DWORD+8=10作为C40A BYTE+8=10。村庄和公寓场景处理程序跳过10/30；普通库存处理程序排除20并否则消耗行；一个单独的特殊列表消费者需要30。特殊请求构建器明确写入30，但一些房间请求站点未初始化请求尾部，因此不要盲目回显任意C409尾部字节或用10替换所有场景响应。保持 `(connection, controller/state, request mode, opcode, length)` 单独。

响应BYTE+9种定了库存可用标志，BYTE+11是计数N，每个行的全部12个字节都被消耗。BYTE+10=6还读取DWORD+0x400，需要初始化长度>=max(12+12N,1028)；+10=0且N=0,12个字节就足够了。普通完成设置库存+0x9A=1并消耗帧。

普通村庄背包使用 `C409/12 DWORD+8=10 -> C40A BYTE+8=10`，并在读取物品行前保持 request mode。房间家具列表使用 mode20，两个路由由场景状态与请求模式共同区分。

C411 TakeOn行从+8开始，步长为8：索引：u16,+2 X：u16,+4 Y：u16,+6 Z：u8,+7 镜像：u8。TakeOff字节索引从+680开始；字计数从+764/+766。C424普通行从+12开始，步长为12：对象ID：u32,+4 X：i16,+6 Y：i16,+8 Z：u8,+9 类型：u8,+10 镜像：u8,+11 索引：u8。地板是一个单独的行在+1020，墙在+1032，不是普通84数组的一部分。

`nanaimo_apartment_state_v1.dat` 使用格式版本1，提供稳定索引分配以及库存／布局独立持久化。布局事务先验证私有副本：索引完整、开／关计数<=84、无重复或矛盾索引、镜像值为0/1、普通对象<=84、目录类型4<=40。验证或保存异常保持现有内存与文件不变。新地板／墙实例清除同类型实例的 TakeOn 标志。每个文件通过 `MoveFileExA(REPLACE_EXISTING|WRITE_THROUGH)` 原子替换；跨文件公寓／货币断电原子性仍待独立验证。

房间入口对象使用 `C392/12 -> C393/1020`：字计数位于 `+8`，终态 `+10=2000`，`+12` 起最多84个已初始化的12字节行，普通对象字段与 C424 一致。客户端仅在 `WORD+10==6000` 时构造下一次 C392；`0`、`2000`及其他非6000值结束分页。记录循环按 count 消费，固定1020字节与清零尾部提供容量边界。地板／墙由 C38E/C424 承载。适配器收到 C392 后返回持久化场景对象快照；C38F/C390 的远程／访客角色按各自所有者作用域处理。

每个公寓响应构造器使用4096字节工作缓冲区，因为共享 `mkpkt` 会清空4096字节，与通信帧长度无关。仅分配64字节的C410删除缓冲区即使通过部分本地检查，仍不满足该写入边界。通信帧长度不因此改变。本地验证覆盖无效／混合行、重复索引、替换失败、地板／墙壁唯一性、容量边界、C393场景重放、重启和精确删除；这些结果只证明适配器构造，不证明客户端渲染。静态调用链见08，入口协议见02。

公寓状态由 C358/C38D/C38E/C392/C393 建立，并记录为连接本地周期。装备面板关闭时抑制 C368/C47F 场景重建；客户端显式发送 C367 时仍返回 C368。host 构造检查覆盖公寓内关闭、客户端显式页面请求、离开公寓和重新进入四种顺序。

### 家具选择的受保护读取边界

房间家具列表使用 `C409/12 DWORD+8=20 -> C40A BYTE+8=0`，对象行从 `+12` 起按12字节步幅读取。普通背包 request10 使用独立路由；两种响应模式按各自消费者契约保持不变。

家具选择中的残留保护器状态失效属于客户端本地 getter，不属于分页状态。物品 getter、实例Index和保护器指针见08；选择在消费适配器记录之后、C411显式提交之前进入 `0x41235F -> 0x5CE700 -> ... -> 0x1011A51`。改变C393长度／终态、删除家具、伪造C411或固定Index均不能初始化缺失的保护器状态。对当前已审查PE，唯一已静态闭合的兼容策略是把五字节入口重定向到已有直接Index getter `0x5CEFE0`；一键启动保留该局部派生，若站点不匹配则拒绝修改。没有live stack、寄存器转储或新原客户端验收，因此不能声称所有路由／可达状态均排除，也不能把局部重定向写成完整保护器恢复。
