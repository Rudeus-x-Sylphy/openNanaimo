## 普通、分体与运行时目标账本

普通、资源已知的 D00D 目标在当前 `DungeonBattleInstance` 内以 **runtime UID** 为稳定身份；`targetIndex` 只是客户端目标向量的遍历／表现索引，同一运行时实例的连续报告可以变化，不能参与 HP 键。相同资源 owner 对应的不同 runtime UID 各自拥有独立 HP、首次终结、得分和掉落，一个实例死亡不得修改同 owner 的其他实例。

只有 `HP > 0 -> HP == 0` 的首次跃迁产生终结状态、得分和掉落。已终结实例的后续报告返回非终结 status0，不再次发送 D00E/status200，也不消费另一条当前或预载表现行。未编目动态实体使用 battle-scoped runtime UID 终结集合。

runtime/deform 目标使用独立的 `selector + generation token` 账本；同 owner、不同 selector 的实例互不影响，generation 改变只重置对应实例。地图、房间或战斗切换创建新 epoch，原生资源域重选也会递增 epoch 并清空 static/runtime 状态。

普通 D00D、runtime/deform、视觉 crate 和 Boss D011/D012/D013 始终使用不同账本。D00E 的客户端警告表示终结 selector 在当前与预载目标池中均未找到；因此重复终结必须在 adapter 端抑制，不能以再次发送 status200 作为补偿。以上键模型与重复终结行为已由资源目录检查、C harness 和 adapter 回归覆盖；原客户端低级地宫的分体可见效果仍待验收。

### 秘密Epi4 / 古代科技PET通关奖励边界

阶段格式器使用隐藏选择器、基于零的副本、副本和阶段值。隐藏选择器1加上副本3因此解决了已发货的**秘密副本4**根节点 `hd1_ep03_dg00_st00`、`hd1_ep03_dg01_st00`、`hd1_ep03_dg02_st00` 以及阶段1延续的dg02。此映射身份本身并不编码PET概率。

## 原生汉斯、卡片优先级和分布边界

原生 D00E 终止 status200/subtype20 使用有符号 DWORD+0x1C 表示 Hans 数量；subtype30 是卡片，不是另一条 Hans 或通用卡片代码通道。Actor+0x7D88 控制是否在匹配目标的 X/Y 处创建可见 Hans 副本，远程副本还需各自角色的门控。Hans 使用原生金币素材与追踪运动，并立即更新战斗 HUD，不走 PvP 星星重叠或 D034 奖励路径。构造函数和散布的详细地址见08，账号奖励策略仅由07维护。

适配器按目标账本的初始化最大生命值计算普通奖励。低于200时，既不发出卡片也不发出 Hans。等于或高于200时，保留的私有1%卡片掷骰首先运行；一个终端发出一个 D00E 通道，因此获胜的卡片会抑制 Hans，否则持续的 Hans 仍然是 `floor(max_hp/50)`。排除了箱子/类型4/被拒绝的对象。D00D、普通种类20碰撞和肉目标的第一个终端共享此策略和生成/状态周期的幂等性。公开适配器是 `release/components/adapter_core/teamplay_adapter.inc`，保留了阈值/卡片或 Hans 的选择。公共功能来源包括 `release/components/combat_economy/coin_drop_runtime.inc` 和 `release/components/combat_economy/collision_damage_runtime.inc`；活跃组合是显式选择的。强制0%/100%测试证明构造，而不是自然速率客户端的可见性。既有自然速率运行样本不能证明当前策略的客户端可见性。

## Boss 组件、分体与多阶段终结

Boss 正生命组件账本限定在 `(battle epoch, mode, authored child, authored ordinal)`。每个组件拥有独立 `component_hp`，伤害先钳制到当前组件剩余 HP，过量部分不进入兄弟组件；首次归零才产生组件终结，重复报告保持幂等。普通 runtime UID 怪物、runtime/deform、crate 与 Boss 账本继续相互独立。

三组件普通 Boss 的客户端可见总血条按 `11880 -> 7920 -> 3960 -> 0` 递减，组件 D011 使用精确 ordinal `0/1/2`，最终组件结束后才产生成功结算。对严格的同 child 正生命 type3 拓扑，若客户端持续报告局部首 tuple，adapter 仍提供“第一个仍存活 authored 组件”的有界折叠；精确非首 ordinal 始终按精确组件处理，owner/source 不参与目标猜测。

多模式 Boss 的内部 `c->hp` 是当前 mode 账本，`result.hp` 可保留当前加后续 mode 的总剩余量，但两者不能无条件当作终结时的客户端 recording。原客户端要求当前 mode 结束的 D012 `+0x28==0` 才授予完成许可，更新循环还再次要求 recording 为0才推进 mode；此前把未来6000留在这里导致组件爆炸后永不换阶段。wire `+0x28` 按当前 mode 账本发布（`mode_recording_hp`）；中间终结处该账本为0，编码器直接发布该值，聚合保留在 `hp`/`cumulative_damage`；states、奖励、排名和 HP/MP 回复增量全部为0，`awaiting_next_mode` 不提前结算。中间终结使用64字节并显式初始化排名尾部，覆盖其他 episode 的条件读取。一次请求只构造一次响应，不补推后续阶段数据。

跨 mode 总血条完全连续的旧承诺已撤回：阶段终结发送0后，下一 mode 初始化可能重置血条。正确换阶段与显示层连续总条是两个边界，后者需单独支持，不再用正 recording 绕开原生终结条件。当前失败 slot7 的构造、重复报告隔离和发送函数回归通过；修复后原客户端自动进入下一 mode 仍待验收。

当前资源审计覆盖339个分体 Boss mode；专项验证独立 HP、过量伤害钳制、组件／child／阶段终结门控、连续总血条和重复报告幂等。普通三组件场景已有原客户端可见观察；其余 mode 保持对应构造证据等级。
