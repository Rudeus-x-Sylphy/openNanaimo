# 07 拾取、结算、EXP 与奖励边界

## 老兵终端 Hans

静态调用链证明，终止 D012 DWORD+0x1C 独立于 D00E 进入原生 Hans 构造函数。适配器自定义策略将选中 Boss 资料定义的各模式 HP 相加得到完整总 HP，要求 HP>=200，在首个最终终止事件仅提交一次 `floor(total_hp/50)`，并将相同数量写入 D012+0x1C；重复及非终止报告携带0。4000-HP 单体 Boss 本地测试只产生一次 score4000 和 Hans80。只有 Boss HP 低于200时，才将 D012+0x20 卡片字段清零。这些数值属于显式适配器自定义策略。可见生成／追踪移动、卡片可达性及账号／重登一致性仍需新一轮运行验证。

## D034/D035

```text
D034 +0x08 WORD  类别：20 卡片、40 战斗效果；独立星星管理器另有 category30
D034 +0x0A WORD  场景物品 UID
D034 +0x0C DWORD category20 卡片代码；category40 类型：1 Power、2 HP、3 MP、4 速度
D035 +0x08/+0x0A 本地角色 UID
D035 +0x0C WORD  回显类别
D035 +0x0E WORD  回显场景物品 UID
D035 +0x10 DWORD 回显卡片代码／效果类型
```

本地 UID 相等性对于本地效果路径是必需的。8/8构造样本未满足`0x006F0A0E`处的UID比较；当前逐客户端响应使用实际收集者UID。共享响应保持 24 字节；category20 本身通过 `+0x13` 消耗，而其他类别分支使用保留的尾部。

对于category20，非零D035 `DWORD +0x10` 是原生的**本战获取卡牌结果载体**。客户端创建一个16字节的`{collector UID, card code, prev, next}`节点，并将其附加到战斗控制器`+0x970`。CF88随后清空该队列，将UID匹配到玩家结果块中的三个之一（位于`+0x64C + 0xC0*i`），并记录最多14个不同的卡牌代码；重复的代码会增加一个字节的计数。`WORD +0x0E`独立地移除场景卡牌对象，无法替换这个结果载体。

D034 的 `+0x08..+0x0F` 复制到 D035 的 `+0x0C..+0x13`；category20 的 `DWORD +0x10` 保持奖励值。category40/category20 拾取保持幂等：首次接受的拾取发送／广播 D035，重复拾取不产生第二个 ACK 或持久化增量。category20 的 codes13000028、13000094 和 13000139 已在原客户端中由 D035 返回，后续 CF88 结算使各持久计数增加1，结果列表可见。确切本地化名称／顺序、同代码 count2、空奖励、重新登录保持和多人收集器归属仍待分别验收。

## CF87/CF88

CF88 是结算/角色资料状态。记录步长为`0x34`，不是`0x38`。

```text
record +0x04 BYTE  升级表现门控
record +0x07 BYTE  结算后的副本等级／称号索引
record +0x0A BYTE  结算后的玩家等级
record +0x0C DWORD 本次结算增加的经验值
record +0x10 DWORD 绝对累计／当前经验值
record +0x14 DWORD 当前等级下限阈值
record +0x18 DWORD 下一等级阈值
```

CF88 同时也是立即获得的副本等级奖励载体。对于本地 UID 记录，`record+0x07` 达到 `0x006FA36E -> sub_40AAF6 -> sub_A72530` 并直接替换账号副本等级；客户端不会根据分数、经验、关卡或难度来计算等级。相同的值稍后必须通过 271A/C355/CF71 来恢复。

该值按角色记录提供。`hd0/episode15/dungeon2/difficulty2` 的 stage0 对应等级23，stage1 归一化为同一 stage0 前沿，确保超级 Boss 只结算一个等级。等级2/st1 状态加载为至少23/st0，并保留更高等级。未知元组使用“字典序严格变强时等级+1”的有界兼容策略。死亡调用 CF88 且进度增量为0；战斗状态周期去重和 `settlement_sent` 防止重复提交。

静态HUD算术运算将当前值限制在下一阈值以内，然后计算无符号的`(current - lower) / (next - lower) * 100`。它不会修复`current < lower`或`next <= lower`；需要一致的适配器阈值。客户端不会推导新的等级或阈值曲线：所有值以上均由适配器提供。`record+0x0A`通过`0x006FA34E -> sub_40FEE8 -> sub_A72570`写入角色资料等级；非零的`record+0x04`会在`0x006FA73B`处进入升级展示分支。此处理函数不会重新计算HP/MP。

原适配器的EXP奖励/曲线在数值上仍为未解决状态。适配器使用显式的确定性自定义策略：成功的请求驱动的CF87/CF88终局结算奖励给请求的角色100 EXP；死亡结算奖励0；从等级L提升的成本为`L * 100`；等级L的累计下限为`50 * (L-1) * L`；等级上限为99。跨越一个或多个阈值会设置`record+0x04=1`并发送结果等级以及一致的当前/下限/下一个值。每个角色/战斗状态周期最多一次结算，并在成功值发出前原子性地保存。

持久化身份、种子、原子替换及村庄／房间载体表见03。请求驱动的 CF88 是通关奖励提交点；重复 CF87 不重复奖励，死亡增量为0，CF8B/CF7F 开启新的战斗周期。本地构建验证 LV1/EXP0 -> LV2/EXP100、重启保持 LV2、第二次通关 EXP200，以及等级37、等级88、阈值附近和等级99上限的载体一致性。

C355、CF71 与 CF88 当前统一使用持久账本的等级、当前 EXP、当前阈值和下一阈值。等级区间百分比按 `(exp-current_threshold)/(next_threshold-current_threshold)` 计算，避免无符号下溢，并保留已获得 EXP。

## 结算页等待与动作授权

2026年9月25日原客户端负面验收撤回了“结构完整的 CF8B 就等同于玩家手动点击”的旧结论。普通结算控制器具有两条可触发 CF8B 的本地自动动作路径。当前客户端派生同时关闭 600-tick 超时块和 action-state 5 自动块，保留鼠标按钮调用点；普通第一／第二关的下一关、第三关的超级 Boss 挑战以及最终页重试都必须由按钮动作触发。adapter 仍要求 `SettlementAwaitingAction`、非死亡结算、完整12字节 CF8B 以及 mode1/2，其他状态不得推进。

有效继续动作只走 `CF8B -> CF8C -> CF70 -> CF71`。已授权连续挑战中的附带 CF73 与 CF1D 都被消费，不向客户端发出 CF1E/C368；主动回城则保持 `CF73 -> CF74 -> CF1D -> CF1E`。CF8B/CF8C 同时推进 managed 有效 tuple：mode2 普通下一关递增 dungeon，mode1 的 `dungeon2/stage0 -> stage1` 进入超级 Boss，超级 Boss 后的 mode2 进入下一逻辑难度。后续 CF71 与 CF87/CF88 因而使用同一持久槽。

继续动作保存下一关 intent、当前 HP/MP 快照和待恢复 P 弹阶段。资源继承见04，回城资源效果见02。当前结论达到静态、构造和客户端派生验证。

## 玩家死亡重试和结算边界

死亡结算使用 `CF87/12 -> CF88` 打开结果页，但不授予成功进度。2026年9月25日原客户端观察到死亡后仍显示 S；检查确认 CF88 每条记录的 `record +0x0B` 被无条件写成5。当前候选将可见评分与 `allow_progress` 分离：成功结算写5，死亡／不允许进度写0；死亡时 EXP added、grade/frontier 推进和成功排名写入均为0，局内分数只作为本局统计保留。评分0的具体客户端显示仍待验收，不把该私有策略表述为原始适配器算法。

同一次负面验收还否定了“先吞一组死亡离场、等待第二组”的假设。死亡结果页发出的第一组 `CF73/8 -> CF1D/8` 就是唯一离场链。当前候选为 CF73 构造 `CF74/12`，让 worker 清理房间；CF1D 继续到 worker并取得 `CF1E/12 status=200`，在响应排队后关闭 worker，以 `DeathReturn` 而不是 `TownReturn` 或 `NextDungeon` 完成边界。协议状态由本节维护，资源结果由02维护。该链已经通过 host 构造测试，尚未完成本候选原客户端卡死回归验收。

## 结果/排名向量

D012状态和排名按槽位编号，每个活跃槽位均有记录。双客户端样本观察到`SUCCESS_CLEAR/S`；该样本不替代release的运行验收。

分数、结果状态、排名和奖励载体是分开的。可见的S级评分并不能证明当前公式或等级阈值。
The persistent "view credits" cache stores only B/A/S as packed two-bit values 1/2/3; C and lower remain 0 and therefore show no rank. Ordinary results are keyed by episode and logical difficulty, while secret results use a separate four-episode ledger. A later lower result never replaces a higher stored rank.


## 普通评分数字来源

客户端目标账本不含每只怪物的独立得分字段。D00E 非终端接收三个绝对得分 DWORD（`+0x08/+0x0C/+0x10`）；D010 非终端接收 `+0x0C` 绝对得分并由 `0x748990` 写入房间槽位；CF88 接收结算总计／排名状态。适配器在非终端攻击中保持得分不变，在目标首次从正 HP 归零时增加一次初始最大 HP；Boss 在首次最终终端时增加模式 HP 总和。重复、过度伤害与无效报告得分为0。

## 货币边界

CF8A 只达到结算/UI状态，并未调用余额设置器。

```text
coin/Hans   group1 u64
nana/Cash   group2 u64
```

生成的目标账本完整记录共有471011行/2642个资源，仅包含reward_kind0（466340行）或reward_kind5（4671行）。所有121295行属于1046个以怪物命名的MMO资源都是reward_kind0；reward_kind5是已核实的道具块随机效果路径，而不是Hans。普通怪物Hans消耗适配器提供的D00E/D012 DWORD+0x1C，而客户端资源仅提供1/10/100/500的展示单位。因此，没有针对每个怪物的Hans的静态封闭数量、概率或分布。普通硬币策略、容量、难度选择、分数/排名/等级阈值以及经验曲线仍属于适配器自定义策略，没有原始适配器的数值封闭。

## 超级Boss的EXP异常边界

两个客户端样本在 `0xB4AB10` 处发生异常，到达 `%.2f` 双重格式化器：

```text
0x008E1D24 -> 0x00B47637 -> sub_B4AA94
```

这不是一个PON/射击游戏基础的`%s`资源名格式化工具。

共享的高层级故障是不一致的EXP状态导致无符号的下溢/除零错误。D3DIM700无效读取是独立的崩溃签名。

## 结果一致性约束

以下是协议／状态约束，不是全部通过客户端验收的声明。

- 结果／排名按活跃槽位分别构造；
- CF88 等级仍然保持角色资料特定；
- EXP当前值、下限及下一阈值保持一致；

- 结算不应覆盖可编辑的Z/X技能状态；
- 重复拾取和容量失效依然安全；
- 自定义评分公式不等于原始适配器行为。

## Ready-room badge and settlement ranking

CF71 `BYTE+0xB4` only controls the selected-stage blank/B/A/S badge. The separate observed settlement chain is `CF87/12 -> CF88 -> CF15/12 -> CF16/252`. CF16 echoes the four-byte CF15 selector and contains ten24-byte rows: GBK name[16], DWORD score, WORD level and WORD level-icon band. On the retained-native playable route, a successful non-death CF87 exchange returns CF88 with the member's D..S result; managed egress persists that personal best rank by the CF6C tuple before the next ready-room request. Death-inventory/no-progress CF88 is intentionally excluded.
OpenNanaimo private policy persists one best team stage-record score per participant and per `hd/episode/dungeon/stage/logical-difficulty`. CF16 returns at most ten rows ordered by score descending, then elapsed time, update time and character id. Ordinary and secret/Super-BOSS stage tables are separate; old aggregate secret history is not guessed into a stage row. This does not change CF88 reward/rating arithmetic or C355/CF71 best-rank values.

## 超级Boss续战与客户端发起的退出

ep7/dg2 退出顺序：

```text
D013 硬编码 child1 -> D012 final -> CF87/CF88 -> CF15/CF16
CF8B real1/show0/mode1 -> CF8C real1/show0/diff1/dg2
客户端 CF73 -> CF1D -> 适配器 CF1E/200
```

客户端在 CF8C 后发起离开；CF8C 长度48，消费字段 `+0x28/+0x29/+0x2C/+0x2E`，并与当前难度／副本一致。Boss 生命周期在离开前完成所有子对象回收与资源 HP 边界结算。

当前构建使用数据驱动的子对象回收，而不是特殊情况下使用。本地构建证明结算并包含 `CF8B -> CF8C -> C587 -> CF70 -> CFEB stage1`；只有客户端运行时可以证明客户端现在选择该路径而不是 CF73/CF1D。不要强制将难度1强制为难度2。

## 原生汉斯和持久账号策略

原生 PvE D00E `status200/subtype20` 将 `DWORD+0x1C` 读取为 Hans 数量，经0x689FA0/0x6D2E10构造 `ef_money_hans_*.eff`，并立即将该数量加入本地战斗 HUD（`0x748950`，字段+0x284）。原生动画按角色 UID 追踪移动；已核实的更新／移除链不发出 D034，也不进行第二次账号奖励。视觉完成与账号持久化是两个独立边界。

Subtype30 是卡片路径（`0x685810`）。D035 的 category30 处理函数位于 `0x6F1B7D..0x6F1D2F`，遍历 `ssky_pvp_star` 管理器并切换集合状态；category20/40 使用各自请求语义。Hans 拾取使用已确认的 subtype20 请求路径。

适配器奖励策略使用目标记账的初始化最大生命值（HP）。HP<200 时首个终端不产生 Hans 或卡片；HP>=200 时先执行1%的普通卡片抽取，命中时使用 subtype30，否则 subtype20 数量为 `floor(max_hp/50)`。绑定种类20与肉目标终端共用该路径。Boss D012 首次最终时携带 `floor(total Boss profile HP/50)`。`shopping_state_save`、溢出保护、事务回滚、战斗／生成终端去重和通信记录前保留共同保障持久化一致性。

运行样本中的余额变化99,999,999 -> 100,000,159只证明subtype0自动入账，不证明动画。subtype10的星扩展实验也不是原生Hans验收。可见生成／归宿、HUD／账号／返回／重登一致性及连接稳定性尚缺完整客户端验证；多客户端分发与结算记账也未闭合。远程视觉副本不能等同于第二份持久奖励。

静态构造函数及包字段见08；目标资格与终端规则见06。
