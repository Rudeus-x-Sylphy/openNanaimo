# 05 房间、加载和多人同步

## 阶段模型

```text
CF09 传输
-> 房主／房间创建
-> CF70/CF71 成员名单和 CF7E 准备／队伍快照
-> CFEB/CFEC 房间资料
-> CFD3/CFD4 and CFD5/CFD6 同伴连接元组
-> 预加载 CF80/CFEC
-> 每个客户端 CF7F
-> 每个客户端 最终 CF80
-> 实时转发
-> 战斗与结算
-> 离开／断线／村庄恢复
```

一个成功的前期阶段并不授权后期阶段中的未经请求的分组。

## 通道选择器登录和GS重新进入

通道选择器使用一个新的登录连接10为`271B/12 -> 271C/176`，然后关闭旧的GS0/login10，重新连接选定的IPv4以及保存的GS端口作为GS0并发送`C351/24 -> C352`。相同逻辑槽位的保留仍然需要在完成旧代理/后端销毁后，仅有一个明确的源IP匹配才能解锁；角色重建在重新进入后仍然保持请求驱动。

每次新登录均初始化帧头：S2C 序列从0开始；第一个完整请求为该套接字固定 `checksum_seed=low5|(low5<<8)`；每个响应复制触发请求的低5位。适配器构造验证覆盖首次低09/16/0E、`0,1..100,1` 序列环、后续响应低位复制、UID21复用及C355资料状态一致性；这些结果不构成客户端运行验收。调用地址见08。

## 房间阶段 C47D 和村庄重建

C47D/144 既用于村庄装备/快捷栏更改，也用于准备房间编辑。其成功的响应必须遵循当前房间标志。在村庄状态下，保留 `C47E -> C368 -> C47F -> C379 -> C3CC -> C44C`，以便重建外观和后续的 PET。在房间/准备状态下，仅发送 `C47E -> C379 -> C3CC -> C44C`：C368 调用场景销毁，清除 shared_scene+0x24，并使准备控制器的初始化标志失效；因此，C47F 也会被抑制。这不会改变 CF80/开始构建或伪造一个阶段管理者。

村庄返回独立地由请求驱动。Selector4 从超级Boss页面18返回的运行观察中没有C36C；对应处理在C367发送C368后，允许首次CB21触发C47F附着。其他选择器在首次CB21附着前仍要求C36C。适配器通信记录验证覆盖两个分支，客户端渲染效果尚未验证。

## 拉明奥斯村庄前置进展

第五个村庄（hd4）有一个独立的64位前置条件字段在**C355全帧+0x80..0x87**。普通的前四个村庄进度和压缩的阶段显示字节不会替代它。它的局部移动谓词需要**每个前置对的两个位**；普通的CheckDungeon路径是分开的。零掩码条件下的客户端运行中，每一对在接收到的C355和只读的运行内存中都是零，这与报告的“挑战完关卡方可移动”边界相符。具体的分派器/写入器/谓词/消息/发送地址、页面映射和本地映射小部件异常属于08。

现行本地无条件开放策略在最终C355发送边界同时规范三个域：`+0x3C..+0x77=0x0F`；`QWORD +0x80..+0x87` 将低44位（22个前继对）置1并保留bit44..63；`+0x88..+0xDE=0x55`（每个2-bit槽为状态1）。`+0x78..+0x7F`及`+0xDF`后的情侣姓名、戒指、复活次数和所有尾部字段保持不变。reference implementation中间构造的`0xFF`填充会被最终unlock helper覆盖为`0x55`，因此线上比较必须以最终发送字节为准。归一化在主构造器和最终校验和前各执行一次，且仍由`C354`请求驱动；没有添加未经请求的C367/C368、角色重建或客户端补丁。必须重新登录／刷新资料，旧客户端缓存不会因替换可执行文件自动改变。

现场失败帧已经具有低44位全1，但`+0x88..+0xDE`全0，证明“只设低44位”的旧检查不足。专项回归现已覆盖普通副本表、前置QWORD、打包阶段域、频道重连及`+0xDF`边界；这是适配器端构造验证，不是可见移动验收。**无条件开放载体仍不等于23个物理副本入口、道路和战斗资源全部存在。** d07叠加抑制（08）、原始物理村庄拓扑和道路派生、action166以及战斗资源加载继续作为独立边界验证；额外C355填充不能创建缺失出口或资源。

### 实体村庄路线和地图内容

随游戏发布的第五村地图包仅连接了前六个副本的路径：页面8、7、6、11、16、17，触发器为160至165。页面17（入口6）有一个返回到页面16的出口，**没有返回到页面18（入口7）的出口**。剩余的17个计划中的副本页面具有相同的网格数据，既没有页面出口也没有副本入口触发器。因此，点亮小地图槽位8至23不能证明对应区域可玩。地图包解析、单元消费链及规划页面顺序见08。

现有村庄道路图在第18页至第24页的剩余规划路线包含16组双向连接；全部23个规划村庄区域具有连通的格点路径，第17/18页的第七入口166与原生返回169保留。道路修改限于17条记录的碰撞、目标和到达来源WORD，不添加167..182副本触发器或替代战斗。准确格点、方向及构造／运行边界见08。原资源包的六入口拓扑与此道路图应分别理解。客户端曾观察到page18/index6/ep22入口，但完整道路的行走／碰撞及第七入口返回／重新进入尚未验收。第18页东端连接18↔19，未连通边界与最终端点仍封闭。村庄道路连通不等于具备完整ep23..38战场资源（06）。

**黑屏观察范围：** 报告的黑屏位于进入准备房间前的创建／列表UI，不是第22关战场开启画面的战场SSTG/SM2/IM3存在或辅助图像解码不能证明该UI正常渲染。Entry166经0x402EF0 -> 0x42FBA0（08）切换至场景状态9；创建／列表背景的具体加载或渲染失败点尚未核实。

客户端的d07强制隐藏标志与村庄道路拓扑独立；道路存在并不消除暗显。显示标志不是出口／到达标记，合成C367/C368交换也不等于玩家移动。缺少VIL单元不能单独证明全部图像或战斗资源缺失；目的地可玩性取决于战斗资源元组、拓扑、图像及客户端实际行为。

## 映射身份和续行

Lumineos episode100保留通信／房间身份；资源查找转换及七个战斗资源范围见06，客户端选择地址见08。七个战斗资源范围与原资源包仅有六个可达入口并不矛盾；现有道路图保留第七入口路径及返回标记，扩展范围仅为村庄道路。

CF77 是一个资源提示，CF6C 是权威的完整房间元组，CFEB 提供初始/重新加载阶段的信息，而 CF8B 提供后续的转换。CF7F 在存在一个一致的 `hd/episode/dungeon/stage/difficulty` 元组之前保持关闭状态。`absolute_slot=difficulty*3+stage_index`；BOSS、普通目标和箱子/掉落物使用相同的快照。有效的 CF77/CFEB 路径可以在没有 CF6C 的情况下建立身份；提示不是混合元组的许可。

现行私有延续策略将CF8B模式2视为下一副本，仅当随附的HP/资源库包含当前关卡/集/难度的`dungeon+1/stage0`时。CF8C和身份在更新CFEB/CF7F之前。本地构建证明dg1→dg2；客户端原始映射和技能验收仍处于开放状态。一次客户端运行回传了`{real=0,show=0,mode=2}`到副本1，而第二次战斗未发出CF9B；仅重置适配器状态不能解释或验证客户端本地门控条件。

第7入口的超级 Boss mode1 重置已定位到资源名称与查找异常；这不同于 mode2 的下一副本策略。失败与验收范围见06，条件式 CF8C 副本设置函数见08。不得通过更改房间的章节／副本元组绕过该问题。

## 成员名单、身份和外观

- 业主可以在成员进入前发送 CF70，并最初仅接收自我 CF71。
- 当成员变为房间活跃时，已同步的所有者将收到恰好一个去重的远程CF71推送。
- 成员 CF70 不能重复记录。
- 一个新的CF09/房间状态周期重新武装了记账簿。
- 合成网络 UID1 CF72 仍被抑制。

多人运行样本使用UID21/22；这些数值是样本身份，不是通用账号ID规则。

CF71字段策略对应公开实现 `release/components/protocol/protocol_state_sync_base.inc`：

```text
+0x34 DWORD = 0 在已保留可见观察对应的元组中
+0x38 DWORD = 选中宠物
+0x3C DWORD = 资料性别 & 1（基础模型 D8）
+0x4A/+0x4C/+0x4E/+0x50 = 角色资料的有效 HP/MP
+0x52 WORD = 0 (房间阶段)
+0x56 BYTE = 房间槽位
+0x57 BYTE = 资料性别 & 1
+0x58 DWORD = 选中宠物
+0xB4 WORD = 1
```

`sub_4EF380` 仅初始化低WORD为0/1的基础模型；`+0x3C=0x2000`不能作为该模型值。CF72基础D8在+0x34同样使用gender0/1，而不是0x4000。CF71的+0x57/+0x58分别取资料性别及选中宠物，不能统一置零。效果、PET、HP载体各有包布局，不能跨包移植。

每个成员名单条目都会为同一个UID发送CF71然后是CF72，**包括远程角色对象**。CF72 case53106会查找带有WORD+8的现有角色；WORD+0x64=1会应用完整角色资料，而BYTE+0x66会刷新PetLevel/启动器。合成UID1的抑制并不等同于远程角色对象的抑制。预CF80的本地刷新是一个独立的边界：现行发布仅发送CF72（03/09）。

## 入口、进度和可见性

CF71 可以在 X=-300 处创建一个离屏角色。CFDA 案例 53210 将数据字+8 匹配到角色数据字+4，激活它并启动一个模式相关的准备房间护卫；0x0578 仅更新加载进度。默认模式下为 `(-300,151+100*slot) -> (77,151+100*slot)`；替代模式使用端点119 和行 `110+100*slot`。确切的本地/远程指令路径在 08 中。不要从一个模式推断出通用的房间位置。

每个CFD9/8请求会为房间中按顺序排列的每个活跃房间角色获得一个CFDA/12。没有预请求的CFDA；战斗屏障保持不变。仅请求方的响应不足以实现远程激活。双客户端运行观察确认两个角色主体进入，但不能证明当前的两台机器自动/定位效果、晚加入或重复状态周期的可见性。CFDA是房间入口帧，**不是地城阶段位置修正**（参见本主题的阶段入口位置分析）。

## 加载和转发

如果成员预加载等待所有者CF7F，一个两-CF80实现仍然可以序列化。

当前构建：

```text
房主 CFEB -> 房主 CFEC -> 成员 预加载 CF80 -> 成员 CFEC
成员 CF7F -> 成员 最终 CF80
房主 CF7F  -> 房主 最终 CF80，仅此响应
全部最终 CF7F 到齐 -> 启用实时转发
```

两个CF80数据包不能证明并发加载。验收需要在所有者CFEB处进行全局时间校验，并且需要可见的进度条行为。

当前适配器转发的编号大类包括移动/活动、0x03E8/0x044C 游戏玩法、成功的效果 CF9C/CF9D 角色效果、普通终端状态、BOSS 生命值/分数，以及拾取物的移除。射击室聊天尚未纳入此转发列表。

每个转发都保留源身份、房间/页面、连接生命周期、请求优先级和顺序规则。

## 对等元组和聊天

CFD4必须解码远程UID、IP和UDP端口，避免端口污染UID字节。运行记录中远程UID/IP/UDP3534正确，但这不单独证明远程角色模型可见。

村庄CB23由适配器路由，已有双向通信观察。准备房间／游戏聊天是独立的对等通道，房间通告端口3534。连接器提供需管理员权限的TCP/UDP3534防火墙选项；防火墙是否导致聊天异常尚无两机通信捕获证明。

## 多人运行验证边界

现有证据尚未完整覆盖先房主后加入、准备前后角色可见性、并发加载、双向自动／归巢弹药、远程PET／效果附着与CF9C转换，以及多状态周期的离开／断线／村庄恢复。客户端现象的归因依赖源UID、帧顺序、请求低位及序列；防火墙因果关系仍未证实。

## 阶段入口位置校准与证据范围

三次客户端运行的校准仅适用于 **hd0/ep0/dg1/st0**。CF80之后，`0x044C`报告与角色整数位置的关系为 **report X = actor X + 53，report Y = actor Y + 5**。记录中的`payload+0x0A`为X、`payload+0x0C`为Y；`payload+0x14`是约59.4–60次/秒的角色时钟，不是坐标。

1. **X、Y必须按同一客户端本地模式配对。** CFDA与CF71的模式相关常量见08。X范围130–172来自房间端点77/119加53，但不能据此单独判定位置有效：
   - 模式字节=0：`(X,Y)=(130,156)`，即房间点`(77,151)`加`(53,5)`。
   - 模式字节非零：`(X,Y)=(172,115)`，即房间点`(119,110)`加`(53,5)`。
   - 样本中的`(172,115)`符合该配对；统一要求Y≈156会误判非零模式。`X<0`或`X>=300`不符合阶段入口判据，300为CF84终点。
2. **Y用于区分位置写入路径，不是单纯的垂直容差。** Y≈305对应CF84路径，不符合入口判据；Y≈257对应CF71常量252仍被写入，不是有效入口或房间边界的证明。无输入样本中`X=-247/Y=257`持续超过6秒，说明适配器触发的客户端放置值可以持续不变，不能仅凭悬空现象归因。
3. **冻结位置不通过入口判据。** 一个样本连续39次报告`X=-247`。`0x044C`仅在关卡中发出，因此不能用准备房间到关卡的“ΔX”比较校准。

上述三次同阶段样本不构成release的运行验收。偏移沿用负载相对标记，其口径是否包含八字节包头尚未独立确认；测得的(+53,+5)及模式配对关系不可外推到其他阶段。
