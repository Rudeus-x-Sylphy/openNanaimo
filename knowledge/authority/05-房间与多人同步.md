# 05 房间、加载和多人同步

## 阶段模型

## 好友与私聊

- 好友申请按收件角色确认，接受、拒绝和稍后处理使用同一持久化申请状态；重复确认保持单次关系提交。
- 客户端联系人添加、好友列表及管理界面共用 `FriendRelations` 和分类数据。添加验证当前账号／角色／会话及屏蔽关系，首次、反向及重复添加均确认本次目标，成功状态与添加操作类型分别编码，双向关系保持幂等和单次通知。
- 私聊按在线角色名定向送达，发送者姓名由活动会话确定。姓名16字节、正文32字节均采用有效的NUL结尾GBK；输出重新编码并清零剩余空间。离线接收者得到系统提示，双向屏蔽关系限制投递。

## 情侣关系与权益

- 求婚绑定发起者、接收者、戒指代码、非零稳定库存实例和30秒有效期；求婚列表与普通游戏道具页共享同一戒指实例身份，响应仅由对应接收会话提交。双方当前账号／角色／会话在库存与关系事务中共同校验，成功建立关系时消耗一枚戒指。
- 情侣姓名、关系和戒指等级持久化。会话刷新与城镇角色构造均同时携带伴侣姓名和戒指等级，空关系清除两者；本人及旁观显示另受持久称号选项门控，C355/C36A字段与显示门控由08维护；结婚、双方分手及强制分手按02定义的同身份角色替换更新，保留场景和位置，同页旁观者取得更新后的角色资料。银、金、钻戒分别增加个人HP／MP道具恢复20%、50%、100%，恢复按有效资源上限封顶，适用于城镇、托管地宫和原生地宫。
- 戒指权益统一按实际代码解析：银戒 `43000001`、金戒 `43000002`、钻戒 `43000003`；未知代码使用零权益。金戒、钻戒在情侣双方参与当前房间同阶段战斗时分别使用120%、150%的角色结算经验；组队、宠物、评级、分数和Hans沿用各自规则。
- 金戒、钻戒解锁情侣心情符号31–39。权限由有效关系和戒指确定，身份由活动角色确定。
- 金币分手券43100001的“使用”校验当前关系和所选实例并打开双方确认；伴侣同意后原子解除关系并扣除一张，拒绝或取消保持关系与库存。两类分手券均使用1..84的游戏道具身份。强制分手券43100002的“使用”建立30秒确认上下文；确认提交时按当前关系、账号／角色／会话及原库存实例执行单次扣券和双向关系更新。取消保留关系与库存，重复使用沿用原确认期限，变更库存或关系后的旧确认失效。
- 求婚资料分别投影人物等级和地宫称号，称号按有效地宫等级索引显示。
- 准备阶段保持房间身份初始化；队员先接收含遭遇开关的CFEC地图预载，不在地图数据前推送CF80。该队员自己的CF7F加载确认到达后，按当前阶段发布一次C588伴侣身份再返回空CF80；托管身份统一使用场景 UID。特殊遭遇在地图准备时按同房有效情侣关系开启，全房成员取得一致的场景状态；战斗开始后按实际参战名单及完整关卡选择校验。情侣经验仍归属于双方有效参战角色。
- 情侣同房同阶段存活时，个人HP／MP道具同时恢复本人及伴侣，按各角色有效上限封顶。托管请求路径在扣药前解析共享对象；库存扣减归属于使用者，伴侣恢复使用独立角色身份及免扣槽位，CF94使用完整24字节并初始化尾部；普通队友保持个人道具规则。恢复事务读取双方选中宠物及装备加成后的有效上限，不按基础MaxHp/MaxMp压低当前资源，也不回写基础最大值。三档戒指恢复倍率、双方资源保存和连续关卡资源状态共同维护。每次原生用药在扣除前重新绑定伴侣的当前连接代次，同身份重连与跨关后使用当前有效绑定。

情侣验证覆盖地图开关、身份顺序、共享恢复及双方持久化；特殊怪物的资源属性与运行实例血量规则归属06，双端显示按实际地图独立验收。

## 师徒关系与课程

师徒申请、邀请、确认、拒绝、取消和解绑按当前账号／角色／会话归属持久化；教学广告与在线列表只显示当前频道的有效角色。生产课程由任务条件绑定到双方同房同阶段的成功通关，双方均提交同一结算身份后才记一次课程进度；重复结算、切换关卡、死亡和不同会话代次保持单次记账。毕业由教师确认，在城镇资料边界执行，按已完成课程、学生等级和关系状态原子结算奖励；重复毕业保持幂等。

## 组队续关与观战

组队邀请绑定可见目标和真实发起身份，接受后双方进入同一队伍；房间开始以成员准备和各客户端最终加载确认分别推进。阵亡成员保持接收房间更新的观战状态，主动道具、技能和拾取按死亡状态限制。

下一地宫动作由当前房间的一位发起者授权。同房同关卡组员共享该动作的确认，保留过渡期连接，并以各自战斗周期校验状态更新；并发继续保持一个房间动作，拒绝时恢复组员原授权。每次有效续关同时更新所有活动成员的地宫、实际阶段、显示阶段和难度，重置上一场的加载屏障及最终开始确认。队员的连接局部状态在后续请求前切换到新关卡准备阶段，队长取得关卡资料时为队员建立新的预加载周期；队员通过自己的资料请求或对应房间初始化完成加载。当前成员的CF70资料刷新保留已下发的预载授权，成员退出、新入房与连接代次变化分别清理授权。离场、断线及连接槽位重新分配按成员代次清理续关状态。获准续关先向每位成员发送CF6D状态10，再发送CF8C；结算中的成员仅凭当前房间续关授权接收该初始化。本人主动CF70对应的本地CF71结束过渡离场保护。新阶段中的阵亡成员恢复生命、魔法和战斗状态，资源冻结持续到对应加载初始化；保留控制器的CFEB／CFEC续关维持已建立的情侣用药身份。掉落与评分的角色归属由07维护。

## 通道选择器登录和GS重新进入

通道选择器使用新的登录连接10完成 `271B/12 -> 271C/176`，随后关闭当前 GS0/login10，按选定 IPv4 与已保存 GS 端口重连 GS0，并发送 `C351/24 -> C352`。原连接和适配器会话释放后，在来源 IP 唯一匹配时保留逻辑槽位；角色重建保持请求驱动。

每次新登录均初始化帧头：S2C 序列从0开始；第一个完整请求为该套接字固定 `checksum_seed=low5|(low5<<8)`；每个响应复制触发请求的低5位。适配器构造验证覆盖首次低09/16/0E、`0,1..100,1` 序列环、后续响应低位复制、UID21复用及C355资料状态一致性；这些结果不构成客户端运行验收。调用地址见08。

## 社交模式运行边界

社交模式不创建新的协议模式，也不使用 Stand_Alone；它沿用 Network 登录、GS、房间和地宫链，将 adapter 与客户端配置到同一个明确局域网 IPv4。GUI 的 P1／P2／P3 按用户名注册账户后分别启动客户端；同一来源 IPv4 的注册按队列消费，其他机器从各自来源 IPv4 隔离接入。该启动便利层不扩大本主题既有的多人可见性或两机运行验收范围；绑定与 GUI 契约见09，来源队列与账户归属见01／02／03。

## 房间阶段 C47D 和村庄重建

C47D/144 既用于村庄装备/快捷栏更改，也用于准备房间编辑。其成功的响应必须遵循当前房间标志。在村庄状态下，保留 `C47E -> C368 -> C47F -> C379 -> C3CC -> C44C`，以便重建外观和后续的 PET。在房间/准备状态下，仅发送 `C47E -> C379 -> C3CC -> C44C`：C368 调用场景销毁，清除 shared_scene+0x24，并使准备控制器的初始化标志失效；因此，C47F 也会被抑制。这不会改变 CF80/开始构建或伪造一个阶段管理者。

## 拉明奥斯村庄前置进展

第五个村庄（hd4）有一个独立的64位前置条件字段在**C355全帧+0x80..0x87**。普通的前四个村庄进度和压缩的阶段显示字节不会替代它。它的局部移动谓词需要**每个前置对的两个位**；普通的CheckDungeon路径是分开的。零掩码条件下的客户端运行中，每一对在接收到的C355和只读的运行内存中都是零，这与报告的“挑战完关卡方可移动”边界相符。具体的分派器/写入器/谓词/消息/发送地址、页面映射和本地映射小部件异常属于08。

C355 final access normalization has two domains: `+0x3C..+0x77=0x0F`, and the low44 predecessor bits of `QWORD +0x80..+0x87` are set while bit44..63 are preserved. The score-board bytes `+0x88..+0xDE` are not normalized: ordinary `+0x88..+0xC3`, secret `+0xC4..+0xC7`, and frontier `+0xC8..+0xDE` retain persisted or zero values. `+0x78..+0x7F` and fields from `+0xDF` onward remain unchanged. C354 remains the request trigger.

构造检查覆盖普通副本表、前置 QWORD、打包阶段域、频道重连及 `+0xDF` 边界。该验证覆盖适配器端 C355 构造；物理入口、道路、action166、战斗资源与原客户端可见移动分别验收。

### 实体村庄路线和地图内容

随游戏发布的第五村地图包仅连接了前六个副本的路径：页面8、7、6、11、16、17，触发器为160至165。页面17（入口6）有一个返回到页面16的出口，**没有返回到页面18（入口7）的出口**。剩余的17个计划中的副本页面具有相同的网格数据，既没有页面出口也没有副本入口触发器。因此，点亮小地图槽位8至23不能证明对应区域可玩。地图包解析、单元消费链及规划页面顺序见08。

现有村庄道路图在第18页至第24页的剩余规划路线包含16组双向连接；全部23个规划村庄区域具有连通的格点路径，第17/18页的第七入口166与原生返回169保留。道路修改限于17条记录的碰撞、目标和到达来源WORD，不添加167..182副本触发器或替代战斗。准确格点、方向及构造／运行边界见08。原资源包的六入口拓扑与此道路图应分别理解。客户端曾观察到page18/index6/ep22入口，但完整道路的行走／碰撞及第七入口返回／重新进入尚未验收。第18页东端连接18↔19，未连通边界与最终端点仍封闭。村庄道路连通不等于具备完整ep23..38战场资源（06）。

**创建／列表界面范围：** 该界面位于进入准备房间之前，使用独立于战场 SSTG/SM2/IM3 的加载与渲染路径。Entry166 经 `0x402EF0 -> 0x42FBA0`（08）切换至场景状态9；创建／列表背景的具体资源与渲染点仍待静态链闭合。

客户端的d07强制隐藏标志与村庄道路拓扑独立；道路存在并不消除暗显。显示标志不是出口／到达标记，合成C367/C368交换也不等于玩家移动。缺少VIL单元不能单独证明全部图像或战斗资源缺失；目的地可玩性取决于战斗资源元组、拓扑、图像及客户端实际行为。

## 映射身份和续行

Lumineos episode100保留通信／房间身份；资源查找转换及七个战斗资源范围见06，客户端选择地址见08。七个战斗资源范围与原资源包仅有六个可达入口并不矛盾；现有道路图保留第七入口路径及返回标记，扩展范围仅为村庄道路。

CF77 mode10/100 的基础选择字节依次为 `hd/episode/dungeon/difficulty`，不含RealStage；初始准备房固定为stage0。CF78完整帧+0x0A/+0x0B必须回送episode/dungeon，+0x0C是DWORD room id；旧实现把+0x0A写成owner/member标志并错把CF77 episode解释为RealStage，会让四村关卡16左转的准备房显示成错误地宫。CF6C仍是权威完整 `hd/episode/dungeon/stage/difficulty` 元组，adapter不篡改客户端后续CF6C；CFEB提供初始/重载阶段，CF8B提供后续转换。`absolute_slot=difficulty*3+stage_index`，CF7F在身份一致前保持关闭。

CF8B模式2选择下一副本，要求资源库包含当前关卡／章节／难度的dungeon+1/stage0；CF8C及房间身份先于CFEB/CF7F更新。构造验证覆盖dg1→dg2；客户端技能授权由其本地加载与技能门控管理。

第7入口的超级 Boss mode1 使用独立的资源名称、查找映射和 CF8C 副本设置边界；mode2 使用下一副本策略。房间章节／副本 tuple 保持原身份，资源层通过限定映射解析。

- CF09建立大厅传输；CF6C房间创建及CF70成员初始化建立实际准备房成员身份。房主最初取得实际入房名单。

多人运行样本使用UID21/22；这些数值是样本身份，不是通用账号ID规则。

CF71字段策略对应公开实现 `release/components/protocol/protocol_state_sync_base.inc`：

```text
+0x34 DWORD = 0 在已保留可见观察对应的元组中
+0x38 DWORD = 选中宠物
+0x3C DWORD = 资料性别 & 1（基础模型 D8）
+0x4A/+0x4C/+0x4E/+0x50 = 角色资料的有效 HP/MP
+0x52 WORD = 0 (房间阶段)
+0x56 BYTE = 房间槽位
+0x57 BYTE = 资料性别 & 1
+0x58 DWORD = 选中宠物
+0xB4 WORD = selected-stage rank in low byte (0 blank,1 B,2 A,3 S), high byte0
```

The previous fixed1/character-level mapping is retracted. CF71 case53105 sends BYTE+0xB4 with BYTE+0x56 room slot to the native badge builder, which supports only0..3. The adapter now resolves each member's persisted rank for the selected stage/difficulty; C355 credits and CF16 settlement records stay independent. The native playable route also persists a successful non-death CF87->CF88 member result before later room entry, so the rank ledger is no longer dependent on the managed-only reward path.
The September25,2026 original-client run and the follow-up database audit are now closed by03/07/08: first the actual native CF71 egress was normalized, then non-death CF87->CF88 personal results were persisted before the next room request. September25,2026 user acceptance confirmed the deployed original-client reported scenario.

`sub_4EF380` 仅初始化低WORD为0/1的基础模型；`+0x3C=0x2000`不能作为该模型值。CF72基础D8在+0x34同样使用gender0/1，而不是0x4000。CF71的+0x57/+0x58分别取资料性别及选中宠物，不能统一置零。效果、PET、HP载体各有包布局，不能跨包移植。

每个成员名单条目都会为同一个UID发送CF71然后是CF72，**包括远程角色对象**。CF72 case53106会查找带有WORD+8的现有角色；WORD+0x64=1会应用完整角色资料，而BYTE+0x66会刷新PetLevel/启动器。合成UID1的抑制并不等同于远程角色对象的抑制。预CF80的本地刷新是一个独立的边界：现行发布仅发送CF72（03/09）。

CF71 可以在 X=-300 处创建一个离屏角色。CFDA 案例 53210 将数据字+8 匹配到角色数据字+4，激活它并启动一个模式相关的准备房间护卫；0x0578 仅更新加载进度。默认模式下为 `(-300,151+100*slot) -> (77,151+100*slot)`；替代模式使用端点119 和行 `110+100*slot`。确切的本地/远程指令路径在 08 中。不要从一个模式推断出通用的房间位置。

## 加载和转发

房间加载、个人战斗状态和共享战斗状态分开维护：

```text
房主 CFEB -> 房主及各成员 CFEC -> 各客户端加载
各成员 CF7F -> 按活动房间与加载周期登记确认
全部确认到齐 -> 向每个成员发送一次 CF80/8 -> 客户端本地倒计时
```

CFEC负责完整关卡资料；CF80负责启动本地倒计时。每个加载周期只初始化一次共享Boss、目标和分数；每位成员独立初始化受伤、技能、资源和死亡状态。成员继承本轮完整关卡、难度及阶段身份，支持房主先完成和成员先完成两种顺序。重复开始确认保持幂等，继续关卡与重新建房分别重置加载屏障。最终响应保留各成员自己的请求低位。

## 阶段入口位置与适用范围

hd0/ep0/dg1/st0中，CF80后0x044C位置关系为 **report X = actor X + 53，report Y = actor Y + 5**。标记为payload+0x0A/+0x0C的字段分别为X/Y，payload+0x14为约59.4–60次／秒的角色时钟。

1. **X、Y必须按同一客户端本地模式配对。** CFDA与CF71的模式相关常量见08。X范围130–172来自房间端点77/119加53，但不能据此单独判定位置有效：
   - 模式字节=0：`(X,Y)=(130,156)`，即房间点`(77,151)`加`(53,5)`。
   - 模式字节非零：`(X,Y)=(172,115)`，即房间点`(119,110)`加`(53,5)`。
   - 样本中的`(172,115)`符合该配对；统一要求Y≈156会误判非零模式。`X<0`或`X>=300`不符合阶段入口判据，300为CF84终点。
2. **Y 用于识别位置写入路径。** Y≈305 对应 CF84 路径；Y≈257 对应 CF71 常量252路径。入口判据使用与同一模式绑定的 X/Y 坐标对。无输入样本中的 `X=-247/Y=257` 持续超过6秒，表明客户端会保持最近一次适配器放置值。
3. **冻结位置不通过入口判据。** 一个样本连续39次报告`X=-247`。`0x044C`仅在关卡中发出，因此不能用准备房间到关卡的“ΔX”比较校准。

上述(+53,+5)与模式配对适用于hd0/ep0/dg1/st0。偏移保留原有payload相对标记，使用时按完整结构确认包头口径；其他阶段按各自位置契约处理。
