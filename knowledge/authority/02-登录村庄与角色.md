## 主线新手引导与配置装备隔离

adapter 按 `TutorialCompleted` 分离保存外观与登录投影。引导中角色的 `271A/68` 使用标志 `+0x0E=0`，`+0x20..+0x43` 发布对应性别的基础初始外观，D6特效与D7宠物置0。`Appearance`、session角色、INI、sidecar、装备所有权及宠物选择保持完整；已完成角色使用保存外观与引导标志2。Network 登录应答的角色存在标志由实际角色状态决定，无角色为0、已有角色为1。无角色账号使用空身份与外观投影；客户端建角兼容项将无角色分支接入原生人物形象创建和命名界面。角色创建成功后解锁后续频道流程。二进制站点、应用与回滚步骤见客户端兼容说明1.1.1节。

引导阶段 `C354` 返回 `C355/728`，携宠标志 `+0x0D=0`。有效 `C353` 原子保存完成状态并返回 `C594/12`；后续 `C354` 按 `C355 -> C476 -> C44C` 初始化普通库存及宠物，首次 `C367/C368` 恢复全部保存装备。非法身份、长度和重复完成事件沿用输入校验与幂等规则。

阶段门控由 adapter 实现。男女各4组装备状态、无角色入口、配置保留与完成后即时恢复已通过数据库及协议构造检查。静态边界见08，发布产物与验证范围见09。

### 一村尼莫引导完成与建角推荐人

一村故事引导完成使用 `C599/88 -> C59A/36`。普通引导提交 `taskType=0, guideId=0..5`，终章提交 `taskType=7, guideId=6`；72字节尾区按不透明数据接受。adapter 在同一事务中更新 `CharacterStoryGuides`、发放一次性奖励并始终返回可消费的 `C59A`。尼莫 `guideId=0` 首次完成增加既有100 Hans奖励；重复提交成功应答但不重复奖励。此前把小整数 guideId 当作普通任务ID拒绝并返回空响应，会使客户端等待完成包而保持输入锁。

建角后的推荐人请求为 `2725/24`，固定16字节GBK姓名；响应为 `2726/28`，`DWORD +8` 结果10/20/30分别表示不存在（含留空）、自己、成功，成功时 `+12` 写16字节规范角色名。客户端结构没有被推荐人奖励字段；当前 adapter 策略在首次成功绑定的同一SQLite事务中给推荐人角色档案增加200推荐点，重传不重复计点。三种输入均返回请求对应响应，不以断开连接处理；结果帧之后继续发送建角完成所需的角色上下文，使确认成功、留空、不存在和自荐均能继续进入游戏。

GUI 的纯新手模式使用独立角色档案：每次生成唯一且隔离的本地账号，初次登录保持无角色状态，并先进入人物形象创建和角色命名界面。完成创建后，新角色固定为等级1、零 Hans/Cash/SP、零库存、零任务行和未完成引导状态，并使用对应性别的完整初始外观。启动器使用独立的中性 runtime profile，固定 `skip_tutorial=0`，并为需要格式化日期的可选权益写入合法且已过期的值 `2000010100`；常规 INI/JSON 保持不变。

## ## 纯新手档持续游玩与地宫前置

纯新手档在创建角色后保留玩家选定的基础外观槽位；教程阶段只暂时屏蔽特效和宠物槽，教程完成或重新进入村庄时恢复已保存的完整外观。纯新手档用户名由启动器单独保存，填写已有用户名即可继续对应角色；历史生成的纯新手账号也支持以其已有角色名找回，已有角色不会被重新创建或覆盖。

纯新手档默认按原始进度逐个开放地宫，只有前一地宫链完成后才允许进入下一地宫。启动器提供“开启全部地宫进入权限”选项，关闭时使用角色真实通关表，开启时沿用便捷开放策略。第五村继续保留既有进入兼容机制，但仍要求前置普通地宫全部满足。

频道选择与重新进入

频道切换保留账号、角色、逻辑槽位、村庄选择器、页面和最后合法坐标。旧连接的代理与后端两侧均完成释放后才允许复用；未完成释放的重叠进入不会占用其他槽位。同一来源存在多个会话时，身份和连接代次保持独立。

新连接重建村庄角色，并重新初始化房间成员关系、战斗状态、过渡状态和一次性标记。延迟角色附件只对创建它的连接代次有效，频道切换后不会落入新场景。

## 页面生命周期

```text
C365/C366  村庄／世界传输与销毁
C367/C368  创建页面和本地角色
C36C       普通页面完成
CB21       移动／活动，以及部分延迟附着门控
```

C365 销毁期间不创建本地角色；C367/C368 保持请求驱动。selector4 不经过 C36C，其 C367/C368 完成后由首个 CB21 触发 C47F 附着；其他选择器保持 `C36C -> 首个 CB21 -> C47F` 顺序。销毁期间不主动添加角色封包。

C365 mode1 的原生坐车费用按出发村与目标村结算：普拉塔诺斯(0)↔桃园(1)双向50金币；桃园(1)↔萨恩(2)、萨恩(2)↔金誉(3)双向70金币；拉米诺斯(4)→金誉(3)为70金币。金誉没有前往拉米诺斯的坐车NPC路径。mode0、同村及未列出的非坐车转换不扣费。当前 managed source 在转换前以在线账号／角色／session原子扣款；余额不足保持原村庄tuple并返回 C366 `BYTE+8=100`，失效会话等非余额失败保留通用状态0，成功状态为200。扣款提交后立即完成城镇切换确认；技能资料和完整角色资料沿独立刷新流程处理，已提交余额保存在角色与会话状态中，后续刷新读取同一结果。客户端状态0映射到消息14／资源1056，状态100映射到独立的消息15／资源1058。

## C368 角色资料载体

```text
+0x30 position_x   u16
+0x32 position_y   u16
+0x34 hp_max       u16
+0x36 mp_max       u16
+0x38 hp_current   u16
+0x3A mp_current   u16
```

这些字段不得套用到 271A、C355、C47F、C377、CF88 或 CF8A 等其他结构。`0x00531BD0` 的 C368 case50024 将 `+0x30/+0x32` 写入页面控制器的浮点位置；`sub_538EE0` 会保存并打印该位置，但 `sub_535530` 只有在 `FirstVillageFlag==0` 时才直接使用它。若该标志为1，角色构造改读当前页面的内建首次进入点，C368 坐标不是最终构造参数。`0x006FC343..0x006FC3A4` 则直接调用角色资料的 HP/MP 设置函数，没有等级查询或按等级推导的运算。等级进度另由271A/CF71/CF88 同步；经验值策略见07。

`FFFF/FFFF` 和旧版钳位结果 `03FF/03FF` 仅作为场景切换哨兵处理，不写入人物档案；需要普通安全回退时使用 `(400,96)`。单轴 `9999` 是地图边界交接值：它在当前切换中原样保留，但不覆盖最后合法坐标，下一页面的合法落点才成为新的持久位置。

明确的合法页面和坐标保持原值，例如 page31 的 `(364,528)` 不会被替换为安全回退点。全新客户端进程在没有可恢复频道状态时使用安全启动页面；频道重新进入则恢复保留的村庄选择器、页面和最后合法坐标，同时重新建立房间与战斗状态。

## 返回城镇、死亡返城与非战斗恢复

正常回城、死亡返城和连续挑战是三个独立边界。2026年9月25日原客户端负面验收撤回了“死亡结算先吞掉第一组离场请求、等待第二组显式请求”的旧策略：客户端在死亡结算页只发送一组 `CF73/CF1D`；旧候选吞掉这一组后没有 `CF74/CF1E`，连接只剩心跳并表现为卡死。

当前候选的死亡返城链为：死亡 `CF87/CF88` 后，第一条 `CF73/8` 即作为玩家离场动作；adapter 构造 `CF74/12`，同时让 worker 执行房间清理；同组 `CF1D/8` 继续到 worker，`CF1E/12 status=200` 排入客户端发送队列后再关闭 worker，并以 `DeathReturn` 提交资源。死亡返回清除战斗专用快照和 P 弹恢复状态，使用部分 HP 与阵亡时剩余 MP；当前部分 HP 策略仍是角色资料最大 HP 的六分之一、最低1。该协议链已完成构造验证，但新候选尚未完成原客户端回城验收。

正常回城使用结算时冻结的当前 HP/MP 快照，最大值统一取 `Character.MaxHp/MaxMp`。C368、C36C 后同步和后续 D8FF 共用该上限与当前值；worker actor 提供的当前值先按配置最大值钳制。现有角色重启时保留数据库当前 HP/MP，启动器不再覆盖。战斗侧权威与优先级由04维护。

城镇与单身公寓使用同一非战斗定时恢复账本，但保持各自场景身份。`C36C` 激活城镇恢复，`C38D/C38F` 切换为公寓恢复；场景进入只同步当前值，不立即增加。此后每约5秒推进一次 `HP +100 / MP +10`，分别封顶当前可见资源上限，并以 D8FF 发布。进入地宫时暂停恢复且不补算错过的 tick。上述均为当前候选策略和构造验证；可见初值、恢复节奏及再次进入地宫后的隔离仍需新版本原客户端验收。

## C47F 附着

C47F/52 针对具体角色。处理函数 `sub_643310` 遍历角色列表，将封包 WORD `+0x08` 与角色 WORD `+0x08` 匹配。

```text
UID 比较        0x00643349..0x00643357
应用外观        0x00643384..0x0064338C
                0x00643478..0x00643484
```

现行构造在远程 C36A 后立即向同一 UID 发送 C47F，携带宠物当前／最大年龄、D0..D5 装备／饰品、D6 效果、D7 宠物和 D8 基础／性别块。`sub_643310` 仅在 `actor+0x3410` 非零时执行完整的宠物阶段／全局分支。因此适配器记录角色与目标的配对，在该角色三个不同的转发 CB21 封包到来时分别重试 C47F，共三次；不是由定时器主动推送三次。对应源码为 `release/components/channel_reentry/current_runtime.inc`，附着重试分支包含立即发送和三次移动触发重试。源码中的实现不等于客户端可见效果已经验收。

角色定向与 `C36A -> immediate C47F -> three distinct CB21/retry C47F pairs`（C36A、立即 C47F、三个不同 CB21 各触发一次 C47F 重试）的顺序已有静态依据和本地自测支持。未保留高阶宠物的原始远程 C47F 通信记录，因此远程宠物／效果的可见恢复仍待运行验证。

本地村庄附着使用独立门控。村庄 C47D 成功后仍立即发送 C368、C47F。selector4 页面或返回重建则在 C367 请求时发送 C368，再于后续首个 CB21 发送一次 C47F，不等待该选择器省略的 C36C。适配器字节验证覆盖了 `C365 -> C366/C379/C389`、`C367 -> C368`、`CB21 -> C47F`；这些结果不证明客户端可见效果。

## 新手教程门控

主教程的进入判定已定位到适配器控制的登录字段：

```text
271A byte +0x0E
  -> sub_4E3830
  -> 角色信息对象 byte +3
C352 成功
  -> sub_4DFAA0 本地 phase5
sub_4DF1E0 phase5
  byte +3 == 0  -> 全局 state12（主教程）
  byte +3 != 0  -> 全局 state1 （跳过教程）
```

Network 模式使用角色资料参数 `skip_tutorial` 控制教程入口。跳过路径仍由请求驱动：C351 只收到 C352，随后客户端直接发出 C354；适配器返回 C355，重新应用角色资料门控，再发送 EA61 scene0。此路径不发送教程 EA61，也不合成 C353。

客户端运行观察记录了 `C351 -> C352 -> C354`，没有 C353，随后出现 `C355 -> EA61(scene0) -> C367/C368`，并观察到直接进入游戏。该观察只证明所记录运行的范围，不代表当前 release 的重新验收。

## 公寓／OzVill 入口调用链

公寓世界属于独立的 GS 场景边界。`C358/8 ENTER_OZVILL` 仅含包头。`C38D/28 REQ_MOVE_MINIROOM` 在 WORD+8 携带 `how_move`，在 +0x0A 携带 16 字节房主 ID；末尾两个声明字节未被已核实的构造函数初始化，必须忽略。`C38E` 成功条件为 BYTE+8=10，读取范围到 +0x6F，最短112字节；包括移动类型、房主／角色摆放数据、访问计数和两条固定 BoardNWall 记录。

运行观察在 t=16s 收到 C358，在 t=17..31s 收到八帧 C38D，因此该样本不支持“请求未到达适配器”的解释。静态分析核实了公寓入口调用链。单房主适配器的 C38E 房主字节取自已配置角色资料，而不回显请求中格式异常／被栈内容污染的房主字段。这是资料来源与适配器自定义策略，不证明原始账号 UID。

房间对象加载是独立的 C392/C393 边界，见03，不是主动发送 C424。相关本地构造结果不证明自有公寓角色可见进入、装修和远程访客角色的完整呈现。普通背包 C40A 路由另见03。
