# 02 登录、村庄页面与角色对象

## 登录与 GS 入口

| 操作码 | 长度 | 作用 |
|---|---:|---|
| 271A | 68 | 登录名、等级、动作门控、外观 |
| C351/C352 | 24/12 | GS 种子、响应低位与校验和初始化 |
| C354/C355 | 8/728 | 村庄角色资料、HP、副本开放数据 |

Network 与 Stand_Alone 是独立的启动模式。Network 初始外观可延迟应用 D6 效果，同时保留 D7 宠物；稍后由请求驱动的 C379 恢复效果。不得将 Network 的延迟行为推广到 Stand_Alone。

## 频道选择与重新进入

```text
新建登录连接10  271B/12 -> 271C/176
选择频道        关闭当前 GS0 和登录连接10；使用选定 IPv4／已保存 GS 端口重连 GS0
重新接入        C351/24 -> C352；成功条件 BYTE+8=100，场景／会话本地值 WORD+0x0A
重建            后续由请求驱动 C367/C368；关闭路径不重建角色
```

重新进入使用 `271B/12 -> 271C/176`，普通初始登录使用 `2719/271A -> 2732 -> 271B`。新登录套接字首帧为271B（`stage0`），来源端点范围内恰好匹配一个存活连接且原适配器会话及注册状态已完全释放时，适配器保留逻辑槽位、UID 和角色资料。新连接重置村庄角色就绪状态、房间成员关系、战斗状态和一次性标记；同 IP 的多个会话保持独立。

## 页面生命周期

```text
C365/C366  村庄／世界传输与销毁
C367/C368  创建页面和本地角色
C36C       普通页面完成
CB21       移动／活动，以及部分延迟附着门控
```

C365 销毁期间不创建本地角色；C367/C368 保持请求驱动。selector4 不经过 C36C，其 C367/C368 完成后由首个 CB21 触发 C47F 附着；其他选择器保持 `C36C -> 首个 CB21 -> C47F` 顺序。销毁期间不主动添加角色封包。

## C368 角色资料载体

```text
+0x30 position_x   u16
+0x32 position_y   u16
+0x34 hp_max       u16
+0x36 mp_max       u16
+0x38 hp_current   u16
+0x3A mp_current   u16
```

这些字段不得套用到 271A、C355、C47F、C377、CF88 或 CF8A 等其他结构。`0x00531BD0` 的 C368 case50024 将 `+0x30/+0x32` 写入页面控制器的浮点位置；首次村庄角色路径 `sub_538EE0` 在 `0x0053D829..0x0053D84D` 消费该位置。`0x006FC343..0x006FC3A4` 则直接调用角色资料的 HP/MP 设置函数，没有等级查询或按等级推导的运算。等级进度另由271A/CF71/CF88 同步；经验值策略见07。

C367/16 page18 的 `FFFF/FFFF` 表示场景哨兵；将其保存为 `65535,65535` 并 clamp 为 `1023,1023` 会使 C368 `+0x30/+0x32` 下发 `03FF/03FF`，客户端据此构造 `CVillageChar(-1,-1)`／`LoadAvatar(-1,99)`。适配器在 C365、C367、CB21 及数据库加载／保存边界过滤哨兵，保留 map/page，并将异常坐标归一化为 `(400,96)`。CB21 哨兵保持原帧路由且不覆盖最后合法坐标。适配器构造与持久化检查通过；原客户端移动验收仍待完成。

## 远程角色 C36A/C36B

```text
C36A 长度       112
+0x3C WORD      角色键载体；已验证安全的测试值为80
+0x3E WORD      已核实角色调用链中的 UID << 4 载体
+0x58 DWORD     ((Y & 0x3FF) << 12) | ((X & 0x3FF) << 2)
+0x6E WORD      角色 UID
C36B 长度       12
```

C36A 结构有效不代表角色可见。还须核实角色注册、控制器／页面归属、场景插入、资源就绪、可见性标记及执行时序。

## C47F 附着

C47F/52 针对具体角色。处理函数 `sub_643310` 遍历角色列表，将封包 WORD `+0x08` 与角色 WORD `+0x08` 匹配。

```text
UID 比较        0x00643349..0x00643357
应用外观        0x00643384..0x0064338C
                0x00643478..0x00643484
```

现行构造在远程 C36A 后立即向同一 UID 发送 C47F，携带宠物当前／最大年龄、D0..D5 装备／饰品、D6 效果、D7 宠物和 D8 基础／性别块。`sub_643310` 仅在 `actor+0x3410` 非零时执行完整的宠物阶段／全局分支。因此适配器记录角色与目标的配对，在该角色三个不同的转发 CB21 封包到来时分别重试 C47F，共三次；不是由定时器主动推送三次。对应源码为 `release/components/channel_reentry/current_runtime.inc`，附着重试分支包含立即发送和三次移动触发重试。源码中的实现不等于客户端可见效果已经验收。

角色定向与 `C36A -> immediate C47F -> three distinct CB21/retry C47F pairs`（C36A、立即 C47F、三个不同 CB21 各触发一次 C47F 重试）的顺序已有静态依据和本地自测支持。未保留高阶宠物的原始远程 C47F 通信记录，因此远程宠物／效果的可见恢复仍待运行验证。

本地村庄附着使用独立门控。村庄 C47D 成功后仍立即发送 C368、C47F。selector4 页面或返回重建则在 C367 请求时发送 C368，再于后续首个 CB21 发送一次 C47F，不等待该选择器省略的 C36C。适配器字节验证覆盖了 `C365 -> C366/C379/C389`、`C367 -> C368`、`CB21 -> C47F`；这些结果不证明客户端可见效果。

## 资料查看与社交路由

- C376/C377 用于查看目标角色资料；远程 C377 不应触发无关的本地 C379/C389 推送。
- CB22 普通社交／表情流量受页面范围限制。
- CB23 使用来源 UID、名称和经过过滤的 GBK 文本；拒绝无效或空文本。
- 活跃连接使用动态 UID21/22 时，不得把合成 UID1 当作当前多人角色。

## 可见性证据范围

## 新手教程门控

主教程的进入判定已定位到适配器控制的登录字段：

```text
271A byte +0x0E
  -> sub_4E3830
  -> 角色信息对象 byte +3
C352 成功
  -> sub_4DFAA0 本地 phase5
sub_4DF1E0 phase5
  byte +3 == 0  -> 全局 state12（主教程）
  byte +3 != 0  -> 全局 state1 （跳过教程）
```

Network 模式使用角色资料参数 `skip_tutorial` 控制教程入口。跳过路径仍由请求驱动：C351 只收到 C352，随后客户端直接发出 C354；适配器返回 C355，重新应用角色资料门控，再发送 EA61 scene0。此路径不发送教程 EA61，也不合成 C353。

客户端运行观察记录了 `C351 -> C352 -> C354`，没有 C353，随后出现 `C355 -> EA61(scene0) -> C367/C368`，并观察到直接进入游戏。该观察只证明所记录运行的范围，不代表当前 release 的重新验收。

## 公寓／OzVill 入口调用链

公寓世界属于独立的 GS 场景边界。`C358/8 ENTER_OZVILL` 仅含包头。`C38D/28 REQ_MOVE_MINIROOM` 在 WORD+8 携带 `how_move`，在 +0x0A 携带 16 字节房主 ID；末尾两个声明字节未被已核实的构造函数初始化，必须忽略。`C38E` 成功条件为 BYTE+8=10，读取范围到 +0x6F，最短112字节；包括移动类型、房主／角色摆放数据、访问计数和两条固定 BoardNWall 记录。

运行观察在 t=16s 收到 C358，在 t=17..31s 收到八帧 C38D，因此该样本不支持“请求未到达适配器”的解释。静态分析核实了公寓入口调用链。单房主适配器的 C38E 房主字节取自已配置角色资料，而不回显请求中格式异常／被栈内容污染的房主字段。这是资料来源与适配器自定义策略，不证明原始账号 UID。

房间对象加载是独立的 C392/C393 边界，见03，不是主动发送 C424。相关本地构造结果不证明自有公寓角色可见进入、装修和远程访客角色的完整呈现。普通背包 C40A 路由另见03。
