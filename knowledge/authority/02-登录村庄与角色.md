# 02 登录、村庄页面与角色对象

## 登录与 GS 入口

| 操作码 | 长度 | 作用 |
|---|---:|---|
| 271A | 68 | 登录名、等级、动作门控、外观 |

`本地模式`是 Network 启动并将客户端与 adapter 绑定到 `127.0.0.1`，不是 Stand_Alone。`社交模式`仍使用同一 Network 协议路径，只把 adapter 绑定地址和客户端发布地址改为明确的局域网 IPv4；Stand_Alone 继续作为独立研究模式。Network 初始外观可延迟应用 D6 效果，同时保留 D7 宠物；稍后由请求驱动的 C379 恢复效果。不得将 Network 的延迟行为推广到 Stand_Alone。

## 主线新手引导与配置装备隔离

所有已建角色从持久化 `Appearance` 恢复登录外观；未完成教程时，仅对 `271A` 的 D6/D7 执行教程安全投影。`Characters.PureNewProfile` 与建角同事务保存，每次登录和频道刷新恢复。`C368`、`C36A` 与尼莫对话前后共享角色保存的外观，档案生命周期由账号和角色身份维护。

引导阶段 `C354` 返回 `C355/728`，携宠标志 `+0x0D=0`。有效 `C353` 原子保存完成状态并返回 `C594/12`；后续 `C354` 按 `C355 -> C476 -> C44C` 初始化普通库存及宠物，首次 `C367/C368` 恢复全部保存装备。非法身份、长度和重复完成事件沿用输入校验与幂等规则。

阶段门控由 adapter 实现。男女各4组装备状态、无角色入口、配置保留与完成后即时恢复已通过数据库及协议构造检查。静态边界见08，发布产物与验证范围见09。

### 一村尼莫引导完成与建角推荐人

一村故事引导完成使用 `C599/88 -> C59A/36`。普通引导提交 `taskType=0, guideId=0..5`，终章提交 `taskType=7, guideId=6`；72字节尾区按不透明数据接受。adapter 在同一事务中更新 `CharacterStoryGuides`、发放一次性奖励并始终返回可消费的 `C59A`。尼莫 `guideId=0` 首次完成向普通游戏道具背包发放 `46000008`（100金币兑换凭证）1张；重复提交成功应答并保持单次领取。凭证使用事务扣除1张并增加100 Hans。

建角后的推荐人请求为 `2725/24`，固定16字节GBK姓名；响应为 `2726/28`，`DWORD +8` 结果10/20/30分别表示不存在（含原始请求中的空名或格式无效）、自己、成功，成功时 `+12` 写16字节规范角色名。adapter 在首次有效绑定的同一SQLite事务中给推荐人角色档案增加200推荐点，重复提交沿用已保存结果。每次请求返回一个完整结果；角色上下文由后续常规登录上下文请求取得。

推荐人结果10／20／30分别创建消息40／41／42；客户端兼容项将三类提示的确认结果接回登录继续流程，并在留空或填写自己姓名时清理本地提交等待旗、恢复填写状态。适配器负责单请求单结果、登录连接作用域、规范姓名和首次有效绑定200推荐点事务。

成功姓名使用16字节NUL结尾GBK字段，适配器校验编码、容量与控制字符；失败结果清零姓名尾区。结果构造、提示状态、等待旗恢复、幂等绑定和后续登录上下文已纳入专项回归。字段与状态调用链见08，完整二进制应用和恢复步骤见客户端兼容说明1.1.2节。
### 启动注册、用户名与来源隔离

注册入口接受 JSON `{LocalAccount, PureNewPlayer}`。社交参与入口请求纯新手创建，并按账号实际状态计算有效模式：无角色账号进入干净创建，已有角色使用其持久化的档案类型、外观、进度和装备。来源 IPv4 隔离后续登录队列；P1/P2/P3 是客户端槽位，账号键保持为用户名。

纯新手生命周期：注册保持无角色状态；`2717/2718` 将提交姓名、性别和36字节外观与 `PureNewProfile=1` 原子保存；`2719/271A` 从数据库恢复档案标志和外观；`C368`、`C36A` 在尼莫及故事引导完成前恢复同一保存形象。验证覆盖响应构造、SQLite 隔离、普通旧账号复用与教程重登。

GUI 的纯新手模式使用独立角色档案。其“构建与启动纯新手档”和“新手档用户名”控件位于普通“用户名／角色显示名”之上；启用后相关跳过教程和全地宫控件被关闭，runtime profile 强制 `skip_tutorial=0` 与 `unlock_all_dungeons=0`。初次登录保持无角色状态，并先进入人物形象创建和角色命名界面。完成创建后，新角色固定为等级1、零 Hans/Cash/SP、零库存、零任务行和未完成引导状态，并使用对应性别的完整初始外观。启动器使用独立的中性 runtime profile，并为需要格式化日期的可选权益写入合法且已过期的值 `2000010100`；常规 INI/JSON 保持不变。

## 纯新手档持续游玩与地宫前置

纯新手档在创建角色后保留玩家选定的基础外观槽位；教程阶段只暂时屏蔽特效和宠物槽，教程完成或重新进入村庄时恢复已保存的完整外观。纯新手档用户名由启动器单独保存，填写已有用户名即可继续对应角色；历史生成的纯新手账号也支持以其已有角色名找回，已有角色不会被重新创建或覆盖。

纯新手档始终按原始进度逐个开放地宫，只有前一地宫链完成后才允许进入下一地宫；该模式不允许开启“全部地宫进入权限”，运行值固定为 `unlock_all_dungeons=0`。第五村继续保留既有进入兼容机制，但仍要求前置普通地宫全部满足。常规角色档是否使用便捷开放策略属于独立配置，不改变纯新手档约束。

频道选择与重新进入

频道切换保留账号、角色、逻辑槽位、村庄选择器、页面和最后合法坐标。旧连接的代理与后端两侧均完成释放后才允许复用；未完成释放的重叠进入不会占用其他槽位。同一来源存在多个会话时，身份和连接代次保持独立。

新连接重建村庄角色，并重新初始化房间成员关系、战斗状态、过渡状态和一次性标记。延迟角色附件只对创建它的连接代次有效，频道切换后不会落入新场景。

## 页面生命周期

```text
C365/C366  村庄／世界传输与销毁
C367/C368  创建页面和本地角色
C36C       普通页面完成
CB21       移动／活动，以及部分延迟附着门控
```

C365负责销毁旧页面，本地角色由C367/C368按请求构造。selector4 的 C367/C368 完成入口初始化，随后发布双向角色快照、C47F附着及静止位置；其他选择器保持C36C完成门控。角色发布统一归属于页面入口完成边界。

C365 mode1 的原生坐车费用按出发村与目标村结算：普拉塔诺斯(0)↔桃园(1)双向50金币；桃园(1)↔萨恩(2)、萨恩(2)↔金誉(3)双向70金币；拉米诺斯(4)→金誉(3)为70金币。金誉没有前往拉米诺斯的坐车NPC路径。mode0、同村及未列出的非坐车转换不扣费。当前 managed source 在转换前以在线账号／角色／session原子扣款；余额不足保持原村庄tuple并返回 C366 `BYTE+8=100`，失效会话等非余额失败保留通用状态0，成功状态为200。扣款提交后立即完成城镇切换确认；技能资料和完整角色资料沿独立刷新流程处理，已提交余额保存在角色与会话状态中，后续刷新读取同一结果。客户端状态0映射到消息14／资源1056，状态100映射到独立的消息15／资源1058。

## C368 角色资料载体

```text
+0x30 position_x   u16
+0x32 position_y   u16
+0x34 hp_max       u16
+0x36 mp_max       u16
+0x38 hp_current   u16
+0x3A mp_current   u16
```

这些字段不得套用到 271A、C355、C47F、C377、CF88 或 CF8A 等其他结构。`0x00531BD0` 的 C368 case50024 将 `+0x30/+0x32` 写入页面控制器的浮点位置；`sub_538EE0` 会保存并打印该位置，但 `sub_535530` 只有在 `FirstVillageFlag==0` 时才直接使用它。若该标志为1，角色构造改读当前页面的内建首次进入点，C368 坐标不是最终构造参数。`0x006FC343..0x006FC3A4` 则直接调用角色资料的 HP/MP 设置函数，没有等级查询或按等级推导的运算。等级进度另由271A/CF71/CF88 同步；经验值策略见07。

`FFFF/FFFF` 和旧版钳位结果 `03FF/03FF` 仅作为场景切换哨兵处理，不写入人物档案；需要普通安全回退时使用 `(400,96)`。单轴 `9999` 是地图边界交接值：它在当前切换中原样保留，但不覆盖最后合法坐标，下一页面的合法落点才成为新的持久位置。

明确的合法页面和坐标保持原值，例如 page31 的 `(364,528)` 不会被替换为安全回退点。全新客户端进程在没有可恢复频道状态时使用安全启动页面；频道重新进入则恢复保留的村庄选择器、页面和最后合法坐标，同时重新建立房间与战斗状态。

## 返回城镇、死亡返城与非战斗恢复

正常回城、死亡返城和连续挑战使用独立状态边界。死亡结算页的首组 `CF73/CF1D` 完成离场，适配器分别返回 `CF74/CF1E`。

当前死亡返城链为：死亡 `CF87/CF88` 后，第一条 `CF73/8` 即作为玩家离场动作；adapter 构造 `CF74/12`，同时让 worker 执行房间清理；同组 `CF1D/8` 继续到 worker，`CF1E/12 status=200` 排入客户端发送队列后再关闭 worker；后续C365/C367负责城镇角色构造，并以 `DeathReturn` 提交资源。死亡返回清除战斗专用快照和 P 弹恢复状态，使用部分 HP 与阵亡时剩余 MP；当前部分 HP 策略仍是角色资料最大 HP 的六分之一、最低1。该协议链已完成构造验证，客户端回城按独立场景验收。

正常回城使用结算时冻结的当前 HP/MP 快照，最大值统一取 `Character.MaxHp/MaxMp`。C368、C36C 后同步和后续 D8FF 共用该上限与当前值；worker actor 提供的当前值先按配置最大值钳制。现有角色重启时保留数据库当前 HP/MP，启动器不再覆盖。战斗侧权威与优先级由04维护。

城镇与单身公寓使用同一非战斗定时恢复账本，但保持各自场景身份。`C36C` 激活城镇恢复，`C38D/C38F` 切换为公寓恢复；场景进入只同步当前值，不立即增加。此后每约5秒推进一次 `HP +100 / MP +10`，分别封顶当前可见资源上限，并以 D8FF 发布。进入地宫时暂停恢复且不补算错过的 tick。上述均为当前策略与构造验证；可见初值、恢复节奏及再次进入地宫后的隔离仍需新版本原客户端验收。

```text

## C47F 附着

C47F/52 针对具体角色。处理函数 `sub_643310` 遍历角色列表，将封包 WORD `+0x08` 与角色 WORD `+0x08` 匹配。

应用外观        0x00643384..0x0064338C
                0x00643478..0x00643484
```

远程 C36A 后立即向同一 UID 发送 C47F，携带宠物当前／最大年龄、D0..D5 装备／饰品、D6 效果、D7 宠物和 D8 基础／性别块。`sub_643310` 在 `actor+0x3410` 非零时执行完整的宠物阶段／全局分支。适配器记录角色与目标的配对，并在该角色三个不同的转发 CB21 到达时分别重试 C47F，共三次。实现位于 `release/components/channel_reentry/current_runtime.inc`；发布范围为立即发送与移动触发重试的构造和生命周期。

角色定向顺序为 `C36A → 立即C47F → 三个不同CB21各触发一次C47F重试`，已完成接口及本地构造验证；高阶宠物与远程效果按客户端场景单独验收。

## 公寓／OzVill 入口调用链

公寓世界属于独立的 GS 场景边界。`C358/8 ENTER_OZVILL` 仅含包头。`C38D/28 REQ_MOVE_MINIROOM` 在 WORD+8 携带 `how_move`，在 +0x0A 携带 16 字节房主 ID；末尾两个声明字节未被已核实的构造函数初始化，必须忽略。`C38E` 成功条件为 BYTE+8=10，读取范围到 +0x6F，最短112字节；包括移动类型、房主／角色摆放数据、访问计数和两条固定 BoardNWall 记录。

## 城镇角色标识

角色资料按被观察角色独立投影，保留其当前城镇页面与最后报告坐标。地宫称号与人物等级分别使用资料中的独立字段；情侣关系显示由双方有效关系及姓名决定。会话刷新同时恢复伴侣姓名与戒指，城镇构造调用统一关系投影；脚底文字同时依赖伴侣姓名、有效戒指和绘制开关。本人的C355设置与他人的C36A显示模式必须分别恢复，具体门控见08。关系变更按同身份先移除再发布更新，参与者和同页其他观察者刷新对应角色的当前资料，保留本地场景。详细字段和调用链由08维护。
