## 启动模式与 GUI 契约

- **本地模式**：使用 Network 参数，adapter、资料注册与客户端目标均为 `127.0.0.1`。“进入 Nanaimo”以用户名／角色显示名文本框选定账号，向已运行的回环adapter提交账号注册，再启动独立客户端。新名字克隆当前管理档并同步全部管理页；首次注册原子导入，已有账号按数据库状态续档。档案复制与只读卡片规则由03维护。
- **社交模式**：自动检测或接受用户填写的特定局域网 IPv4，以该地址绑定登录／世界／资料注册监听并向客户端写入同一地址；不绑定 `0.0.0.0`。GUI 显示检测地址并保存最近使用地址。
- **适配器启动**：社交模式“启动适配器”检查已保存的启动配置存在后，停止本项目已有 adapter／bridge 进程，拒绝复用被其他进程占用的固定端口，再以指定 IPv4 单例启动并验证监听归属。共享服务启动不调用本地角色 `Save-Profile`，不写入本地角色背包或数据库，不受本地纯新手复选框和背包目录校验影响；社交账户由各参与入口单独注册。缺少配置时在停止现有服务之前报错。
- **启动诊断**：背包Python后端在Windows PowerShell 5.1下完整收集stderr与退出码，恢复调用方错误策略后报告完整异常。目录外卡片按03的只读保留规则处理。host验证覆盖启动解耦、完整异常报告和指定局域网IPv4的三端口绑定。
- **参与入口**：P1／P2／P3各有用户名框和参与按钮，用户名定位主机数据库账号。新账号进入纯新手创建，已有角色续用原档，注册结果按来源IPv4入队；各槽位使用独立工作目录与运行时缓存。持久化验证覆盖账号重开和离线卡片保留。
- **纯新手档**：控制行位于普通用户名／角色显示名之上；启用后固定 `skip_tutorial=0`、`unlock_all_dungeons=0`，不能跳过教程或开启全部地宫权限；复用普通 profile 启动的 adapter 时，会话级 C355 门控仍强制保持该限制。
- **目录查询**：“装饰家具查表”使用 `inventory_furniture.json` 及资源图标图集，覆盖781条目录记录，其中775条具有可用图标。图标由InteriorIcon资源解码；缺失项保留明确状态及目录信息。

## 社交模式槽位客户端启动契约

- `gui_launcher/start_social_client.ps1` 是社交参与者的多开入口；本地模式继续直接启动未改写的 `$Client`，不得调用该 helper。
- GUI 完成兼容性检查后，先向多开入口传入槽位、静态资源根目录和独立网络配置执行 `PrepareOnly`；准备成功才注册用户名，然后带客户端参数调用启动入口复核并启动。缓存准备失败不向适配器排入账号。返回对象包含进程、窗口、工作目录、运行时目录和副本身份。
- 槽位副本与源客户端相邻，使用 `Game.openNanaimo-social-NNN.exe`；缓存根目录默认为静态资源根下 `.openNanaimo-social`，其内部按源 SHA-256 和槽位编号隔离 `work`、`runtime` 及元数据。
- 准备状态使用 `social-client.v5` 与 `social-worktree.v2`；文件、源根、缓存根、工作目录、配置哈希和图像解析器共享读补丁共同校验。可写配置与 `Working` 独立，静态资源采用目录映射；`APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 指向槽位目录。图像资源探测保留只读权限并允许并发读取，避免同机多开时将共享读取冲突误判为资源缺失。
- **客户端源哈希变化**：当前哈希槽位尚未生成但源目录旁已有副本时，在同一缓存根内查找该槽位的旧 v4/v5 登记。先校验根路径、工作区／配置、目标哈希及补丁范围，再在内存中仅撤销已登记的互斥体／共享读取改动，要求还原哈希精确等于旧源哈希。唯一合法匹配才把旧副本与登记文件保留到旧槽位 `source-update-backup-*`，按当前客户端生成新工作区与副本；旧工作区不删除。输出包含 `SourceRefreshed`、旧源哈希和备份路径。新准备失败回收本次新槽位并恢复旧副本，保留备份供诊断；显式清理旧源副本同样归档，不能递归清空来源目录或账号数据。
- 槽位复用要求版本、登记身份、内容哈希及唯一匹配全部有效；清理同时校验目录归属与进程状态。验证覆盖源哈希变化、失败回滚、GUI准备与注册顺序，以及P1／P2／P3槽位准备和复用。
- 已运行槽位拒绝重复准备、配置改写和清理；槽位互斥串行化准备及清理。进程身份优先按可解析的绝对可执行路径匹配；当 WMI/进程 API 无法返回路径时，只有对应槽位的 `NanaimoSocNNN` 活动互斥体才将同名进程归属为运行槽位，避免失败启动残留的同名进程阻断重试。启动超时或无窗口失败会回收本次子进程；清理逐目标验证缓存边界，对目录联接只删除联接自身。
- 多开检查覆盖独立名称、配置及目录、参数往返、元数据篡改拒绝、运行槽位保护、失败启动重试和源资源保留。完整二进制站点、应用及回滚步骤见《完整适配器与客户端兼容说明》的社交多开副本章节。
