## 启动和连接

GUI 固定使用本机回环：

```text
11005 登录
11999 角色资料注册
12050 世界入口
```

一键启动顺序为：停止当前运行的 adapter 与客户端 -> 保存资料 -> 校验 adapter 文件闭包并确认 `game.exe` 存在 -> 从使用者自备文件派生并验证家具五字节 Index 重定向、第五村道路及 SSTG/PON 兼容资源 -> 启动完整 adapter -> 等待三个入口 -> 注册资料 -> 启动客户端。启动器保持 emotion EXE 代码不变；表情翻页由有界 C355 情侣姓名／戒指协议保障。C393 提供有界场景快照，本地 getter 负责家具点击路径。客户端整体哈希用于诊断；家具站点按 PE 布局和当前五字节精确匹配。桥接端口供完整 adapter 内部使用，GUI 固定使用 Network 模式，Standalone 构造器用于协议研究。

## 状态一致性

- 等级和经验、货币、库存、任务、宠物及关卡进度由完整 adapter 的持久层保存。
- 进入地宫时，managed 状态通过固定5120字节结构导入桥接组件；离开或结算时按差量事务写回。
- 宠物阶段／等级／经验在 C44C、C379、CF72 和 CF88 间保持同源。
- Hans 与 NaNa 商品按目录币种扣款；整容券按准确库存 identity 消耗。
- 复活次数通过C355／本地CF71恢复。静态CF95/CF96族保持独立；native dungeon复活彩蛋点击为CF83/12 mode1。现行门控使用本地UID D010死亡锁、已观察0x044C战斗坐标和uses>0，不使用仍可能为满值的F102资料HP；worker内部消费一次CF95状态并捕获其响应，客户端仅收到字段完整的CF84/24 variant60。第二WORD不作为Hans门且不扣金币。
- 同一提交ID不重复结算角色经验、宠物经验、货币、卡片或道具。

## 证据边界

当前可以表述为：**静态／源码链闭合，adapter 构造和持久化验证通过。**

仍不能用 host/self-test 代替原客户端试玩。下列项目保留运行验收：

- 宠物页等级、跨阶段提示与多人隔离；
- 整容后的即时动画、重进和重登显示；
- 原客户端 CF83 mode1 复活、次数 33→32、HP／操作恢复，以及准备房间可见数量与 CF71 计数之间的 UI／内存关联；
- 家具选择的完整可见流程；
- 拉米诺斯 C355 载体的原客户端移动；地宫7道路、房间界面、三难度战斗、返回与再次进入；C367/CB21 坐标边界下角色以同页 `(400,96)` 出现、可移动且重登后保持合法坐标；原始客户端文件上的 `+0xDF` 表情翻页边界；
- 好友外部桥、完整竞技／娱乐模式以及全部多人交易边界。
